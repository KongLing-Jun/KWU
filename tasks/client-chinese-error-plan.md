# 客户端中文提示与统一错误拦截实施计划

## 当前根因

客户端各功能自行拼接异常文本，多个入口直接展示 `Error.message`、后端错误码或对象字符串。这样既造成中英文混杂，也可能泄露请求编号、本地路径和服务端细节。Toast 还把错误与普通状态放在同一礼貌播报容器中，错误反馈的可访问性语义不准确。

## 阶段

1. 新增统一错误标准化、中文映射、脱敏日志和去重记录模块。
2. 将 Toast 与全局异常兜底接入统一错误语义。
3. 迁移账户、项目、专家、记忆、设置、自动化、消息等原始错误出口。
4. 收敛模型市场、技能、设置和快捷操作中的英文工程提示。
5. 添加聚焦测试并执行前端完整测试、类型检查、构建和代码守卫。
6. 保持现有 5292/34292 端口与云地址不变，完成浏览器可见回归。

## 风险控制

- 不翻译协议值、配置键、模型 ID 或后端持久化枚举。
- 不修改云平台地址、运行端口或用户配置。
- 不覆盖现有 MCP 任务文档。
- 不提交、不推送、不创建 PR，除非用户另行明确授权。
