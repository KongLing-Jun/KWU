## 实现合同

1. `NewSession` 在调用 controller 前取得并持久化新 topic reservation；登记失败原 tab
   的 topic、session path、正文和 controller 均不变，错误返回前端。
2. controller 成功后再把 reservation 应用到 tab 并持久化；删除当前吞错注释/路径。
3. `Fork` 先登记 fork topic，再调用 controller；源 controller 始终保持在原会话。
4. `forkNamed` 若基础 branch meta 保存失败，调用现有清理 helper 删除本次生成的
   session 及 owned artifacts，再返回原错误；清理失败用组合错误返回并包含路径。
5. App 补写 scope/root/topic/title meta 失败时执行相同边界的桌面清理；不得删除源或
   其他 session。清理失败同样组合原错误、清理错误和 artifact 路径。
6. session 创建失败允许保留已登记、无正文且可见/可复用的话题；不得留下新正文。

## 验收标准

- 组合错误包含原始失败、清理失败和规范化的新 artifact 路径。

## 任务风险

- 预登记顺序可能改变 hook/tab 生命周期；正常与失败路径必须比较调用前后状态。
- 补偿路径误判可能删除源数据；只使用 `ForkSession` 本次返回且校验后的新路径。
- 清理本身可能失败；必须保留原始错误并输出可诊断路径，不得降级成成功。
