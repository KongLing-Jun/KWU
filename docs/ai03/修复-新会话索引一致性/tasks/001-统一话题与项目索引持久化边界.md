## 实现合同

1. 增加 project-file 更新函数：在专用 mutex 内严格读取、规范化、执行内存变更并使用
   现有原子替换保存；不存在视为空，其他 I/O/JSON 错误返回且不得覆盖原字节。
2. 所有生产 project-file RMW 通过该入口；测试 fixture 可保留窄化的原始保存 helper。
3. 增加登记专用严格 title/source/createdAt loader；不得改变共享 topic loader 的现有
   rename/auto-title/model/delete 行为。
4. 新话题登记锁固定在 project-file 锁外层；其他 project writer 不得获取登记锁。
5. 登记完成 scope/root、标题、来源、createdAt、project 存在性和 topic 顺序；每次
   写入错误均向上传递。
6. `CreateTopic` 只在完整登记成功后返回；`EnsureBlankTab` 先登记再创建 session/tab，
   同时保留现有空白 tab/topic 复用与零轮隐藏语义。

## 验收标准

- 覆盖计划 AC-01、AC-04 至 AC-07、AC-10、AC-11 的后端部分。
- project/Global 创建均保存标题、来源、createdAt 和顺序，且新 topic 排在预期位置。
- 损坏 project/topic 登记 JSON 时返回错误，文件字节保持不变。
- 用受控 barrier 交叉执行 topic 创建与 add/remove/reorder/pin；所有成功更新均保留，
  测试有超时保护以发现死锁。
- 任一登记写入失败时不创建 session/tab；失败后原活动 tab 不变。
- 既有空白复用、手工/自动标题优先级、项目操作和迁移测试保持通过。

## 任务风险

- 漏迁一个 project-file writer 会保留丢更新窗口；交付时以完整调用点搜索复核。
- 锁顺序错误可能死锁；用 barrier、超时和嵌套规则共同约束。
- 严格读取误扩散会改变其他 topic 操作；只允许登记专用 loader。
