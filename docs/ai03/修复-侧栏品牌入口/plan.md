# 侧栏品牌入口修复计划

## 背景与现状

创作模式侧栏顶部统一使用 `38px` 上内边距，Windows 无原生菜单安全区需求时品牌区视觉重心偏下。当前品牌名只是静态文本，不能像“新建对话”一样进入空白新会话，也没有展示应用版本。

源码复核确认：

- `desktop/frontend/src/App.tsx` 中“新建对话”直接调用既有 `handleNewTab()`；历史和侧栏收起是相邻的独立按钮。
- `desktop/frontend/src/styles/theme-overrides.css` 的创作模式侧栏规则当前为 `padding: 38px 12px 14px`，应用根节点已有 `app--<platform>` 平台类。
- `desktop/frontend/src/lib/bridge.ts` 已提供异步 `app.Version()`，无需增加后端契约。

## 目标与非目标

目标：

- 仅在 Windows 创作模式将侧栏顶部间距设为 `0`，把品牌内容与原底部间距合并进 `72px` 品牌行，使内容相对品牌到“新建对话”的完整区域居中。
- 将品牌名与动态应用版本组成可访问的两行按钮；点击直接复用 `handleNewTab()`。
- 保持历史和收起按钮为独立兄弟控件。
- 使用轻量 CSS，不增加位移、滤镜、阴影或动画。

非目标：

- 不改变 macOS、Linux、经典或工作台布局。
- 不改变新建会话、历史、收起侧栏或导航的业务逻辑。
- 不增加版本接口、缓存或更新检查行为。

## 方案与边界

在 `App` 中仅当进入创作模式时调用 `app.Version()`，成功且非空时展示格式化版本，失败或空值保持不渲染。版本格式函数去除输入两端空白，并保证恰好一个小写 `v` 前缀（已有大小写 `v` 前缀时不重复）。

创作模式品牌容器继续负责品牌区与工具区排布；左侧新增原生 `button`，右侧历史/收起按钮作为兄弟节点，避免嵌套按钮和事件冒泡。品牌按钮的默认、悬浮和按下状态均保持透明，仅为键盘 `focus-visible` 保留轮廓。Windows 平台使用更具体的 `.app--windows.app--creation` 规则覆盖顶部 padding、品牌行高、行间距和标题/版本行高；其他平台沿用现值。

## 验收标准

- Windows 创作模式侧栏顶部 padding 为 `0`，品牌行与入口高度均为 `72px`、底部 margin 为 `0`，标题/版本行高为 `18px`/`14px`；macOS/Linux 顶部 padding 仍为 `38px`。
- 品牌按钮显示 `BRAND_DISPLAY_NAME`，版本成功读取时在下方显示规范化值。
- 空版本或读取失败时不出现错误占位。
- 点击品牌按钮与“新建对话”调用同一个 `handleNewTab()`；历史与收起仍调用各自处理器。
- 品牌区没有嵌套按钮；键盘焦点清晰可用。
- 品牌区默认、悬浮和按下状态均不出现灰底。
- 新增样式不包含 `transform`、`filter`、`box-shadow` 或动画/过渡。
- 相关契约测试和前端生产构建通过。

## 验证与风险

运行最近的品牌入口契约测试、前端 `pnpm build`、EOL/状态/完整 diff 和 `git diff --check`。主要风险是版本异步返回发生在布局切换之后；effect 使用取消标记避免卸载或离开创作模式后写入。回滚时可整体撤销前端实现提交，不涉及数据迁移。
