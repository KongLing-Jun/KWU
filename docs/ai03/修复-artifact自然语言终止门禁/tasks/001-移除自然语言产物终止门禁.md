## 2. 目标

删除 Root Agent 从普通用户文本推导并强制执行 artifact 完成合同的整条控制链，使普通聊天 final 不再因隐藏的 artifact 推断被撤回、重试或失败，同时保留可见 todo、project checks、running tasks readiness，以及实际文件的安全校验、卡片展示、打开和历史恢复。

## 3. 已证实证据

### 3.1 基线失败

生产 parser 会把以下纯聊天请求解析为 `Required=true` 和一个没有扩展名、没有路径的匿名 target：

```text
请生成一道简短的图表读数练习，轮换覆盖表格、柱状图、折线图、饼图和同比环比。先给出少量明确的模拟数据和问题，再给出答案与解读要点；明确标注数据为示例，不将其描述为真实业务数据。
```

真实 `Agent.Run` 在 provider 连续返回三个可见纯聊天答案时产生：

```text
final-answer readiness failed 3 times: hard requirement: requested workspace artifact has not been verified
```

受控复现命令和完整环境记录见计划第 1.1 节。

### 3.2 根因

根因不是单条正则，而是把自然语言启发式推断接入确定性的 final 硬门禁：

```text
input parser
  -> ArtifactRequirement state/carry
  -> host pre-final verification
  -> evidence target/freshness matcher
  -> rejected final and hidden retry
```

PR #171、#321 和 #362 已多次扩大 parser 规则但未消除误判类别；PR #383 在子任务产物链路遇到同类问题后已删除自然语言完成门禁，改用结构化 writer receipt 和终稿投影。

### 3.3 独立保留能力

- Desktop final 文件卡片由 final 文本和结构化 `artifactPaths` 收集候选后调用 workspace `ReadFile` 验证，不依赖 Root `ArtifactRequirement`。
- `internal/tool/builtin/verifyartifact.go` 独立提供 canonical path、workspace confinement、存在性和普通文件检查。
- 专家团结构化 writer receipt、终稿标记和 artifact path 投影不依赖自然语言 Root gate。

## 6. 必须保留的行为

1. 最新 todo 为 pending/in_progress 且有 progress receipt 时，final 仍被可见 todo readiness 阻止。
2. writer 触发的 AGENTS.md project check 未完成时，final 仍被 project-check readiness 阻止。
3. persistent task 仍运行时，final 仍被 running-task readiness 阻止。
4. 空 final、steer、compaction 和通用最多三次 readiness 重试逻辑保持。
5. 专家团只有成功终稿可投影结构化 writer artifact；失败、中断和非终稿不发布，历史恢复保持。
6. `verify_artifact` builtin 对普通文件、目录、越界和缺失路径的结果保持。
7. boot 继续从模型工具 registry 中排除 `verify_artifact`。
8. Desktop 对真实可读文件显示可打开卡片，对缺失文件不显示假卡片。
