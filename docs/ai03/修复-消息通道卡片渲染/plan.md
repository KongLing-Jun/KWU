# 消息通道卡片渲染兼容修复计划

## 背景与问题

部分 Windows ARM 或低性能设备在消息通道卡片悬浮时出现局部矩形色块。虚拟机 ARM
Windows 11 未能稳定复现，但用户设备与本机均提供了截图证据。色块集中在卡片文本区
或右侧操作图标附近，不影响点击逻辑。

Codegraph 从 `BotsSettingsSection` 追踪到消息通道目录统一使用
`.bot-catalog-card`，右侧图标使用 `.bot-catalog-card__action`。源码和运行时检查确认：

- 卡片悬浮原本同时过渡背景、位移和阴影；
- 父卡片改变背景时，右侧不透明操作图标又独立改变边框与颜色；
- 色块位置与这些父子重绘区域一致，符合低性能 WebView2 合成或失效区域刷新异常。

## 目标与边界

- 仅降低消息通道卡片的悬浮和焦点重绘复杂度。
- 保留卡片点击、连接状态、禁用状态和键盘焦点提示。
- 不修改其他页面卡片、WebView2 启动参数、硬件加速策略或业务逻辑。
- 不要求证明某个特定 GPU 驱动缺陷；以消除前端触发条件和真实设备验收为准。

## 实现方案

- 禁用 `.bot-catalog-card` 的过渡、位移和阴影。
- 悬浮时只改变父卡片边框，不切换整块背景。
- 将右侧操作图标背景改为透明，并取消其独立悬浮变色。
- 使用父卡片 `outline` 保留 `focus-visible` 键盘焦点提示。

不采用全局 `transform: none`，避免影响按钮、拖拽和其他页面的交互动画。

## 验收标准

- QQ、飞书、Lark、微信卡片反复悬浮时不出现文本区或操作图标附近的矩形色块。
- 卡片不发生位移或阴影动画，悬浮边框反馈仍可见。
- Tab 键聚焦卡片时有清晰轮廓，点击行为和连接状态不变。
- 前端生产构建和项目 PR Gate 通过。

## 验证与风险

- 在本地开发页面检查计算样式、页面错误和四张卡片的交互状态。
- 由能够复现色块的用户设备完成最终应用验收。
- 运行 `pnpm build` 和
  `node ./scripts/pr-gate.mjs --base origin/main-v3 --run all`。

剩余风险是特定设备仍可能存在更底层的 WebView2/GPU 驱动问题。若本修复无效，可按
单个 CSS 提交回滚，再评估按设备关闭硬件加速；本修复不涉及数据迁移。
