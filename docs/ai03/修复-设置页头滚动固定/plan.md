# 设置页头滚动固定修复计划

## 背景与问题

桌面端设置中心的右侧内容较长时，用户向下滚动后，当前设置页标题会随内容离开可视区域。用户已确认期望为：标题页头和关闭按钮始终保留在弹窗顶部，只有页头下方的右侧设置内容滚动；左侧导航保持现有独立布局与滚动行为。

基线：`origin/main-v3` @ `b64ede81b89cd77a0cdd946a26fbf45abdd77e77`。Codegraph 索引与工作区源码均基于该提交，直接源码读取已复核关键结构和样式。

## 当前与期望行为

- 当前：`.settings-center__content` 是右侧纵向滚动容器；`SettingsPageShell` 将 `.settings-page__header` 与页面内容一起渲染在该容器内，页头未设置固定定位，因此滚动后必然离开视口。
- 期望：非嵌入式设置弹窗中，页头在右侧内容滚动时保持在初始顶部位置；关闭按钮继续固定在弹窗右上角；左侧导航与页头下方内容维持现有交互。

## 根因与源码证据

- `desktop/frontend/src/features/settings/ui/SettingsPanel.tsx`
  - `.settings-center__content` 的 `<main>` 包含错误横幅、`SettingsPageShell` 与各设置页内容。
  - `SettingsPageShell` 在同一 `.settings-page` 中顺序渲染 `.settings-page__header` 和 `children`，没有独立固定页头层。
  - `.settings-modal__close` 位于 `.settings-center__content` 外，所以关闭按钮不会随右侧内容滚动。
- `desktop/frontend/src/styles/settings.css`
  - `.settings-center__content` 使用 `overflow-y: auto`，是实际滚动容器。
  - `.settings-page__header` 只有间距与分隔线，没有 `position: sticky` 或等价布局约束。
  - `.settings-modal__close` 相对弹窗绝对定位，现有固定行为正确。
- `desktop/frontend/src/styles/features.css`
  - 嵌入式设置工作区复用 `.settings-center__content`，但当前唯一消费者为消息通道机器人页，组件通过 `hideHeader={embedded}` 隐藏页头。
- `desktop/frontend/src/styles/theme-overrides.css`
  - 创建模式会覆盖设置页头的显示、间距和字号；修复必须在最终级联下仍保留固定定位与正确背景。
- Git 追溯显示滚动容器与非固定页头从 `aef5be17` 引入设置中心时即同时存在，属于原始布局契约缺口，而非近期偶发回归。
- 现有测试覆盖设置导航、标题层级和错误时滚动复位，但没有断言页头固定定位。

## 目标

- 让非嵌入式设置中心的页面页头在右侧内容滚动时保持可见且位置稳定。
- 保留关闭按钮、左侧导航、右侧滚动、错误滚动复位和各设置页业务逻辑。
- 用自动化样式契约防止固定页头约束再次丢失。

## 非目标与边界

- 不改变设置项、保存流程、数据加载、标签页路由或后端接口。
- 不改变关闭按钮定位，也不重新设计左侧导航或窄窗口导航。
- 不改变切换设置标签时是否重置滚动位置。
- 不为当前隐藏页头的嵌入式机器人设置页新增页头。
- 不引入新依赖，不调整全局 z-index token 或滚动条样式。

## 选定方案

在现有右侧滚动模型内，将 `.settings-page__header` 设为相对 `.settings-center__content` 的粘性页头，并使用与当前右侧表面一致的背景和局部层级，避免内容从页头下方穿透。粘性偏移应保持页头在未滚动时的现有视觉位置，并针对窄窗口内容内边距同步调整。

选择局部 sticky 方案而不是重构 JSX 为“外部页头 + 内部滚动体”，原因是当前错误横幅、懒加载页和 `contentRef` 的滚动复位都依赖统一滚动容器；拆分会扩大 DOM、滚动与错误展示契约的改动范围。嵌入式消费者隐藏页头，因此局部规则不会改变其可见布局。

## 验收标准

1. 在非嵌入式设置弹窗的“通用”页向下滚动时，页头标题保持在右侧区域的初始顶部位置且持续可见。
2. 滚动内容不会透过页头显示，页头分隔线与背景保持清晰。
3. 关闭按钮始终位于弹窗右上角，左侧导航不随右侧内容滚动。
4. 其他显示页头的设置标签共享同一固定行为；嵌入式机器人设置页继续隐藏页头。
5. 宽窗口与 `max-width: 900px` 的窄窗口布局中，页头偏移分别匹配右侧内容的顶部内边距，不产生首屏跳动或额外空白。
6. 错误横幅触发的右侧滚动复位仍工作，设置项交互与保存行为不变。
7. 相关样式契约测试和前端生产构建通过，无新增相关 console warning/error。

## 验证计划

- 自动化契约：断言 `.settings-page__header` 的 sticky 定位、顶部偏移、背景和层级，并断言窄窗口覆盖使用对应内容内边距。
- 受影响前端验证：运行新增/扩展的设置导航样式测试。
- 应用验收：优先使用 Codex 内置浏览器打开可访问的桌面前端开发页面，进入设置“通用”页，记录滚动前后标题、关闭按钮和左侧导航的可视位置；同时验证窄窗口布局与 console。若桌面桥接无法由浏览器可靠模拟，再使用 Computer Use 验收原生桌面窗口。
- 构建：在 `desktop/frontend` 运行 `pnpm build`。
- 本切片无 Go 或模块文件变更，不运行 Go 测试。
- 当前未授权创建/更新 PR，因此不执行最终 PR Gate；如后续获得 PR 授权，先同步最新 `main-v3`，复跑关键应用路径、相关检查和完整 Gate。

## 风险、兼容与回滚

- 风险：sticky 偏移未对齐响应式内边距会造成页头滚动时跳位；用宽/窄窗口样式契约和应用验收防护。
- 风险：缺少不透明背景或层级过低会让设置项透出；显式设置当前表面背景和局部层级。
- 风险：主题覆盖可能覆盖页头间距；在最终级联下检查计算样式和实际渲染。
- 兼容：只改变 CSS 展示行为，不涉及配置迁移、持久化或 API 兼容。
- 回滚：回退局部页头样式、测试与文档提交即可，设置数据不受影响。
