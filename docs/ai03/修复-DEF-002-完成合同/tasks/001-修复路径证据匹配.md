## 2. 实现依据

- `verifyStepEvidence` 当前对整组 paths 执行三路 OR；L02 的两个 reader/writer 文件与一个
  bash-only README 因此全部被拒绝。
- `normalizePath` 只 clean、统一分隔符及 Windows 大小写，不知道 workspace root。
- `Workspace.Tools` 已为 reader/writer/bash 等工具绑定 `Dir`，但尚未覆盖
  `complete_step`。
- `PathsProvenInSession` 与 per-turn ledger 必须采用相同路径等价规则。
- `diff` 是变更声明，必须继续只由成功 writer 证明。

## 3. 必需行为

1. 为 workspace toolset 中的 `complete_step` 绑定 `Workspace.Dir`；空 Dir 保持现状。
2. 增加窄的 workspace-aware 路径等价能力：
   - 相对路径仅相对绑定 root 解析；
   - 绝对路径 clean 后比较；
   - Windows 保持大小写不敏感；
   - 不使用 basename、任意 suffix、文件存在性或 symlink 猜测。
3. `files` evidence 逐路径判断，每条路径可由以下任一成功来源证明：
   - 当前 turn reader/writer receipt；
   - 当前 turn 成功 bash command mention；
   - session 中非失败 reader/writer call。
4. `diff` 每条路径仍必须匹配当前或 session 成功 writer。
5. 错误列出 evidence 中未匹配路径，不把已匹配路径误报为缺失；保留有上限的实际路径提示。
6. 保留现有公开 ledger helper 的兼容行为，避免改变无关调用者。
7. 更新 `complete_step` schema/description 中路径说明，使模型知道同一 workspace 的规范化
   相对/绝对路径可匹配，但仍应优先引用实际工具路径。

- 一条缺失时只报告该条；
- 失败 bash 不证明路径；

- Workspace.Tools 返回绑定 root 的 complete_step。
