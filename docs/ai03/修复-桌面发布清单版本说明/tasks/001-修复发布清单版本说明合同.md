# 任务 001：修复发布清单版本说明合同

## 目标与预期产物

让所有受支持的桌面发布入口只能生成携带冻结版本说明的 manifest，并修复本地
`Finalize` 漏传说明路径的问题。预期产物是 CLI fail-closed 合同、四类本地调用修复、
覆盖参数与失败路径的自动化测试，以及本任务的完成回执。

## 依赖与执行顺序

- 依赖已批准的 `../plan.md`。
- 单一串行任务，无并行任务或跨 worktree 集成。
- 任务文档先提交；随后实现与聚焦测试形成独立实现提交；若验证发现问题，以新的
  `fix:` 提交修正，不改写已有提交。

## 源码证据与实现依据

- `scripts/desktop-release.ps1` 已验证并持久化冻结 `release-notes.md`，但 target
  GitHub/OSS 及 bootstrap GitHub/OSS manifest 调用均漏传 `--notes-file`。
- `scripts/desktop-actions-publish.ps1` 的四类对应调用均正确传入说明路径。
- `desktop/cmd/sign/main.go` 当前把 `--notes-file` 作为可选参数，省略时会生成空
  `notes`。
- `desktop/cmd/sign/main_test.go` 已证明合法说明会原样进入 GitHub/OSS manifest。
- `scripts/desktop-release-test.ps1` 已捕获本地 Finalize 的 manifest 命令，适合增加
  说明参数断言。
- Codegraph 在本会话不可用；上述证据均在基线
  `8ff823f69bc77d7ea8cad6b0c758d70a2535c38e` 的 worktree 源码中直接复核。

## 实现约束

- `cmd/sign manifest` 的正式 CLI 必须要求 `--notes-file`，且空白说明必须失败。
- manifest 中合法说明保持文件内容，不引入额外格式转换。
- 本地 Finalize 的所有 target 和 bootstrap manifest 必须使用同一冻结快照路径。
- PowerShell 参数数组必须保持整体绑定，末尾位置参数顺序不得变化。
- 修改文件保持仓库 LF EOL。

## 验收标准

1. 不传 `--notes-file` 时，manifest CLI 返回明确错误且不生成发布 manifest。
2. 说明文件不存在或内容为空白时返回错误。
3. 合法说明精确写入 GitHub 与 OSS manifest。
4. 三个 target 的 GitHub/OSS 六条本地 Finalize 命令都恰好包含一次
   `--notes-file <work-root>/desktop-vX.Y.Z/release-notes.md`。
5. bootstrap GitHub/OSS 两条命令也满足相同合同。
6. 既有平台参数、位置参数、DryRun 零写入和发布安全合同继续通过。
7. 完整 PR Gate 通过，分类符合发布基础设施/桌面 Go 实际变更。
