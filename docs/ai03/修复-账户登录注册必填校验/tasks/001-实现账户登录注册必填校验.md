## 任务目标

在账户页主登录/注册表单增加可访问的必填标识和字段级空值校验，确保无效输入不会打开不应开始的真实 CAPTCHA、推进 Fixture 验证或调用云端 bridge；登录/注册切换时同时清除旧横幅和当前表单错误。为同一表单的稳定云端业务错误码增加账户局部中文映射，同时保护未知码 fallback、技术详情和其他页面的全局行为。

## 预期产物

- 主登录字段“手机号、密码”显示红色 `*`。
- 主注册字段“手机号、密码、短信验证码”显示红色 `*`。
- 空值提交同时显示全部对应错误、聚焦第一项并阻止请求。
- 发送验证码前手机号为空时阻止真实/Fixture 验证和短信请求。
- 登录/注册切换清除顶部横幅、字段错误和 `captchaPassed`，保留输入与短信倒计时。
- 自动化测试锁定真实/Fixture 路径、可访问性、状态清理和既有成功行为。
- 常见登录、注册、滑块、短信、限流、网络和账号状态错误显示确定中文横幅；未知码不显示云端原始消息。

## 实现约束

1. 在 `AccountCenter` 内维护 `phone`、`password`、`smsCode` 的本地错误与输入 ref；错误不进入账户 Store。
2. 手机号和短信验证码用 `trim()` 判空；密码只判断空字符串。
3. 认证校验一次返回全部错误，并按手机号、密码、短信验证码顺序聚焦第一项。
4. 手机号/短信验证码只有在 `trim()` 后非空时清除对应错误；密码输入非空即清除。
5. 真实 CAPTCHA 打开前执行前置校验；无效点击必须阻止 SDK 捕获意图和弹窗。
6. `login`、`register`、`sendSMS` 在 `beginOperation`/bridge 前再次执行同一校验并立即返回。
7. Fixture 注册验证按钮空手机号时不得设置 `captchaPassed`；短信按钮和 `sendSMS` 仍保留防御性检查。
8. 模式切换统一清除 `setError(null)`、字段错误和 `captchaPassed`；不清除输入或倒计时。
9. `AccountPasswordField` 的必填、错误、描述关联和 ref 属性保持可选，账号切换调用不传入。
10. 输入使用 `required`、`aria-invalid`、`aria-describedby`；红色星号对辅助技术隐藏，错误文本拥有稳定 ID。
11. 保留 busy、CAPTCHA loading/error retry、cooldown、敏感值清理、成功请求和云端错误展示行为。
12. 账户专属 `knownMessages` 同时用于错误提交和最终横幅 presentation；未知码使用 `account.requestFailed`。
13. 技术详情继续保留安全 code/request ID；structured object 与 Wails string 解析链路均不得回归。

## 验收标准

- 登录全空：两条错误同时出现，手机号获焦点，Fixture/真实模式 `CloudLogin` 调用均为零，真实滑块不启动。
- 登录部分空：只显示缺项，补成有效非空后对应错误立即清除。
- 注册全空：三条错误同时出现，手机号获焦点，`CloudRegister` 调用为零。
- 注册部分空与空白字符：错误集合、清除时机和首错顺序符合判空语义。
- 空手机号验证/发送短信：不弹真实滑块、不推进 Fixture 状态、`CloudSendRegisterSMS` 调用为零。
- 处理函数级防线：绕过按钮前置入口直接触发处理函数仍不调用 bridge。
- 登录错误横幅切注册、注册错误横幅切登录：横幅和字段错误清除；输入、倒计时保留。
- 主表单星号、`required`、`aria-invalid`、`aria-describedby` 正确；账号切换表单无新增星号或字段错误。
- 有效 Fixture/真实登录、发送短信和注册仍各调用一次原 bridge，原请求内容与敏感值生命周期不变。
- 既有密码清理、CAPTCHA 重建、cooldown 和账号切换测试继续通过。
- 已知普通账户码显示已确认中文文案；至少直接覆盖登录凭据错误、注册短信码错误/过期、滑块过期、账号禁用、注册服务不可用、密码解密失败、短信限流和网络失败。
- 未知码显示“云请求失败”，不显示原始消息，且 code/request ID 仍存在于技术详情。
- 无账户局部映射时，全局 `clientErrorPresentation` 对账户码继续使用调用方 fallback。
