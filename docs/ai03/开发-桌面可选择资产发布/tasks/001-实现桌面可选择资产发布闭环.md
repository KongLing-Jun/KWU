## 2. 实现依据

任务基线为 `origin/main-v3@5a189b3213634f8998d4c5144aa735a6549b2a7d`：

- Actions、本地 `Finalize` 和资产校验固定要求 AMD64、ARM64、Universal DMG 全部齐全。
- `desktop/cmd/sign` 已支持平台过滤；云发布已按平台/架构保持单调与同版本幂等，但
  入口仍限制 `full/windows-arm64`，macOS 记录还隐式依赖 Windows。
- 更新器固定读取全局 OSS/GitHub manifest；`Manifest` schema 本身可表达单目标。
- Withdraw 只恢复全局 pointer 并改变整个 GitHub Release 可见性，不适合共享 Release
  内的单目标撤回。
- Windows 签名构建在固定本地机；Actions 只构建 macOS Universal。

Codegraph 索引 `D:\Reasonix@6a20a057...` 仅用于确认 manifest、更新器和缓存授权的调用
范围；索引落后，最终实现必须以最新 worktree 源码、实际 diff 和测试为准。

## 3. 必须实现的闭环

### 目标与发布

- 统一目标为 `windows-amd64`、`windows-arm64`、`macos-universal`；空/未知值失败，
  重复值去重并固定排序，`all` 显式展开。
- 普通确认固定为
  `PUBLISH <tag> TARGETS <normalized-target-list>`；完整迁移固定为
  `PUBLISH <tag> TARGETS windows-amd64,windows-arm64,macos-universal BOOTSTRAP`。
- 未选目标不构建、不下载、不验证、不阻塞，也不改变 pointer/云记录。
- Windows 只在固定本地机按选择构建和签名；Actions 可发布已上传的 Windows Draft
  资产并按选择构建 macOS，不迁移 Windows 证书。
- 每个目标生成 GitHub/OSS manifest；macOS 一份 manifest 同时覆盖两个 Darwin 架构。
- GitHub/OSS 采用追加式同名保护：同名同 SHA 幂等，同名异内容拒绝；同版本可追加
  此前未发布目标，未知资产仍拒绝。
- 云端只发布所选目标，macOS 不依赖 Windows 输入；保持单调、同版本幂等和冲突拒绝。
- 写入顺序固定为 zero-write 预检、immutable 资产/签名/manifests、云记录、目标
  pointer；中断用相同 Tag/目标集合精确续跑。cloud-only 只能补齐同请求云步骤。

### 更新器与迁移

- 运行平台映射到一个目标，以 `channels/stable/<target>/latest.json` 为版本权威。
- 取得目标版本后，精确定位 GitHub 同 Tag 的 `latest-<target>.json` 作为同版本下载
  兜底；版本、平台键或资产身份不一致即拒绝。
- 目标 pointer 不可用时回退冻结的旧全局入口；云端只补充同版本说明，不能发现更高
  版本或授权安装。
- 缓存安装前必须由当前目标 pointer 重新授权；撤回、不可用或身份变化均 fail closed。
- bootstrap 必须一次发布三个目标和旧全局 manifest，并固定 GitHub Latest。后续部分
  发布验证冻结的全局 OSS/GitHub 入口和三个已建立 pointer，不再改变全局入口。
- 不修改 manifest schema、canary、macOS manual-only、安装执行、缓存格式或 PR #254
  的其他 updater 行为。

### 按目标撤回

- Withdraw 确认固定为
  `WITHDRAW <bad_tag> RESTORE <recovery_tag> TARGET <target>`；单行原因另行必填。
- 只恢复 `channels/stable/<target>/latest.json` 并公开读回验证。
- 不改变共享 GitHub Release、其他目标/全局 pointer、immutable 资产或追加式云记录。
- `macos-universal` 作为一个原子目标，同时保留两个 Darwin 平台键。

### 保留的安全边界

- canonical annotated Tag、提交属于 `main-v3`、标签提交内发布说明、minisign、SHA256
  和 cloud required 保持强制。
- `SkipCloud`、非 main-v3、轻量 Tag、emergency source bypass 均拒绝。
- ARM64 SHA 只在选择 ARM64 时要求；DPAPI 文件读取后清理和环境恢复不得回归。
- 发布者可接受质量警告，但资产缺失/目标或 SHA 不符、签名/凭据不可用、降级和远端
  内容冲突必须硬失败。

## 4. 范围

无关 updater 行为。新增文件必须直接服务本合同并经主会话确认。

## 5. 验收与验证

自动化覆盖七种非空目标组合、空/未知/重复/乱序、确认不一致、同版本追加/冲突/降级、
每个目的地中断续跑、bootstrap 门禁、三平台发现与下载、云版本不一致、缓存重授权和
单目标撤回隔离。

聚焦命令至少包括：

```powershell
pwsh scripts/desktop-actions-common-test.ps1
pwsh scripts/desktop-candidates-test.ps1
pwsh scripts/desktop-actions-draft-test.ps1
pwsh scripts/desktop-actions-publish-test.ps1
pwsh scripts/desktop-actions-withdraw-test.ps1
pwsh scripts/desktop-release-test.ps1
pwsh scripts/desktop-release-doc-test.ps1
pwsh scripts/desktop-workflow-test.ps1
Push-Location desktop
go test ./cmd/sign
go test ./cmd/publish-cloud-release
go test .
go test ./internal/update
Pop-Location
```

主会话在 fixture/隔离端验收完整 bootstrap、三平台独立版本、同版本分批、精确续跑、
目标撤回及缓存安装拒绝；对七种组合执行 Actions DryRun，并对 Windows 单/双目标执行
本地 BuildWindows/Finalize DryRun，复跑 DPAPI 清理。不得写生产端。

同步最新 `main-v3` 后运行完整 PR Gate。所有实现、测试、文档、任务回执和应用验收
必须在同一个实现 PR 中交付。

## 6. 风险、回滚与完成回执

误伤或更新器把非权威来源当成新版本。任一发生都阻止提交实现 PR。
