# 001：统一输入框权限入口

## 目标与产物

将 composer 的工具权限控件统一为固定宽度的「图标＋当前权限文案」按钮，继续调用已有的权限浮层和三种模式切换。默认 ask 模式显示「需要批准」，切换后对应显示「自动批准」或「完全访问」。产物为前端代码、聚焦回归测试及本任务完成回执。

## 依据与依赖

- 依赖已批准计划：`docs/ai03/开发-输入框权限入口/plan.md`。
- `Composer.tsx` 已有 `AnchoredPopover`、三项 `menuitemradio`、`chooseCompactApprovalMode` 和焦点回归；仅替换入口呈现并删去勾选图标。
- `session.css` 在 760px 断点切换三段式与图标入口；需改为所有断点固定宽度入口。
- `composer-responsive-toolbar.test.tsx` 是现有响应式与菜单交互的最近测试。

## 允许范围

- `desktop/frontend/src/features/composer/ui/Composer.tsx`
- `desktop/frontend/src/styles/session.css`
- `desktop/frontend/src/styles/theme-overrides.css`
- `desktop/frontend/src/__tests__/composer-responsive-toolbar.test.tsx`
- 本任务文档和同目录 `progress.md`

禁止修改：权限后端/桥接、配置默认值、权限策略及无关工具栏控件。

## 验收与验证

- 所有 composer 容器宽度下只有一个图标＋当前权限文案的固定宽度入口；ask、auto、yolo 分别显示「需要批准」「自动批准」「完全访问」。
- 打开、键盘导航、三项选择、焦点回归与 `aria-checked` 保持；菜单不显示勾选图标，固定 176px 宽度并仅显示图标和名称。
- 运行聚焦测试和 `desktop/frontend` 的 `pnpm build`。
- 使用内置浏览器实际观察普通与窄窗口下的入口、菜单和一次权限切换。
