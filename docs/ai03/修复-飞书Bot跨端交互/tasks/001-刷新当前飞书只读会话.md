## 2. 目标与预期产物

Bot 一轮结束并更新 session 文件后，当前打开的同一飞书只读会话自动重读磁盘历史：

- 磁盘内容变化时显示手机消息和 Agent 完整回复，无需切换会话；
- 正文位于底部时跟随新增内容，上翻阅读时保持消息锚点与偏移；
- 其他 session、普通可编辑会话和已切换目标不受影响；
- 失败或迟到的磁盘读取不清空、覆盖或切换当前正文；
- 不增加 token 流式同步、文件 watcher、固定频率正文轮询或新事件协议。

## 4. 实现合同

### 4.1 触发与读取边界

- 从 `useController` 暴露一个有界的当前 channel history revalidation 入口。
- `App.refreshSessionSurfaces` 每轮只对当前 tab 同时满足
  `readOnly === true`、`sessionPath` 非空、身份仍指向该 path 时调用该入口。
- 使用 `app.PreviewSession(path)` 获取最新磁盘事实；不得使用 `HistoryForTab`，
  不得调用 `OpenChannelSessionForTab` 或重绑当前 Controller。
- 保留现有 revision 事件、10 秒可见窗口 catch-up 和
  `refreshInFlightRef/refreshQueuedRef`；不增加新的计时器或 Bot 专用事件。

### 4.2 竞态、更新与失败语义

- 请求发起时固定 tab ID、surface activation、规范化 session identity、load seq
  和当前 items 引用；响应后任一条件变化即丢弃。
- 当前正文出现运行时尾部或已被其他事件更新时，不得用磁盘快照覆盖。
- 使用 `prepareHistoryRevalidation` 比较指纹；只有变化时 dispatch
  `history_revalidated`，相同内容不产生 React 状态更新。
- 多个 revision 可合并，但旧请求结果不得覆盖更晚请求、tab 切换或 session 切换。
- `PreviewSession` 失败只留下可诊断日志并等待下次 revision/focus catch-up，不清空
  正文、不弹出误导性成功提示。

### 4.3 滚动行为

- 沿用 Transcript 和 session view snapshot 的 pinned/anchor 恢复机制。
- pinned-bottom 在新增内容投影后跟随底部；非 pinned 以原消息锚点及偏移恢复。
- 若现有 reducer/snapshot 不能满足两种行为，可做最小邻近修正并补行为测试；不得
  用无条件 `scrollToBottom` 或重建整个 tab 绕过。
