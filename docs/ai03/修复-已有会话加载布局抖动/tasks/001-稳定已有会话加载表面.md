## 2. 目标与预期产物

## 3. 源码与调用路径证据

任务拆解基于 `origin/main-v3` 的实际工作树源码。Codegraph 索引基线仍用于定位动态调用路径；从该索引基线到任务拆解基线，以下相关前端文件无源码差异，最终判断以当前工作树为准。

| 位置 | 已确认事实 | 实现影响 |
| --- | --- | --- |
| `sessionState.ts` / reducer / Controller | 状态无法区分 blank、existing、unknown；各入口异步写入历史 | 增加显式意图并沿用现有序列、120ms 计时器和 stale-response 守卫 |
| `ListProjectTree` / resolver / cache | 普通行点击目标需包含零 turn，且重复刷新不能退化为目录 I/O | 与 actor-aware resolver 共用选择语义及版本缓存 |
| `topicSessionMatch` / selection / `ProjectNode` | 索引已有 turns 与 BranchMeta 场景，但原传播只到 path | 传播精确 `sessionTurns/scene/sceneState`，运行时值优先 |
| 启动 tab preload / `ListTabs` | Controller ready 前可先发布 tab 元数据 | 复用既有 preload 写 `sessionTurns`；`ListTabs` 不读盘 |
| ProjectTree / App / `SurfaceTarget` | click 延迟 200ms，场景和可取消意图原本未同步建立 | click 内准备 token、目标身份与场景，延迟后复用 |
| App / Composer key | 过渡时 `activeTab` 仍可能是来源 tab | 从 rendered target 生成同源草稿 key |
| Transcript / Welcome / StatusBar | blank 分帧挂载，已有加载无独立展示，live status 可能重复 | 一次挂载完整 blank；已有加载使用唯一提示 |
| 场景首帧 | 零轮目标曾先猜 Office并隐藏内容 | prepared 场景完整展示；绑定前只锁交互，fallback 不迁移 |

入口统一经 App 的共享打开请求或 Controller 入口进入 `beginSurfaceTransition/switchTab/open*/resume*`，再由 `hydrate_start → HistoryForTab → history/hydrate_done|hydrate_error` 完成。

## 4. 已解决的技术决策

### 4.1 状态与动作契约

- 使用 `SessionSurfaceIntent = "blank" | "existing-session" | "unknown"`，State 字段使用 `surfaceIntent`。
- `hydrate_start` 原子替换旧意图；`sessionPath` 只负责身份，精确 turns 的 `>0/0/缺失` 分别映射 existing/blank/unknown，禁止从 reason 或聚合 turns 猜测。
- 项目树普通行与子项传播 resolver 实际会打开目标的 `sessionPath/sessionTurns/scene/sceneState`；零值保留，真正无会话保持空路径，Wails 方法签名不变。
- 现代 draft/locked 场景保真；legacy、缺失、损坏只生成 Office/draft 展示回退，不迁移 sidecar。复用既有索引/缓存，运行时 tab 与激活返回优先。
- 启动恢复复用既有 preload 写 `TabMeta.sessionTurns`；运行期从 Controller 内存校正，`ListTabs` 禁止读 session 文件。
- `newSession`、`clearSession`、`ensureBlankTab`、`ensureBlankSurface` 产生 `blank`，保持清空后回到 creation 空白态的现有行为。
- history/reset/error 动作保留当前目标布局语义；频道/路径恢复必须先建立 transition，再创建空运行时 tab。
- 项目树首次 click 同步 supersede 旧 running/pending 并建立不透明 prepared token；200ms 后只有最新 token 入队。相同行第二击取消并恢复来源，不同目标替换旧意图；pathless token 也可取消但不提前伪造 blank。

### 4.2 渲染目标与草稿 key

- Controller 向 App 暴露当前 `renderedViewTarget`；不得使用格式不同的 `sessionViewKey` 充当 draft key。
- 保留 `composerDraftKeyForTab` 作为唯一 key 生成函数，并导出其结构化身份输入类型；transition target 与激活后的 TabMeta 对同一会话必须产生完全相同的 key。
- App 新增独立的 `composerSessionKey` 计算：transition 时使用 `renderedViewTarget`，其他时候使用 `activeTab/activeTabId`。现有 `conversationStateKey` 保持不变，继续服务工作区面板等非 Composer 状态。
- 不把草稿写入 `SessionViewSnapshot`，不升级 snapshot 版本。

### 4.3 布局、提示和可访问性

- creation 空白布局条件改为“无内容且当前目标不是明确已有会话”；不得把所有 hydrating 都压到底部。
- 已有会话冷加载直接使用空的目标 transcript，不使用 `hydratePlaceholderItems`；目标自身缓存快照仍可立即显示。
- 复用 `useController` 中现有 120ms 计时器，不新增专用 hook。计时器必须受 transition seq/目标身份约束，并在完成、失败、目标切换和卸载时取消。
- Transcript 增加明确的已有会话历史加载展示输入，在空历史区渲染紧凑图标和“正在加载会话…”。
- 该节点使用 `role="status"` 与 `aria-live="polite"`；显示该节点时抑制 StatusBar 的 hydration live status，其他 blank/unknown 水合状态的 StatusBar 行为保持不变。
- 持续旋转只放在 `prefers-reduced-motion: no-preference` 中。
- 明确 blank 的水合不抑制 Welcome；creation 标题、场景入口和 Composer 必须同帧挂载，禁止以延迟或动画遮掩位移。
- 显式新建 pending 默认 Office/draft；仅顶部“新建对话”允许当前已绑定、同 scope/root、精确零轮、无运行/过渡的 blank 重复请求保存当前场景预览。专家/项目树等入口不变，后端返回 meta 最终校正。
- pending 期间一级模式与所有二级场景均用原生 disabled；绑定后复用同一节点启用。现代 locked 仍保持可见且禁用。

### 4.4 编辑与发送

- `surfaceIntent === "existing-session"` 且历史或目标运行时未就绪时，加入 Composer 的 `submitDisabled` 和 `ready` 判定。
- 不加入 textarea 的 `disabled` 判定，保留编辑、粘贴及目标草稿能力。
- 保留并补齐 Controller 的提交守卫；禁止通过 Enter、按钮或直接调用活动表面 `send` 绕过门禁。
- 显式面向其他 tab 的 `sendToTab` 后台操作契约保持不变；新增门禁只作用于当前渲染表面的 `send`。

### 4.5 测试落点

- `tab-switch-hydration` 覆盖 120ms、缓存、失败、频道/路径恢复和目标场景校正；draft/reducer 邻近测试覆盖 key、clear 与意图生命周期。
- `app-chrome-tabs` 与 `project-tree-navigation-intent` 覆盖各入口、同步 click、199/200ms、重命名取消和最新目标竞态。
- `existing-session-loading-presentation`、`welcome-creation-modes` 与 creation 样式测试覆盖唯一 status、完整 Office/Design/Coding 首帧、fallback、锁定及原位启用。
- Go 与 `project-tree-runtime` 测试覆盖 resolver、零 turn、tie-break、缓存、场景 fallback/运行时优先和精确摘要传播。

## 6. 保持行为、风险与控制

- 沿用 `surfaceActivationSeq`、`sessionLoadSeq`、`stillCurrent` 和现有缓存 identity；快速导航只有最后目标可更新状态。
- 缓存继续恢复目标 transcript 与滚动锚点；历史失败沿用现有 Banner；新建/清空后的 blank 继续居中显示 Welcome。
- 文案只进入 `zh.ts`；任何外部行为、API、兼容、错误恢复、持久化或范围变化都必须停止实现并回到计划审批。

| 风险 | 真实触发条件 | 强制控制 |
| --- | --- | --- |
| 草稿错绑或激活后消失 | `ActivateTopic` pending 时用户输入 | 首帧使用目标 key；验证目标保留、来源不污染 |
| 频道恢复闪过 blank | `ensureBlankSurface` 先于 `resume/openChannel` | path transition 必须在创建空运行时表面前启动 |
| 陈旧意图、计时器或历史覆盖新目标 | 200ms click 延迟或 120ms 水合阈值内连续导航 | click 层按 prepared token 取消，App 映射可选 transition id，Controller 继续用序列守卫 |
| 清空后仍保持底部 | existing 状态执行 `clearSession` | clear 明确写入 blank，并做 reducer/Controller 回归 |
| 同一零消息会话从全局或工作空间项目树变成已有布局 | 非空 path 被直接等同于有历史 | 所有 topic/session 节点传播精确 `sessionTurns=0`；覆盖应用重启后的冷树数据 |
| 重启首帧仍误判或 `ListTabs` 退化为 I/O | tab 已恢复但 Controller/project tree 尚未 ready | tab 发布前复用构建 preload；锁定首次快照显式零、legacy 非零、损坏缺失和单次读取 |
| 新建页 Composer 二次位移 | blank 水合统一隐藏 Welcome | blank 水合首帧挂载完整 creation 组合；deferred history 验证节点和布局不变 |
| 零轮持久化场景首帧错误 | sidecar 场景未传播或 stale cache 覆盖运行时 | 同索引传播摘要、运行时优先；覆盖三种场景、两种现代状态及 fallback |
| pending 二级场景仍可操作 | 只锁一级模式或隐藏内容 | 全部按钮原生 disabled；验证不可点击/聚焦及绑定后同节点启用 |
| 重复新建闪 Office或真实新 tab 继承旧场景 | pending 一律 Office 或宽松复用 | 仅顶部新建严格匹配当前 blank 才保留；existing、stale、跨 scope、未知 turns、专家/项目树/过渡均 Office |
| 重复播报 | Transcript 与 StatusBar 同时持有 live status | 已有会话加载节点可见时抑制 StatusBar hydration status |
| 误伤后台发送 | 把表面门禁加到通用 `sendToTab` | 只守卫当前渲染表面 `send`，测试保持后台契约 |
