## 2. 目标

- AMD64/ARM64 安装器在 payload 前精确检测目标文件占用。
- 交互安装要求用户从应用菜单或托盘完全退出，再点击重试。
- 安装器不自动关闭、不强制终止、不等待 60 秒。
- 静默安装遇到占用或检测错误时非零退出，不修改现有安装。
- 应用内更新继续由应用主动保存并退出，保留 `/UPDATEPID`。
- 删除第一版无效的 Windows 退出消息钩子。

## 3. 失败证据与实现依据

| 证据 | 结论 |
| --- | --- |
| ARM64 真机运行 v1.1.0 后打开第一版测试包 | 窗口消失但进程驻留，60 秒后安装失败 |
| `desktop-v1.1.0` Tag | Windows 没有新消息钩子；普通关闭可按用户设置隐藏到后台 |
| 新安装包内的程序 | 写入 payload 前尚未运行，不能帮助 v1.1.0 响应安装关闭 |
| `InstallUpdate` | 启动 `/S /UPDATEPID` 安装器后执行既有 `shutdown` 和 `os.Exit(0)` |
| Restart Manager | 可按精确文件检测占用，无需调用 shutdown |

第一版 x64 验收用“含新钩子的程序”作为被关闭对象，只证明未来版本能响应消息，未覆盖
v1.1.0 → 新包的首次升级。该结果不再作为当前方案的应用验收证据。

## 4. 技术合同

### 4.1 精确检测

- 注册 `$INSTDIR\clouvia-desktop.exe`。
- 品牌迁移仅注册已由现有卸载信息认证的旧目录 `kwu-desktop.exe`。
- 使用 `RmGetList` 判断占用。
- 每次重试建立新 Restart Manager session；所有分支结束 session。
- 初始化、注册或查询失败必须阻止 `wails.files`。
- 安装路径禁止 `RmShutdown`、`RmForceShutdown` 和 `taskkill`。

### 4.2 交互与静默

1. `/UPDATEPID` 等待和品牌迁移认证保持原顺序。
2. 在 WebView2 和 payload 前检测最终安装目录。
3. 交互占用时显示菜单/托盘完全退出说明和“重试 / 取消”。
4. 重试回到检测起点；取消不产生安装副作用。
5. 交互检测失败允许重试或取消。
6. 静默占用或检测失败设置非零退出码并终止。

### 4.3 应用代码

- 删除 `system_quit_windows.go` 和对应测试。
- `system_quit_stub.go` 恢复 `!darwin`，Windows 不安装 WndProc 钩子。
- `system_quit.go` 移除仅由 Windows 第一版使用的清理函数。
- Darwin 系统退出路径和普通关闭到后台行为保持不变。
