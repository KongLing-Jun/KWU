## 实现合同

1. 在 `branch.go` 中保留私有 `readBranchMetaFile` 能力：
   - 非 Windows 第一次 `os.ReadFile` 成功或失败后立即返回；
   - Windows 只对 `syscall.Errno(32)` / `(33)` 重试；
   - 最多 8 次 retry、9 次总读取，等待为 20、40、…、160ms；
   - 预算耗尽或非瞬态错误返回最后一次原始错误。
2. 删除两个原平台生产文件后，不能留下重复 symbol 或 build-tag 行为差异。
3. `mutateBranchMeta` 继续先拒绝空路径与 nil callback，再 acquire canonical sidecar path lock。
4. 新 lock-scoped helper 只负责 load、missing/ensure、callback、strict save：
   - load error 返回 `false, err`；
   - missing existing-only 返回 `false, nil`，不调用 callback；
   - ensure missing 创建默认 meta，callback 失败或 save 失败仍返回 `true, err`；
   - 成功返回 `true, nil`。
5. 外层必须在任何返回或 catalog refresh 前释放锁；仅 `ok && err == nil` 时 refresh。
6. 每个新增或改动函数必须在真实 code guard 中不超过复杂度 10，不用 baseline 例外。

1. 非 Windows 分支仍只执行一次 `os.ReadFile` 并直接返回其 payload/error；Windows 分支完整保留原
   `syscall.Errno(32)` / `(33)` 判断、8 次 retry / 9 次总读取和 20–160ms 线性退避，预算耗尽仍返回
   最后一次原始读取错误。
2. `mutateBranchMeta` 的空路径与 nil callback 校验仍发生在 acquire 前；acquire 后仅调用锁内 helper，
   helper 的 load、missing/ensure、callback、校验/marshal/strict publish 全部处于同一把路径锁内。
3. 锁内 helper 对 load error 返回 `false, err`，对 missing existing-only 返回 `false, nil`，对已存在或
   ensure-created 的 callback/save error 返回 `true, err`；这与原 `ok` 和错误返回合同一致。
4. 外层在检查 `(ok, err)` 或刷新 catalog 前显式 release；只有 `ok && err == nil` 才刷新。公共 API、
   public 调用点和 sidecar schema 未改变。
