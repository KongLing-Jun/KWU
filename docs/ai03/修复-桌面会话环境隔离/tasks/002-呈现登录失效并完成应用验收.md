## 2. 目标与预期产物

把任务 001 产生的 expired 状态呈现为用户已确认的重新登录流程：

- 左下角从 UID 改为“登录已失效”，点击仍先展开菜单；
- 菜单顶部显示失效说明并进入现有登录/注册页；
- 菜单其余 DOM 与行为完全复用 anonymous：保留本地头像上传、余额和套餐支付的
  既有未登录占位入口，不显示旧云数据或退出登录；
- 账户页直接显示现有登录/注册表单和内联重新登录说明；
- expired 不恢复旧云头像、余额、订阅、支付或订阅模型内存可达性；
- anonymous 与 offline 保持现有区别；
- 完成正式构建零出站和受控 dev/test 重新登录应用验收。

不增加中间页、额外按钮、弹窗、Toast 或“清除登录状态”操作。

## 4. UI 与桌面合同

### 4.1 状态判定

- `hasRecoverableCloudIdentity` 只接受 authenticated，以及带稳定 ID 的 offline。
- 增加单一 `requiresReauthentication` 判断 expired；不得把本地 I/O、timeout、
  5xx、限流或 anonymous 纳入。
- expired DTO 应保留顺序保护需要的 binding UID/generation，避免同 generation
  状态被 store 拒收；它们只作不透明内部身份。display name/role 必须清空，任何
  UI、头像和 snapshot 恢复都不得读取 expired UID。
- applyBootstrap 接收 expired 后，余额、订阅、支付和对应 snapshot 内存视图为空；
  不删除磁盘 cache。

### 4.2 侧栏和账户页

- 折叠入口文案为“登录已失效”，仍由现有箭头展开菜单，不直接导航。
- 菜单顶部为“登录状态已失效”与“点击登录 / 注册”；只有该顶部入口打开账户页。
- expired 菜单完整复用 anonymous 的本地头像与头像上传、总余额、套餐支付、设置、
  更新和外观结构；余额与套餐支付使用既有未登录占位值。只替换顶部身份文案，不显示
  UID、旧云头像、云余额、订阅、支付数据或退出登录。
- AccountCenter 复用现有 login/register tabs 与表单，在表单上方内联显示
  “登录状态已失效，请重新登录”。
- 登录原账号、其他账号或注册成功后恢复普通账户 UI；anonymous 始终显示现有
  “登录 / 注册”，不带失效提示。

### 4.3 Billing 内存撤权

- `AccountExpired` 或 binding expired/mismatch/unbound 撤销旧 controller binding，
  清空内存 subscription model catalog，并保持 `authorized=false`。
- `AccountOffline + BindingBound` 保留 scope/catalog 与 retryable gateway 行为。
- 不删除资产、余额、订阅、事件或支付磁盘缓存，不改 billing route。

## 7. 风险、回滚与完成回执

| 风险 | 强制控制 |
| --- | --- |
| expired 被当 anonymous，用户不知道发生过失效 | 独立 helper 和三状态测试 |
| 折叠入口直接跳页，违背确认交互 | 菜单展开与顶部导航分别测试 |
| offline 被清空或丢失 catalog | desktop/frontend 对照测试 |
| UID 或旧云资产从 DTO、头像或 snapshot 回填 | expired DTO、store、hook 三层断言；菜单只读本地头像与空内存占位 |
| billing 内存撤权误删磁盘缓存 | 只验证 manager/catalog 内存状态，不调用 cache Clear |

实现 PR 必须整体回滚；不得只回滚任务 002、恢复旧 UID UI，却保留任务 001 的
强制凭据拒绝。

独立应用验收结论：

- 正式构建在进程级代理阻断下仅出现 updater 的 OSS/GitHub CONNECT，无
  `www.suiyuan-ai.com` CONNECT/HTTP；v1 binding/v2 sessions 未改写，expired
  入口、菜单、表单与同根重启通过。
- Windows dev Wails 在 override 下请求 stub `/api/v1/me` 并收到 `AUTH_REQUIRED`；
  session v3 清空 access/refresh token，持久化 `termination_reason=AUTH_REQUIRED`
  与 `terminated_at`，binding 保留；stub 下线重启不再恢复。
- device、config、workspace/tabs/window、billing、session 均在 override，隔离
  APPDATA 下未创建 `Clouvia`。
- 唯一 dev URL 连接拒绝时保持 offline、token/device/expiry/UID，UI 显示
  `usr_retryable_offline` 而非失效文案。
- 成功认证替换由 `TestRejectedDurableCredentialsCanOnlyBeReplacedBySuccessfulAuthentication`
  及相邻聚焦测试覆盖；fixture 单实例被另一用户进程占用，未干扰该进程，也不构成阻塞。

上述安全边界、持久化、路径隔离、retryable 和表单证据继续有效。主会话随后在同步后
的最终树重建正式桌面程序，并使用 prod legacy fixture 完成最新菜单边界复验：

- 底部入口显示“登录已失效”；展开后顶部显示“登录状态已失效 / 点击登录 / 注册”；
- 菜单显示本地头像与更换头像、总余额“—”、套餐与支付“当前订阅”，以及设置、更新、
  外观；
- 菜单不显示 UID 或退出登录；AccountCenter 显示
  “登录状态已失效，请重新登录”；
- 未执行真实登录：没有可用凭据，且本轮验收目标不要求真实生产认证；登录成功替换
  继续由既有合同测试覆盖，因此不构成验收缺口。
