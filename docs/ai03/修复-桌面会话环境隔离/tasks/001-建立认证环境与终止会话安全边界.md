## 2. 目标与预期产物

实现计划中的认证安全边界：

- durable binding/session 明确绑定 prod/dev 和 dev A/dev B 环境；
- 旧、未知、损坏或环境不匹配的认证文档不返回 token；
- 本地 I/O 错误保持可重试，不改写原凭据；
- 被拒绝凭据可在远端认证成功后通过窄入口安全替换；
- 显式 refresh 和 authenticated request 两条终止路径都清理当前 session
  认证材料、保存稳定原因，并保护 rotation 后的新 session；
- real 与 fixture/test runtime 都显式注入环境身份。

## 4. 实现合同

### 4.1 环境身份

- 新增 `EnvironmentIdentity` 纯值对象，包含完整 SHA-256 `environment_id` 和规范化
  base URL；ID 输入包含构建类别与 URL，并使用无歧义分隔。
- `version == "dev"` 为 development，其余候选/发布版本为 production。
- real runtime 不允许省略身份；fixture/test 使用显式、稳定、非生产身份。
- 读取时 ID 与 URL 必须同时相等。不得把环境字段加入 `BindingScope`、云端 API 或
  dev profile 目录 ID。

### 4.2 Durable 拒绝与认证成功替换

- binding v2、session v3 envelope 保存环境身份；同环境新 schema 正常恢复。
- 旧/未知 schema、环境不匹配或内容不可信返回包内稳定拒绝 code：
  `LEGACY_CREDENTIAL_STATE`、`ENVIRONMENT_MISMATCH`、
  `DURABLE_CREDENTIAL_STATE_INVALID`。
- 语义拒绝不得返回 token；临时 open/read/permission I/O 错误不得改写文件。
- durable 错误分类必须保持 wrapping/`errors.Is` 可用，且不得改变资产、支付、任务等
  非认证 durable repository 的既有读取行为。
- rejected binding 投影为 `BindingExpired` / `AccountExpired`，但 UID、环境和
  原始错误不得进入面向前端的错误文本。
- 只有远端登录/注册结果完成现有校验后，才允许在 path lock 下分别原子替换被拒绝
  binding/session；普通启动、普通 Save 和失败认证不得调用该入口。
- 有可信旧 generation 时使用下一代；没有可信 generation 时必须用聚焦测试证明
  新 scope 不会命中旧缓存。若这需要改变计划中的通用 generation 规则，停止并返回
  主会话，不得自行扩面。
- 任一替换写失败都保持 fail closed；不增加两文件事务。

### 4.3 运行时终止

- `AuthApplication.persistFailure` 与 authenticated request executor 遵循同一
  session scrub/reason 合同，可复用小型 helper。
- 确定性终止清空 access/refresh token、session device ID、所有 token expiry，
  写入 `SessionExpired`、稳定 code 和 UTC 时间；安装级 `cloud/device-id` 不动。
- executor 在现有 `refreshMu` 内比较 observed/current token/session；已 rotation
  时不得覆盖新 session。重复终止必须幂等。
- timeout、断网、5xx、限流和非终止业务错误保留 token 与 offline/retry 语义。
- 不修改 binding，不推进运行时 generation，不接入账号切换锁。

## 6. 验收、验证与风险

覆盖计划 AC-01 至 AC-09，以及 AC-12 的后端重新认证部分。必须包含：

- prod/dev、dev A/dev B、等价 URL、URL 变化和 fixture 身份固定向量；
- v1/v2 旧文档、未知/损坏内容、同环境新 schema、临时 I/O；
- token 零出站证明、重启后 expired、认证成功替换和旧 scope 隔离；
- 两条终止写入路径、迟到终止、重复终止、offline/5xx/限流保持；
- 登录、注册、同账号 refresh、账号切换现有测试不回归。

迭代期运行：

```powershell
go test ./internal/cloud -count=1
go vet ./internal/cloud

cd desktop
go test . -count=1
go vet .
```

最大风险是误拒正常凭据、普通 Save 绕过拒绝状态或迟到错误清掉新 token。固定向量、
typed 读取结果、窄替换入口和 observed/current 测试必须分别锁定这些风险。回滚整个
任务提交即可；不得恢复或重新使用旧 token。
