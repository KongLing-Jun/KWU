## 实现与验收要求

1. 两类卡片默认使用主题表面；普通 hover/focus 只改变背景与 accent 边框且即时生效。
2. 普通规则显式排除 current 与 disabled，current（包括 current+busy）使用更强静态
   主题色表面。
3. 普通 disabled/busy 使用中性静态表面与禁用指针，不使用 opacity 表达；所有
   disabled/busy 均不响应 hover/focus。
4. 清理详情卡的整卡 shadow、transform、animation、will-change 与大面积 transition；
   删除未被组件使用且含阴影的详情卡 current 死规则。
5. 样式契约同时覆盖两类卡的性能禁区、主题表面、accent 边框及状态选择器优先级。
6. 运行两项定向测试与生产构建，检查 EOL、状态和 diff 后创建一个合规提交。
7. 厂商/套餐共用筛选触发器、弹层、普通项与选中项只允许调整 CSS；移除阴影和
   transform/filter/opacity/动画过渡，不改变组件结构、筛选逻辑或键盘交互。
8. 打开弹层前读取触发器已计算的 accent/surface/border/fg token，通过专属 popover
   style 转交；不得修改共享 `AnchoredPopover`。组件测试必须证明 Portal 收到触发器值。
