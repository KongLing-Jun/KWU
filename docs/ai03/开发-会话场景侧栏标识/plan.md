# 创作版侧栏会话场景标识开发计划

## 1. 背景与问题

Desktop 会话已经绑定 `office`、`coding` 或 `design` 顶层场景。场景会写入会话
元数据，并在首次提交时作为隐藏系统提示词的一部分锁定；但会话开始后，创作版
侧栏只显示标题、时间和运行状态，用户无法在进入会话前判断它采用了哪个场景。

创建页中的“文档处理”“网站开发”等具体入口目前只是开局提示词模板，不是持久化
会话属性。本功能只呈现真实持久化的顶层场景，不把提示词模板包装成新的会话配置。

期望在创作版左侧会话标题前增加紧凑的 `办公`、`开发`、`设计` 标签，让用户可以
快速扫视会话所属场景，并为未来可能按场景扩展工具能力保留清晰的会话身份入口。

## 2. 基线与证据

- Codegraph 调查基线：主工作区 `main-v3@6b3321449ecdbe567ab5fe454e410cba29ee2397`；
  用于定位场景、会话树、提示词和刷新路径。
- 执行基线：`origin/main-v3@5e1021a17850071a6bdfcb6d66ed587ac714a775`；
  已在 `core.autocrlf=false` 的独立 worktree 中用直接源码重新确认关键结论。
- `internal/scene/scene.go` 定义三个可选场景、`draft/locked/legacy` 生命周期及各自
  隐藏提示词片段。旧会话缺少场景字段时恢复为 `legacy`，并不获得场景提示词。
- `desktop/tabs.go` 已在主题节点和多运行会话子节点中返回 `scene/sceneState`；
  `projectTreeScenePresentationStatus` 会过滤非法组合，不需要扩展接口或持久化结构。
- `ProjectTree.tsx` 已区分 `classic/workbench/creation` 三种变体。创作版标题、右侧
  时间、运行状态和操作按钮共享同一行，是最小且语义正确的展示扩展点。
- `App.tsx` 在 `turn_done` 后增加 `projectRevision` 并刷新会话树。草稿场景切换只
  更新当前 tab，不刷新树；首版可据此避免增加实时同步路径。
- Desktop 当前固定使用简体中文，`en`、`zh-TW` 仅为旧配置兼容值；本功能不需要
  新增英文界面文案。

## 3. 已确认决策

- 只修改创作版侧栏；经典版和工作台版保持不变。
- 标签位于可见会话标题之前，使用 `办公`、`开发`、`设计` 两字短标签。
- 标签使用低饱和度的暖灰、蓝灰、紫灰，带淡色背景和圆角；不显示方括号或图标。
- 只在 `sceneState === "locked"` 且场景值有效时显示。
- 新建空白会话和仍为 `draft` 的会话不显示，也不增加场景切换时的侧栏实时同步。
- 缺少场景字段的旧会话、`legacy` 状态和非法组合不显示，不能默认标为“办公”。
- 首次对话结束并触发现有会话树刷新后，标签自然出现。
- 若同一主题展开多个运行会话子节点，每个可见节点按自身场景独立呈现。
- 右侧时间、运行状态、置顶/归档操作、当前选中标记和标题截断行为必须保持。

## 4. 目标与非目标

### 目标

- 用户在创作版侧栏进入会话前即可识别已锁定的顶层场景。
- 标签语义与会话真实隐藏提示词配置一致。
- 保持窄侧栏下标题可读、时间稳定、操作按钮可用。
- 使用现有树数据完成纯前端渲染，不引入请求、缓存或状态同步。

### 非目标

- 不允许在已开始的会话中切换场景。
- 不展示具体开局提示词模板或推断未持久化的子场景。
- 不让场景控制、增减或授权工具；不修改任何隐藏提示词。
- 不为草稿会话提供实时侧栏反馈。
- 不修改经典版、工作台版、顶部会话栏、Composer 或 Welcome 布局。
- 不修改 Go/Wails 契约、会话 schema、迁移逻辑、依赖或 PR Gate 路由。

## 5. 用户场景与验收标准

| ID | 场景 | 验收结果 |
| --- | --- | --- |
| AC-01 | 创作版打开已锁定办公会话 | 标题前显示暖灰色 `办公` 标签 |
| AC-02 | 创作版打开已锁定代码会话 | 标题前显示蓝灰色 `开发` 标签 |
| AC-03 | 创作版打开已锁定设计会话 | 标题前显示紫灰色 `设计` 标签 |
| AC-04 | `draft`、`legacy`、缺字段或非法组合 | 不显示标签，也不保留空白占位 |
| AC-05 | 经典版或工作台版查看同一节点 | 不显示场景标签，现有布局不变 |
| AC-06 | 标题较长或侧栏较窄 | 标签保持完整，标题单行省略，右侧时间不被覆盖 |
| AC-07 | 节点处于 active、running、hover、focus 或菜单打开状态 | 选中标记、状态点、时间隐藏和操作按钮交互保持现有行为 |
| AC-08 | 同一主题展开多个运行会话 | 主题行和子会话行各自按节点的锁定场景显示，不串用场景 |
| AC-09 | 首次提交前后 | 提交前不显示；现有 `turn_done` 刷新后显示，无额外请求 |
| AC-10 | 性能与边界 | 会话树加载次数、接口载荷、提示词、工具集合和持久化均不变 |

## 6. 选定方案

### 6.1 展示判定

在前端建立小型纯函数，把 `variant/scene/sceneState` 映射为可选展示对象：

- 只有 `variant === "creation"` 和 `sceneState === "locked"` 才继续匹配。
- 仅接受 `office/coding/design` 三个精确值；任何未知值返回空。
- 展示对象包含短标签、完整场景说明和稳定的 tone class。
- 不调用 `normalizeScenePresentation`，避免其默认办公行为把旧会话误标为办公。

### 6.2 DOM 与样式

- 在 `project-tree__topic-heading` 内、标题文本之前渲染不可交互的场景标签。
- 标签 `flex: 0 0 auto`，标题继续 `min-width: 0` 和 ellipsis，右侧时间列保持不动。
- 使用中文短标签作为可见文本，并通过 `title` 提供完整场景名称。
- 样式仅以 `.app--creation` 为作用域，不能影响 classic/workbench。
- 颜色使用现有主题变量和 `color-mix`，同时覆盖默认主题与
  `data-theme-style` 路径；不引入固定亮色或新设计 token。
- 标签不参与搜索、重命名、点击、右键菜单、快捷键或可聚焦顺序。

### 6.3 刷新与数据

复用 `ProjectNode.scene/sceneState`。不把当前 tab 的草稿场景注入树组件，也不在
`handleSelectScene` 中增加 `projectRevision`。首次回合完成后的既有树刷新会读取
已经锁定的会话元数据，满足首版出现时机。

## 7. 预计影响范围

| 文件/区域 | 预计改动 |
| --- | --- |
| `desktop/frontend/src/features/workspace/ui/ProjectTree.tsx` | 场景展示映射与创作版条件渲染 |
| `desktop/frontend/src/styles/theme-overrides.css` | 仅创作版标签布局与三种低饱和度 tone |
| `desktop/frontend/src/locales/zh.ts` | 三个短标签及必要的完整说明文案 |
| `desktop/frontend/src/__tests__/` 邻近 ProjectTree 测试 | 展示矩阵、变体隔离和节点场景独立性 |
| 本计划后续任务文档 | 实现合同与完成回执 |

最终文件清单以实际 diff 为准。若实现需要修改上述范围之外的产品代码，先判断是否
改变目标、外部行为、接口或风险；有实质变化时停止实现并回到方案审批。

## 8. 兼容性、性能与迁移

- 不改变现有类型、JSON 字段或后端返回，旧版本与旧会话无需迁移。
- 每个可见节点只增加常数次字符串比较和最多一个轻量 `span`；无新增 I/O、订阅、
  定时器或网络请求，性能影响可忽略。
- 经典版和工作台版 DOM 不增加标签；创作版无标签节点不保留占位。
- 回滚前端渲染、样式、文案和测试即可恢复原界面，不影响任何已保存会话。

## 9. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 默认办公归一化误标旧会话 | 不复用带默认值的 presentation helper，严格匹配 locked + 精确场景 |
| 标签挤压长标题或右侧时间 | 标签固定不收缩，标题承担 ellipsis；覆盖窄宽度和长标题验收 |
| 颜色与 active/status 抢层级 | 使用低饱和度主题混色，active 仍由现有标记和文字颜色表达 |
| hover 操作按钮遮挡内容 | 回归现有 side 隐藏与 action 显示路径，不改变其定位和层级 |
| 共享组件误影响其他布局 | 渲染判定和 CSS 都限定 creation，并用测试锁定 classic/workbench 无标签 |
| 主题行与子会话场景串用 | 只读取当前 `node` 的字段，覆盖不同场景的父子节点 fixture |

整体难度和性能风险均低。主要审查点是运行时防御、窄侧栏布局以及共享 ProjectTree
的变体隔离，而不是数据或后端行为。

## 10. 验证计划

### 聚焦自动化

- 为场景展示映射覆盖三种 locked 场景，以及 draft、legacy、缺失和非法输入。
- 渲染创作版树，验证短标签顺序、完整说明、父子节点独立场景和无空占位。
- 用同一 fixture 渲染 classic/workbench，验证场景标签不存在。
- 回归现有 ProjectTree 导航、重命名、时间、状态、快捷键和操作按钮测试。

迭代阶段运行新测试及邻近 ProjectTree 测试。实现稳定后，从
`desktop/frontend` 运行 `pnpm build`；本功能不修改 Go，按项目规则不运行 Go 测试。

### 应用验收

- 优先用 Codex 内置浏览器打开本地可访问的创作版开发界面或确定性 fixture。
- 准备 locked 的办公、开发、设计节点，以及 draft、legacy、长标题和不同场景父子节点。
- 在正常与窄侧栏、浅色与深色主题下检查标签、标题省略、时间、active、hover 和菜单。
- 若浏览器开发表面无法可靠覆盖 Wails 会话树，则使用 Computer Use 在真实 Desktop
  中完成相同路径；只有凭据或人工审美判断无法替代时才请求用户补充验收。

### PR Gate

获得 PR 授权后，先同步最新 `origin/main-v3`，完成关键应用路径复验，再执行根
`AGENTS.md` 的 common checks 和：

```powershell
node ./scripts/pr-gate.mjs --base origin/main-v3 --run all
```

预期分类为 frontend + docs，运行生产构建而不运行 Go。以 Gate 实际分类摘要为准；
任何必需检查失败时不得创建或更新 PR。

## 11. 回滚

本功能没有数据迁移。回滚对应前端实现提交即可移除标签、文案、样式和测试，现有
`scene/sceneState` 元数据、隐藏提示词和会话刷新流程不受影响。

## 12. 后续关口

计划文档获批并合并后，从最新 `main-v3` 创建 Stage 2 独立 worktree，编写一个
自包含的实现任务合同。任务文档合并并获得明确实现授权后，才开始产品代码修改。
计划 PR、任务 PR 和实现 PR 默认均为 Draft，创建、更新、Ready 和合并分别授权，
不得自动合并。
