## 复开原因

首次验收只确认最终时刻存在卡片，没有把“子专家完成后、根任务最终回复前”设为独立观察点。复盘录屏和
事件链后确认：修复版在根任务尚未结束的进度消息上已经提前出现卡片。因此首次通过结论撤销，本任务必须
按修正后的终稿发布合同重新执行。

未修复版同次 A/B 因主模型恰好在终稿中主动写出 Markdown 路径，正文解析也生成了卡片，所以原缺卡没有
稳定复现。这不否定历史截图中的缺陷，但意味着最终验收不能再以“基线必缺、修复版有”作为唯一判断；应
直接验证确定性的发布时机与结构化 fallback。

## 验收场景

1. **针对性成功路径：** 新建主任务，选择技术研发专家团，请其创建带唯一文件名的可运行 HTML 小游戏；
   提示词不要求主回复引用路径，也不夹带结构化回执等实现细节。
2. 子专家 completed lifecycle 出现规范 artifact 与同路径成功 `artifact_observed` 时，确认文件侧栏/子专家
   历史可查看，但主消息区进度回复没有文件卡片。
3. 根任务成功结束后，确认卡片首次出现在最终主回复，且只有一张；即使最终正文不写路径也必须出现。
4. 点击卡片打开正确唯一文件；切换到其他任务再返回，卡片仍只挂在同一最终回复，子专家历史仍存在。
5. **普通用户路径：** 另建全新任务使用原话“帮我写个贪吃蛇”，重复第 2～4 步；若无法控制最终正文，
   以持久化 `final_answer`、结构化 artifact 与卡片路径三者一致作为证据，并注明模型非确定性。
6. **负向路径：** 用确定性测试或可控开发会话产生 root interruption/error 或无最终回答；已完成子产物不得
   被挂到主进度消息。不得为了负例破坏其他用户会话或文件。

## 通过标准

- 卡片发布时间严格为根任务成功最终回复；子专家完成和主专家进度阶段均无主消息卡片。
- 最终正文没有路径时，结构化 fallback 仍显示一张可打开卡片；正文也有等价路径时仍只有一张。
- root failure/interruption/plan approval/no-final 不挂；文件侧栏与子专家历史保持可查看。
- 历史重载依赖持久化 `final_answer` 恢复同一位置，不把未标记进度消息猜成终稿。
- 两个成功场景没有因产物意图正则误判而产生连锁失败，也没有自动切换窗口。
- 应用无崩溃，验收进程已精确停止，证据注明模型非确定性和实际观察结果。
