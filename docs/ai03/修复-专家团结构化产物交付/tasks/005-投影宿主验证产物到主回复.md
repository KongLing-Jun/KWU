## 复开证据

当前实现虽然正确筛选了宿主验证 artifact，但把目标定义为“receipt 之后的最后一个主 assistant”，并在每个
根级 `message` 到达时立即投影。真实修复版运行因此在根任务未结束的进度消息上提前出现文件卡片。

`Agent.Run` 证明根级 `message` 只是一次模型流候选；成功 `turn_done` 才闭合根回合。历史又不保存
`turn_done`，普通中间候选与接受终稿都没有类型标记，所以仅删除 live 的 `message` 投影仍会让历史继续靠
顺序猜测。这是本任务复开的根因，不是 artifact 路径筛选或 `ReadFile` 去重问题。

## 目标与产物

保留 completed lifecycle 的宿主验证路径交集，但只把它挂到宿主明确接受、且根回合成功结束的最终
assistant。live 与历史使用同一个终稿身份；失败、中断、plan approval、被拒候选和无终稿都不挂。

## 必须先证明的旧红

1. **live 提前发布：** completed receipt 后到达根级进度 `message`、尚无 `turn_done`；当前实现已给该
   assistant 写入 `artifactPaths`，修正后必须为空。
2. **live 成功终态：** 同序列随后到达无错误 `turn_done`；只有本回合最后根 assistant 获得一条路径。
3. **live 负例：** `turn_done` 带 error、interrupted、plan approval、无本轮 assistant，或候选收到
   `final_candidate_rejected`；均无新增卡片，也不复用前一轮 assistant。
4. **history 误猜：** receipt 后只有未标记普通 assistant；当前 history helper 会挂路径，修正后必须为空。
5. **history 显式终稿：** receipt 后只有持久化 `final_answer` assistant；重建后只在该条挂路径。
6. **Agent 类型：** readiness retry、空回答 retry、executor handoff retry、待消费 steer 和失败退出均不得
   持久化 `final_answer`；成功返回的最后无工具 assistant 必须持久化该类型。
7. **历史兼容：** readiness rejected candidate 仍被过滤；未标记旧消息只保留正文文件链接行为。

## 实现约束

1. 在既有 `provider.MessageKind` 增加本地 `final_answer`；provider 请求不得携带该本地字段。
2. `Agent.Run` 只在所有最终门禁通过、即将成功返回时持久化 `final_answer`；继续执行或失败的候选不能误标。
3. Desktop 两种历史来源都把该类型投影为可选 `finalAnswer`，旧字段为空时为 false。
4. live 根级 `message` 只记录本回合 candidate id，不运行 artifact 投影；rejection 清除对应 id。
5. 仅成功、非中断、非 plan approval 的 `turn_done` 把本回合 candidate 标成终稿并投影；所有终态都清理
   candidate id。
6. 共享 helper 只选择 receipt 之后、同一 user 边界内显式 `finalAnswer` assistant。
7. 结构化路径仍由 `ReadFile` 验证；与文本别名指向同一文件时只显示一张卡片。
