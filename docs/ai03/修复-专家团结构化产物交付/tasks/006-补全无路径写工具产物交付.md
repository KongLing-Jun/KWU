## 问题与根因

`newSubagentArtifactHandoff` 只在 `artifactRequirementFromInput(prompt).Required` 时保存 before snapshot。
带路径的 `write_file` 等工具可由 receipt 直接产生 writer artifact；`bash` 和 opaque generator 的参数没有
结构化输出路径，只能依靠 workspace delta。因此未命中正则的自然实现提示可以写出文件，但 handoff 为空。

任务 004 已证明“实现单文件贪吃蛇浏览器游戏”不命中正则。现有 opaque writer 测试也证明无路径生成器是
受支持的真实工具形态。任务 003 的两个实际样本均走 writer，未覆盖二者组合。

## 目标与非目标

目标：无路径写工具产生的本轮文件，不依赖 prompt 正则；只有被子专家成功终稿明确作为 Markdown 文件链接
声明的 workspace delta 才进入结构化 handoff。带路径 writer 行为、来源优先级和根终稿发布时机不变。

非目标：不把全部工作区增量当产物，不解析用户或主专家正文，不增加动作词/产品词，不增加 event/schema、
不修改前端，不承诺恢复未声明路径的无路径写入，不处理历史记录迁移。

## 必须先证明的 A 侧旧红

使用确定性 provider 和工具 fixture，不依赖真实模型随机选择：

1. 子任务 prompt 为不命中 `artifactRequirementFromInput` 的自然实现表达。
2. 无路径 writer 成功新增目标 HTML，同时新增一个未在终稿声明的普通日志/YML。
3. 子专家成功终稿包含目标 HTML 的规范 Markdown 链接。
4. 未修复提交的 task/A2A 回执缺少目标 HTML；测试必须先失败并保存命令与失败断言。
5. 带路径 writer、失败 writer、工作区外路径、隐藏 snapshot、未链接 snapshot 和同路径 writer 优先均有邻近保护。

## 实现约束

1. writer-capable 子任务取得受限 before snapshot，不以 prompt 作为采集开关。
2. `runSubSessionWithArtifactOutcome` 和 parallel 分支在成功 answer 已知后解析 handoff；失败结果不得新增 snapshot artifact。
3. writer receipt 候选仍直接验证并交付；snapshot-only 候选必须与最终 answer 中的 Markdown 链接目标匹配。
4. 链接目标必须规范化后位于 owning workspace，并与本轮新增/修改文件等价；支持 Windows/Unix 分隔符和绝对/工作区相对链接。
5. writer 与 snapshot 指向同一规范路径时 writer 优先；未链接日志/YML、隐藏目录、旧文件和工作区外路径均排除。
6. 子专家系统提示以“本地交付物”定义声明义务，不枚举自然语言动作词。
