# 任务 003：修复无权模型切换闪烁

## 状态与目标

- 状态：已完成并通过原生 dev 验收。
- 目标：切换到当前身份无权使用的已有会话模型时，从第一个目标帧直接显示
  “请选择模型”，不经过源模型或无权目标模型。
- 依赖：任务 001、002 已完成；沿用当前独立 worktree 和分支，小步提交。

## 根因与证据

- `App.tsx` 在 `surfaceTransitionActive` 时把目标会话原始 `modelRef` 直接传给
  Composer，并把模型选择标记为 pending。
- `ModelSwitcher.tsx` 在 pending 且 label 非空时会格式化并显示该原始 ref，即使
  当前 entitlement 已明确不允许该 `subscription_pool` 模型。
- transition 结束后，订阅模型才经 `filterModelInfosForSubscriptionAccess` 过滤；
  `resolveCurrentModel` 找不到目标，最终显示“请选择模型”。
- 原生 dev 复现：从“你好4”切换到“当前是v4”，354–533ms 仍为
  `gpt/gpt-5.5`，654–1032ms 为无权目标 `deepseek-v4-pro`，1149ms 后才为
  “请选择模型”。

## 允许范围

- App 的目标模型展示投影及账号级已结算模型目录快照。
- `ModelSwitcher` 的显式 resolved/choose/pending 展示状态和轻量淡入样式。
- 直接相邻的纯函数、组件/源码契约测试与本计划目录文档。

## 禁止范围

- 不修改会话保存的模型、BranchMeta、模型 fallback、套餐规则或发送门禁。
- 不新增网络请求、依赖、数据库迁移或账号权限持久化。
- 不改变 BYOK 模型的独立配置语义，不自动替用户选择替代模型。

## 实现约束

1. 判定依据是当前身份对目标路由的 entitlement，不是“是否登录”布尔值。
2. 明确 allowed 显示目标模型；明确 unavailable 显示“请选择模型”。
3. 权限或目录 unknown 时固定模型控件布局、视觉文字为空且控件禁用；只在最终
   结果后淡入一次，不显示骨架条或潜在无权模型。
4. 复用已结算账号目录快照，切换时不发起额外请求；账号 scope 变化后旧快照
   不得参与新身份判定。
5. 目标模型 identity 在目标权限结算前保持展示所有权，迟到的源 tab facts 不得
   覆盖目标投影。

## 验收标准

1. 非登录和明确套餐不匹配的 `subscription_pool` 目标首帧即为“请选择模型”，
   连续采样中没有源模型或无权目标模型。
2. 当前套餐允许的目标直接显示目标模型；BYOK 会话保持原行为。
3. unknown 状态不改变 Composer 宽高，不显示文字；权威结果只淡入一次。
4. 会话保存的 `modelRef`/`billingSource` 不被清空或重写，发送门禁不变。
5. 聚焦测试、Playwright、生产构建、仓库检查及原生 dev 验收通过。

## 完成回执

### 交付内容

- `App.tsx` 保留当前账号 scope 的已结算模型目录快照，并在会话切换/目标 facts
  加载期间对目标订阅模型先做 entitlement 投影；显式用户切模型不进入该路径。
- 新增纯函数区分 `resolved`、`choose`、`pending`：明确无权直接选择模型，未知
  权限隐藏临时文字，BYOK 不依赖订阅权限。
- `ModelSwitcher` 保持既有固定宽度，只对最终标签做 120ms 淡入；减少动态效果
  偏好下关闭过渡。
- 未写入或清空会话 `modelRef`/`billingSource`，未改变套餐规则、fallback、发送
  门禁、网络请求和依赖。
