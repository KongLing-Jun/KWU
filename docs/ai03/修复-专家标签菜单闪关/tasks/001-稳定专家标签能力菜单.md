## 2. 目标与实现依据

目标是让活动专家标签成为能力面板的合法触发入口：首次点击稳定打开“召唤专家”
分区，第二次点击关闭，独立 `×` 继续只清除专家。

最新基线 `origin/main-v3@e94d08a43e7abb5ade21e4b9367695b21e15c113` 的直接源码
证据：

| 位置 | 当前事实 | 必需结果 |
| --- | --- | --- |
| `Composer.tsx` | `intentMenuAnchorRef` 只绑定“＋”，专家标签也调用 `openIntentMenu` | 共享面板的所有标签内触发入口进入同一 anchor 边界 |
| `AnchoredPopover.tsx` | document click 排除 popover 和唯一 anchor 后关闭 | 不修改通用规则；让专家标签正确属于 anchor |
| `composer-goal-toggle.test.tsx` | 已覆盖“＋”和独立 `×`，未点击专家标签 | 新增首次打开保持、选中状态、二次关闭 |

失败路径为：专家标签 React click 打开 → 同一次原生 click 到达 document → target
不在“＋”anchor 或 popover → `onClose`。用户截图中的“先打开马上关闭”与该路径一致。

- 当前专家在最近专家列表中的选中态
- 选择当前专家不重复切换，选择其他专家沿用现有回调
- 独立 `×` 只调用一次清除且不打开面板
- 关闭动画、焦点、禁用态和现有可访问性属性

## 4. 实现要求

1. 先扩展现有测试并在未修代码上运行，记录目标断言失败，证明回归可捕获。
2. 将现有意图控制组用作 `AnchoredPopover` 的共享 anchor；不得增加时序延迟或事件
   全局拦截。
3. anchor 左边界仍与“＋”一致，面板定位与样式不变。
4. 测试至少证明：
   - 专家标签首次 click 后 `aria-expanded=true`；
   - 面板在 event/timer flush 后仍为 open；
   - “召唤专家”分区显示，当前专家条目为 active；
   - 第二次 click 进入关闭并在现有动画后消失；
   - 之后独立 `×` 仍只清除一次且不打开面板。
5. 更新本文件完成回执，不在文档中记录包含本回执的提交哈希。
6. 在高度不超过 760px 的视口限制面板为约 70vw × 65vh，并让左右栏各自纵向滚动；
   大视口尺寸和双栏结构保持不变。

## 5. 验证

聚焦自动化：

```powershell
pnpm exec tsx src/__tests__/composer-goal-toggle.test.tsx
pnpm exec tsx src/__tests__/anchored-popover-scroll.test.tsx
pnpm exec tsx src/__tests__/expert-contract.test.ts

```

真实交互：

1. 打开带活动专家的 Composer。
2. 点击专家标签，确认完整面板稳定显示“召唤专家”和当前专家选中。
3. 再次点击标签并确认关闭。
4. 重开后点击外部、按 `Esc`，分别确认关闭。
5. 点击独立 `×`，确认专家被清除且面板未打开。

最终执行项目 common checks 和 `node ./scripts/pr-gate.mjs --base origin/main-v3 --run all`。
若最终 diff 只有文档和前端 TSX，按分类不运行 Go 测试；前端必须完成生产构建。
