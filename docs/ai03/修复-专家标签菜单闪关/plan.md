# 专家标签菜单闪关修复计划

## 1. 背景与问题

用户从“专家 → 选择专家 → 召唤专家”进入带专家的新会话后，点击 Composer 底部已选
专家标签，完整的“添加上下文和能力”面板会短暂出现后立即关闭。预期是面板稳定打开
并默认定位到“召唤专家”，当前专家继续保持选中；取消专家只由标签右侧独立的 `×`
按钮执行。

已确认的关闭规则为：再次点击专家标签、点击面板外或按 `Esc` 关闭面板。首次修复处理
专家标签被误判为外部点击的问题；用户在实际 Wails 应用验收时进一步发现，小高度窗口
中面板使用接近整个视口的高度，遮挡了几乎全部页面主体。本计划追加紧凑小屏布局，不
改变专家选择协议或其他 Composer 行为。

## 2. 基线、当前行为与证据

- 实施基线：`origin/main-v3@e94d08a43e7abb5ade21e4b9367695b21e15c113`。
- 初始 Codegraph 导航来自只读主工作区 `10c4581d44f787fd87ee9d612faaf02dce022750`；
  工作树基线更新后，以下结论均由工作树源码、Git blame 和用户截图重新确认。
- `Composer.tsx` 的 `intentMenuAnchorRef` 只绑定“＋”按钮；专家标签是相邻的独立按钮，
  但复用同一个 `openIntentMenu("experts")` 状态。
- `AnchoredPopover.tsx` 在 document `click` 上关闭弹层，只把弹层节点和
  `anchorRef.current` 视为内部点击。
- 因此专家标签的 React `onClick` 先打开弹层，同一次 click 随后到达 document；
  其 target 不属于“＋”锚点或弹层，被立即执行 `onClose`，形成闪开闪关。
- `composer-goal-toggle.test.tsx` 已覆盖“＋”入口和独立 `×` 清除，但没有覆盖专家标签
  打开、保持、再次关闭的事件传播路径。
- 该组合由 `1c2799cae` 的统一能力菜单改造引入；共享弹层的外部关闭逻辑更早存在。
- `.composer-add-menu` 当前高度为 `min(540px, calc(100vh - 24px))`；在约 610px 高的
  实际窗口中会占用接近全部内容高度，且导航与内容面板均为 `overflow: hidden`。

## 3. 目标与非目标

### 目标

- 已选专家标签首次点击后稳定打开完整能力面板，并默认显示“召唤专家”分区。
- 面板显示当前专家的选中状态，不触发清除或重复选择。
- 再次点击专家标签关闭面板；外部点击和 `Esc` 关闭行为保持不变。
- 独立 `×` 仍是唯一直接取消当前专家的标签内控件，且不会误开面板。
- 保留“＋”入口、面板定位、关闭动画和可访问性状态。
- 小高度窗口使用紧凑双栏浮层：宽度不超过约 70vw，高度不超过约 65vh，导航和内容
  在空间不足时各自内部滚动，页面主体保持明显可见。

### 非目标

- 不改变专家/专家团创建新会话、最近专家、切换确认或提示词组装。
- 不修改 Go、Wails、持久化、专家目录、后端契约或数据。
- 不把能力面板改成单栏、抽屉或全屏模式，不重设计 Composer、Tooltip 或菜单内容。
- 不修改 `AnchoredPopover` 的通用 API 或其他弹层消费者。

## 4. 验收标准

| ID | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 新会话已有活动专家，首次点击专家标签 | 完整能力面板保持打开，不闪关 |
| AC-02 | 面板打开后的内容 | 默认位于“召唤专家”，当前专家显示选中 |
| AC-03 | 再次点击专家标签 | 进入现有关闭动画并关闭 |
| AC-04 | 点击面板外或按 `Esc` | 沿用现有关闭行为 |
| AC-05 | 点击独立 `×` | 只调用一次清除专家，不打开能力面板 |
| AC-06 | 点击“＋” | 原有打开/再次点击关闭行为不变 |
| AC-07 | 范围 | 无后端、数据、依赖和 code guard baseline 变更；样式只改能力面板小屏尺寸与滚动 |
| AC-08 | 视口高度不超过 760px | 面板宽度不超过约 70vw、高度不超过约 65vh，页面主体仍明显可见 |
| AC-09 | 紧凑面板内容超出可用高度 | 左侧导航和右侧内容可内部滚动，无裁切或页面级滚动陷阱 |

## 5. 选定方案与替代方案

将现有 `.composer-meta__control--intent` 控制组登记为能力面板的共享锚点，而不是只登记
其中的“＋”按钮。该控制组本来就拥有所有复用此面板的意图入口；使用其左边界定位不会
改变面板的起始位置，同时让“＋”和专家标签都进入外部点击排除范围。

预计改动：

- `Composer.tsx`：把锚点 ref 类型调整为控制组元素，并将 ref 从“＋”移到已有容器。
- `composer-goal-toggle.test.tsx`：增加专家标签打开后保持、当前专家选中、二次点击关闭
  的回归覆盖，并保留独立 `×` 断言。
- `session.css`：仅在小高度媒体条件下限制面板占屏比例并启用双栏内部滚动。
- `browser-smoke.spec.ts`：在小视口验证面板尺寸上限与滚动容器。
- 本主题任务完成回执和进展快照。

不采用以下方案：

- 专家标签 `stopPropagation`：改动更小，但把正确性依赖在合成/原生事件传播细节上，
  没有表达“多个入口共享一个弹层锚点”的真实结构。
- 给 `AnchoredPopover` 增加额外排除 ref：会扩大共享组件 API 和影响面，本问题无需。
- 延迟注册外部点击或延迟打开：只能掩盖竞态，增加时序风险。

## 6. 兼容性、风险与回滚

该改动只改变外部点击命中边界，不改变状态或协议，无迁移。主要风险及控制：

| 风险 | 控制 |
| --- | --- |
| 面板定位轻微变化 | 共享控制组与原“＋”左边界一致；真实渲染验证位置 |
| 其他意图按钮不再被当作外部点击 | 它们已有显式选择/关闭处理；聚焦回归“＋”、专家标签和 `×` |
| 二次点击受关闭动画影响 | 断言 `aria-expanded`/关闭状态并等待现有动画完成 |
| 只在测试 DOM 生效 | 通过浏览器实际点击、DOM 状态和截图验证 |
| 紧凑高度裁切导航或内容 | 双栏分别启用纵向滚动，并用小视口真实渲染验证 |

若回归，整体回滚 Composer 锚点与对应测试即可；不存在数据回滚。

## 7. 验证计划

迭代验证：

```powershell
pnpm exec tsx src/__tests__/composer-goal-toggle.test.tsx
pnpm exec tsx src/__tests__/anchored-popover-scroll.test.tsx
pnpm exec tsx src/__tests__/expert-contract.test.ts
pnpm build
```

真实交互流程：带活动专家的 Composer → 点击专家标签 → 确认能力面板稳定显示“召唤
专家”和当前专家选中 → 缩小到约 900×620，确认面板不再占满主体且双栏可滚动 → 再次
点击标签关闭 → 重开后点击外部关闭 → 点击独立 `×` 只清除专家。优先使用 Codex内置
浏览器，并在实际 Wails 小窗口中由用户复核视觉占屏比例。

最终提交前检查实际 diff、EOL、任务回执和项目 common checks；获得 PR 授权后再同步
最新 `main-v3` 并运行完整 `pr-gate.mjs`。未获得授权前不推送或创建 PR。
