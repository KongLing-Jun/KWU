## 目标与预期产物

## 必须保持的行为

- 任务保存失败和立即执行失败继续显示现有可见错误。
- 禁用任务不能手动执行。
- 不同任务可以独立触发，不因另一任务运行而全局禁用。
- 运行详情只能用后端真实 `runId` 打开；本地启动行不可点击。
- 会话创建/打开、取消、开关、删除、调度和最近三条历史行为不变。
- 关闭页面不取消后端运行；重开后从真实 manifest 恢复。

## 实现合同

- 以 task ID 保存本次前端触发状态，至少能区分触发起点和请求代次。
- 点击处理必须先同步登记触发状态，再启动异步 TriggerNow。
- `TaskCard` 接收明确的 `triggering` 状态。
- 当本次真实 manifest 尚未出现时，显示独立、不可点击、可访问的“启动中”行。
- 立即执行按钮在 `!task.enabled || triggering` 时禁用，并保留明确的 title/aria-label 或等价忙碌语义。
- 提取按 task ID 读取最近三条记录的逻辑。
- 所有 `runsByTask` 更新使用函数式、按 task ID 合并，不能覆盖其他任务的新记录。
- TriggerNow pending 时约每 500ms 刷新当前 task；第一轮不得等待 TriggerNow 完成。
- 使用代次、令牌或等价机制拒绝旧的初始加载、旧轮询和旧触发结果。
- 真实 run 是否属于本次触发，必须按任务和触发起点判断；不得仅因存在历史记录而隐藏启动状态。
- TriggerNow resolve/reject 后最终刷新再清理；单次 ListRuns 失败不得清空记录，pending 时继续轮询。
- 任务删除、面板关闭、组件卸载或请求代次失效时停止对应 UI 轮询。
- 失效异步返回不得恢复旧状态或产生卸载更新警告；清理不得取消后台运行。

## 应用验收

实现者完成聚焦测试后，由主会话或独立验证代理执行：

1. 新建“每次新建会话”的任务，首次执行只点击一次。
2. 确认同一交互周期出现“启动中”，左侧可同时出现新会话。
3. 不刷新页面，确认真实状态自动出现；本任务按钮禁用，另一任务仍可执行；终态后按钮恢复且详情可打开。
4. 关闭并重开页面，确认记录一致且无控制台警告。

优先使用内置浏览器；Wails 绑定必须由桌面运行时提供时改用 Computer Use 控制 `wails dev`。工具无法可靠完成或需要凭据时才请求用户验收。

## 停止与回退条件

- 需要修改 TriggerNow 后端生命周期/租约合同，或 Wails 不允许 pending 时并发 ListRuns；
- 无法按任务隔离轮询，或必须引入全局状态；
- 验收、外部行为、兼容性、风险或回滚假设实质变化。

回滚应整体撤销前端状态、轮询、启动行和测试，恢复当前 TriggerNow 完成后整页刷新的行为。
