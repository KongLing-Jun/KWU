# “查看更多”层级修复计划

## 问题与目标

侧栏任务列表与工作空间会话列表的“查看更多 / 收起”目前拥有独立按钮缩进，看起来像分区级操作。目标是让它与所在列表中的会话行处于同一视觉层级，同时保留展开、收起、隐藏数量和活动会话自动展开行为。

## 已确认设计

- 任务区“查看更多”与全局会话行使用相同的行高、左右边界、圆角和浅色悬浮反馈。
- 工作空间下“查看更多”与该工作空间的直接会话子项使用相同的层级缩进；不提升为工作空间标题操作。
- 不显示会话图标、时间、状态或菜单；它仍然只是列表分页操作。
- 不引入 transform、filter、阴影或额外合成层，兼容低性能设备。

## 源码依据与影响范围

- `ProjectTree.tsx` 的 `renderShowMoreButton` 同时服务任务和工作空间两种入口，业务行为可保持不变。
- 任务入口位于 `project-tree__task-section-body`，工作空间入口位于根项目的直接子项之后。
- `overlays.css` 和 `base.css` 分别定义通用及 workbench 覆盖；当前 workspace modifier 通过额外 margin/padding 单独定位。
- 直接消费者为 `ProjectTree`；现有 `project-tree-show-more.test.tsx` 覆盖数量、展开/收起、工作空间隔离和活动项恢复。

## 范围与非目标

仅调整“查看更多 / 收起”的结构性 class/样式和相关契约测试。不修改阈值、数据过滤、点击回调、工作空间树结构、会话导航或持久化行为。

## 验收标准

1. 任务“查看更多”与普通任务会话行处于同一视觉层级。
2. 每个工作空间的“查看更多”与其直接会话子项处于同一视觉层级。
3. hover/focus 只使用单层浅色背景与既有焦点反馈，无位移和高成本效果。
4. 展开、收起、隐藏数量、不同工作空间独立状态及活动项行为保持不变。
5. 相关测试与 `pnpm build` 通过。

## 风险与回滚

风险限于 creation/workbench 侧栏缩进和命中区域。可通过回退本实现提交恢复；业务状态不需要迁移。
