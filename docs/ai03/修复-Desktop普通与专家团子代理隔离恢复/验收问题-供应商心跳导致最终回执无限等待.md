# 验收问题：供应商心跳导致最终回执无限等待

## 现象与影响

任务008真实专家团验收中，同一代码审查成员在第二轮于21:48:09写入6502字节的`README.md`，并于
21:48:13完成`read_file`回读；之后子 Session不再新增可见消息或`[DONE]`，但到自定义 OpenAI兼容
供应商`192.168.10.231:8080`的连接持续为 Established。等待超过十分钟后人工停止，child终态为
interrupted/killed。

父专家在此期间累计反复调用`wait_task`；整场两轮验收共11次`wait_task`、42次模型请求和907,036
raw token。Provider后台也显示后期单次请求约30k输入、约29.2k缓存命中。该 token不是全部由卡住
阶段产生，但每次有界等待返回`running`都会让父模型重新携带完整上下文，显著放大请求与缓存读取成本。

## 已核验证据

- 文件写入与回读总计约4秒，卡点不在磁盘I/O、task派发、工具权限或任务008的tool scope。
- 同一成员两轮ref和`toolSchemaHash`稳定，第二轮`write_file/read_file`均成功。
- `internal/provider/openai/openai.go`的`readStream`在每次`scanner.Scan()`成功后、解析SSE行之前调用
  `pingStreamActivity`。注释心跳、空行或其他不产生模型进展的行也会重置120秒idle timer。
- 真实父JSONL中的`wait_task`由模型显式传入60或120秒；每次返回running后都会新增一次父模型请求。
  `expertTeamWaitDefaultTimeoutSeconds = 1`及`expertTeamBoundedWaitTool`虽仍在源码中，但当前专家控制
  路径未实例化该包装器，属于应清理的遗留代码，不能作为本次真实行为的解释。
- 907,036由42条Provider usage逐条累加，正好对应父Agent 26次和两个child各8次模型请求；其中
  891,188为prompt、15,848为completion、754,688为cache hit，未发现Desktop重复累计。
- 停止原成员后，主专家又自动启动测试策略成员做复核；使用父轮总停止后两个running成员均收敛为
  interrupted，供应商活动连接归零，已写文件和成员历史保留。

## 已确认修复合同

本问题独立于任务008，进入任务010，普通聊天与专家团复用同一修复：

1. 网络连续120秒没有任何数据时，当前Provider请求按连接停滞处理。
2. 只有心跳、连续5分钟没有reasoning、content、tool、usage或明确终态时，按无进展超时处理；心跳
   不能续期该计时器。
3. 单次模型请求绝对上限10分钟；整个child task不设总时长上限，工具调用继续使用各自超时合同。
4. 收到`finish_reason`后最多等待5秒收集`[DONE]`/usage；兼容供应商遗漏`[DONE]`，不能无限保持连接。
5. 完全没有有效输出的无进展请求只安全重试一次；已有输出或tool call时不自动重放，避免重复副作用。
6. 请求最终失败时仅把当前child turn标记为failed，保留Session、历史和已完成工具记录，并通过
   `wait_task`向父Agent返回结构化失败回执。
7. 模型可见的`wait_task`不再暴露`timeout_seconds`；调用后由宿主等待job终态或父context取消。等待
   期间父Provider请求数必须保持不变。
8. 现有token聚合继续表示会话累计且按executor/subagent分源，不把907,036误写为父Agent单独用量；
   本任务不扩展BYOK计费账本或token UI。

## 修复后验收结论

- 开发应用重建、重启后，以自然请求派发代码审查与测试策略两个持久child；两者均完成多个工具轮次并
  进入`completed`，父Agent只调用一次`wait_task`并在两个终态到齐后继续，没有有界超时返回running。
- `wait_task`等待期间父JSONL不增长，child终态后才恢复写入，说明父Provider没有轮询；父页面也没有
  串入child内部工具消息。
- 本轮按JSONL中的assistant记录精确对应20次Provider请求：父10次、两个child各5次。结束时telemetry
  累计61次请求、1,676,933 raw token，但它包含该Session此前多轮；因为本轮开始前未保存telemetry
  快照，不把累计值或推测差值写成本轮独立token。
- heartbeat-only故障、一次无输出安全重放、已有输出不重放、finish grace和failed终态由可控Provider
  聚焦测试覆盖；真实Provider正常链路完成，不通过篡改用户Provider制造故障。
