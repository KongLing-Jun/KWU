## 目标

让专家团成员头像旁的状态点准确表达该成员最近一次持久化`task`：未调用不显示，运行中黄色，完成绿色，
失败/停止/取消/超时/异常中断红色；状态在当前页面及时更新，并在会话切换或应用重启后保持一致。

## 当前证据与根因

- `desktop/subagent_history.go`的`ExpertTeamForTab`已经从owned child meta返回持久化`Status`，重载真源
  无需新增。
- `ExpertTeamSession.tsx`把未知状态默认映射成`stopped`并无条件渲染状态点，所以未调用/未知成员会出现
  灰黑点。
- `session.css`把`running`设为主题`accent`并附4px外圈；当前主题下呈现为黑点带外圈，而非黄色。
- 后台child只更新meta时没有内容无关的状态通知，因此终态通常要切换页面才重新读取。
- 父task lifecycle直接覆盖显示会产生旧running压住新meta终态的竞态；采用“meta唯一真源、事件仅触发
  重读”可同时覆盖超快child和重载恢复，不需要轮询或第二套显示状态。

## 实现合同

1. child meta是当前与重载后的唯一显示真源；状态事件只携带ref/status并触发`ExpertTeamForTab`重读。
2. 只处理`task`，不从`parallel_tasks`推导成员状态。
3. running和终态meta成功写入后才发送事件；超快child即使早于父task卡也不能丢失刷新信号。
4. 同一成员再次派发时立即回黄，最近任务终态覆盖旧绿/红；状态不变时不执行周期性文件读取。
5. 仅追加内容无关event/wire字段，不新增bridge接口、sidecar字段或child meta格式。

## 验收标准

- 未调用或未知状态不显示点。
- running为黄色且无外圈；completed为绿色；failed/interrupted及停止/取消为红色。
- running/终态落盘后无需切页或父wait回执即可更新；无状态变化时不轮询。
- 再次派发同一成员会从旧终态切回黄色。
- 切换会话、刷新和完整重启后从child meta恢复相同终态。
- 无running成员时没有持续定时刷新；`parallel_tasks`不会改变成员点。
