# 任务 010：终止无进展子请求并改为事件等待

## 状态与依赖

- 状态：已实现并完成自动化与真实应用验收。
- 串行组：Serial-10。
- 依赖：任务001至009、任务008真实续写验收、供应商请求与本地telemetry核对。
- 未授权push、PR或合并；文档与实现分别小步提交。

## 目标

关闭“工具已完成，但最后一次模型请求只有心跳且没有终态，child永久running”的链路；同时消除
父Agent通过有界`wait_task`反复重新请求模型导致的token放大。

## 实现合同

1. OpenAI兼容stream分别维护transport idle、semantic progress、request wall clock和finish grace。
2. 默认值固定为120秒、5分钟、10分钟和5秒；测试可以使用更短注入值。
3. heartbeat、空行和无内容JSON不算semantic progress；reasoning、content、tool、usage、
   `finish_reason`和`[DONE]`算进展或终态。
4. 本任务新增的progress timeout或request wall-clock timeout，仅在完全无有效输出时最多透明重放
   一次；保留既有连接reset合同，不能在已输出后重放。
5. 最终Provider错误沿现有`runPersistedTaskTurn -> SaveFailed -> jobs.Failed`链路收口；不得删除Session。
6. 普通与专家`wait_task`都不向模型暴露`timeout_seconds`，内部等待job终态或父context取消。
7. 清理未接入的`expertTeamBoundedWaitTool`及其1秒常量，避免源码继续表达虚假行为。
8. 不修改token累计算法、BYOK计费账本、ContextPanel、Task Tree或专家目录资源。

## 禁止范围

- 新建子代理runtime、第二套专家等待器或跨Provider fallback。
- 给child task设置总时长上限。
- 在已有模型输出或tool call后自动重放请求。
- 修改用户拥有的`.workbuddy/`或历史Session文件。

## 自动化验收

- heartbeat持续发送但无semantic progress时按progress timeout关闭，不被transport activity续期。
- 正常reasoning/content/tool进展刷新progress窗口，`[DONE]`正常完成。
- `finish_reason`后供应商遗漏`[DONE]`时在grace窗口结束，不无限等待。
- 完全无输出的无进展请求只重试一次；第二次失败返回明确错误。
- 已有输出后超时不重放，返回`StreamInterruptedError`。
- 普通与专家`wait_task`schema均无`timeout_seconds`，一次调用等待到completed/failed/interrupted。
- 父context取消可立即打断等待，child历史与终态规则不回归。

## 真实应用验收

使用开发环境的自定义Provider和`gpt/gpt-5.6-luna`执行不限定工具顺序的自然任务：

1. 专家团自主派发至少一个需要多个工具轮次的成员任务。
2. 父Agent进入`wait_task`后记录Provider父请求数；child终态前该数不得增长。
3. 正常场景必须收到completed回执并由父Agent整合；父页面不串入child消息。
4. 使用可控heartbeat-only fixture复验超时与一次安全重试，最终必须failed而非永久running。
5. 检查child历史、已完成工具记录、会话切换和重启恢复；失败turn仍可续写同一Session。
6. 对比修复前42请求/907,036 raw token样本，记录新请求数与token，但不设脱离任务形状的固定总量门槛。
