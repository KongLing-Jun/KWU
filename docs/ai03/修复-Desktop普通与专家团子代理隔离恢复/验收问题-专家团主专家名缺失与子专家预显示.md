# 验收发现问题：专家团主专家名缺失与子专家头像预显示

## 1. 文档地位

本文记录 Serial-01 至 Serial-05 修复完成后，真实 Desktop 验收中发现的 UI 缺陷。只记录证据和根因，
**不包含解决方案**。

后续独立源码复核更正：`team.name`是团队名，不是 lead 名字；当前 sidecar/view 只保存子成员，缺少
配置中 `kind=lead`的身份快照。此前把 `team.name`称为“主专家实际名字”的段落均以本更正为准。
用户已确认：首 tab 显示配置 lead 的名字和头像；子成员只有取得可信 `subagentRef`后才显示。

**修复状态（任务006）**：代码、自动化与真实 Desktop 复验通过。sidecar/view 已增加 lead 快照；
bridge 和前端只显示当前父会话拥有可信 ref 的成员；聚焦测试 11/11 和生产构建通过。真实复验确认
未派发时仅显示“架构顾问”，task 绑定后才出现“代码审查专家”，切换会话和重启后均恢复。

## 2. 问题描述

### 2.1 现象

用户在 Desktop 选择"代码交付专家团"后，专家团头像栏（`ExpertTeamSessionView` 底部 tab 列表）出现
两个问题：

**问题 A：主专家（主理人）位置显示通用文案而非实际名字，且无头像图片**

头像栏第一个位置（主专家 tab）的 label 渲染了通用文案"主专家"（来自 `t("agentWorkspace.overview")`，
zh.ts:480），而非主专家的实际名字（如"代码交付专家"）。头像位置只有 avatar 容器的蓝色 CSS 底色，
没有专家头像图片（`<img>` 未渲染）。

用户口述"主专家名字和头像都没了"——实际含义是：名字显示的是通用文案"主专家"而非主专家实际名字；
头像位置只有蓝色底色，没有头像图片。后三个子专家位置正常显示名字和头像。

**问题 B：子专家全部预显示**

所有配置的子专家都显示在头像栏，包括尚未派发任务的。鼠标悬浮未派发的成员时显示"尚未派发任务"
（zh.ts:488）。用户期望：只有被 `task` 派发了任务的子专家才出现，未派发的不显示。

### 2.2 用户影响

- 主专家位置显示通用文案"主专家"而非实际名字，用户无法辨认当前主理人是谁。
- 主专家位置无头像图片，只有蓝色底色，视觉上与子专家不一致。
- 子专家全部预显示（含未派发的），给用户"一堆还没干活的专家"的视觉噪音。

## 3. 复现方法

### 3.1 前提条件

- Desktop 处于专家团模式（`team_active`）。
- 已配置专家团（如"代码交付专家团"），含主专家和若干子专家。

### 3.2 复现步骤

1. 在 Desktop 选择一个专家团（如"代码交付专家团"）。
2. 观察底部专家团头像栏。

### 3.3 预期 vs 实际

**问题 A 预期**：第一个 tab 显示主专家的实际名字（如"代码交付专家"）和正确头像图片。
**问题 A 实际**：第一个 tab 显示通用文案"主专家"；头像位置只有蓝色 CSS 底色，无头像图片。

**问题 B 预期**：只有被 `task` 派发了任务的子专家才出现在头像栏。
**问题 B 实际**：所有配置的子专家都出现，未派发的用 disabled 状态标记，悬浮显示"尚未派发任务"。

## 5. 根因分析

本节按确定性分为三部分。

### 5.1 已确认部分

#### 5.1.1 子专家全部预显示（问题 B）

`ExpertTeamSession.tsx:151` 的 `team.members.map(...)` 不按 `subagentRef` 过滤，所有配置成员都
渲染为 tab。未派发的成员用 `disabled` + `title="尚未派发任务"` 标记，但仍然显示头像和名字。

**确认结论**：当前实现是"全部预显示 + disabled 标记"，不是"按需出现"。用户期望"按需出现"。

#### 5.1.2 主专家 tab label 使用通用文案而非实际名字（问题 A）

`ExpertTeamSession.tsx:149` 显示 `t("agentWorkspace.overview")` = "主专家"（zh.ts:480）。这是一个
通用文案；现有 view 没有提供配置 `kind=lead`成员的名字。

Go 端 `ExpertTeamForTab`（subagent_history.go:51）返回 `Name: meta.ExpertName`（团队名），前端把它用于
头像查找同样无法得到 lead 头像。lead 身份必须来自选择专家团时配置的 `kind=lead`成员快照。

用户确认：第一个位置确实渲染了"主专家"三个字，但不是主专家的实际名字。

**确认结论**：label 显示通用文案"主专家"；`team.name`也不是正确替代，真正缺失的是 lead 快照。

#### 5.1.3 主专家头像找不到图片，渲染了 fallback（问题 A）

`ExpertTeamSession.tsx:120`：`const teamAvatar = expertAvatarSrcForName(team.name)`。

用户确认：第一个位置没有头像图片，只有 avatar 容器的蓝色 CSS 底色。这说明 `expertAvatarSrcForName(team.name)`
返回了 undefined，走了 fallback 分支（line 147 的 `initialFor(t("agentWorkspace.overview"))` = "主"）。

avatar 容器的蓝色底色来自 CSS `.agent-workspace__avatar--main` 的背景样式，不是头像图片。

**确认结论**：`expertAvatarSrcForName(team.name)` 找不到主专家的头像图，渲染了 fallback。

### 5.2 未确认部分

#### 5.2.1 `expertAvatarSrcForName` 为什么找不到主专家头像

`expertAvatarSrcForName(team.name)`用团队名查询成员头像；专家团配置实际把 lead 头像放在
`kind=lead`成员的 `AvatarKey`。当前 view 没有 lead 字段，所以前端无法使用正确身份和头像。

#### 5.2.2 `team.name` 的实际运行时值

源码已确认 `meta.ExpertName`来自所选专家定义的团队名；内置 `code-delivery-team`的 lead 是配置成员
“架构顾问”，团队名为“代码交付专家团”，二者不能混用。

### 5.3 产品设计层面

以下两点是**已确认的产品设计问题**，独立于 5.2 的未确认部分：

1. **主专家 tab 应显示实际名字**：当前 label 用 `t("agentWorkspace.overview")` = "主专家"通用文案，
   应使用配置 `kind=lead`成员的持久快照，不能使用团队名 `team.name`。
2. **子专家应按需出现**：当前全部预显示，应改为只显示有 `subagentRef` 的成员。

## 6. 影响范围

### 6.1 直接受影响场景

- **专家团模式（team_active）**：主专家 tab 显示通用文案 + 无头像；子专家全部预显示。
- **专家团归档（team_archived）**：同样使用 `ExpertTeamSessionView`，问题 A 同样存在。问题 B 在
  archived 状态下取决于成员是否都有 `subagentRef`（已派发过的成员有 ref，未派发的无 ref 仍会预显示）。

### 6.2 不受影响场景

- **普通 chat 模式**：不渲染 `ExpertTeamSessionView`，不受影响。
- **legacy 专家团路径**（`AgentWorkspace` 组件）：`AgentWorkspace.tsx:548-561` 也有类似的"overview"
  tab 设计，但该路径只在 `persistedExpertWorkspaceActive` 为 false 时使用（即 bridge 不可用或返回
  null）。正常 Desktop 走 `ExpertTeamSessionView`。**未验证 legacy 路径是否有同样问题**。
