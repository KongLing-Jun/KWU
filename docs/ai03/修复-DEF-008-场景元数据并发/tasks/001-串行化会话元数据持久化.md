## 目标与产物

为每个 `.jsonl.meta` 建立进程内 transaction mutation 边界，消除同进程 load-modify-save 的陈旧
快照覆盖；BranchMeta 使用严格原子替换，并在 Windows 读取阶段容忍短暂 sharing/lock violation。

产物包括：per-path ref-counted lock、locked/unlocked helper、导出的 ensure/existing-only mutation
契约、agent 内部 writer 迁移、Windows retry helper，以及确定性并发/锁回归测试。

## 证据与实现约束

- `internal/agent/branch.go:241-252` 的 `os.ReadFile` 无重试；L21 fatal operation 为 `open`。
- `branch.go:308-327` 使用带 copy fallback 的 `ReplaceFile`；并发诊断已观察到 decode corruption。
- `saveBranchMeta` 在落盘后调用会回读 metadata 的 catalog refresh，路径锁必须在 refresh 前释放。
- `TouchBranchMeta`、`RenameSession`、`SetBranchModelPreserveUpdated`、`UpdateSessionMeta` 当前都把
  ensure/load 与 save 分开，必须在本任务迁移。

允许修改 `internal/agent/branch.go`、必要的同 package 平台 helper 和邻近测试。若无需改变通用
`internal/fileutil` 契约，不得修改它；优先复用现有 `AtomicWriteFileStrict`。

禁止修改 Desktop、Controller、Provider、prompt、配置、schema 或发起外部请求。不得把全局单锁
作为实现，不得无限重试，不得在持有路径锁时调用 catalog refresh。

## 保持行为

- BranchMeta JSON 字段、Validate、CreatedAt/UpdatedAt、missing-sidecar 与 NotExist 语义不变。
- 普通 Save 继续 touch UpdatedAt，PreserveUpdated 继续保留时间；`UpdateSessionMeta(markActivity)`
  保持动态语义。
- 不同 sidecar 不互相阻塞；完整 Save API 仍可用于新记录和显式 transaction rollback。

## 验收标准

1. 同一路径的 mutation closure 从 load/ensure 到 strict publish 全程互斥，公共 load/save 也服从路径锁。
2. 两个受控并发 mutation 分别写 title 与 scene/model 后，最终记录同时保留两者且为有效 JSON。
3. 重复并发 mutation/load 不出现 decode error、字段回退、deadlock 或 race。
4. Windows errno 32/33 在约 100–150ms 后释放时读取成功；持续锁定时在预算内返回原始错误。
5. 非 Windows 或非 transient 错误不重试；strict publish 失败时旧 destination 保持完整。
6. lock entry 在最后一个 waiter 退出后可回收；不同 canonical path 可并行。
7. 所有生产调用者搜索结果在 receipt 中分类为“已迁移”“新记录完整 Save”或“显式 rollback”。
