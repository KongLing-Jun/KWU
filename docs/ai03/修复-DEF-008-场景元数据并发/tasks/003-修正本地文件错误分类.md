# 任务 003：修正本地文件错误分类

## 状态与依赖

- 状态：已完成
- 执行顺序：3 / 3
- 依赖：行为上独立；为保持单一交付链在任务 002 后执行
- 指派：`/root/implement_def008`
- 预期提交：`fix:避免将本地文件错误归类为模型断流`

## 目标与产物

收窄 connection-reset 判定，使 Windows filesystem `PathError` 不再显示为模型流断开，同时保留
明确的 transport 中断、EOF 和 stalled stream 行为。

## 证据与实现约束

- `internal/provider/retry.go:183-184` 当前接受任意 `net.Error`。
- Windows `syscall.Errno` 满足 `net.Error`，无 Provider overlay 已证明 sharing violation
  `PathError` 被 `IsConnReset` 与 `ExplainError` 误分类。
- `internal/control/errmsg.go:21-26` 的 UI projection 只是消费错误分类；主故障仍是 scene/meta
  persistence，二者必须能独立回滚和审查。

允许修改 `internal/provider/retry.go`、`retry_test.go`、`internal/control/errmsg_test.go` 及必要的
Windows-only test helper。禁止修改 Desktop 前端文案、Provider retry policy、请求发送、prompt 或配置。

## 保持行为

- `ErrStreamStalled`、EOF、unexpected EOF、`net.ErrClosed`、ECONNRESET、ECONNABORTED 继续为 true。
- wrapped `*net.OpError` 继续作为连接级 transport failure；context canceled/deadline 继续为 false。
- 未识别错误由 `ExplainError` 原样返回，不创建新持久化错误类型或 schema。

## 验收标准

1. Windows `*os.PathError{Op:"open", Err: ERROR_SHARING_VIOLATION}` 的 `IsConnReset` 为 false。
2. 同一错误经过 `control.ExplainError` 后保留本地 save/open 原因，不含 model stream、recovery/retry、
   provider 或 proxy 建议。
3. wrapped `*net.OpError`、EOF、ECONNRESET 与 `ErrStreamStalled` 正向用例仍为 true。
4. context cancel/deadline 与普通 protocol/application errors 为 false。
5. 该任务不改变主 persistence 实现，也不发起网络请求。

## 聚焦验证

- `go test ./internal/provider ./internal/control`
- Windows-only errno 用例与跨平台 transport table 分开，避免非 Windows 编译依赖。

## 完成回执

- 实际状态：已完成。`IsConnReset` 不再接受任意 `net.Error`，仅在明确 sentinel/errno 未命中后接受
  具体 `*net.OpError` transport wrapper。Windows filesystem `PathError` 的 errno 32/33 因而保持本地
  persistence 错误，不再进入模型流断开投影。
- 变更文件：`internal/provider/retry.go`、`retry_test.go`、`retry_windows_test.go`、
  `internal/control/errmsg_windows_test.go` 及本回执。
- 测试结果：`go test ./internal/provider ./internal/control` 通过（provider 7.833s；control 16.370s）。
  正向覆盖 ErrStreamStalled、EOF、unexpected EOF、net.ErrClosed、ECONNRESET、ECONNABORTED 与 wrapped
  `*net.OpError`；反向覆盖 nil、context cancel/deadline、普通 protocol error、非 OpError 的 net.Error、
  Windows sharing/lock violation PathError。UI projection 测试确认保留 save/open/path 原因且不包含
  model stream/recovery/retry/provider/proxy 建议。
- 偏差：无。未改变 retry 次数、请求发送、Desktop 文案、prompt、配置或 persistence 实现；未发起网络
  请求。
- 残余风险：未知的第三方 transport 错误若既不包装 `*net.OpError` 也不匹配明确 sentinel，将不再按
  connection reset 处理；这是为避免把本地 `net.Error` 实现误归类而接受的计划内收窄。
