## 目标与产物

让 Draft Scene 在 JSONL 与 sidecar 成功持久化后才发布到 Controller 内存，并把 scene fields 与
model/preview/counts 合并为一次 BranchMeta mutation；迁移 Desktop 对既有 sidecar 的活跃字段更新，
使 accepted-turn 自动标题和 scene commit 并发时不再互相覆盖。

## 证据与实现约束

- `internal/control/task_lifecycle.go:72-90` 当前先改内存、后保存，并对 sidecar 执行两次独立 RMW。
- `internal/control/turn_orchestrator.go:85` 先通知 accepted turn；`desktop/app.go:1215` 启动自动标题
  goroutine；`desktop/tabs.go:5897-5907` 与 scene commit 操作同一 sidecar。
- L21 sidecar 保留自动标题但为 Draft，JSONL 已换 Design system prompt，证明部分提交真实存在。

允许修改 `internal/control/task_lifecycle.go`、scene commit 邻近测试、`desktop/tabs.go`、
`desktop/project_session_policy.go` 和为迁移/测试确有必要的邻近 Desktop Go 文件及测试。

禁止修改前端、prompt 内容、Provider、运行时配置、schema 和 project-context transaction 的外部
语义。新 branch/session 首次完整 Save 与显式 commit/rollback 不得机械改成字段 mutation。

## 实现边界

- staged Session/prompt/Expert/status 只存局部变量；先保存 JSONL，再以一次 mutation 提交
  model/preview/counts/schema + Locked scene，最后更新 executor 和 Controller 字段。
- 默认 `saveSceneCommitSession` 不再夹带 BranchMeta 与 Expert 写入；独立 Expert metadata 保持
  best-effort，并在成功发布内存后保存。
- 保留 `SceneSessionSaver`、`SceneStatusSaver` 测试 seam；失败时 runner 0 次且内存保持旧值。
- `SetDraftScene` 先 mutation sidecar，成功后改内存。
- 迁移自动标题、tab metadata、tool approval、legacy migration、restore topic、permanent-read-only 等
  既有记录更新；closure 只改路径拥有的字段，保留其他 goroutine 已提交内容。

## 保持行为

- scene 仍在 root runner 前从 Draft 变为 Locked；成功路径生成的 system prompt 和 Expert selection 不变。
- topic 自动标题仍在 accepted turn 时尽早可见；topic index invalidation 与 topic model 同步不变。
- BillingSource、Effort、ToolApprovalMode、Scope、WorkspaceRoot、TopicID/Title 和 ProjectContext 语义不变。
- status/JSONL 最终失败仍返回现有 `save scene session` 或 `save locked scene` error chain，不 dispatch。

## 验收标准

1. session saver 与 status saver 分别注入失败时，executor Session、system prompt、Expert、scene state
   均等于调用前，fake runner 调用 0 次。
2. 成功时 sidecar 用一次 transaction mutation 得到 model/preview/counts/schema 与 `design/locked`，
   runner 恰好一次。
3. accepted-turn 标题 goroutine与 Design commit 受控交错时，最终 title 与 Locked scene 同时存在。
4. Windows share=0 句柄在 100–150ms 后释放时，无 Provider 首轮提交成功且 fake runner 恰好一次。
5. Desktop 所有对既有 sidecar 的普通 RMW 已使用 task 001 mutation；完整 Save 例外逐一有理由。
6. 现有 scene、topic、tab、project-session 测试保持通过，无 frontend 变更。
