# Reasonix Desktop Agent 30 次稳定性与运行成本最终报告

## 结论

在锁定的 `origin/main-v3@6cfe5af68bf6cfaeea5f315b49a4c652cbaf54ad` 上，使用
`gpt-5.6-luna`、真实 Wails Desktop、持久化 dev 环境完成了 30/30 个有效矩阵样本。产品代码、系统提示词、
Scene Profile 和运行时配置均未修改。

对修复前 12 次候选数据，唯一严格同口径的 L01–L12 显示：模型交付质量保持 12/12，Agent 正常结束由
6/12 提升到 12/12；总 tokens 下降 48.36%，模型调用下降 46.57%，工具调用下降 40.06%，审批下降 11.94%。
但模型耗时上升 8.16%，所以结论是“更省 tokens 与步骤、完成态显著更稳”，不是“端到端更快”。

扩大到全部 30 次后，模型交付质量为 28/30，Agent 正常结束和当前会话实时 final 均为 29/30。29 个有 final
的样本全部无需切换会话，未观察到重复回复；但仍有 1 次模型请求前硬失败、1 次设计成品视觉失败、18 次自动
恢复和 A06 的 26.672s 完成尾延迟。近期运行时修复有效，但长尾故障与完成步骤开销尚未清零。

## 后续提示词与产品建议

本轮不修改提示词。按证据，建议后续单独评估：

1. 优先修运行时而非重写主系统提示词：复现并解决 DEF-008 的 metadata 文件锁/序列化路径；把本地文件错误从
   “模型流断开”分类中排除；为 DEF-009 分别埋点 final 落盘、投影、runner 完成和 composer idle。
2. 收紧完成步骤提示：只有成功执行后才提交 `complete_step`，引用当轮真实 receipt 的精确命令与文件路径；本轮
   114 次调用中有 22 次拒绝，是最明确的可减成本项。
3. Windows 校验指引显式要求 UTF-8，并使用有界、可终止的本地 HTTP 验证；避免默认 GBK 和后台 server 尾挂。
4. 设计任务在声称 responsive 前，必须用真实浏览器检查 1440px 与 320px 的 `scrollWidth`、元素越界和面板重叠；
   静态结构 grader 不能替代视觉验收。
5. 对中小型代码任务明确 child/skill 路由阈值，避免相同任务在 A02/A05 产生不同父子执行形态；先测量再决定是否
   修改 Scene Profile。
6. 审批下降幅度只有 11.94%，低于 tokens/调用改善。可以在独立产品任务研究安全的只读验证合并或会话级授权，
   不应仅靠提示词规避审批合同。
