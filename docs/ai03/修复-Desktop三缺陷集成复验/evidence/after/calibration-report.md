# 三场景集成复验校准回执

## 结论

在完全相同的冻结任务、提示词、模型、low effort、Provider 和持久化 dev 环境口径下，集成修复版的
三个校准样本均交付正确成品、均在当前真实 Wails Desktop 会话中实时显示 final 并正常回到 idle。
与修复前相同三个样本相比：

- 模型交付质量：3/3 → 3/3，持平；
- Agent 正常完成：1/3 → 3/3；
- Desktop 当前会话实时 final：3/3 → 3/3；修复后无切换会话、无重复父回复；
- 总 tokens：690,749 → 505,916，下降 26.8%；
- 模型调用：39 → 33，下降 15.4%；
- 模型耗时：787.276s → 621.207s，下降 21.1%；
- 用户可见 final 合计耗时：823.907s → 656.744s，下降 20.3%。

这是校准检查点，不是 30 次最终结论。三样本已经证明统计链路可用，也未复现 DEF-002/008/009/010，
但不足以证明方差、长期稳定性或各修复的发生率。

## 三条相互独立的判定

1. 模型交付质量：3/3 冻结 grader 通过；L02 六项 unittest 通过；L03 HTML/CSS、本地 HTTP、桌面/移动、
   键盘焦点、深色模式和 reduced-motion 均通过。
2. Agent 执行效率：总体 tokens、调用、模型耗时、拒绝恢复链改善；但 L02 工具数和耗时变差，L03 仍有
   非移植命令、额外审批与副作用，不能给出“全面改善”结论。
3. Desktop 实时完成稳定性：3/3 正常结束，3/3 当前会话实时 final，0 次切换、0 次重复父回复；
   相比修复前校准的 1/3 正常结束有明显改善。

## 新发现与测试设施问题

- FIND-L03-001（D）：模型混用 Bash/cmd/PowerShell 语法，并用 || exit 0 掩盖清理失败；正式成品通过，
  但留下 3 个临时文件和一个 HTTP listener。listener 固定证据后已按精确 PID 停止，文件保留在原始 workspace。
- TI-001（E）：Computer Use 偶发返回 Reasonix tree 与 Codex 截图不一致；两次都在动作前被交叉检查拦截，
  未污染 Desktop 样本。
- TI-002（E）：Playwright CLI 在 Windows 的版本/帮助命令出现 libuv assertion，且一次多命令批处理挂起；
  改为单步后完整通过，不计入 Reasonix 指标。

校准阶段没有发现新的确定性严重 Reasonix 产品缺陷，因此具备继续 L04–A06 剩余 27 次矩阵的条件。
