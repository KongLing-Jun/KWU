# Desktop 三场景 30 次集成修复复验最终报告

## 最终判断

在锁定产品 `6a93ac2c64287b0e103bb81ae3abc07b692caaba`、证据基线
`00897dccd4247f09396c4e9d9a293c3285dfbc32`、同一持久 dev 环境和 `gpt-5.6-luna` 下，30/30 次
真实 Wails Desktop 矩阵完成。测试期间未同步远端、未重建二进制、未修改产品代码、系统提示词或运行时配置。

结论必须分三轴看：

1. **模型交付质量**：30/30 语义成品通过，修复前三缺陷同矩阵为 28/30；旧未优化提示词和 Extended V2
   候选严格 12 次均为 12/12，说明提示词优化的主要价值不是提高该冻结任务集的通过率，而是降低执行成本。
2. **Agent 执行效率**：严格 12 次相对同提示词、三缺陷修复前再降 6.06% tokens、5.41% 模型调用、
   5.10% 工具调用、22.37% 模型耗时和 49.15% 审批。low 24 也整体改善；但 auto 6 因 A03/A06
   本地服务尾部而明显回退，全 30 tokens 因此反而微升 1.03%。
3. **Desktop 实时完成稳定性**：30/30 正常结束、30/30 当前会话实时显示接受 final、切换恢复 0、接受后
   重复回复 0；修复前三缺陷同矩阵为 29/30，候选发布期正常结束仅 6/12。`DEF-002/008/009/010`
   在本轮均未复现。

因此可以说：三项修复的集成构建在真实 Desktop 完成稳定性上通过全量复验，且固定 low 的效率更好；不能说
运行成本已经全面稳定，设计/auto 的后台 HTTP 服务生命周期仍制造高成本尾部，final CV 也比修复前高。

## 提示词与后续建议

本轮没有证据支持再次大改主系统提示词：模型语义质量已经 30/30，三个目标完成态缺陷属于 runtime/Desktop，
不是 A 类提示词问题。建议顺序是：

1. **优先独立修 B/D 类后台服务生命周期**：在 Windows 上最小复现 `bash` 后台服务、显式 `kill`、
   `preserve_background_processes`、`wait`、`kill_shell` 与 readiness 的组合；让本地打开验证默认使用有界、
   自清理的单进程方案。
2. **降低验证命令环境歧义**：场景 guidance 可用很小的增量明确 Windows 文本读取必须显式 UTF-8、临时
   server 必须在 final 前停止；这是定向策略建议，不是重写主提示词。
3. **不针对 grader 假阴性改提示词**：dashboard HTML→SVG 新契约和 budget `Unknown` 同义词应修评测合同，
   否则会为了评分污染真实任务。
4. **继续优化 receipt 可用性**：提供结构化成功命令 receipt/候选选择，减少模型引用不存在或缩写命令造成的
   `complete_step` 拒绝；不要靠增加静态提示词重复说明。
5. **auto 先做小样本再默认启用成本宣传**：当前 auto 对匹配 low 显著更贵且设计尾部严重。应在后台服务问题
   修复后再跑至少每任务 4 次，保持 Provider、模型、任务和矩阵不变。
6. **单独修 TI-001**：Computer Use 返回的 window/tree/screenshot 必须属于同一前台窗口；在修复前继续执行
   三方一致性检查，错配状态绝不输入。

## 限制

- Provider 和模型有自然波动；固定 commit 与任务不能消除供应商时延/采样方差。
- 场景内 auto 只有 N=2，无法估计长期尾分布；全 30 的 P90/P95 只描述本轮混合矩阵。
- 旧候选没有完整 realtime final、todo、wait、child 和审批等待埋点，因此这些字段不能按 0 比较。
- 修复前三缺陷 30-run 与当前集成构建之间除三缺陷外还包含 DEF-010 和上游 main 集成，不能将全部变化单因果
  归给某一个提交；严格同提示词数据证明的是“集成修复组合”的结果。
- 审批等待包含取证者观察与点击时间，不与模型耗时相加作纯模型性能。

最终结论：集成分支具备进入后续代码审查/PR 准备的稳定性证据，但在任何合并决定前，应把 `FIND-L12-001`
作为明确剩余风险；本测试任务没有修改产品代码，也没有授权 push、创建 PR 或合并。
