## 缺陷与判定边界

1. `DEF-002`、`DEF-008`、`DEF-009`、`DEF-010` 在当前 12 次均未复现。尤其没有 final 落盘后持续 loading、切换后才显示的情况，也没有会话元数据锁或 BranchMeta 并发写入症状。
2. `FIND-L04-001` 在 L04/L06/L10/L12 共 4/12 复现：模型写入 JSONL 的某一个 final 成品链接漏掉路径中的 `-def008`。成品真实存在且验收通过，Desktop 完成态通过；这是 D 类 final 包装质量问题，不是 Desktop 投影恢复问题。
3. `FIND-L10-001`：一次 Windows 默认 GBK 读取 UTF-8 文件失败，显式 UTF-8 重试通过；D 类、非阻断。
4. `FIND-L12-001`：后台 HTTP 校验在显式 `kill` 和 `preserve_background_processes:false` 下仍命中两分钟超时；同会话用有界检查恢复。该现象影响效率，当前按 B/D 类记录，尚需最小复现才能锁定运行时根因。
5. 5/12 样本出现额外文件：4 个代码样本因正常执行测试产生 `__pycache__`；L03 另有已记录的混合 shell 清理副作用。它们均在 extra files/side effects 中单列。
6. Computer Use 曾出现一次 Wails accessibility tree 与 Codex 截图目标不一致；顶层任务未在错误窗口点击或输入，重新激活并重绑窗口后恢复，记录为测试基础设施 `TI-001`，不计产品缺陷。

## 阶段判断与下一步

集成修复后的最强证据是完成态：12/12 当前会话实时 final、0 次切换恢复、0 次重复回复，目标缺陷均未复现。成本相对两套基线均改善，完成步骤拒绝和审批显著减少。当前最弱证据是方差：只有每任务两次重复，dashboard 成本回退且 L12 有两分钟超时，final 时延 CV 反而更高。

下一阶段保持同一 commit、二进制、dev profile、Provider、模型和统计口径，继续 L13–L24 的第 3/4 次重复；不因当前阶段结果修改产品或提示词。到 L24 再判断 dashboard 回退是偶发波动、命令策略问题还是可复现运行时成本。
