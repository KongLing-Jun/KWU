# TI-004：补充浏览器验收遗留 HTTP 服务污染后续样本

## 分类与影响

- 分类：E（测试基础设施问题），不是 Reasonix 产品缺陷。
- 发生点：L18 第一次本地 HTTP 验证。
- 质量影响：无；三份交付文件最终均返回 200，且独立 Playwright 视觉验收通过。
- 效率影响：有；增加一次 bash 审批、一次模型恢复判断和相应 tokens/耗时，因此 L18 的原始成本保留但标注基础设施污染。

## 现象与证据

L18 在当前工作区运行 `python -m http.server 8765` 后，请求 `operations-dashboard.html` 返回 404。事后只读检查确认：

- `8765` 已被 PID 42340 监听；其父 PID 为 44468，两者创建于 `2026-08-13 20:20:36`。
- 两个进程的命令行均为 `python -m http.server 8765`，创建时间对应 L15 的 Playwright 补充验收。
- 访问该服务根目录只列出 L15 的 `empty-state.html`、`empty-state.css`、两个冻结输入和 `.clouvia/`，因此 L18 请求必然得到 404。
- L18 随后改用端口 8766，HTML/CSS/SVG 分别返回 200 和正确 MIME 类型。

模型把首次 404 表述为“服务进程启动目录不是交付文件所在目录”。更准确的根因是新服务因端口占用未成功监听，curl 命中了 L15 遗留服务；恢复动作本身仍然有效。

## 处置与防复发

- 已核对监听 PID、父子关系、命令行和所服务目录后，精确终止 PID 42340/44468；确认 8765 不再监听。
- 后续补充浏览器验收使用每次唯一端口，并在启动后核对实际监听 PID。
- 清理时同时处理 Python 启动包装进程及其实际监听子进程，不能只按 `Start-Process` 返回的父 PID 判断。
- L18 不重跑、不删除原始成本；最终汇总同时展示原始值并注明本次 E 类污染。
