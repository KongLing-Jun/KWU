## 目标

把“使用当前默认模型”严格收敛为未保存表单的选择语义。每次创建、更新或批量保存实际自动化任务时，Desktop 必须解析并持久化当时可用的具体 `model + billingSource`，同时让 `Capabilities.ModelRef` 与之相同。模板继续只保存模板种子，不保存模型。

实施前先复述目标、证据、允许范围、保留行为和禁止范围；如发现必须改变 schema、模板结构、计费规则或兼容策略，停止并报告，不自行扩展。

## 交付物

1. 物化前按既有 `automationTopicScope` 规则规范化并写回 task：非 project 统一为 `global`/空 root，project root 统一为绝对路径；route lookup 和随后运行使用同一个 scope/root/actor。
2. `AutomationCreateTask` 在调用 core service 前物化任务路由，返回和存储的 task 均为具体路由。
3. `AutomationUpdateTask` 在调用 core service 前物化任务路由；编辑器把模型清空时，快照编辑保存时的当前默认路由。
4. `AutomationSaveTasks` 先完成整个输入列表的路由物化，再进行唯一一次 core service 调用；任一任务失败时不调用保存，避免部分落盘。
5. `HeartbeatSaveTasks` 在兼容转换和合并 native task 后复用同一个完整列表物化 helper，再进行唯一一次 service 调用；保留该入口当前不发送 `automation:task_changed` 的行为。
6. model 为空时快照完整默认 route，即使输入残留非空 billing source 也用默认 source 覆盖；显式 `model + billingSource` 则按当前 Desktop automation catalog 精确验证并规范化，不可用时返回现有路由错误。
7. 三个字段一致写入：`Prompt.Model`、`Prompt.BillingSource`、`Capabilities.ModelRef`。
8. `AutomationSaveTaskTemplate` 不物化 route；内置模板和用户模板都继续不含模型字段，模板生成的草稿在实际 `AutomationCreateTask` 时快照。
9. 自动化编辑器的空草稿选项在完整页和紧凑视图统一显示“使用当前默认模型（保存后固定）”。
10. 增加最窄的回归测试，覆盖 scope/root 规范化、创建、更新、两个批量入口的原子拒绝、显式路由、残留 source 和模板边界。

## 必须保留的行为

- 除本合同明确规范化的 scope/root 和 route 外，任务名称、调度、topic、能力、审批和投递仍由既有 core service 规范化、校验和 revision 控制。
- global/stale-root 输入保存为 global/空 `workspaceRoot`；project 相对路径保存为绝对 root，并使用对应 actor/profile。
- 显式 route 继续接受既有 picker compatibility 规范化，不增加新的猜测或 provider 改写。
- 保存模板、删除/恢复模板和从模板填充表单不依赖模型目录。
- native create/update/bulk 保存继续各发送既有 `automation:task_changed` 成功事件一次，失败时不发送；heartbeat compat bulk 继续不发送该事件。

## 验收标准映射

- AC-01：空模型经 create、native bulk 或 heartbeat compat bulk 保存后，返回值/fake/store 捕获值包含同一个具体 route 和一致 capability model；scope/root 已规范化。
- AC-02：创建后改变默认设置不修改已存 task；再次读取仍是创建时 route。
- AC-03：更新时清空模型，保存结果快照更新时的默认 route；保存路径不触碰 Controller。
- AC-04：模板结构和保存结果不含 route；模板草稿创建后实际 task 含 route。
- AC-05：显式/默认 route 不可用时 create/update/native bulk/heartbeat compat bulk 失败；bulk 中任一失败时 service 的保存调用次数为零，原存储不变；空 model 的残留 source 被完整默认 route 覆盖。
- AC-09：完整页和紧凑视图都显示“使用当前默认模型（保存后固定）”；保存返回后编辑值为具体 model/source。
- AC-11：schema、依赖、gate baseline 和运行期代码不变。
