# 任务 002：修复工具卡披露状态

## 状态与指派

- 状态：已完成，主会话 Computer Use 与用户联合验收通过。
- 执行组：Serial-02，依赖任务 001 的稳定 Transcript 展示面。
- 指派：主会话（系统分配模型，未显式覆盖）。
- 依赖：[`001`](./001-修复完成态永久加载.md)、[`../plan.md`](../plan.md)。
- 交付：一个可独立回滚的 `fix:` 提交，包含代码、测试、总体计划/进度与本回执。

## 目标与产物

所有普通工具卡只能由用户点击或既有 shell 快捷键展开/收起；running、nested arrival 和 completion 不得自行改变 disclosure。用户展开选择需跨虚拟化和完成态分组 remount 保留。

## 根因与源码依据

- `ToolCard.tsx`：旧 `running && (hasNested || isShellTool)` 推导 `defaultOpen`，导致无点击展开，完成后又自动收起。
- `Transcript.tsx`/`ToolGroup.tsx`：running shell 为独立卡，完成后重组进 ToolGroup 并 remount；仅保留卡片局部 state 仍会丢失用户选择。
- `toolDisclosure.tsx`：以 `semanticViewKey` 为作用域持有用户对 tool ID 的选择。
- `tool-card-running.test.tsx`：覆盖默认折叠、nested/status 更新、新组 remount 与已有组吸收。

## 允许与禁止范围

- 允许：`ToolCard.tsx`、`ToolGroup.tsx`、`toolDisclosure.tsx`、直接相关测试、总体计划/进度与本回执。
- 禁止：工具执行状态、媒体工具组既有自动预览策略、模型或 provider、持久化格式、通用 Transcript 重构。

## 必须保留

- 折叠卡不挂载重型代码、diff 或归档详情；展开时按需加载。
- media tool preview 与 shell 快捷键继续工作。
- 用户选择不跨 `semanticViewKey` 泄漏到其他会话。
- 未操作工具组保持折叠；吸收用户已展开卡片时只继承该明确选择。

## 验收标准

1. running shell 与 nested 工具在无输入时全程折叠，无展开/收起闪烁。
2. 用户展开后跨 status、nested、output、虚拟化和完成态分组 remount 保持展开。
3. 新建或已有 ToolGroup 吸收已展开卡片时组与卡均可见；其他卡不被误展开。
4. DEV trace 只记录 opaque token 和 presentation 状态，不记录工具参数、输出或正文。

## 完成回执

- 红测：旧自动 disclosure 使 7 个断言稳定失败；局部 state 方案在 completion regroup 上另有 3 个稳定失败。
- 自动化：最终 ToolCard 39/39；相邻 Vitest 3/3；expert workspace virtualization 221/221；测试 TypeScript 与生产构建通过。
- Computer Use：未点击 running shell 保持折叠；手动展开后完成并重组为“终端 1 次命令”，组、卡和输出仍展开。
- 用户联合验收：3 个 shell 从 running 到 done 均保持 `open=false`、无 toggle；全部 `open=true` presentation 均有此前 `source=pointer`，`OPEN_WITHOUT_PRIOR_USER_TOGGLE=0`。
