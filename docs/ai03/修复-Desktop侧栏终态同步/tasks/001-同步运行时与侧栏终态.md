## 目标与交付物

当 `turn_done` 丢失、既有 terminal reconciliation 已确认后端空闲时，让 App 的现有
`ListTabs()` metadata 轮询触发项目树既有刷新链，从而在下一次 2 秒轮询后清除侧栏残留转圈。

交付物：

- 一个只包含项目树实际依赖字段的 tab runtime 刷新键纯函数；
- App 中首次建立基线、后续键变化才递增 `projectRevision` 的接线；
- running/idle、background tab、pending prompt、background job、session rebind 与无关 metadata
  的确定性测试；
- 本任务完成回执。

## 依据与失败路径

- 用户真实截图显示 Todo `3/3`、正文 final、Composer 空闲，但左侧同一会话仍转圈。
- `ProjectTreeStateIndicator` 只消费 `ListProjectTree()` 返回的节点状态，不消费 Todo 或 controller
  本地 state。
- `ProjectTree` 只在 `refreshSignal=projectRevision` 变化时重取树。
- 正常 `turn_done` 会触发 tree revision；丢失 `turn_done` 时，`useController` 的 backend 对账只清除
  本地状态，没有递增 App revision。
- App 已每 2 秒刷新 `tabMetas`，而 `ListProjectTree()` 本身可以根据当前 `RuntimeStatus()` 正确抑制
  空闲 tab 的旧 ActivityStatus。因此缺少的只是 metadata runtime 变化到现有树刷新链的接线。
