# 系统提示词真实评测结论

## 结论

本轮不修改生产 `DefaultSystemPrompt`、三个 Scene 文案或示例配置。WorkBuddy 的职责分层、
按需能力和运行时纠偏方式帮助形成了更清晰的候选，但没有一个候选达到计划冻结的
诊断集 18/18 与回归集 12/12 端到端门槛。

Extended 是唯一值得保留的实验候选：诊断成功率与当前提示词同为 16/18，同时完整运行
token、模型调用、工具调用和耗时分别降低约 21%、31%、34% 和 21%；回归集端到端从
5/12 提升到 9/12。但它仍出现真实代码逻辑错误和产物完成后未正常结束，不能设为无人群体
的产品默认值。这个结果也直接验证了“提示词更长不等于更强”。

## 评测身份与边界

- 日期：2026-08-04；模型：`gpt-5.6-luna`；供应商：用户确认的 OpenAI-compatible
  `http://192.168.10.231:8080/v1`。
- 参数：low effort、temperature 0、max steps 18、auto plan off、context window 200000、
  单次墙钟 4 分钟、每任务两次重复。
- 运行路径复用生产 `boot.Build`、Controller、Scene 和工具注册；grader 为
  `prompt-eval-v5`。
- key 只进入一次性 Profile；版本化文档和报告不含 key。最终对 Git 忽略目录（含隐藏文件）
  扫描无 `sk-…` 样式残留。
- Windows 没有可用的 OS shell sandbox；评测工作区和 Profile 已隔离，但本结果是能力评测，
  不是安全证明。

## 诊断集

9 个任务、每个重复 2 次。Artifact 表示产物满足 rubric，Run 表示 Controller 正常结束，
E2E 要求两者同时通过。

| Prompt | 静态保守估算 | Artifact | Run | E2E | 总 tokens | 模型调用 | 工具调用 | 累计耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 当前内置提示词 | 基础约 186 | 18/18 | 16/18 | 16/18 | 5,235,061 | 303 | 331 | 1,885.1s |
| Compact | 1,266 | 17/18 | 15/18 | 14/18 | 4,886,998 | 253 | 271 | 1,692.2s |
| Standard | 2,253 | 18/18 | 15/18 | 15/18 | 4,910,796 | 244 | 278 | 1,631.1s |
| Extended | 3,428 | 18/18 | 16/18 | 16/18 | 4,152,715 | 208 | 217 | 1,488.9s |

静态估算沿用仓库保守算法，不能冒充供应商 tokenizer；真实 usage 才用于效果比较。当前提示词
由运行时内置，因此 evaluator 报告中的外部候选长度为 0，上表使用源码审计的基础内核估算。

Decisive 与 Direct 是针对“验证后立即交付”的进一步短候选。两者各自只执行两个 SVG smoke：
都为 0/2 端到端，出现无效 XML 或产物正确但墙钟超时，因此没有浪费资源跑完整诊断集。

## 冻结回归集

6 个任务、每个重复 2 次。只有诊断集表现最好的 Extended 与当前提示词进入完整回归对照。

| Prompt | Artifact | Run | E2E | 总 tokens | 模型调用 | 工具调用 | 累计耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 当前内置提示词 | 6/12 | 9/12 | 5/12 | 3,972,333 | 192 | 215 | 1,407.6s |
| Extended | 10/12 | 10/12 | 9/12 | 2,970,789 | 167 | 177 | 1,060.4s |

Extended 的三个端到端失败不是 grader 假阴性：

- `coding-retry-delay` 一次产物正确但 Controller 未正常结束；另一次断言实测得到错误退避结果。
- `design-profile-card-svg` 一次缺少真实可见焦点且未正常结束；另一次产物正确但未正常结束。

当前提示词也暴露了更多事实、结构和完成态失败，所以 Extended 具有真实相对收益；但计划要求
默认内核对冻结集合全绿，不能用“比旧版好”掩盖已知错误。

## Scene Profile 结论

在 Extended 之上试验的增强 Scene Profile 只先跑了两个 Design SVG smoke，结果为 0/2：
两个 SVG 都无效且运行未正常结束。该生产代码改动已单独回滚，当前三个 Scene 文案和工具
schema 与基线一致。由于通用内核没有通过门槛，按任务依赖不再扩大 Office/Coding/Design
配对运行。

## Desktop 真实应用验收

使用本 worktree 实际编译的 Wails `kwu-desktop-dev.exe` 和一次性开发 Profile 完成。应用内
新增自定义供应商，真实 `/models` 发现返回 13 个模型，最终只启用并选择
`Prompt Eval/gpt-5.6-luna`。每个新会话在发送前均确认底部模型标签和 Scene 标题。

| Scene | 真实输入摘要 | 观察结果 |
| --- | --- | --- |
| Office | 三项项目周报 | 返回完成、风险、下周三项事实并正常停止；普通换行被 Markdown 折叠为同段显示 |
| Coding | `normalize_tags` Python 函数 | 正确实现去空白、小写、去重和首次顺序，附匹配 assert，无工具调用并正常停止 |
| Design | SaaS 空状态卡片 8 条规范 | 正好 8 条，覆盖标题、说明、主/次按钮、图标、间距、浅/深色和禁用渐变并正常停止 |

因为没有候选进入生产，这次 Desktop 是“保留当前提示词”的兼容验收，不伪装成候选通过。
隔离云端故意指向本机不可用端口以避免开发版单实例冲突，所以专家列表出现预期的网络告警，
不影响 BYOK 会话。验收后只停止本 worktree 的应用/Wails 进程，并删除含密钥的临时 `.env`。

## 产品决策与后续边界

- 合入价值：评测器、grader fixture、候选资产、真实证据和 no-go 决策。
- 不合入：任何默认提示词、Scene 文案、工具、权限、运行时重试或完成态逻辑改动。
- 若继续下一轮，应先形成新的、可解释的候选并重跑完整诊断集与回归集；不能只修失败题，
  也不应把本轮发现扩成无关的运行时重构。
