## 3. 行为与实现要求

### 3.1 专家状态正确性

- 状态至少表达 `{ tabId, status: pending | ready | error, selection }`；owner 与当前
  tab 不匹配时同步投影 `pending + null`，不能等待 effect。
- 只有 `ready + selection=null` 表示普通 `Craft`；只有 owner 匹配的 ready selection
  可以显示、打开菜单或进入 `buildExpertSubmitText`。
- 查询提交同时校验请求序列与目标 tab；首次解析失败进入 error、显示现有 Toast 并
  允许手动重试。同 tab 后台目录刷新失败不得抹掉已确认选择。
- Set/Clear、乐观选择、失败回滚及“召唤到新任务”绑定调用前捕获的目标 tab，并使更早
  请求失效。
- single-surface 复用相同 tab ID 时，在目标导航开始前使来源身份失效；取消导航只恢复
  对应意图，旧取消/旧响应不能覆盖较新的导航。
- pending/error 保持 textarea 和草稿可编辑，但按钮、Enter 与 App 直接提交入口均
  禁止发送；错误入口只重试，不打开旧专家菜单。

### 3.2 固定专家可见区域

- 普通、pending、error、单专家和专家团共享一个专家槽位及可见触发区尺寸合同。
- 宽屏、≤760px、≤520px 分别以当前专家总占位约 216px、118px、60px 为基准；
  实现可抽取尺寸 token，但同一断点内所有状态的最终总宽高必须完全一致。
- “总占位”包含背景、边框、主按钮、间距和专家清除按钮。只把透明 wrapper 设为
  等宽、而 `Craft`/pending 的着色按钮仍较短，不算完成。
- 长名称在固定槽内截断；清除按钮、菜单、键盘可达性和点击热区保持可用。
- 内容替换不得移动模型、发送按钮或 Composer 外框，也不得造成工具栏换行。

### 3.3 固定推理强度槽位

- 宽屏无论 `effort` 为 loading、unsupported 或 supported，都挂载同一个约 92px
  外层 wrapper；只有 supported 且 levels 非空时挂载现有 `EffortSwitcher`。
- 空 wrapper 不得产生可聚焦、可读屏的伪控件；supported 状态的选择、禁用和 More
  菜单行为保持不变。
- ≤760px 沿用现有 `display:none`，不为紧凑布局预留空白。
- 不改变 `EffortForTab` 时序、模型能力判断、后端契约或持久化。
