# 任务 001：通知多目标失败隔离

## 状态

已完成

## 目标与产物

让一个通知目标失败时不阻断同一运行的其余通知目标，并用测试证明多目标投递的真实行为。

产物：后端投递循环修正与聚焦单元测试。

## 依赖与交付顺序

- 依赖已批准的 `../plan.md`。
- 作为第一个实现切片，先于前端多选任务完成。
- 实现代码使用独立 `fix:` 提交；验证通过后用独立 `docs:` 提交更新本收据。

## 证据

- `DeliveryPolicy.Targets` 为数组并经过逐项规范化与校验。
- `enqueueRunDeliveries` 遍历所有目标，但 `dispatchDelivery` 返回错误时立即退出循环。
- 当前测试仅覆盖单个通知目标。

## 允许范围

- `internal/automation/engine.go`
- `internal/automation/engine_test.go`
- 本任务收据

## 禁止范围

- 不改变通知数据模型、投递适配器接口、重试 API 或持久化格式。
- 不修改桌面机器人目标解析和凭据逻辑。
- 不吞掉投递错误，不把失败改成成功。

## 保持行为与约束

- 每个目标仍创建独立、幂等的投递尝试。
- 单目标成功和单目标失败语义保持不变。
- 所有目标完成后返回聚合错误。
- 使用最小控制流修改，不引入新抽象。

## 验收标准

- 两个目标均成功时产生两个成功尝试。
- 第一个目标失败时第二个目标仍被调用并产生自己的尝试。
- 存在目标失败时调用方仍收到非空错误。
- 现有投递、重试与自动化包测试通过。
