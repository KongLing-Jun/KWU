# 001 会话持久化合同与事务后端

## 状态

已完成

## 目标与产物

在现有 `BranchMeta`/`sessionComposerState` 上增加可区分 missing 与显式 Ask 的审批姿态，并使桌面 setter 在持久化成功后才提交 runtime/tab 状态。

产物：additive JSON 合同、恢复/继承路径、事务 setter、Go 自动化测试。

## 约束

- `BranchMeta.ToolApprovalMode` 必须保留字段存在性；有效值仅 `ask|auto|yolo`。
- setter 写 sidecar 时不得持有 App 主锁；写后必须验证目标 tab/session 未被切换或关闭。
- 无 session path 的普通空白 tab 可更新待创建值；有 session path 的会话必须先落盘。
- 失败不得修改 controller、tab、tab snapshot。

## 验收标准

- sidecar round-trip 能区分 nil、显式 Ask、Auto、YOLO。
- legacy missing/非法值安全回退 Ask 且不回写。
- restore/rebind 按 session sidecar 优先于 stale desktop tab entry。
- A/B 会话复用同一 tab 时恢复独立姿态。
- fork/派生深拷贝并继承父姿态。
- 写失败返回 error 且所有运行时状态保持旧值。
- 快速切换期间旧写入不提交到新绑定会话。
