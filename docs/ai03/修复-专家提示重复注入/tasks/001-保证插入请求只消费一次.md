# 任务 001：保证插入请求只消费一次

## 状态

- 状态：完成
- 执行者：主会话 Codex
- 依赖：`../plan.md`
- PR 映射：一个独立前端修复切片；当前未获 PR 创建授权

## 目标与产物

让 `ComposerInsertRequest` 在 App 生命周期内只消费一次，防止 Composer 重挂载后把
已删除的专家问题写回原会话或复用的空白会话。

产物：App/Composer 消费回执、组件回归测试、计划/进度/任务完成收据。

## 允许范围

- `desktop/frontend/src/App.tsx`
- `desktop/frontend/src/features/composer/ui/Composer.tsx`
- `desktop/frontend/src/__tests__/composer-session-draft.test.tsx`
- `docs/ai03/修复-专家提示重复注入/**`

## 禁止范围

- Go 后端、`EnsureBlankTab`、专家激活和持久化 schema。
- Composer 草稿 key 或会话切换架构重写。
- 与本问题无关的样式、模型、技能和连接器行为调整。

## 实现合同

1. Composer 暴露可选消费回调，参数为已处理请求 ID。
2. 现有本地 ID 去重保留；每个新 ID 首次进入 effect 时发出一次回执。
3. App 仅在当前请求 ID 匹配回执时清为 `null`。
4. 请求处理分支保持现有 replace、skill、workspace reference 和普通插入语义。
5. 测试必须覆盖父级清理后卸载/重挂载不重放，以及随后新 ID 仍能执行。

## 验收标准

- 首次专家 prompt 正常注入。
- 消费后 App 不再持有旧请求。
- Composer 重挂载不重放旧请求。
- ID 条件清理不影响更晚的新请求。
- 复用空白会话的稳定应用路径不再命中。
- 聚焦测试、前端构建和 code guard 通过。
