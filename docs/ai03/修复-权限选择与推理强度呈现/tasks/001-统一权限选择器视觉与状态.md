# 001：统一权限选择器视觉与状态

## 目标与预期产物

将 Composer 权限入口和弹层对齐模型选择器的浅色边框与主题浮层语言，并让 ask、auto、yolo 的图标、文案及状态色由同一映射驱动。产物包含前端实现、聚焦回归测试和本任务完成回执。

## 依赖与执行分组

- 依赖同目录 `../plan.md` 的已确认视觉决策。
- 属于串行组 A，先于任务 002 提交，便于独立审查和回滚。
- 用户授权同一分支连续交付，不创建中间 PR；本任务映射到权限视觉独立 commit。

## Codegraph 与源代码依据

- `Composer.tsx` 的权限菜单已定义 `Shield`、`ShieldCheck`、`ShieldAlert`，触发器仍固定渲染 `Shield`。
- `session.css` 的 `.composer-approval-trigger` 和 `.composer-access-menu` 与模型选择器使用不同圆角、背景和阴影规则。
- `theme-overrides.css` 的创建页浅色表面覆盖包含 `.modelsw__trigger`，未包含 `.composer-approval-trigger`。
- `base.css` 的主题浮层覆盖包含 `.modelsw__menu`，未包含 `.composer-approval-menu`。
- `composer-responsive-toolbar.test.tsx` 已覆盖权限菜单选择、键盘和响应式行为，是最近回归入口。

## 必须保留的行为与约束

- 点击菜单项继续调用现有 `onSetToolApprovalMode`，关闭菜单并恢复输入焦点。
- `menuitemradio`、`aria-checked`、方向键、Home、End、Escape 和禁用态保持。
- ask、auto 使用普通强调色；yolo 仅强调图标和文字，按钮边框和背景保持中性浅色。
- 默认、悬浮、焦点、打开、禁用以及当前主题样式都必须可辨识。
- 不通过复制模型选择器 DOM 来复用外观，只对齐权威 token/选择器组。

## 验收标准

- ask、auto、yolo 入口分别显示普通盾牌、带勾盾牌、警示盾牌及对应文案。
- 切换权限后，入口和弹层的图标、文案、活动状态在同一次渲染中对应当前值。
- yolo 入口与活动菜单项使用警示红色；菜单活动项允许轻微危险色底，hover/open 不覆盖语义色。
- 权限入口与模型入口的浅色边框、背景和圆角一致；权限弹层与模型弹层的主题边框、圆角、背景和阴影一致。
- 权限弹层标题与外层入口使用相同的常规字重；ask/auto 活动色和 yolo 危险色语义保持。
- 现有紧凑宽度不溢出，键盘和焦点行为不回退。
