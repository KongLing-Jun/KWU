## 目标与预期产物

## 状态与刷新合同

- 组合阶段为 pending、ready、degraded、updating-effort，并带每标签页单调选择序列。
- 任意 meta/optimistic_meta 引入不同 `modelRef` 时旧 effort 立即失效并进入 pending。
- pending 通过现有 `selectionPresentation="pending"` 隐藏半更新文案，不显示新模型配旧强度。
- 首次/会话加载把 pending 呈现为空白加载壳；显式模型切换保存上一组确认的模型、billing source 和 effort，内部 pending 期间继续显示并禁用旧组合，待新目录身份与新组合同时就绪后一次替换。
- 唯一刷新辅助函数并发读取 meta 与 effort；只有匹配当前标签页、选择序列和返回 `modelRef` 的组合 action 可发布 ready。
- meta 成功、effort 失败时发布 degraded：清除旧 effort，显示当前模型，选择器保持可用。
- 直接模型切换开始时状态进入 pending，但 UI 保留旧确认组合；切换成功一次替换，失败恢复切换前完整组合。
- 直接强度切换保持模型和新强度可见，以 updating-effort 短暂禁用选择器；成功回到 ready，失败恢复旧组合并显示警告。
- context、balance、jobs、checkpoints 独立加载，不阻塞组合身份。

## 验收标准

- 支持强度的模型在首次进入、历史会话打开、冷/缓存切换和直接模型切换时以“模型 · 强度”一次呈现。
- 支持与不支持强度的模型互切不会遗留上一模型强度。
- 显式切换模型期间旧的“模型 · 强度”持续可见，新组合就绪后一次替换，选择框不消失。
- 同一模型切换强度时模型选择框不消失，新强度立即显示，失败恢复旧强度。
- 模型与推理强度文案使用相同前景色，不因显式强度单独变为 accent 色。
- 延迟 context/balance/jobs/checkpoints 不延迟组合身份。
- 快速连续切换时旧请求不能覆盖最后一次选择。
- effort 失败会进入 degraded 并显示模型，不永久 loading。
- 不支持强度的模型正常只显示模型；现有模型目录、订阅门禁和切换失败提示不回退。
