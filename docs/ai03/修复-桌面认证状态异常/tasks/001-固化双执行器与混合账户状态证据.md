## 2. 目标与交付物

用最小、确定性的自动化测试证明以下当前行为，而不是修复它：

1. 两个不同 `AuthenticatedRequestExecutor` 共享一个 session store 时，可同时使用
   同一旧 refresh token；winner rotation 后，loser 的 terminal error 因
   `sameObservedSession=false` 不终止 replacement。
2. bootstrap 因此可返回 authenticated/bound、cloud user ID present、display name
   absent、terminal `operation_error`。
3. 前端会保存这个 account/error，身份标签回退 user ID，且不会显示 expired 专用
   重新登录提示。
4. replacement 被服务端 family revoke 后，下一次 `AUTH_REQUIRED` 会把当前 session
   scrub 为 expired，随后 bootstrap/frontend 才进入重新登录状态。

交付物为 Go/TypeScript 回归证据、聚焦测试结果、安全日志样例和准确任务回执。

## 4. 测试合同

### 4.1 双 executor 核心测试

- 创建一个 scope 和一个过期 authenticated session。
- 创建一个共享 store 和两个独立 executor；断言对象身份不同。
- barrier 记录两个 refresh attempt 都已进入，之后才释放响应。
- 固定一个 attempt 成功并保存 replacement；另一个返回
  `REFRESH_TOKEN_REUSED` + 固定 request_id。
- 断言：winner 请求成功；loser 返回原 code/request_id；store 仍为 authenticated
  replacement；old/replacement expiry 不同；等价于 `sameObservedSession=false`。
- 将 stub 切换为 replacement 受保护请求返回 `AUTH_REQUIRED`，再次执行。
- 断言 session 为 expired，token present 均 false，termination reason/time 存在。

不得使用 sleep 决定顺序；不得只从一个 executor 启动两个 goroutine。

### 4.2 Desktop bootstrap 测试

- 通过真实 `newRealCloudRuntime...` composition 或等价现有测试 helper 创建 runtime；
  不复制 `cloudBootstrapForActor` 逻辑。
- 预置与 runtime environment/profile/binding generation 一致的 durable session。
- 使用 account executor 与 runtime shared executor 触发同一 barrier rotation。
- 第一阶段断言 `CloudBootstrapView`：
  `account.status=authenticated`、`binding_status=bound`、generation 不变、
  cloud user ID present、display name absent、`operation_error.code` 为
  `REFRESH_TOKEN_REUSED` 或同等 terminal error、request_id 保留。
- 第二阶段让 replacement `/me` 返回 `AUTH_REQUIRED`，断言下一次 bootstrap account
  为 expired、display name absent、operation error 保留，durable session 已 scrub。

若现有 composition 无法在不改产品代码的情况下确定性暴露两个 executor，必须停止并
在回执记录阻塞点，不得退化为复制生产分支的假测试。

### 4.3 前端纯状态测试

- 通过 Zustand `applyBootstrap` 注入第一阶段 DTO。
- 断言 account 仍 authenticated、error code/request_id 被保存、
  `requiresReauthentication=false`。
- 渲染真实 AccountCenter，断言 identity 显示内部 user ID、普通错误 alert 可见、
  `data-account-reauthentication` 不存在。
- 注入第二阶段 expired DTO，断言 assets/payments 清空、
  `requiresReauthentication=true`、user ID 不作为正常账户标题、重新登录提示出现。

测试名称与断言文案必须明确这是“证明当前异常合同”的基线证据，不能写成已修复。

## 6. 保存行为

- 单 executor 并发仍只 refresh 一次。
- 已 rotation 的新 session 不被迟到旧错误覆盖。
- 当前 session 的 terminal error 仍 scrub + expired。
- offline/network/5xx/rate-limit 不被测试改写为 terminal。
- environment/schema/profile rejection 与 generation 规则不变。
- AccountCenter 现有普通 error code/request_id 呈现不变。
