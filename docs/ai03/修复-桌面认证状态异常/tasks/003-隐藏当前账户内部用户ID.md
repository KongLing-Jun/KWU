## 2. 目标与证据

修复 hydration 失败时当前账户可见标签退化为内部 `usr_*` 的展示问题：

- `desktop/frontend/src/App.tsx` 的 sidebar label 当前使用
  `display_name || cloud_user_id`。
- `desktop/frontend/src/features/account/ui/AccountCenter.tsx` 的 `identityLabel` 使用同样
  fallback。
- `desktop/frontend/src/locales/zh.ts` 已存在 `account.nameUnavailable`，无需增加文案或
  locale 文件。
- 当前 store 必须继续保存 cloud user ID 作为 binding/scope/feedback 身份，问题仅是把它
  当普通用户名渲染。

## 3. 交付行为

1. sidebar 对 authenticated/offline recoverable account：有非空 display name 时照常显示；
   缺失时显示 `account.nameUnavailable`，不显示 cloud user ID。
2. AccountCenter 当前账户 overview、payments header 等所有使用当前 `identityLabel` 的位置
   采用同一安全标签。
3. expired 仍优先显示现有“登录已失效”；anonymous 仍显示登录/注册；loading/unavailable
   行为不变。
4. profile mismatch 的 candidate switch 仍可使用现有 candidate identity 合同；本任务不
   改 candidate 数据、scope key、feedback identity 或 API DTO。

- `desktop/frontend/src/App.tsx`

  现有测试

不得新增 helper、组件、CSS 或 locale key，除非现有结构无法完成并先停止说明材料原因。

## 5. 禁止范围

- 不修改 Go、store DTO、bridge、cloud user ID 持久化、scope/generation、feedback、avatar、
  account switch、支付、登录表单或错误呈现。
- 不把 display name 持久化到 credential/session 文件，不引入新的缓存或迁移。
- 不隐藏安全 operation error code/request_id，不把 hydration failure 伪装为登录失效。
- 不修改、删除或清理主工作区及其 `artifacts`，不推送、不创建 PR、不继续委派。

## 6. 必须保留

- 正常 hydrated display name、expired UI、anonymous 登录入口、profile mismatch candidate、
  AccountCenter operation error 和 sidebar/account store 同 generation 状态。
- cloud user ID 在内存 DTO 和内部 scope 仍然存在，只是不作为当前账户可见用户名。
- 当前唯一简体中文 i18n 合同与既有 `account.nameUnavailable` 文案。

## 7. 验收

- authenticated 与 offline recoverable account 在 display name 缺失、cloud user ID present
  时，sidebar 和 AccountCenter 都显示“账号名称暂不可用”，DOM 不包含该 user ID。
- display name present 时两个入口继续显示 display name。
- expired/anonymous/loading/unavailable 和 candidate switch 现有测试继续通过。
- AccountCenter 仍呈现 operation error 的安全 code/request_id；不新增 credential 或完整
  cloud user ID 日志。
- 生产前端 build 通过，diff 不包含无关格式化或样式变化。
