## 2. 目标与证据

修复已由 production request_id 和确定性测试证明的跨 executor refresh race，并让幂等
`/me` 对迟到 terminal error 重新验证当前 replacement。根因位于：

- `internal/cloud/auth_identity_lifecycle.go`：`RemoteAccountApplication` 隐式创建 executor，
  `refreshMu` 只属于 executor 实例，`persistFailureLocked` 对 changed observed session 跳过
  终止。
- `desktop/cloud_runtime.go`：remote account 隐式 executor 与 runtime shared executor 同时
  存在并共享一个 durable store。
- `desktop/cloud_api_real_auth_state_test.go`：基线证明两次 refresh 后出现
  authenticated + terminal operation error；固定 replacement expiry 另有跨日夹具缺陷。

## 3. 交付行为

1. `NewRemoteAccountApplication(bindings, sessions, client, executor, observers...)` 必须以显式
   `AuthenticatedRequestExecutor` 参数替换原 `now` 参数，不再在构造器内部创建第二个
   executor，也不保留无用 `now` 或兼容 constructor。
2. desktop runtime 先创建唯一 executor，再把同一个实例注入 remote account、project、
   credit、payment、event、MaaS 等现有消费者。
3. `RemoteAccountApplication.CurrentUser` 在首次 hydration 前，使用首次 binding 的固定
   `BindingScope` 从现有 underlying session store 记录 observed session。第一次返回 session
   terminal error 后在同一 scope 加载 current，并确认 actor binding 仍等于首次 binding；
   仅当 current 为 authenticated 且与 observed credential/expiry 不同时，最多再
   通过同一 executor 执行一次 `/me`；第二次结果为最终结果。
4. replacement 可用时返回完整 `AccountState`；replacement 终止时沿既有 executor 路径
   scrub credential、转 expired。current 已 expired、未变化、缺失或 post-load 失败时
   返回第一次原始 terminal error，保留 code/request_id。binding 已切换、network/retryable
   error 不进入第二次 terminal 验证。
5. 把 desktop 基线测试改为修复合同：并发 project/account 只发生一次 refresh；account
   使用 replacement hydration 成功。另保留 replacement 被拒绝后同一次 bootstrap 输出
   expired 的覆盖，并修复固定绝对 expiry 的跨日不稳定。

  校验和 observer 行为保持不变。
- dev/prod environment isolation、session schema v3 和现有 cloud clients 的 transport 选择
  保持不变。
- `/me` observer 只在最终 validated `AccountState` 成功后执行一次。

## 7. 验收

- 构造器依赖校验拒绝 nil executor；仓库内所有调用者显式注入。
- runtime 测试证明 remote account 与 project path 使用同一个 executor，并且 barrier 并发
  只调用一次 refresh endpoint。
- 第一次旧 session terminal、store 已有可用 authenticated replacement：只多一次
  `/me`，最终成功、
  display name present、无 terminal operation error、session authenticated。
- replacement 也返回 `AUTH_REQUIRED`：最终 durable session expired，access/refresh/device
  与 expiry scrub，termination reason/time 正确，bootstrap account.status=expired 且保留安全
  code/request_id。
- current session terminal 已转 expired、session offline、session 未变化、post-load 失败及
  network/retryable error 都不做 terminal retry；返回第一次 terminal 时 request_id 不丢失，
  且不会形成无限重试。
- pre/post 比较固定在首次 scope；并发 rebind/account switch 不读取新 binding session、
  不发起旧 binding 的额外 `/me`、不执行 observer。
- 迟到 terminal 后 replacement hydration 成功时 observer 恰好执行一次，且只收到最终
  validated `AccountState`；current expired、post-load failure、binding switch 和 replacement
  terminal 路径 observer 均为零次。
- 测试不依赖墙钟日期，不使用概率 sleep；安全日志审计通过。
