## 目标与产物

让历史团队工作区只由父 Session 的`ExpertTeamForTab`视图驱动，不再依赖当前 Composer 的
`activeExpert`。active与archived在切换和重启后都恢复成员页签和只读 child历史，当前回复身份仍与
历史工作区严格分离。

产物包括：

- Transcript团队加载、解析和呈现门禁解耦；
- archived + CurrentExpert none 的真实 App/Transcript跨层回归；
- 普通 task、missing/corrupt sidecar和tab竞态保持失败关闭；
- 必要的 Desktop bridge所有权回归，但不改变 sidecar权威。

## 证据与实现依据

- `App.tsx/useExpertCatalog`把`CurrentExpertForTab=none`映射为`activeExpert=null`并传给 Transcript。
- `Transcript.tsx`当前在父工具恢复、团队候选接受、加载重试、工作区 item和成员映射中多次检查
  `activeExpert?.mode === "team"`，并要求持久团队 ID 等于当前专家 ID。
- `desktop/subagent_history.go:ExpertTeamForTab`已能从 active/archived sidecar返回团队快照，并只暴露
  通过父所有权校验的成员 ref。
- 现有测试分别覆盖 backend archived视图和组件手工输入 archived，但缺少
  `CurrentExpertForTab=none -> App/Transcript reload -> 历史团队仍显示`链路。
- 提交`00aa1c29`确立 missing-sidecar普通 transcript fallback；本任务保留该兼容边界。

## 保持行为与约束

1. Composer、当前回复身份和当前专家头像只消费`CurrentExpert`。
2. 历史团队标识、成员顺序和可打开 ref只消费`ExpertTeamForTab`返回值。
3. `team_archived`工作区只读；不得恢复主专家 prompt或成员调度能力。
4. `ExpertTeamForTab=null`继续显示普通 transcript，不显示空壳 AgentWorkspace。
5. bridge error不得被吞成伪造团队；保留明确错误/重试边界。
6. tab/scope/rewind代际必须隔离，迟到请求不得污染当前 tab。
7. child ref必须继续由 Desktop父所有权验证；Frontend不能自行拼接或选择 ref。
8. 普通 task即使名称与专家成员相同也不得产生成员页签。

## 验收标准

- H-01：active团队在切换/重载后显示持久成员，而非依赖实时 task item。
- H-03：archived + CurrentExpert none在重载后显示同一团队与成员。
- H-04：有 owned ref的成员可打开只读历史并返回父 transcript。
- H-05：archived的专家选择仍被锁定，但普通 Composer可继续聊天。
- H-06/H-07：archived后的普通 task及普通会话 child均不进入团队成员。
- H-08/H-09：missing/corrupt sidecar不触发文本或 artifact恢复。
- H-10：快速tab切换、rewind和迟到加载不串团队。
