# 用户反馈功能开发计划

## 1. 背景与当前行为

创作型桌面的侧栏账户菜单已有总余额、套餐与支付、设置、更新、外观和退出登录，但没有稳定可发现的用户反馈入口。设置中心也没有“帮助与反馈”页面。

当前仓库存在两类相邻能力，但都不能直接完成本需求：

- `desktop/crash_app.go` 上报匿名崩溃 JSON，端点、身份和数据契约均不同。
- `internal/cloud` 已有登录态、令牌刷新、设备与版本请求头及 multipart JSON
  传输，但没有 `/api/v1/error-reports` 的领域客户端。

## 2. 期望行为

创作型侧栏账户菜单在“外观”之后增加“帮助与反馈”。点击后关闭菜单并打开设置中心的“帮助与反馈”标签；设置左侧新增末尾“支持”分组，右侧直接展示意见反馈表单，不再打开二级弹窗。

表单严格映射云平台提交接口：

- `description`：必填，界面按可见字符限制为 300 个。
- `file`：可选；没有图片时不发送。
- 不发送可选的 `error_code` 和 `occurred_at`。
- 不增加分类、标题、联系方式、评分、日志、协议或其他服务端不接收的字段。

`POST` 返回成功后，桌面端立即使用同一登录用户调用
`GET /api/v1/error-reports/{report_id}` 回读；只有报告编号一致且状态仍为
`submitted` 才向用户显示成功。不提供反馈历史或管理页面。

## 3. 目标、非目标与边界

- 为已登录用户提供文字及少量问题截图的反馈闭环。
- 自动复用当前云端身份、设备 ID、客户端版本和安全错误模型。
- 以幂等提交处理令牌刷新重放和用户手动重试。
- 图片路径不进入前端，原图和反馈草稿不落盘。
- 保持现有设置中心和创作型侧栏的视觉语言。

非目标是匿名/英文/其他布局、日志或任意文件上传、图片编辑、反馈查询与管理后台；不得修改云平台接口、认证、账号绑定、崩溃上报或遥测。

- 最多 4 张 PNG/JPEG，单张选择文件与净化结果均不超过 5 MiB；所有存活令牌对应的净化字节合计不超过 20 MiB。
- 拒绝任一边超过 8192 像素、总像素超过 2500 万、格式与文件签名不符或无法完整解码的图片；逐张处理。
- 接受的图片保持原分辨率；PNG 无损重编码，JPEG 高质量重编码，移除 EXIF、GPS 等元数据。
- 1 张图片直接作为 `file` 上传；2–4 张生成确定性 `feedback-images.zip`。
- 前端只接收最长边 320 像素且单张不超过 256 KiB 的缩略图、文件名、大小和一次会话内的随机令牌。

## 4. 用户场景与验收标准

| 场景 | 验收结果 |
| --- | --- |
| 从创作型账户菜单进入 | “帮助与反馈”位于“外观”后；一次点击打开对应设置标签 |
| 未登录或登录失效 | 入口仍可见；表单不可提交，显示中文登录引导和“去登录” |
| 纯文字提交 | 只发送 `description`，不包含 `file`、`error_code`、`occurred_at` |
| 选择 1 张合法图片 | 显示安全缩略图；上传净化后的 PNG/JPEG 原分辨率文件 |
| 选择 2–4 张合法图片 | 上传一个可解压且图片清晰的确定性 ZIP |
| 非法格式、超限或解码失败 | 本地中文提示；不创建云端请求，不泄露路径 |
| POST 与随后 GET 均为 HTTP 200 | 报告编号一致且状态为 `submitted` 后清空文字和图片，显示可复制的 `report_id` |
| POST 成功但 GET 失败/404/不一致 | 不显示成功、不清空草稿；显示中文错误及可复制的查询 `request_id` |
| 响应丢失后手动重试 | 内容未改时沿用幂等键；`replayed=true` 也按成功处理 |
| 网络、5xx 或不可重试错误 | 保留草稿；中文提示安全错误码和可复制 `request_id` |
| 修改失败草稿后重试 | 生成新的幂等键，避免同键不同内容冲突 |
| 切换设置标签 | 草稿仍保留 |
| 关闭有内容的设置窗口 | 使用应用现有确认能力提示放弃；确认后释放内存图片 |
| 提交尚未结束 | 禁止关闭、切换账号、重复提交及遮罩/Esc 退出；120 秒超时后恢复操作并保留草稿 |

页面只发布简体中文文案；当前前端本身固定为简体中文，本计划不新增英文资源。

## 5. 云平台契约

提交请求为 `POST /api/v1/error-reports`，携带 Bearer Token、scope-bound 幂等键、
现有客户端版本和设备 ID；`Content-Type` 使用客户端生成 boundary 的
`multipart/form-data`。提交成功后以同一用户 Token 请求
`GET /api/v1/error-reports/{report_id}`，确认报告真实可回读。

服务端约束为：`description` 必填且最多 10,000 bytes；`error_code` 可选且最多 128 bytes；`occurred_at` 可选且为 RFC3339；单个 `file` 可选且最多 100 MiB；整个请求最多 101 MiB。客户端提交前对描述执行 `trim`，要求至少 1 个、最多 300 个用户可见字符且 UTF-8 编码不超过 10,000 bytes；20 MiB 附件限制是有意收紧。

multipart boundary 必须由 `multipart.Writer` 生成，不手工设置。成功响应至少校验
`data.report.report_id`、`data.report.status`、`data.replayed` 和顶层 `request_id`。
重放响应中的 `report` 可能只有精简字段，附件不存在时也没有 `attachment`；客户端不得因此判定失败。附件元数据可以解码但不向用户暴露 OSS 键、下载地址或正文。

## 7. 选定方案

### 7.1 导航与表单

1. 扩展 `SettingsTab`、设置分组、标签标题和中文文案。
2. 新建独立 `FeedbackSettingsSection`；反馈页不触发完整设置快照加载。
3. `App` 将当前账号状态和“去登录”动作传入设置中心。
4. 反馈 section 向设置中心报告 dirty 和 submitting 状态；有草稿时关闭按钮、
   Esc、遮罩和“去登录”统一经过既有 `ConfirmAction`，提交中则统一禁止退出
   反馈流程，不新增跨 Wails 的请求取消协议。

### 7.2 图片选择与内存隔离

1. 新建桌面反馈图片存储，原生多选后立即逐张读取、签名校验、像素检查、
   解码、重编码和生成小缩略图。
2. 净化后的原图仅保存在 `App` 进程内的有界 map；前端得到随机令牌，不得到
   路径或原图。
3. 删除图片、放弃草稿、提交成功或账号切换时立即释放对应字节；意外丢失前端
   状态时最多保留 20 MiB 至应用退出，不使用可能误删活跃草稿的定时过期。
4. 提交失败不释放图片，从而保证同一幂等键重试时附件字节一致。

### 7.3 云端提交

1. 在 `internal/cloud` 新增 `ErrorReportClient` 领域契约与 HTTP 实现。
2. 复用现有有界内存 multipart 传输；20 MiB 客户端上限避免改造共享流式
   transport，并为上传使用显式 120 秒请求超时。
3. 单图使用净化后的真实 MIME 和安全文件名；多图 ZIP 固定顺序、条目名和
   时间戳，保证重试内容确定。
4. 前端首次提交生成随机尝试 ID；桌面端结合绑定 scope 生成
   `X-Idempotency-Key`。内容或图片变化后清除尝试 ID。
5. 除令牌过期重放外不自动重试；新增 `FeedbackSubmitView`，提供 `report_id`、
   `replayed`，或含中文 `message`、安全 `code`、
   `retryable`、`request_id` 的
   `operation_error`。预期云错误不解析 Wails 错误字符串；其他错误只给中文通用提示。
6. POST 成功后在同一 120 秒 deadline 内执行一次 GET 回读；回读失败保留草稿和
   原幂等键，手动重试仍可安全取得首次提交结果，不自动生成重复报告。

## 9. 兼容性、风险与回滚

- 只新增桌面方法、设置标签和云客户端；无数据库、配置或本地文件迁移。
- 不改变既有设置、账号、更新、外观、崩溃上报及支付行为。
- fake/不可用云运行时返回“云服务不可用”，不得伪造提交成功。

- **敏感图片**：仅用户主动选择；固定简短提示；清除元数据；不采集日志。
- **任意文件泄露**：后端选择并保存净化字节，前端不能提交路径。
- **解压/解码炸弹**：选择大小、格式、尺寸、像素和净化后大小多重上限。
- **内存峰值**：存活净化字节总计 20 MiB；单边 8192/总像素 2500 万；逐张解码；单张缩略图 320 像素/256 KiB；按生命周期释放。
- **重复创建**：scope-bound 幂等键、稳定附件字节和手动重试。
- **成功响应与目标数据库不一致**：POST 后强制 GET 回读；仅在报告编号和状态
  均一致后显示成功。
- **慢网与关闭竞态**：独立 120 秒超时；提交中禁止关闭、去登录和重复提交，避免增加跨桥取消机制及状态不明的重复报告。
- **嵌套关闭路径漏拦截**：关闭按钮、Esc、遮罩和去登录共享 dirty/submitting guard。
- **ZIP 后台不可在线预览**：已接受；多图至少可下载解压，单图可直接预览。

回退实现提交即可移除入口、设置页、内存图片和云客户端。没有持久化数据、
云端迁移或本地草稿需要回滚；已成功提交的云端反馈不因客户端回滚删除。

  图片增删、成功清空、失败保留、重试键、关闭确认及提交中退出拦截。
- 前端最终运行 `pnpm build`；不运行项目规则排除的全量前端测试。

1. 在创作型账户菜单和设置导航核对入口、布局、明暗主题与中文文案。

## 11. 未解决问题与停止条件

没有待用户决定的产品问题。Stage 2 需把云客户端、桌面图片/提交桥接和前端表单
划分为可审查任务，并明确共享文件所有权。

若实施发现云端不接受省略 `error_code`/`occurred_at`、不接受 ZIP、幂等比较要求
不同，或必须增加日志、持久化、依赖、其他布局或新的隐私协议，停止实施，更新本
计划并重新 Grill/审批。当前新增的单报告 GET 回读已由用户在真实验收失败后批准；
它不扩展为反馈历史或管理功能。
