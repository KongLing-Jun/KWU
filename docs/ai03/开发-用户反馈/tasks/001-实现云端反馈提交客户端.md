## 任务目标与预期产物

在 `internal/cloud` 增加只负责 `POST /api/v1/error-reports` 的认证领域客户端。
该包是编译进桌面进程的本地出站 HTTP 客户端，不是云平台服务端；复用现有令牌
刷新执行器和 multipart transport，稳定解析首次及幂等重放响应。

预期产物是 `ErrorReportClient`、输入/结果/附件契约、HTTP 实现和包级测试。
本任务不提供桌面方法、图片处理或前端入口。

## 实现约束

1. 输入含 `description`、幂等键及可选单附件；描述 trim 后非空且不超过
   10,000 UTF-8 bytes，附件在本客户端再次防御性限制为 20 MiB。
2. 使用 `multipart.Writer` 生成 boundary；没有附件时完全省略 `file`。
3. 设置 `X-Idempotency-Key`，认证、设备 ID、客户端版本仍由共享 transport 写入。
4. multipart 字节在调用 executor 前只构建一次，令牌刷新重放复用完全相同的
   payload、Content-Type 和幂等键。
5. 只解析 `data.report.report_id`、`data.report.status`、`data.replayed`；
   接受精简重放报告及缺失 `attachment`，拒绝空报告 ID、空/未知必要状态和坏 envelope。
6. 调用方提供的 deadline 必须原样向下传递；不得把 120 秒产品超时写成共享默认值。
7. 云错误保留现有安全 `code`、`retryable`、`request_id`，协议错误走既有
   `CLOUD_PROTOCOL_ERROR` 规则。

## 验收标准

- 纯文字请求只有 `description`；附件请求只有 `description` 与一个 `file`。
- boundary、真实 MIME、安全文件名和 `X-Idempotency-Key` 正确。
- 完整首次响应与精简 `replayed=true` 响应都返回同一报告 ID 语义。
- 无附件响应可成功解析；错误 envelope 带回安全 request ID。
- 令牌过期只刷新/重放一次，且两次请求 body、Content-Type、幂等键一致。
- 同键不同内容冲突、网络错误、取消和 deadline 都按现有错误模型返回。
- 不存在任何 GET、查询历史或附件下载能力。
