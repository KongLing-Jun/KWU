## 实现约束

1. `App` 持有并发安全的 feedback image store；令牌使用加密随机值并绑定当前
   `BindingScope`，所有存活净化字节总计最多 20 MiB。
2. 原生多选最多补足到 4 张；选择操作全有或全无，任一文件失败即释放本次新增字节。
3. 先限制选择文件 5 MiB，再校验 PNG/JPEG 签名、完整解码、单边 8192、总像素
   2500 万；PNG 无损、JPEG quality 95 重编码，净化结果仍须不超过 5 MiB。
4. 重编码结果不含 EXIF/GPS；缩略图最长边 320、单张不超过 256 KiB，只返回
   data URL、令牌、安全文件名、MIME 和净化后大小，不返回路径。
5. 删除、放弃、提交成功、成功退出/换号和 shutdown 释放对应 scope 字节；
   提交失败保留，未知/跨 scope/重复令牌拒绝。
6. 单图上传净化原图；多图按请求令牌顺序生成稳定条目名、固定 ZIP 时间戳和
   `feedback-images.zip`，相同输入必须逐字节一致。
7. 提交请求只含 trim 后描述、前端随机 attempt ID 和令牌；后端按 Unicode
   code point 重验非空、最多 300 个字符、10,000 UTF-8 bytes、数量与 scope，
   并生成 scope-bound 幂等键。
8. 使用 `context.WithTimeout(a.bootContext(), 120*time.Second)`；成功才释放图片。
9. `FeedbackSubmitView` 返回 `report_id`、`replayed` 或 `operation_error`；
   operation error 只含中文 message、安全 code、retryable、request_id。
10. 未登录、过期、Fixture、disabled 或 init error 均 fail-closed，不得伪造报告 ID。

## 验收标准

- 非法格式、签名伪装、损坏、文件/尺寸/像素/内存超限均在发网前中文失败。
- 1 张 PNG/JPEG 元数据被移除且云端仍可看清；2–4 张 ZIP 可解压、顺序稳定。
- 前端可见结构及错误中不出现绝对路径、原图字节、token、用户 ID 或内部错误。
- 纯文字、单图、多图请求严格映射任务 001 客户端；没有可选字段泄漏。
- 同内容手动重试及令牌刷新复用稳定附件和幂等键；修改 attempt ID 后生成新键。
- 失败保留草稿令牌，成功/放弃/删除/换号/退出释放；跨账号令牌不可提交。
- 120 秒 deadline 可验证；Fixture/不可用云运行时明确失败。
