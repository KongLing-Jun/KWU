# 会话操作菜单悬浮关闭修复计划

## 1. 问题与预期

创作界面中，助手消息下方的“总结”和“回滚”按钮会在鼠标悬浮时打开操作面板；鼠标
移出按钮和面板后，面板仍持续显示，必须点击外部区域才能关闭。

已确认的预期是简单悬浮交互：进入任一按钮时打开对应面板，指针移入该面板时保持
打开，离开“按钮 + 面板”整体区域后关闭；点击不固定面板。允许约 150ms 的短暂关闭
宽限，用于跨越按钮与绝对定位面板之间的视觉间隙，期间重新进入区域应取消关闭。

## 2. 基线、当前行为与根因

- 计划基线：`origin/main-v3@6391e4bfb5b499b4f0065e7a7e1bc606795d4eee`。
- 主工作区 Codegraph 索引导航与同一提交上的独立 worktree 源码复核一致：
  `App.tsx` 仅在 `sidebarCreation && !hydratePlaceholderActive` 时向 `Transcript` 传入
  `actionHoverMenus=true`；`Transcript` 以 `openAction` 统一控制当前回合和菜单。
- `TurnActions` 的两个菜单组只通过 `onMouseEnter` 调用 `openHoverMenu`，没有
  `onMouseLeave` 或延迟关闭处理。
- `Transcript` 现有 document `mousedown` 监听只在点击 `.turn-actions` 外部时清空
  `openAction`，不能响应单纯的指针移出。这是截图中面板残留的直接原因。
- `TurnActions` 只有 `Transcript` 一个消费者；Codegraph 未发现其交互覆盖测试。现有
  Vitest + Testing Library 基础设施可直接覆盖受控菜单的鼠标事件和定时器。
- 工作树源码与索引基线相同；实施阶段不在独立 worktree 重新调用 Codegraph，所有修改
  以工作树直接源码、测试、构建和实际 Git diff 为准。

## 3. 目标与非目标

### 目标

- 悬浮进入“总结”或“回滚”按钮即显示对应面板。
- 从按钮移动到其面板时面板保持显示；短暂经过两者间隙不会闪关。
- 离开按钮和面板整体区域约 150ms 后关闭；宽限期内重新进入会取消关闭。
- 在两个按钮间移动时切换为当前悬浮按钮的面板，不残留旧面板。
- 悬浮模式下点击不固定或反向关闭面板；菜单项点击行为保持不变。

### 非目标

- 不改变非悬浮模式下通过点击打开、再次点击关闭及点击外部关闭的行为。
- 不改变总结、分支、回滚的可用条件、二次确认、文件提示、执行协议或文案。
- 不修改菜单视觉、定位、层级、尺寸、动画、后端、数据、依赖或 Go/Wails 契约。
- 不扩大为通用 Tooltip、Popover 或其他悬浮表面的重构。

## 4. 验收标准

| ID | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 悬浮进入“总结”按钮 | “总结”面板立即打开，`aria-expanded=true` |
| AC-02 | 从“总结”按钮移入其面板 | 面板持续显示，不因视觉间隙闪关 |
| AC-03 | 离开“总结”的按钮和面板 | 约 150ms 后面板消失，`aria-expanded=false` |
| AC-04 | 关闭宽限期内重新进入原区域 | 取消待关闭操作，面板保持显示 |
| AC-05 | 从“总结”移动到“回滚”按钮 | 只显示“回滚”面板，不残留“总结”面板 |
| AC-06 | 悬浮模式下点击已打开按钮 | 面板不被固定，也不在仍悬浮时反向关闭；离开后仍消失 |
| AC-07 | 非悬浮模式 | 现有点击切换、外部点击、菜单动作和键盘可达路径不变 |
| AC-08 | 范围 | 无样式、后端、依赖及 `scripts/code_guard_baseline.json` 变更 |

## 5. 选定方案与影响范围

在 `TurnActions` 内维护一个可清理的短时关闭计时器：

- 悬浮进入任一菜单组时取消待关闭计时器并打开对应菜单；
- 悬浮离开菜单组时仅在 `hoverMenus=true` 下安排约 150ms 后关闭；
- 组件卸载时清理计时器，避免卸载后回调；
- 悬浮模式的按钮点击只确保对应菜单打开，不使用点击切换形成固定状态；
- `hoverMenus=false` 时继续使用现有 `toggleMenu` 路径。

预计影响文件：

- `desktop/frontend/src/components/Message.tsx`：补齐悬浮进入、离开、定时清理与点击分流。
- `desktop/frontend/src/vitest/turn-actions-hover-menu.vitest.test.tsx`：覆盖打开、跨入面板、
  延迟关闭、重新进入取消、菜单切换、点击不固定及非悬浮点击回归。
- 本主题任务回执与 `progress.md`：记录实施边界和验证结果。

不把关闭状态下沉到 `Transcript`：计时与命中区域都属于 `TurnActions` 局部交互，下沉会
扩大父组件契约并让 hot/warm 两条渲染路径重复处理同一规则。

## 6. 兼容性、风险与回滚

该修复只改变创作界面的菜单展示生命周期，无数据或接口迁移。

| 风险 | 控制 |
| --- | --- |
| 绝对定位面板与按钮间隙触发过早关闭 | 使用 150ms 宽限，进入同组按钮或面板时取消计时器 |
| 旧计时器关闭后来打开的另一菜单 | 打开/切换前取消旧计时器，并让关闭仅作用于受控菜单状态 |
| 组件卸载后计时器写状态 | effect cleanup 清除计时器 |
| 破坏普通会话点击菜单 | 仅在 `hoverMenus=true` 时启用新分支，增加非悬浮回归测试 |
| 只在测试 DOM 正常 | 在实际桌面应用复现截图路径，验证两组按钮和面板命中区域 |

若出现回归，整体回退 `TurnActions` 悬浮生命周期及对应测试即可；无数据回滚。
