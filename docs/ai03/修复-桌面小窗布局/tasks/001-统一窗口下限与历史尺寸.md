# 001 统一窗口下限与历史尺寸

## 执行契约

- 目标：将 Desktop 原生窗口下限设为 `1200 × 800`，默认尺寸同步为 `1240 × 800`，并使历史正数小尺寸按同一契约归一化。
- 产物：Wails 启动选项与窗口状态加载共用的尺寸常量、历史尺寸归一化逻辑和单元测试。
- 依赖：[plan.md](../plan.md) 已稳定并提交；无代码任务依赖。
- 执行顺序：串行组 A，先于任务 002 执行，便于主会话分片审查。
- 建议实现提交：`fix:限制桌面窗口最小尺寸`。
- 建议回执提交：`docs:记录桌面窗口尺寸修复结果`。

## 证据与实现基础

- `desktop/main.go` 使用默认 `1240 × 720`，但 `MinWidth` / `MinHeight` 仅为 `400` / `480`。
- `desktop/window_state.go` 当前对宽 `<400` 和高 `<300` 置零，不会把旧的正数小尺寸提升到新下限。
- `900 × 600` 原生验收显示窗口整体过小且侧边栏会收起；用户据实际截图要求提高下限。`1200px` 外窗宽度为固定展开侧边栏和主区保留更合理的空间，无需修改响应式逻辑。
- `desktop/window_state_test.go` 已覆盖 profile 隔离，尚缺尺寸归一化契约。

## 允许范围

- `desktop/main.go`
- `desktop/window_state.go`
- `desktop/window_state_test.go`

## 禁止范围

- 不改变窗口状态 JSON 结构或 profile 存储路径。
- 不改变窗口位置校验、最大化恢复、单实例启动或窗口图标逻辑。
- 不改变侧边栏常量、响应式断点或前端布局。
- 不增加通用尺寸抽象或新包；常量保留在 Desktop `main` 包内。

## 必须保持的行为

- 无历史状态时仍居中，默认宽度仍为 `1240`，默认高度随窗口下限提升为 `800`。
- 已保存的宽高大于下限时原样恢复。
- 仅为正数且低于下限的维度执行提升；非正数维度仍走默认值/原迁移语义。
- 位置和 `Maximised` 不随尺寸归一化而改变。

## 验收标准

1. Wails 选项的 `MinWidth` 为 `1200`，`MinHeight` 为 `800`，默认宽高为 `1240` / `800`。
2. 宽高都低于下限的历史正数状态返回 `1200 × 800`。
3. 只有一个维度低于下限时只提升该维度。
4. 已超过下限、缺失/无效状态、全零迁移守卫、位置、最大化和 profile 隔离行为保持。
5. 改动仅落在允许文件内，EOL 保持 LF。

## 完成回执

- 实际改动文件：任务累计改动 `desktop/main.go`、`desktop/window_state.go`、`desktop/window_state_test.go`；本轮从 `1200 × 720` 调整到 `1200 × 800` 仅改动 `desktop/main.go` 与 `desktop/window_state_test.go`。
- 测试结果：本轮在 `desktop` 运行 `go test . -run '^(TestDesktopWindowSizeContract|TestLoadWindowStateNormalizesSavedDimensions)$'` 通过；首次运行 `go test .` 读取 `desktop/kwu-desktop-res.syso` 失败，错误为 `The system cannot find the file specified.`，随后只读确认该文件不存在且工作树无额外变化，重试 `go test .` 通过；主会话独立重跑同一聚焦测试通过；`git diff --check` 通过，目标文件保持 LF。
- 偏差：首次实现采用 `900 × 600`；首次真实验收确认整体过小，第二次 `1200 × 720` 真实验收又确认 Composer 底部被裁切，因此按用户反馈再次提高高度。
- 剩余风险：`1200 × 800` 会进一步限制低逻辑分辨率/高缩放屏幕的可缩放范围，为当前待实测候选边界。
- 交接说明：默认尺寸已由 `1240 × 720` 联动调整为 `1240 × 800`，候选最小尺寸已由 `1200 × 720` 调整为 `1200 × 800`；新增常量契约测试防止默认尺寸低于下限，历史尺寸归一化及既有回退语义保持。主会话先在隔离 profile 的 Wails 原生应用中确认尺寸下限，再按用户要求关闭原主工作区 dev 进程，从本修改 worktree 以标准 dev profile 重新启动；未设置 `KWU_DEV_PROFILE_ROOT`、`KWU_CLOUD_FAKE` 或 `KWU_CLOUD_BASE_URL`。标准 dev 实例客户区为 `1186 × 793`，侧栏保持展开且 Composer 的底边和操作栏完整可见；该实例保持开启供用户继续实测。
