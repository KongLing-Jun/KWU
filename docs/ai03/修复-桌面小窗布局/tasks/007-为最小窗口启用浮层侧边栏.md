# 007 为最小窗口启用浮层侧边栏

## 执行契约

- 目标：创建版最小窗口默认隐藏固定侧边栏，同时保留 WorkBuddy 同类的左上入口，以临时浮层访问导航。
- 产物：创建版紧凑侧栏断点、自动折叠/恢复状态流、浮层样式和聚焦测试。
- 依赖：任务 006 已实现并验证，创建页宽度与 Composer 布局稳定。
- 交付切片：一个 `fix:` 实现提交，验证通过后一个 `docs:` 回执提交。
- 建议实现提交：`fix:启用最小窗口浮层侧边栏`。
- 建议回执提交：`docs:记录最小窗口侧栏结果`。

## 证据与实现基础

- 原生最小外窗 `1200px` 在当前 Windows 环境对应约 `1186px` 客户区，默认 `1240px` 外窗对应约 `1226px` 客户区。
- `App.tsx` 的 `CREATION_SIDEBAR_FLOAT_BREAKPOINT` 当前为 `820`，最小窗口不会进入浮层侧栏状态。
- 现有 `sidebarAutoCollapsedRef`、`sidebarManualExpandedRef`、`toggleSidebar` 和 `closeNarrowSidebar` 已覆盖自动折叠、临时手动展开、导航后收起及放大恢复，可扩展而无需新增持久化字段。
- Codegraph 显示侧边栏状态同时影响布局 class、主题栏入口、快捷键和工作区宽度计算；实现必须复用现有 `sidebarCollapsed` 状态，不另建平行状态。

## 允许范围

- `desktop/frontend/src/App.tsx`
- 创建版侧栏相关 CSS 文件中的限定规则
- `desktop/frontend/src/lib/workspaceLayout.ts`（仅在现有 helper 契约确有需要时）
- `desktop/frontend/src/__tests__/workspace-layout.test.ts`
- 受断点变化直接影响的现有创建版导航契约测试

## 禁止范围

- 不改变原生窗口 `1200 × 800` 下限和默认尺寸。
- 不改变侧边栏持久化键、宽度、内容、导航数据或非创建版布局。
- 不把自动折叠写入用户偏好，不新增配置项。
- 不调整创建页四行内容、场景滚动或 Composer。

## 必须保持的行为

- 用户原本手动收起侧边栏时，窗口放大后仍保持收起。
- 因进入紧凑宽度而自动收起时，窗口放大后恢复展开。
- 最小窗口保留左上展开按钮；手动展开仅为临时浮层，导航后自动收起。
- 非创建版原有 `820px` 窄屏行为不变。

## 验收标准

1. 创建版客户区宽度 `<= 1200px` 时自动收起侧边栏，`> 1200px` 时退出紧凑状态。
2. 最小原生窗口启动或缩小时默认无固定侧栏，主区获得完整宽度。
3. 左上入口可打开覆盖主区的侧栏浮层，不挤压 Composer；完成导航后自动收起。
4. 自动收起不调用持久化保存；放大后正确恢复进入前状态。
5. 用户原本手动收起或在宽窗口手动收起的偏好保持。
6. 受影响的布局/导航聚焦测试、生产构建和真实 dev 应用验收通过。
