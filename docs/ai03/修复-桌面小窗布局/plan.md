# 桌面小窗布局修复计划

## 问题与证据

- 用户截图中，创建页的品牌图标在较矮窗口中逼近应用顶部，布局显得拥挤。
- `desktop/main.go` 当前允许窗口缩小到 `400 × 480`，低于桌面布局的实际可用范围。
- `desktop/window_state.go` 会恢复历史小尺寸，与新的窗口下限需求不一致。
- `Welcome.tsx` 已有可复用的“图标 + 品牌名”结构，但创建页 CSS 隐藏其图标，另外渲染一个绝对定位的 `.welcome-creation__mascot`。该图标位于品牌行上方，是较矮窗口中贴顶的直接原因。
- 本机 WorkBuddy 5.3.11 的打包前端源码显示：一级三场景使用 `36px` 高、`100px` 圆角的外层胶囊，内部按钮为 `32px` 高、`100px` 圆角；二级场景按钮独立使用 `32px` 高、`100px` 圆角，场景行本身没有额外外框。云智企办当前对应圆角仅为 `10px` / `12px`，视觉仍是圆角矩形。
- WorkBuddy 的二级场景由 `QuickActions` 实现为不换行的横向滚动列表；左右箭头和边缘渐隐只在对应方向仍可滚动时出现，点击箭头按步长平滑移动。其场景条与 Composer 同属 `HomeComposer`，可通过右侧预留空间形成略短于 Composer 的视觉宽度。
- 云智企办原实现将每个一级场景的二级标题拆成 featured 与“更多”两段；用户确认这不符合目标，三个一级场景应各自直接展示完整的二级标题集合。
- 当前创建页已有“品牌、Slogan、一级模式、二级场景”四层内容，但品牌、Slogan 左对齐，二级场景条与 Composer 等宽，不符合已确认的居中层级与内收关系。
- 原生最小外窗 `1200px` 在当前 Windows 环境对应约 `1186px` 客户区；创建版侧边栏浮层断点仍为 `820px`，因此最小窗口仍显示固定侧边栏。
- 二级场景写入 Composer 后会生成 Skill 标签；该标签原先使用硬编码紫灰背景、紫色边框和 `5px` 圆角，与创建页的中性黑白灰体系不协调。

## 索引基线与直接核对

- Codegraph 索引对应主工作区基线 `b60489ee7b6e4b06c2c5cd526197212b9dff6971`，用于定位窗口恢复、`Welcome`、侧边栏自动折叠状态流及测试覆盖。
- 本 worktree 基于最新 `origin/main-v3` 的 `0489d62b47869f53e0548f5fdeb18205b4bdc955`。两个基线之间的目标文件无差异；仍已在 worktree 中直接核对源码、测试和 EOL。
- Codegraph 爆炸半径显示：`Welcome` 由 `Transcript` 的空会话路径消费，相关前端契约测试为 `welcome-creation-modes.test.tsx`；`loadWindowStateFromPath` 仅由窗口状态加载入口消费。

## 目标

- 将桌面窗口最小尺寸统一为 `1200 × 800`。
- 创建版客户区宽度不超过 `1200px` 时默认自动收起侧边栏，以临时浮层入口提供导航；放大后恢复进入紧凑宽度前的展开/收起状态，自动折叠不覆盖持久化偏好。
- 历史保存尺寸为正数且低于新下限时，分别提升到新下限。
- 创建页在所有窗口尺寸下都将品牌图标放在“云智企办”左侧的同一行，不再使用绝对定位的悬浮图标。
- 创建页一级三场景与二级场景按钮采用 WorkBuddy 同类控件的全圆弧胶囊几何。
- 创建页保持“图标 + 品牌名、动态 Slogan、一级模式、二级场景”四行；前三行居中，二级场景条居中并按 WorkBuddy 截图中的可见比例收敛到 Composer 的约 `86%`，当前上限为 `656px`。
- 二级场景条采用 WorkBuddy `QuickActions` 同类的单行滚动交互：不换行、隐藏滚动条、按方向显示渐隐和圆形箭头，箭头点击后平滑横移。
- 创建页从最小窗口放大到最大化时，品牌至 Composer 的整体位置连续变化；最小窗口保持紧凑位置，最大化在主内容可用区域内纵向居中，不出现高度断点跳变。
- 创建页场景生成的 Composer Skill 标签采用中性、主题自适应的全圆弧胶囊样式。

## 非目标与边界

- 不强制每次启动最大化，不改变用户上次的最大化状态。
- 首次启动仍居中，默认宽度保持 `1240`；默认高度随新下限由 `720` 提升到 `800`。
- 不改变侧边栏宽度、折叠持久化数据、聊天区最小宽度或非创建版布局；仅扩展创建版的紧凑浮层侧栏范围。
- 除删除“更多”控制外，不改变创建模式或二级场景按钮的文案、图标、颜色、交互和数据，不调整输入框或普通非创建版欢迎页。
- 不删除或改写动态 Slogan，不把用户截图中的红框实现为界面元素。
- 不把场景行为改为插入提示词，不改变 Skill 标签的锤子图标、删除交互或消息历史中的 Skill 标签样式。
- 不引入新依赖、数据格式或用户配置开关。

## 已选方案

### 窗口尺寸与恢复

- 在 Desktop `main` 包中定义单一组默认尺寸和最小尺寸常量，供 Wails 启动选项和窗口状态迁移共用。
- Wails `MinWidth` / `MinHeight` 设为 `1200` / `800`，默认尺寸同步设为 `1240 × 800`，避免默认高度低于窗口下限。
- 加载历史状态时，对正数宽高做下限钳制；缺失或无效的非正数维度仍交给启动默认值处理，原有全零首次启动迁移守卫保留。
- 窗口位置、最大化状态、按 profile 隔离的存储路径不变。

### 创建页品牌行

- 复用现有 `BrandLockup` 中的 `.welcome__brand-logo`，删除创建页额外的 `.welcome-creation__mascot` DOM。
- 取消创建页对 `.welcome__brand-logo` 的隐藏，在 `.welcome__brand` 中设置稳定的水平间距，使图标与品牌名同行且垂直居中。
- 删除不再有消费者的 mascot 样式和对应窄/矮窗口规则，保留现有紧凑尺寸变量与场景控件降级逻辑。

### 创建页场景胶囊

- 一级三场景外层改为 `36px` 高、`2px` 内边距、`100px` 圆角，内部按钮改为 `32px` 高、`0 12px` 内边距、`100px` 圆角。
- 二级场景按钮改为 `32px` 高、`0 12px` 内边距、`100px` 圆角；不为整行添加外框。
- 保留现有选中、悬停、焦点、禁用和小尺寸降级行为；删除“更多”控制及其展开状态。

### 创建页四行层级与二级场景滚动

- 保留现有四层 DOM 语义：第一行品牌锁定、第二行动态 Slogan、第三行一级模式、第四行二级场景。
- 前三行在创建页内容宽度内水平居中；第四行容器使用 `min(calc(100% - 32px), 656px)` 并居中，在标准 `760px` Composer 下约占 `86%`，窄容器继续保留左右安全间距。
- 每个一级场景直接提供自己的完整二级标题数组，并在同一个 `nowrap` 横向列表中全部渲染；不再区分 featured / additional，也不渲染“更多”。
- 使用列表元素的 `scrollWidth`、`clientWidth` 和 `scrollLeft` 维护左右可滚动状态；在挂载、模式切换、滚动和尺寸变化后同步。
- 场景条在 `656px` 总宽内使用“左箭头固定槽 / 中间滚动标题区 / 右箭头固定槽”；两侧槽始终占位，箭头只在对应方向可滚动时渲染，点击后平滑横移，边缘渐隐只覆盖中间标题区。
- 保留键盘焦点、`aria-pressed`、禁用态、场景 Prompt/Skill 数据流及按钮胶囊样式。

### 创建页连续纵向布局

- 把空创建页的主内容与 Footer 作为同一视觉组，在 Topicbar 以下的可用区域用成对自动外边距居中，使 Composer 自定义高度也参与整体测量。
- 最小窗口使用连续的负向视觉补偿保持现有紧凑位置；补偿随视口高度平滑衰减，在最大化高度归零，不再使用 `700px` / `701px` 两套相差悬殊的 `margin-top`。
- 极矮窗口原有隐藏二级场景、隐藏一级模式和缩小品牌规则保持不变。

### 最小窗口浮层侧边栏

- 将创建版浮层侧栏断点从 `820px` 扩展到 `1200px` 客户区宽度，以覆盖 `1200px` 原生最小外窗在 Windows 边框后的实际客户区。
- 进入该宽度时沿用现有自动折叠状态流，且不调用持久化写入；离开时仅恢复由本次自动折叠产生的展开状态，原本手动收起的偏好保持。
- 保留左上展开按钮；用户手动展开时侧栏以覆盖主内容的浮层出现。执行导航或打开内容后沿用 `closeNarrowSidebar` 自动收起。
- 浮层范围和遮罩样式仅限定创建版，非创建版原有 `820px` 响应式行为不变。

### Composer Skill 标签胶囊

- 仅覆盖 `.composer-skill-token`：使用 `999px` 圆角、主题 `--bg-soft` 背景和 `--border` 边框，移除输入区标签的硬编码紫色视觉。
- Hover / focus 使用前景色与主题表面的小比例混色，兼容现有浅色和深色主题。
- 保留消息历史标签、Skill 数据流、结构化执行及删除控件行为。

## 兼容性与迁移

- 窗口状态 JSON 结构不变，无需版本字段或一次性文件重写。
- 旧宽高在内存中归一化，下次正常保存时自然持久化新尺寸。
- 已保存的位置和 `maximised` 不被覆盖。
- 用户主动收起侧边栏时，即使窗口处于最小宽度也不强制重新展开。
- 自动进入紧凑宽度不会写入侧边栏持久化偏好；离开紧凑宽度后恢复进入前的状态。

## 验收场景

1. 首次启动无历史状态时，窗口为 `1240 × 800` 并居中。
2. 普通窗口无法缩小到 `1200 × 800` 以下。
3. 在最小窗口中，侧边栏默认收起，主聊天区无水平溢出；左上按钮可将侧栏作为浮层临时打开，导航后自动收起。
4. 历史状态为小于下限的正数宽高时，恢复结果分别为至少 `1200` 和 `800`，位置与最大化标志不变。
5. 历史状态已大于下限时保持原尺寸；无效/缺失尺寸仍按原逻辑回退。
6. 创建页仅渲染一个品牌图标，其在“云智企办”左侧同行排列，不存在绝对定位 mascot。
7. `1200 × 800`、`1240 × 800` 和最大化三种尺寸下，品牌行不贴顶，模式、场景与 Composer 完整可见且不重叠。
8. 一级三场景呈现为一个分段胶囊，二级场景各自呈现为独立胶囊；不存在用户截图中的红色标注框或新增的场景行外框。
9. 连续选择多个二级场景时，Composer 中的 Skill 标签以中性雾灰胶囊并排或换行展示，消息历史标签和 Skill 行为不变。
10. 创建页保持四行且不删除动态 Slogan；品牌行、Slogan 和一级模式居中，二级场景条在标准宽度下不超过 `656px`，约为 Composer 的 `86%`，窄容器自适应缩小。
11. 二级场景始终只有一行；内容溢出时按方向在标题区之外的固定槽中出现圆形箭头，渐隐只覆盖标题区；点击箭头可平滑移动并在到达边界后隐藏对应箭头，标题和整行不因箭头显隐发生位移。
12. 日常办公、代码开发、设计创意分别直接显示各自全部二级标题，不出现“更多”；切换一级模式后标题集合、滚动位置与箭头状态正确重置。
13. 从最小窗口逐步放大到最大化时，品牌至 Composer 整体平滑移动，无突然下跳；最大化时整体在 Topicbar 以下的可用主区纵向居中，Composer 自定义高度不会破坏居中。
13. 从最小宽度放大到默认宽度时，侧边栏恢复进入紧凑宽度前的状态；用户原本手动收起时仍保持收起。

## 风险与回滚

- `1200 × 800` 会明显减少低逻辑分辨率或高缩放屏幕上的可缩放范围；这是根据 `900 × 600` 整体过小及 `1200 × 720` Composer 被裁切的真实应用验收结果重新选择的桌面产品边界。
- `1200px` 是浏览器客户区断点而非原生外窗宽度；当前 Windows 最小外窗客户区约 `1186px`，默认 `1240px` 外窗客户区约 `1226px`，可在两者之间稳定区分。不同系统装饰宽度通过真实应用验收确认。
- 场景条引入测量和 ResizeObserver 后可能出现首帧箭头抖动；实现保持同步函数局部化并在无溢出时不渲染箭头，避免新增全局布局状态。
- 共用 `BrandLockup` 也用于非创建欢迎页；实现只调整 `.app--creation .welcome--creation` 限定下的标记与样式，避免改变普通变体。
- 胶囊高度由现有 `34px` 收紧为 `32px`，会轻微降低控件视觉体量；CSS 改动限定在创建页选择器内，可独立回滚。
- 回滚时可独立恢复窗口尺寸/迁移提交与创建页品牌行提交，两者无数据格式耽合。
