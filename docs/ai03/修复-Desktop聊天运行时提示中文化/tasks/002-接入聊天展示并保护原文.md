## 必须保留的行为

- retry 仍在 Composer，CompactionCard 仍负责压缩状态和摘要。
- 用户主动中断继续显示既有中文，并在切换/历史恢复后一致。
- task card、专家头像状态点、子专家历史和父子消息隔离不变。
- Markdown/JSON 仍含原始英文、动态详情和 `task-N` ID。
- 未知 Notice 和 turn_done 错误在 UI 原样显示。
- 历史和实时路径使用同一映射结果，不产生双消息。

## 实现约束

1. 映射发生在 `stripHiddenSystemPrompt` 后的最终可见文本上，但不得把结果写回 state。
2. 优先由通用 NoticeCard 覆盖 turn_done 生成的 Notice，避免 reducer 重复分支。
3. Translator 获取方式须符合现有 `useT` 模式；不得新建全局 locale 状态。
4. DOM 测试同时断言中文存在、已映射英文不存在、state/export 原文仍存在。
5. 测试必须包含模型或工具正文中出现相同短语但不被转换的负路径。
6. 不因测试方便导出新的生产接口；如需测试 helper，沿用现有可测试边界。

## 验收标准

1. 已知 Notice、Phase、turn_done 错误在普通和专家团 transcript 中显示相同中文。
2. `state.items` 对应 `text` 保持原始英文。
3. Markdown 与 JSON 导出包含原文、动态错误详情和 task ID。
4. 未知文本与模型/工具正文完全不变。
5. task 完成/失败/停止/卡住可见中文不含内部 ID；start 不增加重复提示。
6. retry、compaction、取消、非活动 task 和 parallel_tasks 行为无变化。
7. 没有新增组件、CSS、生产依赖或 Go 改动。
