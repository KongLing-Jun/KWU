## 真实验收矩阵

### A. 真实 Luna 自然场景

1. 普通聊天：自然问题、工具调用、Phase、正常 final。
2. 普通持久 task：完成、失败或停止、continue_from、切换会话后返回。
3. 专家团：成员 task、头像状态、进入成员历史、父 transcript 隔离。
4. parallel_tasks：多个临时分支只保留聚合结果。
5. 上下文压缩：触发、完成、展开摘要并继续对话。
6. 用户中断与实际 retry：位置和中文状态不退化。
7. Markdown 复制与 JSON 导出：UI 中文对应原始英文仍存在。

自然 prompt 不得把唯一工具、执行顺序或期望内部错误写死；应允许模型真实规划，避免“只剩一条路”的虚假通过。

### B. 受控开发 Provider

确定性脚本分别触发：空 final、readiness 拒绝、限流/重连 retry、指定 finish reason、未知 Provider 错误和终端错误；上下文压缩由真实 Luna 会话验收。

每个脚本必须记录：输入事件、原始文本、可见中文或 identity 结果、DOM 位置、Item/导出原文，以及夹具未进入生产路径的证明。

### C. 保持性压力检查

- 普通/专家团会话往返至少 20 轮，无 WebView 崩溃、重复 Notice 或消息串页。
- 历史重载后已知提示仍中文、未知提示仍原样，组件顺序和 task/头像状态不变。
- task 在非活动会话完成时不出现合成 Notice；父 Agent 下一轮仍能消费完成摘要。
