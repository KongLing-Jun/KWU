# 首页文字质感修复计划

## 背景与问题

Reasonix 首页在 Windows 浅色 Carbon 主题下，主导航和任务列表整体显得偏细、偏浅。目标不是自行增强字重，而是按 WorkBuddy 的真实实现对齐文字层级，同时保留 Reasonix 的主题色图标。

当前首页专用样式主动将主导航设为 `12px / 540 / --fg-dim`，任务标题设为 `12px / 500 / --fg-dim`。WorkBuddy 源码与运行时均显示，普通导航和普通任务标题使用 `13px / 400` 及主文字色，选中任务才使用 `600`。

## 当前与期望行为

- 当前：主导航、任务标题与交互按钮大量使用次级灰；主要内容和元信息的层级差不足。
- 期望：主导航和普通任务标题使用更清晰的主文字色，但保持常规字重；点击后当前导航项和选中任务使用 `600`；时间、说明、小标签仍保持浅灰；导航图标继续使用 Reasonix 主题色。

## 目标

- 对齐 WorkBuddy 的主导航与任务标题字号、常规/选中字重和文字色层级。
- 保持 Reasonix 的主题色图标和现有中央欢迎区样式。
- 保持 Carbon 浅色主题的中性、克制视觉方向。

## 非目标与边界

- 不更换全局字体，不引入网络字体或新依赖。
- 不修改聊天正文、设置页、能力页等非首页页面。
- 不改变组件结构、尺寸布局、交互和数据行为。
- 不改中央模式、场景按钮和输入提示。
- 不将普通文案无条件加粗。

## 实现依据

- Codegraph 索引基线：`a3b2f6550b733de9bdc0aabb0f7437d50a1056ef`（`main-v3`）。
- `desktop/frontend/src/styles/theme-overrides.css` 中 `.app--creation` 已是首页视觉隔离边界。
- `desktop/frontend/src/styles/tokens.css` 定义 `--fg`、`--fg-dim`、`--fg-faint`，可在不破坏主题切换的前提下建立层级。
- `desktop/frontend/src/__tests__/workbuddy-creation-theme.test.ts` 已覆盖首页视觉契约，适合补充文字层级断言。
- WorkBuddy 5.2.6 源码中 `.conversation-list-tab-button` 为 `13px / 400`，活动项为 `600`；运行时普通导航计算值为 `13px / 400 / rgba(0,0,0,.9)`。
- WorkBuddy 运行时普通任务标题为 `13px / 400 / rgba(0,0,0,.9)`，选中标题为 `13px / 600`。
- WorkBuddy 导航实际字体为 `Arial`，任务标题使用系统字体栈；两者均为 `22px` 行高与 `antialiased`。Reasonix 修改前使用 `Segoe UI Variable Text`，导航行高 `20.8px`、任务行高 `17.55px` 且未指定抗锯齿。

## 方案

1. 仅在 `.app--creation` 下调整现有规则，不更改全局 token。
2. 主导航使用正文前景色和 `13px / 400`，当前导航项使用 `600`；空白会话首页将“新建对话”标记为当前项；图标保持原有 accent 混色。
3. 普通任务标题使用正文前景色和 `13px / 400`，仅活动项使用 `600`；时间继续使用 faint 层级。
4. 导航使用 WorkBuddy 的 `Arial` 栈，任务标题使用其系统字体栈；两者统一 `22px` 行高和 `antialiased`。
5. 会话行在 hover、键盘焦点和菜单打开时直接复用“任务”标题的 `--sidebar-hover` 中性灰背景、透明边框和 `600` 字重；当前会话持续使用该背景和字重并保留左侧标记。
6. 撤回没有 WorkBuddy 源码依据的中央欢迎区、占位提示、分组标题和文件夹标题调整。
7. 扩展样式契约测试，锁定主题图标、字体栈和常规/选中字重层级。

## 影响文件与契约

- `desktop/frontend/src/styles/theme-overrides.css`：首页专用视觉规则。
- `desktop/frontend/src/styles/features.css`：首页导航当前项字重。
- `desktop/frontend/src/App.tsx`：根据既有空白会话状态为“新建对话”补充当前项类名与可访问状态。
- `desktop/frontend/src/__tests__/workbuddy-creation-theme.test.ts`：首页文字层级契约。
- 本目录文档：计划、任务契约与当前进度。

不改变 React props、DOM 结构、业务流程、后端 API、持久化数据或主题设置兼容性。

## 风险与回滚

- 风险：主文字色可能使信息密度上升；通过 `400` 常规字重和浅色元信息保持层级。
- 风险：活动项与普通项区分不足；仅活动任务保留 `600`，同时沿用现有选中背景。
- 风险：深色主题对比过强；使用主题 token 而非浅色硬编码，并在浏览器中检查浅色主场景。
- 回滚：回退本次 CSS 和对应契约测试即可，无数据迁移。

## 验收标准

- 首页主导航普通态为 `13px / 400` 主文字色，当前项为 `600`，图标保持主题色。
- 普通任务标题为 `13px / 400`，选中任务为 `600`，时间和辅助说明仍明显更浅。
- 导航和任务标题的字体栈、`22px` 行高与抗锯齿与 WorkBuddy 运行时一致。
- 会话行悬浮时直接复用“任务”标题的 `--sidebar-hover` 中性灰背景、无可见边框并使用 `600` 字重；当前会话持续保留相同背景、`600` 字重和左侧标记。
- 会话行的置顶与归档按钮默认透明且无可见边框，仅在按钮自身悬浮或键盘聚焦时显示 `--sidebar-hover` 中性灰反馈；置顶和归档状态色保留。
- 中央模式、场景按钮和输入提示维持本次修改前样式。
- 非 `.app--creation` 页面样式不受影响。
- 首页样式契约测试与 `pnpm build` 通过。
- 通过内置浏览器连接已启动后端，真实首页无溢出、截断或布局回归。

## 验证计划

- 自动化：运行 WorkBuddy/首页视觉契约测试和前端生产构建。
- 应用验证：在内置浏览器中打开现有后端，检查默认浅色 Carbon 首页的侧栏、中央欢迎区和输入框；必要时检查窄窗口适配。
