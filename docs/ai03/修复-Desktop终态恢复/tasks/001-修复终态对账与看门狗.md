## 目标与产物

让 Desktop 在顶层 final 已投影而 `turn_done` 丢失/延迟时，通过 100ms 后的 backend
权威状态查询及时恢复 Composer idle；backend 仍运行或状态未知时不提前解锁。同时修复
长回合 stale watchdog 一次到期后不再布防的问题，并用无 Provider 的确定性测试锁定行为。

预期产物：

- `useController` 内每 tab 单链 terminal reconciliation、回合身份保护及 timer 清理；
- 可自重排且限频的 30s stale watchdog；
- 脱敏 breadcrumb；
- hook 级 fake-clock 回归测试；
- 本文档更新为完成回执。

- 最新基线相关既有测试已通过：`use-controller-meta` 97/97、
  `use-controller-cancel-reconcile` 6/6。

## 实施约束

1. terminal reconciliation 只接受 `parentId` 与 `subagentRef` 均为空的顶层 `message`。
2. 每 tab 同时最多一个 timer/重试链；新 message 替换旧链。
3. 初始宽限 100ms；第一次仍 running 或未知后等待 300ms；其后以 1s 为上限持续重试，
   直到 `turn_done`、backend idle、新回合/新会话、tab 不再 running 或卸载。
4. 使用现有 runtime-status 投影与 `foregroundRunningFromRuntimeMeta`；不得复制 reducer 的
   清状态规则。
5. 异步查询发起前及返回后、应用状态前，必须验证同一 tab、`running && turnActive`、
   `sessionGen` 和 `turnStartAt`；失配时丢弃旧结果。
6. `turn_done` 和新的 `turn_started` 必须使旧 timer 与在途结果失效；effect cleanup 清理
   所有 terminal timers。
7. stale watchdog 依据 ref 中最新活动时间重排；一次查询后若同一回合仍在运行或状态
   未知，至少 30s 后再查询，不能 0ms 紧循环。
8. breadcrumb 只记录 `terminal/watchdog`、`scheduled/waiting/recovered/unavailable`、
   attempt 和 tab 标识；重复 1s running 重试不得淹没固定大小 ring buffer。
9. 保持 LF；所有编辑使用现有 React/TypeScript 能力，不新增通用抽象或依赖。

## 验收标准

1. 正常 `turn_done` 在 100ms 内到达时，既有路径立即 idle，且没有 terminal `ListTabs`。
2. `turn_done` 丢失且 backend 已 idle 时，100ms 后清除 Stop/loading，测试耗时 ≤500ms。
3. backend 在第一次查询仍 running 时不清除；第二次变 idle 后在 300ms 退避点清除。
4. backend 持续 running 时不清除，并在 1s 上限持续单链重试。
5. `ListTabs` reject、返回空数组或缺少目标 tab 时不清除，并继续退避。
6. child/subagent final 不创建 terminal 查询。
7. 旧 terminal 查询延迟返回 idle 时，不能清除随后开始的新回合。
8. 长回合首次 watchdog 到期时若最新活动尚新，会重新安排；再次 stale 且 backend idle
   时能清除状态。
9. watchdog 查询到 backend running 或查询失败后继续低频布防，不产生紧循环。
10. 卸载清除 timer，在途回调不再派发；无 React act 或悬空更新警告。
11. breadcrumb 不包含测试消息文本或模拟错误文本。
12. 无允许范围外生产代码、协议、依赖、证据或 baseline 变更。
