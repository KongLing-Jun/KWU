# 桌面专家与专家团闭环修复计划

## 1. 背景与问题

`wails dev` 连接 DEV 云平台时，匿名用户可以在 8080 端口直接读取系统专家，
但桌面端仍把系统目录当作登录资产：它在发送 HTTP 请求前检查本地登录状态，
因此专家页为空，打开已有会话又可能连续弹出多个
`AUTH_REQUIRED: authentication is required`。

当前实现还把系统目录读取、当前会话专家恢复和“我的专家”刷新绑定在同一个
`refreshExpertState` 中。打开一个已有会话会同时经历 tab 变化、会话 ready 状态变化
和显式刷新；每次都重新调用云端目录，单一鉴权错误由此被放大成多个 Toast。

“我的专家/专家团”本来已有设备级 `experts.json` CRUD，但真实云模式下创建被分流到
云端 POST，带 `exp_`/`exg_` ID 的本地镜像又不能编辑或删除。结果是登录状态改变了
桌面本地资产权限，也形成了云端与本地双写但无法完整更新、删除的半闭环。

## 2. 基线与调查证据

- 实施基线：`origin/main-v3@36e2623305f1f42e4b27cdd26b5f1b8edc568a49`。
- Codegraph 在主工作区 `f1777a582545d3146ec184a1a89c1f0a9c754910`
  上用于调用路径和影响面导航；所有实质结论已在独立 worktree 最新基线源码复核。
- 完整运行证据、源码位置、调用链和兼容性事实见
  [`evidence.md`](./evidence.md)。
- 核心结论是：8080 当前匿名 GET 成功；桌面端在 HTTP 前错误鉴权；目录读取被 tab
  刷新重复触发；SQLite 已有可复用缓存；JSON 已有完整本地 CRUD。
- 云仓库源码仍保护该 GET。用户已确认本次不改云端，并接受重新部署可能回归 401 的风险。

## 3. 已确认产品模型

1. **系统专家/专家团**：8080 云端公开只读；本地 SQLite 仅作缓存。桌面端不创建、
   编辑或删除系统资产。
2. **我的专家/专家团**：设备本地资产；匿名用户与登录用户同权读取、使用、创建、导入、
   复制、编辑和删除，不按云账号隔离。
3. **云端普通用户专家 POST**：桌面端停止调用，不删除云客户端兼容代码，也不清理云端
   历史数据。
4. **历史本地数据**：`exp_`/`exg_` 只视为普通本地 ID，不再触发权限或路由特判。
5. **Fixture**：仅用于开发测试；启动时提示一次，专家页常驻“测试数据”标识。

SQLite 中可能存在旧版 `source=user` 记录。本次不删除或强制迁移；它们继续作为
“我的专家”的本地兼容数据被读取和管理，但正常新建统一写入 `experts.json`。
这不是新的产品分类，后续可另行安排无损归一化。

## 4. 目标与非目标

### 目标

- 匿名启动可以读取、使用系统专家和专家团，不经过桌面账户鉴权。
- 应用先展示 SQLite 缓存，后台自动刷新一次；不阻塞应用外壳、可解析的会话或其他 tab。
- 旧会话保存了本地无法解析的专家 ID 时，只暂停该 tab 的发送，等待同一目录刷新；
  历史始终可查看，绝不静默降级为无专家。
- 同一进程自动初始化最多发出一个 GET；并发调用合并。
- 专家页常驻一个“刷新”按钮，同时刷新专家和专家团；用户每次主动操作允许新 GET。
- 自动失败有缓存时静默使用缓存；无缓存时只显示内容区空态。
- 手动成功 Toast 为“系统专家已刷新”；手动失败保留旧列表并只弹一次错误 Toast。
- 会话切换、本地 CRUD、标签切换不再请求系统目录。
- 登录状态不改变“我的专家”的本地权限；历史云 ID 本地记录可完整 CRUD。
- Fixture 明确可见，刷新只重载本地测试目录，不访问 8080。

### 非目标

- 不修改、部署或测试 `Reasonix-Cloud`，不改变 8080 API 形状。
- 不实现云端用户专家同步、账号隔离、多设备同步或云端历史数据清理。
- 不新增按错误文本全局去重；不同操作和不同错误仍独立可见。
- 不改“我的专家”文案，不增加登录引导或登录门禁。
- 不重写旧会话历史、隐藏提示词或已建立的专家提示快照。
- 不在本次强制迁移 SQLite 旧用户记录，不新增第三种正式产品数据。

## 5. 选定方案

### 5.1 公共系统目录客户端

- 将 `ExpertAssetsClient.ListSystem` 改为不接收 `BindingScope`，直接通过现有
  `HTTPSessionClient` 发起无 Authorization 的 GET。
- 保留普通用户专家 POST 的认证执行器和接口实现，但桌面 App 不再调用。
- 增加契约测试，明确系统 GET 无 query、无 Authorization；现有 POST 仍要求 Token。

### 5.2 缓存读取与刷新分离

- `ListExperts` 改为纯本地快照读取：云模式读取当前 `experts.sqlite`，不访问网络。
- 自动初始化由 Desktop 后端在 `startup` 发起；Wails 方法提供本地快照、刷新状态和
  手动刷新，返回专家列表及目录模式 `remote/fixture/builtin`。
- App 级协调器使用互斥锁和 in-flight 结果：
  - 自动初始化在一个桌面进程内最多执行一次；
  - 并发自动或手动调用共享同一个在途请求；
  - 已完成的下一次手动刷新仍可发起新请求。
- Remote 成功后验证响应，再用 `ReplaceOfficial` 原子替换 official 行并刷新运行时目录。
  失败不清空、不覆盖旧缓存。
- Fixture/builtin 刷新用 `BuiltinDefinitions` 替换 official 行，不进行 HTTP 请求。
- “重置专家”只事务删除 SQLite `source=user`、清空 `experts.json` 及收藏/最近状态；
  不改 official 缓存、不发网络请求。系统目录更新只由独立“刷新”入口负责。
- 恢复 tab 时若会话专家可由 SQLite/JSON 解析，立即继续；无法解析时只让该 tab 等待
  同一个自动刷新结果，不阻塞应用外壳和其他 tab。

### 5.3 前端目录唯一所有权

- `useExpertCatalog` 拆分为系统目录加载和 tab 会话状态刷新：
  - 首次先调用本地 `ListExperts` 展示缓存；
  - 后台调用自动初始化，成功后热更新；
  - tab 刷新只读取当前选择、本地用户专家和收藏/最近状态。
- 本地创建、编辑、删除、复制后只刷新本地和当前 tab 状态。
- App 把同一 `expertCatalog` 传给专家页和两个 `HeartbeatPanel`，自动化面板不再自行读取。
- 保留请求序列与目标 tab 保护；系统目录更新不改变当前 tab 的专家所有权。

### 5.4 页面与反馈

- 在主内容区“专家 / 专家团”标签行最右侧放置“刷新图标 + 刷新”轻量按钮，不增加页面
  右上角已有操作密度。
- 按钮刷新中旋转并禁用；同一请求同时更新专家与专家团。
- 自动刷新失败：
  - 有 official 缓存：无 Toast，继续展示；
  - 无 official 缓存：系统内容区显示“系统专家暂时无法加载”，保留“刷新”。
- 手动刷新失败保留现有列表并显示一个错误 Toast；成功显示一个成功 Toast。
- Fixture 初始化显示一次信息提示，按钮旁常驻“测试数据”；点击刷新只重载本地目录。
- 无法解析旧会话专家时复用现有发送可用性区域，不增加弹窗：
  - 刷新进行中显示“正在恢复此会话使用的专家…”，历史可看、输入暂不可发送；
  - 网络失败显示“此会话使用的专家暂时无法加载”，只提供“重试”；
  - 请求成功但 ID 仍不存在，显示“此会话使用的专家已不存在或不可用”，只在用户点击
    “不使用专家继续”后清除该会话绑定。

### 5.5 本地专家闭环

- `CreateUserExpert` 无条件调用 Controller 的 JSON 创建路径。
- 删除云创建镜像分支以及更新、删除、复制中的云 ID 特判。
- 前端移除 `isCloudUserAssetID` 对编辑、删除的隐藏；source 为 user 即按本地资产管理。
- 系统 official 继续只读；现有运行中专家的更新/删除保护、多 tab 同步和确认交互保留。
- 系统目录刷新不重写活跃会话的 system prompt；新目录在重新选择或新会话时生效。
- 未解析的恢复态不是活跃会话：刷新成功后按原 ID 构建 prompt；失败时保持绑定并允许
  重试；只有用户明确选择“不使用专家继续”才以无专家状态重建。

## 6. 兼容性、迁移与边界

- `experts.sqlite` 与 `experts.json` 路径不变，不新增用户可见迁移步骤。
- `ReplaceOfficial` 保留 SQLite `source=user` 行；刷新失败也不触碰任何缓存行。
- 旧 `exp_`/`exg_` JSON 记录保留 ID 和内容，只改变其可编辑、可删除能力。
- 官方专家被云端移除时，目录刷新后不再供新选择；当前仍运行的会话保留既有提示快照。
  后续冷恢复若已无法解析该 ID，历史仍可看，由用户明确选择是否不使用专家继续。
- 云端源码若重新以 `requireAuth` 部署，已有缓存仍可用，但新安装匿名用户会失败；
  这是用户已接受且必须写入 PR 风险说明的外部依赖。

| --- | --- | --- |

| AC-02 | 匿名、有缓存、云端离线 | 立即显示缓存，无启动 Toast，会话可正常使用 |
| AC-03 | 匿名、无缓存、云端离线 | 系统内容区显示失败空态；普通会话可用；未解析专家会话历史可看并显示“重试”，无全局 Toast |
| AC-04 | 连续打开多个旧会话 | 不产生系统目录 GET，不再出现目录导致的登录 Toast |
| AC-05 | 手动刷新成功 | 一个 GET 同时更新两类目录和 SQLite，显示“系统专家已刷新” |
| AC-06 | 手动刷新失败 | 旧列表不清空，只显示一个错误 Toast，按钮恢复可用 |
| AC-07 | 快速连续点击 | 在途期间按钮禁用；并发入口共享一个请求 |
| AC-08 | 登录状态变化 | “我的专家”列表和 CRUD 权限不变，不触发云专家 POST |
| AC-09 | 历史云 ID 本地记录 | 可使用、复制、编辑、删除，结果仅写本地 |
| AC-10 | Fixture 启动与刷新 | 一次启动提示、常驻“测试数据”，刷新零 HTTP |

| AC-12 | 系统只读 | official 不出现编辑、删除入口；本地 user 仍保留运行中保护 |
| AC-13 | 空缓存恢复系统专家会话 | 该 tab 显示恢复提示并暂停发送；同一 GET 成功后保留原专家和 prompt |
| AC-14 | 专家刷新后仍不存在 | 不静默降级；历史可看；明确点击“不使用专家继续”后才能清除绑定并发送 |
| AC-15 | 断网重置专家 | JSON/SQLite 用户专家、收藏和最近记录清空；official 缓存保留；零 HTTP |

## 8. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 云端部署回退为鉴权 GET | 记录已接受风险；缓存保护老用户，真实验收覆盖空缓存匿名访问 |
| StrictMode 或多消费者重复请求 | 后端自动 once + single-flight；前端只有一个目录所有者 |
| 空缓存时旧会话先于目录完成构建 | 后端在 startup 发起初始化；仅未解析专家 tab 等待同一结果 |
| 刷新失败误清空缓存 | 先验证远端、成功后事务替换；失败不写库 |
| 重置误清或并发改写 official | 重置只删 user 与库状态，完全不进入目录刷新管线 |
| 目录更新影响活跃会话 | 只重载可选目录，不重写当前选择提示快照 |
| 未解析专家被静默降级 | 暂停该 tab 发送；失败可重试；清除必须由用户显式确认 |
| 去除云 ID 特判误改 official | 权限只看 `source`，official 始终只读 |
| 保留 SQLite 旧 user 形成内部双源 | 不新增该路径；先保数据，后续单独无损迁移 |
| Fixture 被误认作线上数据 | 启动提示、常驻标识、测试验证零 HTTP |

整体难度为中等。改动跨 Go 云客户端、Desktop 协调器、Wails 前端状态和 UI，但复用现有 SQLite 事务缓存与 JSON CRUD，不新增服务端、账号同步或数据 schema。

## 9. 回滚

- 实现提交按“公共目录加载”和“本地专家闭环”可独立评审、验证和回滚。
- 回滚不会迁移或删除用户数据；SQLite official 缓存与 JSON 用户专家仍在原路径。
- 若公共 GET 契约回滚，恢复旧版会再次要求桌面登录；PR 必须明确该可见后果。
- 不回滚或改写 `Reasonix-Cloud`，也不自动清理新版本期间创建的本地专家。

## 10. 验证计划

### 聚焦自动化

- `internal/cloud`：系统 GET 无 Authorization；POST 认证保持；协议错误不覆盖结果。
- `internal/expert`：继续覆盖 `ReplaceOfficial` 原子替换并保留 user。
- `desktop`：自动一次、并发合并、手动再次请求、失败保留缓存、Fixture 零 HTTP；
  startup 与未解析 tab 共享请求、三种恢复结果；重置只删 user；云运行时下用户专家仍
  只写 JSON，云 ID 可更新/删除/复制。
- Frontend：缓存先显示、自动/手动反馈、无缓存空态、按钮位置与禁用、Fixture 标识；
  tab 和 CRUD 刷新不调用系统目录；Heartbeat 使用共享列表；恢复中、可重试和明确放弃
  专家的发送可用性提示。
- 运行受影响 Go 包的 `go vet`、`go test`，以及前端聚焦测试、`pnpm test:typecheck`。

### 真实应用验收

- 清理或隔离测试 profile 的 official 缓存，以匿名身份运行 `cd desktop; wails dev`。
- 用代理/请求计数确认启动仅一个无 Token GET，打开至少三个旧会话后计数不增加。
- 空缓存打开绑定系统专家的旧会话，确认历史可见、发送暂缓，刷新成功后原专家仍生效；
  再覆盖断网重试和云端已无该 ID 时的明确放弃流程。
- 成功刷新一次，随后断开 8080 并重启，确认缓存即时可用且无启动 Toast。
- 在断网状态手动刷新，确认列表保留且只有一个错误 Toast。
- 创建、编辑、复制、删除专家与专家团；登录、退出后数据与权限保持。
- 用包含 `exp_`/`exg_` ID 的本地测试记录回归完整 CRUD。
- 断网执行“重置专家”，确认两类本地用户存储和库状态清空、official 保留且无 HTTP。
- 以 `KWU_CLOUD_FAKE=1` 启动，确认提示、标识和刷新过程无 8080 请求。

应用稳定后运行受影响模块完整测试、前端 `pnpm test:all` 与 `pnpm build`。获得 PR 授权后，
同步最新 `origin/main-v3`，执行项目 common checks 和：

```powershell
node ./scripts/pr-gate.mjs --base origin/main-v3 --run all
```

任何必需检查失败时不得创建或更新 PR。

本计划获批并合并后，从最新 `main-v3` 创建 Stage 2 任务文档，按可独立审查和回滚的切片映射公共目录加载、本地专家闭环及集成验收。任务 PR 合并并获得明确实现授权前，不编写实现代码。
