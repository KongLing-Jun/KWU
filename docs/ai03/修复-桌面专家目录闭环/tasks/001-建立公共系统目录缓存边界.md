## 3. 行为与实现要求

### 3.1 公共客户端

- `ExpertAssetsClient.ListSystem` 不再接收 `BindingScope`，直接通过
  `HTTPSessionClient` 请求 `/api/v1/expert-assets/system`。
- 请求必须无 Authorization、无用户 query、无 durable binding/session 读取。
- 普通用户专家创建 POST 的认证 executor、接口和契约保持不变；本任务不删除兼容代码。
- 保持现有 request ID、超时、响应上限、错误 envelope 和 URL 校验。

### 3.2 本地快照与刷新协调器

- `ListExperts` 和 `ListExpertsByFilter` 只返回当前 SQLite 快照，不访问网络。
- App 级协调器明确区分 `remote | fixture | builtin`，并提供：
  - startup 自动初始化：同一进程最多启动一次；
  - in-flight 合并：自动、恢复等待者和并发手动入口共享同一请求；
  - 手动刷新：前一请求完成后允许再次发起；
  - 当前快照、是否有 official 缓存和最近刷新结果。
- remote 成功响应先完整转换/校验，再调用 `ReplaceOfficial`；任何网络、协议、转换或
  SQLite 错误都不得清空旧 official。
- fixture/builtin 使用 `BuiltinDefinitions` 更新 official，必须证明零 HTTP。
- startup 只启动后台工作，不等待网络，不阻塞 webview、tab 恢复或其他启动任务。
- 协调器使用 App 生命周期 context；退出、取消及并发完成不得泄漏 goroutine 或锁。

### 3.3 重置

- Store 增加事务型“只删除 `source=user`”能力；不得复用 `Reset` 的 DROP TABLE。
- `ResetExperts` 清除 SQLite user、`experts.json`、收藏和最近状态，保留 official；
  不调用公共 GET，也不进入刷新协调器。
- 两个持久化载体各自保持现有原子写语义；不新增跨 SQLite/JSON 两阶段事务。
- 重置后清理/重载运行时选择遵循现有 running 保护；失败必须返回错误，不能报告假成功。
