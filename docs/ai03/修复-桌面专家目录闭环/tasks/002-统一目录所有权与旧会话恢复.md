## 3. 后端恢复合同

- tab sidecar 无专家或 ID 可由 SQLite/JSON 解析时立即构建，不等待网络。
- 只有“保存了非空专家 ID 且本地无法解析”的 tab 等待任务 001 已在途/已启动的自动刷新；
  不阻塞应用外壳、其他 tab、普通会话或本地专家会话。
- 等待期间历史数据保持可投影，发送状态为“正在恢复专家”，输入不可发送。
- 刷新成功且 ID 可解析后，按原 ID 构建 Controller；CurrentExpert 和 system prompt
  必须保留，不得经历中间 `none`。
- 网络/协议/缓存写失败进入“专家暂时无法加载”；绑定和 sidecar 保持，动作“重试”复用
  同一刷新管线后重新构建，不显示全局 Toast。
- 请求成功但 ID 仍不存在进入“专家已不存在或不可用”；不得无限重试或静默清除。
- “不使用专家继续”必须是目标 tab 的显式 Wails 动作：在 generation/目标检查后清除
  sidecar，再按 ExplicitNone 重建；迟到请求不得覆盖新选择或已关闭 tab。
- 不修改 `internal/boot` 的 CLI 兼容行为，不把完整 prompt 写入 sidecar。

## 4. 前端目录与反馈合同

- App 是系统目录唯一 owner；启动先显示 `ListExperts` 本地快照，再订阅/等待后端自动结果。
- tab、标签、本地 CRUD、收藏/最近切换只刷新各自局部状态，不调用系统刷新。
- 保留请求序列与目标 tab 双守卫；迟到目录结果不能改变当前 tab 的 activeExpert。
- 专家页标签行最右侧显示常驻“刷新图标 + 刷新”；刷新中旋转、禁用，一次更新专家与专家团。
- 自动失败：有 official 缓存静默；无缓存只显示系统内容区空态和“刷新”。
- 手动成功一个“系统专家已刷新”Toast；手动失败保留列表并显示一个操作错误 Toast。
- fixture 启动信息提示每进程一次，页面常驻“测试数据”；刷新零 HTTP。
- 两个 HeartbeatPanel 和 ExpertDirectory 只消费 App 传入目录，不自行 `ListExperts`。
- 发送可用性区域增加专家专用文案：
  - 恢复中：无按钮；
  - 暂时失败：只有“重试”；
  - 已不存在：只有“不使用专家继续”。
- 不弹登录提示、不跳转专家页、不新增全局错误文本去重。
