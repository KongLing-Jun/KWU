# 专家能力工作区对齐 WorkBuddy 与低性能渲染兼容计划

## 背景与问题

Reasonix 专家页已经具备顶部专家/技能/连接器导航、精选场景、专家/专家团切换、分类、排序、详情与召唤能力，但视觉密度和交互反馈与 WorkBuddy 专家页存在差异：专家卡片最小宽度为 320px、最小高度为 190px，默认带灰色背景与阴影，召唤按钮始终显示；悬浮还会同时改变大面积背景、阴影并执行位移。精选场景外层也执行同类悬浮效果，背景图使用 CSS `filter`。

这些效果会让卡片显得厚重，也增加低性能 Windows/WebView2 设备的重绘与合成压力。目标是在保留 Reasonix 数据和功能的前提下，对齐 WorkBuddy 专家页的紧凑层级，并采用更保守的渲染实现。

同一能力工作区中的技能页和连接器页还使用另一套顶部背景、分隔线、居中宽度与动态内边距，导致三页切换时画布和内容起点跳变。后续确认将技能、连接器的外层画布与间距统一到专家页，并把专家/专家团、连接器目录和已新增 MCP 卡片收敛为技能卡片同款浅色表面及低成本主题色边框反馈；保留各页数据、操作和状态语义。

## 当前行为与预期行为

当前行为：

- 专家目录卡片通常只能显示 3 列，卡片默认为灰色、有边框和阴影。
- 卡片悬浮执行背景、边框、阴影和 `translateY` 过渡。
- 召唤按钮始终可见。
- 精选场景整卡也有悬浮位移、阴影和背景变化。
- 技能/连接器顶部有独立背景和分隔线，主体使用较大的动态内边距，与专家页全宽 24px 对齐方式不同。

预期行为：

- 1920×1080、100% 系统显示缩放下通常显示 4 列专家卡片，内容区变窄时按可用宽度自然降为 3/2/1 列。
- 专家/专家团卡片采用 WorkBuddy 的紧凑层级：约 288px 最小列宽、12px 间距、154px 最小高度、16px 圆角和更紧凑的头像、文字、描述与标签间距。
- 专家/专家团卡片默认使用技能卡片同款浅色主题表面、边框透明且无阴影；悬浮或键盘聚焦时只即时出现主题色边框，不改变背景。
- 召唤按钮在精确指针设备上仅于卡片悬浮或键盘聚焦时显示；不支持悬浮的触屏/粗指针设备上始终显示。
- 精选场景保持现有 4 个场景和图片，只对齐 WorkBuddy 的紧凑尺寸；整卡不做悬浮变化，仅内部专家行显示小面积浅灰反馈。
- 专家、技能、连接器使用同一页面背景和外层节奏：桌面顶部 14px 24px、主体 20px 24px，无独立顶部分隔线。
- 连接器目录和已新增 MCP 卡片复用技能卡片的浅色主题表面；普通卡片悬浮/聚焦只显示主题色边框，已用于任务的绿色状态与配置错误的红色状态优先保留。

## 已确认的产品边界

- 对齐专家页内容区，以及技能/连接器页的外层画布、顶部导航和主体内边距；Reasonix 左侧导航保持不变。
- 保留现有 4 个精选场景、专家数据、专家/专家团分类和“最热/最新”排序，不引入 WorkBuddy 数据，也不新增“综合”排序。
- 保留卡片打开详情、独立召唤按钮、搜索、分类、排序、专家/专家团切换及“我的专家”功能。
- 使用 Reasonix 主题变量表达 WorkBuddy 的明暗层级，不硬编码仅适用于亮色模式的颜色。
- 不修改技能/连接器内部工具栏、卡片内容、数据与交互；仅统一连接器目录和已新增 MCP 外层卡片的表面、边框及高成本效果。不修改后端接口、数据模型、持久化、召唤流程或其他页面卡片。

## 依据

### WorkBuddy 源码证据

本机安装包 `D:\workbuddy\resources\app.asar` 中的专家页产物可直接追溯到以下构建模块：

- `renderer/assets/agent-mail-DaA1SKc5.css`：专家页真实样式。
- `renderer/assets/agent-mail-CiuzbR2o.js`：精选场景、专家卡片和专家网格组件产物。
- `renderer/assets/center-B7qS8xvs.css`：专家中心基础变量及部分网格规则。

可复用的设计参数包括：专家网格 `minmax(288px, 1fr)`、12px 间距；专家卡片 154px 最小高度、16px 20px 内边距、16px 圆角；默认透明边框，悬浮为浅灰背景与边框；精选场景卡片 246×224px，内部专家行单独悬浮。

WorkBuddy 原版同时包含卡片 `transform`、阴影过渡和入场动画。本次只复用视觉尺寸与层级，不复制这些高成本效果。

### Reasonix 源码与 Codegraph 证据

- Codegraph 基线定位 `desktop/frontend/src/features/experts/ui/ExpertDirectory.tsx` 为专家页唯一目录入口，由 `App.tsx` 懒加载；卡片详情与召唤分别由现有按钮处理。
- Codegraph 与工作树源码确认 `App.tsx` 将三页放在同一个 `.capability-workspace-shell` 中，但专家页自行承载导航，技能/连接器则使用外层导航和 `.primary-workspace--capabilities`，差异可在公共 CSS 中收敛而无需修改业务组件。
- 最新工作树源码确认现有 DOM 已包含 `.expert-scenes`、`.expert-scene-person`、`.expert-grid`、`.expert-card-shell`、`.expert-card` 和独立 `.expert-card__summon`，因此无需修改组件结构即可完成本次呈现。
- `desktop/frontend/src/styles/features.css` 当前对场景卡片和专家卡片共享背景、阴影、位移过渡；专家卡片还有更具体的悬浮覆盖。
- `desktop/frontend/src/__tests__/expert-directory-contract.test.ts` 已覆盖网格、场景、详情与召唤契约；`expert-directory-backend.test.tsx` 覆盖真实目录交互路径。

## 实现方案

1. 在 `features.css` 中将精选场景和专家目录卡片的基础/交互规则拆开，避免共享的整卡悬浮副作用。
2. 专家网格改为基于内容宽度的 288px 最小列宽和 12px 间距，并移除会强制窄视口单列的冲突覆盖。
3. 压缩专家卡片高度、内边距、头像、文字、描述和标签规格；默认使用技能卡片同款浅色主题表面和透明边框，不使用静态或悬浮阴影。
4. 专家卡片默认使用技能卡片同款浅色主题表面；悬浮、`focus-within` 和键盘焦点只即时切换主题色边框；按压不改变背景、不缩放、不位移。
5. 召唤按钮用 `visibility` 即时显隐，不做透明度动画；触屏/粗指针媒体查询下保持可见。
6. 精选场景采用 246×224px 紧凑横向卡片，移除整卡悬浮反馈和图片 `filter`；保留内部专家行的小面积背景反馈。
7. 更新/补充样式契约测试，固定低性能兼容约束及响应式、按钮可达性规则。
8. 将能力工作区公共画布设为专家页背景；技能/连接器顶部取消独立背景和分隔线，主体改为与专家页一致的全宽 24px 节奏，小屏同步使用 16px 节奏。
9. 将连接器目录和已新增 MCP 卡片的默认表面统一为技能卡片背景公式，移除静态/悬浮阴影和过渡；普通卡片悬浮或聚焦显示主题色边框，绿色启用及红色错误状态不被覆盖。

## 性能与兼容约束

- 专家页及连接器页外层卡片悬浮不得使用 `transform`、`filter`、`box-shadow`、`opacity` 动画或 `will-change`。
- 不对大面积背景、阴影或位移做 transition；背景和边框即时切换。
- 场景图片不使用 CSS `filter`，静态渐变遮罩允许保留。
- 键盘 `focus-visible` 必须保持清晰；按钮不能因默认隐藏而失去键盘访问路径。
- 触屏/粗指针设备不能依赖 hover 才能显示召唤入口。
- 响应式依据专家内容容器宽度，而不是仅依据整个窗口宽度。

## 验收标准

- 在 1920×1080、100% 系统显示缩放的最大化应用中，专家目录通常为 4 列；缩窄内容区后自然降为 3/2/1 列且无横向溢出。
- 专家与专家团卡片默认显示技能卡片同款浅色主题表面；悬浮/聚焦时只显示主题色边框，无背景切换、位移、缩放、阴影或动画残影。
- 精确指针下召唤按钮仅在悬浮/聚焦时显示，键盘可访问；触屏/粗指针下始终显示。
- 精选场景保持 4 个现有场景，整卡无悬浮变化，内部专家行仍有清晰的小面积反馈。
- 卡片点击仍打开详情，召唤按钮仍直接召唤；搜索、分类、排序、专家/专家团切换与“我的专家”行为不变。
- 亮色和暗色主题均可读，无硬编码白底导致的主题断裂。
- 技能和连接器切换后与专家页保持相同背景、顶部高度、左右内容起点和无分隔线结构；各自搜索、管理、开关和卡片交互保持不变。
- 连接器目录与已新增 MCP 卡片默认表面和技能卡片一致，普通悬浮/聚焦仅显示主题色边框；已用于任务的绿色状态和配置错误的红色状态保持可辨识。

## 验证计划

- 样式契约：验证网格尺寸、专家与连接器卡片默认/悬浮/状态样式、无高成本属性、召唤按钮精确指针与粗指针规则、精选场景规则，以及三页公共画布和间距。
- 目录交互：运行专家目录后端交互测试，确认详情、召唤、分类、排序和团队路径不回归。
- 构建：运行前端 `pnpm build`。
- 应用验收：优先在 Codex 内置浏览器中检查宽屏、窄屏、悬浮、键盘聚焦和召唤入口；最终由用户确认视觉效果。

## 风险与回滚

- 风险：卡片变窄后长名称和标签更容易截断；通过单行省略、两行描述和标签数量上限保持稳定。
- 风险：默认隐藏召唤按钮可能影响发现性；悬浮/聚焦显示并在触屏设备常驻作为补偿。
- 风险：内置浏览器右侧面板不能完整展示 1920px 画布；布局断点以 CSS 内容宽度和真实应用验收共同判断。
- 风险：技能/连接器主体变为全宽后同屏卡片数可能增加；保留既有卡片最小宽度和响应式网格，并仅调整外层间距。
- 风险：主题色悬浮规则可能覆盖连接器的启用或错误状态；通过排除状态类的选择器保留绿色和红色状态优先级。
- 回滚：恢复本次 `features.css` 与对应契约测试提交即可，不涉及数据迁移。
