## 目标

让会话页 `ModelSwitcher` 与模型广场“当前可切换模型”消费 App 提供的同一份模型目录状态，删除两个子组件的独立目录读取，使页面往返不再触发重复 loading，同时保留现有事件驱动刷新、权限过滤和价格目录行为。

## 预期产物

- 一个前端共享模型目录状态类型。
- `App` 从既有 `subscriptionRepairFacts` 投影并分发共享状态。
- `Composer` 仅透传该状态。
- `ModelSwitcher` 与 `ModelMarketplace` 成为共享状态消费者，不直接读取模型目录。
- 聚焦组件/契约测试与完成收据。

- `desktop/frontend/src/App.tsx:1709-1750` 已有带 request sequence 与 scope key 的 routes/marketplace 权威读取。

- 用户在独立应用验收中指出两处集合相同但顺序可能不一致；源码复核确认 `ModelMarketplace` 直接遍历过滤后的 routes，而 `ModelSwitcher` 先将含 `subscription_pool` 的 provider 置顶，再按本地化 provider label/provider 排序并保留组内原始顺序。

## 必须保留的行为

- 两处继续使用 `filterModelInfosForSubscriptionAccess`，订阅权限结果不变。
- 当前模型、provider 分组、搜索、选择动作和选择 pending 行为不变。
- 选择模型后仍返回会话页并触发权威目录刷新。
- `ModelMarketplace()` 仍只读价格缓存；`RefreshModelMarketplace()` 仍是远端价格刷新入口。
- 现有刷新按钮成功刷新价格后继续触发 `refreshModelCatalog`。
- stale request 仍由 `subscriptionRepairRequestRef` 防护。

## 实现约束

1. 共享状态必须区分：
   - `loading`：无旧 routes 可供展示；
   - `ready`：routes 请求成功，包括合法空数组，并携带可选 marketplace snapshot；
   - `unavailable`：routes 请求失败。
2. `App` 必须是 routes 与权限过滤 marketplace snapshot 的唯一生产者。
3. 子组件不得根据 mount、页面切换或本地 refresh signal 调用 `ModelsForTab`、`Models` 或用于过滤的 `ModelMarketplace`。
4. 两处必须基于同一 shared state 与同一 subscription access 过滤。
5. unavailable 与 ready 空数组必须使用不同文案/状态。
6. 真实失效时不保留旧 scope 的列表。
7. 避免无关重构；优先最小、可读的 props 契约。
