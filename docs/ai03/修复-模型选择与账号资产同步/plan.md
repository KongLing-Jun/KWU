# 模型选择与账号资产同步修复计划

## 背景与问题

桌面端模型选择框在已登录供应商场景下，每次打开都会依次出现加载态、未稳定筛选的模型列表和最终套餐模型列表。模型名称变化还会改变按钮宽度，带动输入框工具栏布局跳动。

同一账号的余额与套餐变更存在两条本地快照写入路径：云事件同步会刷新并写入资产快照，真实模型任务的结算观察器也会直接写入最新余额。前者原先没有通知前端，Task 002 已补充 post-checkpoint 通知；真实结算路径仍只写缓存、不发送通知，导致左侧账号菜单和账户页共用的余额状态在进入账户页触发 `CloudBootstrap` 前持续停留在旧值。

本计划覆盖两个可独立交付和回滚的修复切片：

1. 模型选择器稳定化。
2. 账号资产事件同步。

### 模型选择器：原始缺陷与已合并切片

以下行为描述原计划获批时的实现基线，用于保留已合并 Task 001 的目标和边界；打开弹层重复读取、分步列表和宽度跳动已经由原 Task 001 修复，不代表当前主分支仍存在。

- `desktop/frontend/src/components/ModelSwitcher.tsx`
  - `loadModels` 分别提交路由模型和商城模型请求结果，并在每次请求前把 `modelsLoading` 与 `marketplaceState` 重置为加载态。
  - 组件挂载或刷新信号变化时加载一次，`open` 变为真时又加载一次；因此一次点击会制造额外状态转换和重复调用。
  - 可见模型在商城状态尚未稳定时就随中间结果重新计算。
  - 当前模型从未过滤的 `routeModels` 解析，即使该模型已不在套餐或自定义可选列表中，触发器仍继续显示旧模型。
  - 供应商分组当前优先排列“当前模型所属供应商”，选择自定义模型后会改变分组顺序。
  - 触发器宽度通过 `ResizeObserver` 测量并用于弹层最小宽度，按钮自身没有桌面固定宽度。
- `desktop/frontend/src/styles/session.css`
  - 桌面布局只有 `380px`/`320px` 最大宽度，没有固定宽度。
  - `760px` 以下已有 `168px` 上限，`520px` 以下已有 `32px` 图标模式。
- `desktop/frontend/src/lib/subscriptionModelAccess.ts`
  - Free 套餐是有效套餐：`free + status=free` 使用 `Subscribe_Free` 标签筛选。
  - 非套餐计费来源不会被套餐筛选移除；商城或权限证据不足时，套餐模型按失败关闭处理。
- `desktop/frontend/src/App.tsx`
  - App 另有一条用于默认模型修复和发送门禁的事实链路，以请求代次保护并行读取 `ModelsForTab`、`Settings` 和 `ModelMarketplace`。
  - ModelSwitcher 与 App 的读取均为本地配置或缓存视图，但当前只共享刷新数字，不共享同一个 React 状态快照。
  - 当前路由不存在或无权使用时，现有 `subscriptionModelInvocationAccess` 已阻止发送，并能显示“当前模型不可用”恢复入口。
  - 因此本修复保留两条职责不同的事实链路及既有发送门禁，不为消除短暂重复读取而把 ModelSwitcher 状态提升到 App。

Task 001 合并后的真实 Wails 补充验收发现，点击模型框已稳定，但“切换已有会话”仍存在另一条未被原验收覆盖的闪烁链路：

- 应用恢复及连续切换 Flash、Pro、Qwen 等已有会话时，诊断锚点稳定记录到“暂无可选模型”；执行模型与显式 planner 不同的会话还会经过“请选择模型”后才恢复绑定模型。本次样本中保存模型的规范值在早期状态已经可见，但现有前端 DTO 没有独立 `modelRef` 保证。
- `ModelSwitcher` 的目录 key 包含 tab ID；tab 改变会立即使旧目录快照失效，而触发器只有在目标模型已能从候选目录解析时才显示模型，因此即使后端 `WorkspaceTab.model` 已保存目标 ref，前端仍会暂时显示“暂无可选模型”。
- 控制器就绪后会把 `tab.Label` 更新为类似 `qwen3.6-plus + planner deepseek-v4-flash` 的人类展示标签；App 又把该标签参与模型 facts key 和路由解析，造成一次额外的目录重读与短暂“请选择模型”。展示标签不是稳定模型身份。
- 新增 Settings 原始值锚点确认本次真实配置始终为 `default=Flash`、`planner=Flash`，planner 并非空值继承。设置页用 `plannerRef === defaultRef` 把显式同值错误显示成“使用当前模型（单模型）”；真实继承在运行时只由空 `planner_model` 表示。
- 默认模型变化会保留同一计费来源的显式 planner，这是既有且有测试覆盖的行为；因此问题不是 planner 异步切回执行模型，而是设置页误报继承，加上复合展示标签误作模型身份。
- Desktop 已持有并持久化规范 `tab.model`，但 `Meta`、`TabMeta` 和对应前端类型只暴露可变 `label`；仅靠前端最近确认缓存无法覆盖首次访问或缓存尚未建立的已有会话。
- “正在验证模型权限”来自既有发送门禁。它可以在后台继续加载并保持发送禁用，但不应替换模型选择器中已经确定的会话绑定模型。

完整毫秒时间线、源码对应和修复证明要求见 [evidence.md](evidence.md)。

### 账号资产

- `internal/cloud/event_sync_application.go`
  - `balance.updated` 会执行 `BalanceApplication.Refresh`。
  - `subscription.updated` 会执行 `SubscriptionApplication.Refresh`。
  - 冻结和结算事件也会刷新余额。
  - 成功处理后会确认绑定作用域并提交事件检查点，但没有“已应用事件”观察者通知桌面前端。
- `internal/cloud/payment_application.go` 与 `internal/cloud/subscription_application.go`
  - 刷新结果会写入完整绑定作用域隔离的资产快照。
  - `BalanceApplication.View` 和 `SubscriptionApplication.View` 可只读返回当前绑定的最后确认快照，不需要再次联网。
- `desktop/cloud_runtime.go`
  - 事件工作器只记录运行完成结果，没有把单个已应用资产事件发送到 Wails 前端。
- `desktop/model_billing.go`
  - 未启用 fake 的真实订阅任务由 `desktopRemoteSettlementObserver.CreditSettlementObserved` 在终态结算持久化后读取当前云账号，复核完整 binding scope，并调用 `StoreBalance` 写入权威余额快照。
  - `StoreBalance` 成功后直接返回，没有调用 runtime 已有的 `assetNotifier`；真实 runtime 又明确保持 `Realtime=false` 且不构造事件 worker，因此同一 Desktop 发起的真实模型任务不会经云事件路径补发 `cloud-assets:changed`。
- `desktop/frontend/src/features/account/controller/useAccountSidebar.ts`
  - 仅在首次初始化时调用 `CloudBootstrap`；初始化完成后再次打开账号菜单不会刷新。
  - 左侧账号菜单余额、套餐、状态和版本均直接来自 `accountStore`。
- `desktop/frontend/src/features/account/ui/AccountCenter.tsx`
  - 账户页余额卡片读取同一个 `accountStore.balance`，不是第二套余额状态。
  - 账户页挂载时会调用一次 `CloudBootstrap`，这解释了当前“进入账户页后两个余额才一起刷新”的现象；该联网恢复入口继续保留为登录、套餐和支付状态校准兜底。
- `desktop/frontend/src/features/account/store/accountStore.ts`
  - 已有账号作用域、绑定代次和迟到 Bootstrap 防护，但没有专门应用后台资产快照的动作。

真实验收在 Task 003 工作树中使用未启用 fake 的登录账号发送最小请求：发送和 `turn_done` 时 Store 余额均为 `94063.7412`、版本 `15`，随后 30 秒内没有收到 `cloud-assets:changed`；进入账户页触发 `CloudBootstrap` 后，左侧菜单和账户页余额同时更新为 `93841.0328`。源码和运行时证据共同证明缺口位于真实结算写缓存后的通知边界，而不是两个余额组件各自缺少刷新。

## 期望行为

### 启动与基础模型列表

- 首次恢复配置和账号状态期间，模型框显示现有“暂无可选模型”文案并保持禁用，不开放中间列表。
- 未登录且配置了自定义供应商时，只显示已确认的自定义模型。
- 已登录时，同时显示当前套餐允许的平台模型和已确认的自定义模型。
- 未登录且没有自定义供应商时，保持现有“暂无可选模型”。
- Free 套餐显示 `Subscribe_Free` 允许的模型；付费套餐到期并降级为 Free 后切换到 Free 模型集合。

### 交互稳定性

- 点击模型框只执行打开/关闭、清空搜索词和聚焦，不触发模型或商城读取。
- 路由模型与套餐筛选证据形成一个可展示快照后一次性提交，不渲染部分完成的组合。
- ModelSwitcher 继续拥有目录展示快照；App 的模型调用门禁继续拥有独立事实快照并作为能否发送的权威。两者都必须按 tab、账号完整绑定作用域和请求代次丢弃迟到结果。
- App 只向 ModelSwitcher 传递权威的当前模型身份（`ref` 与 `billingSource`）及门禁展示文案，不共享或接管候选目录；手动选择和默认修复据此更新选中态而不重新读取目录。
- 套餐供应商固定排在所有自定义供应商之前；当前选中自定义模型也不改变分组顺序。
- 模型框响应式固定宽度：
  - 桌面：`240px`。
  - 紧凑布局：`168px`。
  - 极窄布局：`32px` 图标模式。
- 长模型名使用省略号；完整名称保留在 Tooltip 和无障碍名称中。
- 弹层至少与当前响应式按钮同宽，不随按钮文字变化重新测量或跳动。

### 已有会话切换

- 目标会话存在已保存绑定模型时，从目标 tab 首次成为活动展示起始终显示该目标模型；目录和权限尚未确认时可以禁用选择，但不得显示“暂无可选模型”或“请选择模型”。
- 人类展示标签中的 planner、执行模式或其他说明不得作为模型 ref、计费来源或目录请求身份。
- 只有目标会话没有可确认绑定模型时，才允许在加载期间复用禁用的“暂无可选模型”。
- 只有目录与权限事实已经稳定且确认原绑定模型不可用时，才显示“请选择模型”并要求用户显式重选。
- 发送门禁继续独立且权威；稳定显示目标模型不代表提前允许发送。

### 规划模型配置语义

- “使用当前模型（单模型）”只对应原始 `plannerModel` 为空；默认模型变化后继续自动跟随。
- 非空 `plannerModel` 始终是显式配置，即使它暂时等于默认模型也必须显示实际模型，不得伪装成继承。
- 用户主动选择“使用当前模型（单模型）”时调用既有保存接口写入空值；选择具体模型时写入规范 ref。
- 不自动迁移或清空已有非空同值配置，因为无法判断用户原始意图；修复后只把它如实显示为显式配置。

### 模型快照状态转换

| 触发 | 读取与提交 | 刷新期间和失败后的展示 |
| --- | --- | --- |
| 首次加载或账号完整绑定作用域变化，且没有已确认会话模型 | 旧作用域快照立即失效；以新代次并行读取路由与商城缓存，全部结束后一次提交 | 完成前复用禁用的“暂无可选模型”；路由失败时提交空列表，商城失败时只保留已确认自定义模型 |
| 同一账号作用域内切换已有会话 | 目标 tab 的目录快照按请求代次加载；保存的绑定 ref 与目录事实分开管理 | 从目标 tab 首次展示起稳定显示其绑定模型并禁用选择；事实稳定后直接启用，确认失效后才进入显式重选 |
| 同一作用域的供应商/模型配置或商城缓存变化 | 启动新代次读取；旧稳定快照只用于保持触发器文案和宽度 | 刷新期间禁止选择，App 门禁保持权威；完成后原子替换，失败规则同上，不无限保留旧候选 |
| 同一作用域的套餐 plan/status/version 变化 | 不读取路由或商城，直接用新套餐权限本地重筛稳定快照 | 一次切换为最终套餐集合；套餐证据不足时隐藏平台模型，自定义模型保留 |
| 用户选择模型或默认模型修复 | 不刷新目录数据；仅更新当前模型身份，App 自行刷新门禁事实 | 不出现加载或“暂无可选模型”中间态 |
| 任意迟到结果 | 比较 tab、完整绑定作用域和请求代次后丢弃 | 不改变当前触发器、候选或发送状态 |

目录刷新输入必须区分“目录/作用域变化”和“套餐权限/当前模型变化”，不得继续用一个无法区分原因的刷新数字触发所有读取。

### 当前模型失效

- 当前会话模型仍在可选快照中时正常显示并允许发送。
- 当前模型不再可选、但仍有其他模型时，显示“请选择模型”，允许打开列表，并沿用现有门禁禁止发送。
- 当前模型不再可选且没有候选模型时，显示“暂无可选模型”，模型框与发送按钮均禁用。
- 用户明确选择新模型后才更新会话模型；系统不自动选择第一个模型。

### 账号资产实时更新

- 后台事件成功刷新并提交资产快照后，发送不含令牌、余额值或账号详情的资产变化通知。
- 当前 Desktop 发起的真实订阅模型任务完成云端终态结算、复核完整 binding scope 并成功写入余额缓存后，使用同一通知器发送 `balanceChanged` 唤醒；不等待或伪造真实事件传输。
- 前端收到通知后，从当前账号绑定的只读缓存接口读取最新余额和套餐快照，不轮询、不重复联网。
- 余额变化更新共享 `accountStore.balance`，左侧账号菜单和已打开的账户页余额卡片同时重渲染。
- 套餐变化更新账号仓库、套餐筛选和模型列表。
- 多个连续事件允许合并读取，但最终必须应用最新已确认快照。
- 旧账号、旧本地配置或旧绑定代次的迟到通知及迟到响应不得覆盖当前状态。
- 进入账户页时现有 `CloudBootstrap` 继续作为账号恢复、外部余额变化、套餐和支付状态的联网校准入口；本修复不承诺其他设备消费、充值或后台调整等外部变化实时到达。

## 目标

- 消除打开模型框时的加载、全量列表和套餐列表闪烁。
- 消除目标 tab 展示后在“暂无可选模型”、绑定模型和“请选择模型”之间的多次闪烁，并防止误用其他 tab 身份。
- 让独立规划模型设置如实区分空值继承和显式模型。
- 消除模型框因文案变化造成的水平布局跳动。
- 统一当前模型失效后的显式重选行为。
- 让余额和套餐界面跟随后台已确认事件更新。
- 保持套餐权限失败关闭和账号作用域隔离。

## 非目标

- 不新增自动模型切换规则。
- 不移除或放宽会话切换期间的发送权限验证和发送禁用。
- 不修改现有订阅默认模型修复策略。
- 不自动迁移或清空已有的非空 planner 配置。
- 不改变模型调用、计费或后端授权规则。
- 不通过轮询保持余额或套餐新鲜度。
- 不新增真实云事件传输，也不保证充值、其他设备消费或后台调整等外部余额变化实时同步；这些变化继续由账户页进入或手动刷新校准。
- 不删除或弱化账户页挂载时的 `CloudBootstrap`，因为它还承担账号、套餐和支付恢复。
- 不刷新远端模型商城价格；模型选择器继续读取其现有缓存视图。
- 不合并 ModelSwitcher 与 App 的模型事实状态，不以扩大状态所有权换取本地缓存读取去重。
- 不修改账号凭证、令牌或绑定持久化格式。

## 方案

### 切片一：模型选择器稳定化

1. ModelSwitcher 保持目录展示所有权，将路由、商城结果和失败状态组合为单个带 tab、账号完整绑定作用域及请求代次的稳定快照。
2. 删除打开弹层时的加载；以独立的目录刷新输入响应初始化、标签页/绑定作用域、供应商/模型配置和商城缓存变化。
3. 套餐 plan/status/version 变化只在本地重新筛选稳定快照；未确认套餐证据保持失败关闭，自定义模型不受套餐筛选影响。
4. Desktop 在既有 `Meta`/`TabMeta` DTO 上增量暴露由 `WorkspaceTab.model` 提供的规范 `modelRef`；`billingSource` 沿用既有路由字段。App 只用规范字段构造当前模型身份，用户选择模型和默认模型修复只更新该身份，不刷新目录数据。
5. 按“模型快照状态转换”表处理刷新、部分失败和迟到结果；任何结果都不得分步提交路由与套餐列表。
6. 从已过滤可选列表解析当前模型；原始路由存在但已被过滤时进入“请选择模型”状态。

### 切片二：账号资产事件同步

1. 为 `EventSyncApplication` 增加窄的可选 post-checkpoint 观察者，仅在刷新、作用域复核和 `CommitApplied` 成功后投递已应用资产类别。
2. 事件分类固定为：
   - `balance.updated`、`freeze.created`、`freeze.expired`、`settlement.completed`、`settlement.exception` → `balanceChanged`。
   - `subscription.updated` → `subscriptionChanged`。
   - `payment.updated` 与 `third_party_sync.updated` 不触发资产通知，因为现有 dispatch 不刷新余额或套餐。
3. 观察者不返回错误；调用侧隔离 panic，Desktop 实现只做非阻塞入队。通知失败、队列已满或 Wails 尚未就绪都不得改变已提交云事件的结果。
4. `cloudRuntime` 在构造 `EventSyncApplication` 时向其传入闭包，闭包只写入 runtime 所有的通知槽；App startup 后绑定 Wails 发送器，shutdown 前先停止 worker 再清除发送器，从而避免 App/cloudRuntime 构造循环且不让 cloud 核心依赖 Wails。
5. 真实订阅模型任务的 `desktopRemoteSettlementObserver` 在远端账号和完整 binding scope 复核通过、`StoreBalance` 成功后，向同一个 runtime 通知器提交 `balanceChanged`。远端读取、scope 复核或缓存写入失败时不通知；通知器为 nil、未绑定或已关闭时安全退化，且通知不能改变结算结果。
6. Desktop 以 pending/dirty 类别位合并连续事件或真实结算唤醒后发送 `cloud-assets:changed`；队列已有唤醒时必须合并类别而非丢失最终 dirty 状态。运行时载荷只包含 `balanceChanged`、`subscriptionChanged`，不包含事件版本、资产值、用户标识或凭证；两个类别只用于合并和诊断，任意唤醒都读取余额与套餐的组合缓存快照。事件版本继续只作为后端检查点顺序，不作为前端资产排序依据。
7. 新增当前活动账号的缓存只读 DTO/API，组合：
   - 当前完整绑定作用域：`profile_id`、`cloud_user_id`、`binding_generation`。
   - 余额 UI 字段及权威 `balance.version`。
   - 套餐视图及权威 `subscription.current.version`。
   接口只调用 `BalanceApplication.View` 和 `SubscriptionApplication.View`，不得发起远端请求。
8. 前端账号控制器监听通知，以“单飞 + dirty 再跑一次”合并并发读取；每次响应提交前再次校验 context、完整 scope 和请求代次。
9. `accountStore` 使用共享资产合并函数处理 Bootstrap、支付操作、手动刷新和事件快照：跨 scope 一律拒绝；同 scope 的余额与套餐分别按各自快照版本单调应用。缺失/零版本只允许当前请求代次应用，且不得覆盖已有正版本快照。共享函数只决定 `balance`、`subscription` 两个字段是否前进，不接管或重构 `initialized`、`busy`、`error`、`payments`、账号候选、登录/退出和账号切换生命周期。
10. 套餐资产更新只改变 `subscriptionAccess` 并本地重筛模型稳定快照，不触发模型/商城读取；余额更新直接刷新两个共享 Store 消费面及依赖余额的发送可用性。

## 契约与兼容性

- 新运行时通知是增量契约；旧前端忽略未知通知，旧后端不会触发新监听。
- `cloud-assets:changed` 是无身份、无资产值的唤醒通知，不承诺用事件版本表达资产新旧。
- 真实结算只复用该事件与 `balanceChanged` 类别，不改变 `Realtime=false` 能力声明，也不新增服务端事件 transport。
- 新缓存读取 API 只返回当前活动完整绑定的 UI 安全字段；新增余额版本仅用于同 scope 的前端单调合并。
- 不变更配置文件、会话文件和资产快照磁盘结构，不需要迁移。
- `plannerModel == ""` 继续是单模型继承的唯一持久化表示；已有非空同值配置不迁移，升级后显示为显式模型。
- `Meta.modelRef`/`TabMeta.modelRef` 是既有 JSON DTO 的增量字段；旧前端忽略未知字段，现有调用方不改变方法签名。字段值只来自已经持久化的 `WorkspaceTab.model`，不得从 `Label` 反向解析。
- 现有 Free/Lite/Plus/Pro 标签规则、BYOK 路由和套餐失败关闭语义保持不变。
- 现有默认模型修复、发送门禁、后端调用授权继续作为权威行为。
- App 与 ModelSwitcher 的事实状态保持独立；新增目录刷新输入只缩小读取触发范围，模型身份 DTO 只补足展示所需的既有本地状态，不改变模型选择或调用 API。

## 风险与缓解

- **迟到事件污染新账号**：后端只在成功检查点后通知；前端读取当前作用域并在提交前复核完整 scope/代次。
- **事件风暴重复读取**：Desktop 合并 pending/dirty 类别；前端单飞读取期间只记录 dirty，完成后至多再读一次。任意唤醒读取组合快照，因此通知次数可以减少但最终资产版本不可丢失。
- **真实结算重试产生重复唤醒**：真实结算观察器可能在本地终态提交失败后重试；通知器会合并重复类别，前端按余额版本单调应用。多余唤醒最多增加一次本地缓存读取，不会回退余额或重复计费。
- **结算通知早于本地任务完成**：通知只在云端权威余额已成功写入缓存后发生；即使后续本地 workflow 状态更新失败，展示该权威余额仍然正确，且通知无返回值、非阻塞，不参与结算成功判定。
- **事件与支付响应交错**：所有写入账号仓库的资产入口共用同 scope、分资产版本合并，事件检查点版本不参与比较。
- **快照读取失败**：保留同一作用域最后确认资产；不清空为零，也不展示跨作用域旧值。
- **当前模型错误失效**：使用 ref、计费来源和套餐筛选后的唯一候选共同判定，并覆盖重名路由测试。
- **目标 tab 展示了其他 tab 身份**：稳定身份必须按目标 tab 保存和读取，禁止跨 tab 复用；目标身份尚未取得时宁可保持不可交互，也不能把其他身份标记为目标会话当前模型。
- **增量 DTO 被误作新状态所有者**：`modelRef` 只投影现有 `WorkspaceTab.model`，不缓存目录、不执行回退、不改变模型；Go 契约测试覆盖恢复、切换和 planner label 更新后字段保持规范。
- **稳定展示掩盖真实失效**：稳定身份只用于禁用状态下的展示，发送门禁不读取该展示状态；目录与权限稳定后必须切换为已确认模型或显式重选。
- **组合标签再次被当作模型身份**：模型身份只接受目录 route 或保存的规范 ref；planner/模式等人类说明只用于独立展示。
- **纠正显示后用户发现旧显式 planner**：这是对真实配置的揭示，不自动改变行为；用户可主动选择“使用当前模型（单模型）”清空，设置测试覆盖空值、显式异值和显式同值。
- **目录刷新短暂展示旧值**：同 scope 刷新期间只保留稳定文案并禁止选择，App 门禁保持权威；新代次完成或失败后必须原子替换，不能无限保留旧候选。
- **两条模型事实链路短暂不同步**：两者均读取相同本地配置/缓存并丢弃迟到结果；任何分歧期间只允许 App 门禁更严格，不允许选择器放宽发送权限。
- **固定宽度破坏窄屏**：保留 `760px` 和 `520px` 容器断点，验证带意图标签和多能力按钮的极端工具栏。
- **核心事件语义被 UI 失败影响**：post-checkpoint 观察者无错误返回、隔离 panic，Desktop 仅非阻塞入队；通知为提交后的尽力而为副作用。

## 验收场景

1. 已登录 Pro，打开模型框多次：不新增模型/商城调用，不出现加载或未筛选列表。
2. 已登录且有自定义供应商：套餐供应商始终第一，自定义供应商稳定排列。
3. 未登录且有自定义供应商：仅显示自定义模型。
4. 未登录且无自定义供应商：显示“暂无可选模型”且不可打开。
5. 启动恢复延迟：仅显示禁用的“暂无可选模型”，完成后一次切换为最终快照。
6. Pro 降级为 Free：只显示 Free 标签模型，不经过全部套餐模型。
7. 当前模型被套餐或配置移除：有候选时显示“请选择模型”并禁止发送；选择后恢复。
8. 当前模型被移除且无候选：显示“暂无可选模型”，发送保持禁止。
9. 桌面、紧凑、极窄布局分别稳定为 `240px`、`168px`、`32px`，长名称不改变布局。
10. 收到余额事件或当前 Desktop 真实任务结算唤醒：后台快照成功后左侧账号菜单和已打开的账户页余额同时更新，无额外云端读取。
11. 收到套餐事件：套餐状态和可选模型更新，无需点击模型框。
12. 快速切换账号并收到旧通知：当前账号余额、套餐和模型列表不被覆盖。
13. 同一账号配置刷新期间：触发器宽度和稳定文案不跳动，候选暂不可选；成功后一次替换，路由失败为空，商城失败只保留自定义模型。
14. 套餐版本变化：只发生本地重筛，不新增 `ModelsForTab` 或 `ModelMarketplace` 调用。
15. 余额事件与支付/手动刷新响应交错：最终仓库保持最高余额版本和最高套餐版本，两个资产可独立前进。
16. `payment.updated`、`third_party_sync.updated`、重复/旧事件或 checkpoint 失败：不发送 `cloud-assets:changed`；资产类成功事件只发送对应类别。
17. 未启用 fake 的真实账号登录：启动完成后模型框一次显示最终套餐与自定义模型，反复打开零读取；一次经授权的最小真实模型调用完成终态结算并写入余额缓存后，左侧账号菜单和账户页共享余额无需进入账户页触发刷新即可与当前缓存资产快照一致。其他设备、充值或后台调整不属于该实时保证。
18. 未启用 fake 的真实账号中连续切换 Flash、Pro、Qwen 等已有会话：选择器从目标 tab 首次出现起始终显示其绑定模型，不经过“暂无可选模型”或“请选择模型”，也不误用其他 tab 身份；全程不发送消息。
19. 带独立 planner 的已有会话就绪后：控制器可显示 planner 说明，但模型选择器身份不改变、不重读目录、不短暂失效。
20. 原始 planner 为空：设置页显示“使用当前模型（单模型）”；改变默认模型后仍为空并跟随新默认模型。
21. 原始 planner 非空且等于默认模型：设置页显示该显式模型；改变默认模型后按既有策略保留该显式 planner。
22. 从显式 planner 选择“使用当前模型（单模型）”：保存并重新读取 Settings 后 `plannerModel` 为空，不需要配置迁移。
