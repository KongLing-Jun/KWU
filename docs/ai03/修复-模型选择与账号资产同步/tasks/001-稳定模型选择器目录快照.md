# 任务 001：稳定模型选择器目录快照

## 目标与交付物

在不改变模型调用授权、默认模型修复和后端路由契约的前提下，让模型选择器只展示完整、稳定、已按套餐筛选的目录快照，消除打开时闪烁和文字驱动的宽度跳动。

交付物包括：

- ModelSwitcher 原子目录快照与明确的刷新输入。
- 当前模型失效后的“请选择模型”或“暂无可选模型”状态。
- 套餐供应商优先的稳定分组。
- `240px`、`168px`、`32px` 三档固定宽度及长名称无障碍展示。
- 规划模型设置只以原始空值表示继承，显式同值不再伪装成单模型模式。
- 覆盖状态矩阵、调用次数、排序、失效模型和响应式布局的前端测试。

## 禁止范围

- 不新增 Wails 方法，不修改会话/tab 持久化格式、账号资产事件或缓存代码；Go 改动仅限投影既有 `WorkspaceTab.model` 和相邻契约测试。
- 不改变 Free/Lite/Plus/Pro 标签规则、BYOK 路由和套餐失败关闭语义。
- 不自动选择第一个候选，不调用 `onPick` 修复失效模型。
- 不改变默认模型修复策略或放宽 App 的发送门禁。
- 不自动迁移或清空已有非空 planner 配置，不改变同计费来源显式派生模型保留策略。
- 不把 ModelSwitcher 目录快照提升到 App、Zustand 或新的全局仓库。
- 不通过轮询、打开弹层读取或远端商城刷新保持目录新鲜。

## 必须保持的行为

- 未登录且有自定义供应商时仍可选择自定义模型。
- 未登录且无自定义供应商时复用禁用的“暂无可选模型”。
- Free 套餐按 `Subscribe_Free` 筛选；套餐证据不足时平台模型失败关闭，自定义模型保留。
- App 与 ModelSwitcher 保持独立事实快照，任何短暂分歧只能由 App 门禁更严格。
- 同一 ref 的不同计费来源必须按 `ref + billingSource` 正确识别当前模型。
- 模型选择器的稳定会话身份与发送授权分离；目录或权限 pending 时仍然禁止选择和发送。
- controller 的 planner/模式展示标签不再承担模型 ref 职责，但其他需要展示该说明的界面可以继续使用它。
- 原始空 planner 继续表示单模型继承；显式 planner 即使等于默认模型也继续保留并如实显示。

## 实现约束

1. 目录快照至少携带 tab、完整账号绑定 scope 和请求代次；跨 scope 立即失效，迟到结果必须丢弃。
2. 路由与商城读取并行完成后一次提交；不得先显示全量路由再显示套餐结果。
3. 同 scope 配置或商城缓存刷新期间保留稳定触发器文案但禁止选择；失败后按计划规定提交空路由或仅自定义模型。
4. 套餐 plan/status/version 变化只重筛已确认快照，不调用 `ModelsForTab` 或 `ModelMarketplace`。
5. 当前模型身份变化只更新选中态，不重新读取目录。
6. 打开弹层只处理 UI 状态、搜索词和焦点，不发起目录读取。
7. 套餐供应商按是否包含 `subscription_pool` 固定排第一，其余供应商稳定排序。
8. 从已过滤候选解析当前模型；失效且有候选显示“请选择模型”，无候选显示“暂无可选模型”。
9. 按钮和弹层使用响应式固定宽度；长名称省略但保留 Tooltip、title 或等价无障碍完整名称。
10. 同一账号作用域切换到已有会话时，从目标 tab 首次成为活动展示起使用后端 DTO 提供的规范 `modelRef + billingSource`；目录 pending 期间保持该目标文案并禁用，不得显示其他 tab 身份或通用空态。
11. 同 tab 最近确认身份只允许作为 DTO 同值的短暂展示缓存，并按完整账号绑定 scope 隔离；首次访问、账号、profile、binding generation 或目标 tab 改变后不得借用其他身份。
12. `state.meta.label` 或 `tab.Label` 含 planner/模式说明时不得作为模型 ref；`ModelsForTab` 唯一 current route 只负责可选性确认和失效收敛，不负责首次提供当前身份。
13. facts 稳定后若目标模型确实不在可选候选中，仍按既有规则显示“请选择模型”或“暂无可选模型”，不得用稳定展示无限掩盖失效。
14. 设置页只按原始 planner 是否为空判断“使用当前模型（单模型）”；选择该项必须通过既有 `SetPlannerModel("")` 保存空值，显式同值不得在读取阶段折叠为空。

## 验收标准

- 首次账号/配置恢复或跨账号 scope 且没有可确认会话绑定时，加载完成前只有禁用的“暂无可选模型”，完成后一次切换为最终列表；已有会话只要 DTO 提供保存绑定，就从首次展示起显示该模型。
- 反复打开和关闭模型框不会增加模型或商城调用。
- 路由与商城请求以任意顺序完成都不会展示中间组合。
- 套餐变更直接得到最终筛选列表，套餐供应商始终第一。
- 当前模型失效时不自动切换；有候选可打开重选但不能发送，无候选时选择器和发送均禁用。
- 桌面、紧凑、极窄宽度分别稳定为 `240px`、`168px`、`32px`，长模型名不推动工具栏。
- App 现有发送门禁、默认修复及 BYOK 行为保持通过。
- 连续切换绑定 Flash、Pro、Qwen 等模型的已有会话，选择器从目标 tab 首次呈现起只显示目标绑定模型；不得经过“暂无可选模型”或“请选择模型”，也不得误用其他 tab 身份。
- 带独立 planner 的控制器 Meta 就绪不会改变选择器模型身份、触发目录读取或产生额外闪烁。
- 空 planner 显示并保持真继承；显式同值显示实际模型且不被自动迁移；用户选择单模型后重新读取 Settings 得到空 planner。
- 会话切换 pending 期间选择器与发送保持禁用；最终确认可用后直接启用，最终确认失效后要求用户显式重选。
