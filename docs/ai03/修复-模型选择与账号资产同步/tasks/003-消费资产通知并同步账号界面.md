# 任务 003：消费资产通知并同步账号界面

## 目标与交付物

让前端账号控制器消费任务 002 的资产变化通知，以合并读取方式取得当前账号的组合缓存快照，并在 accountStore 中按完整 scope 和分资产版本单调更新余额与套餐，使左侧账号菜单、账户页余额卡片、套餐权限和模型筛选自动收敛。

交付物包括：

- `cloud-assets:changed` 的生命周期安全监听和单飞 + dirty 读取控制。
- 当前资产缓存 API 的前端桥接和类型。
- Bootstrap、支付、手动刷新、事件快照共享的资产合并函数。
- 左侧账号菜单与账户页共享余额、订阅访问和模型本地重筛的端到端更新。
- 覆盖交错响应、迟到 scope、版本单调和最终真实登录事件闭环的测试证据。

## 禁止范围

- 不修改 Go 事件分类、Desktop 通知器、缓存 API 语义或持久化格式。
- 不复用会联网的 `CloudRefreshAssets` 响应事件通知。
- 不增加轮询、定时刷新或每次打开菜单刷新。
- 不重构登录、退出、候选账号、账号切换、支付状态机、payments、busy、error 或 initialized 生命周期。
- 共享合并函数只处理 `balance` 和 `subscription`；不得成为整个 accountStore 的通用 reducer。
- 不用事件版本排序资产，不允许旧 scope 或低资产版本覆盖当前状态。
- 不自动切换模型，不放宽 App 发送门禁。

## 必须保持的行为

- 已有 Bootstrap 去重、AccountCenter 手动操作和支付轮询继续按各自生命周期工作。
- 退出、凭证过期和绑定切换仍清除或替换对应账号状态。
- 余额读取失败保留同 scope 最后确认余额；不回退为零。
- 套餐证据不足时平台模型继续失败关闭，自定义模型保留。
- 通知载荷只作唤醒，前端总是读取组合缓存快照。
- 套餐资产变化可以使真正失效的当前模型进入显式重选，但不得把会话切换或 facts pending 误判为模型失效。
- 账号资产重筛不得清除任务 001 按目标 tab 保存的确认模型身份，也不得把 controller 的 planner 展示标签作为模型 ref。

## 实现约束

1. 监听跟随 `contextKey` 和组件生命周期注册/注销；运行环境无 Wails listener 时安全退化。
2. 同一 context 的通知读取采用单飞；运行中收到通知只置 dirty，完成后至多立即再读一次。
3. 每个请求记录 context、当前完整 scope 和请求代次；提交前再次核对三者。
4. 共享资产合并函数由 Bootstrap、支付、手动刷新和事件快照共同调用，但只决定余额、套餐字段是否前进。
5. 跨 scope 一律拒绝；同 scope 分别比较 `balance.version` 与 `subscription.current.version`。
6. 正版本只允许更高版本替换；同版本冲突失败关闭。缺失或零版本只允许当前请求代次应用，且不得覆盖已有正版本。
7. 余额与套餐可以独立前进，不能因其中一个版本较旧拒绝另一个较新资产。
8. 缓存读取失败只记录可诊断状态，不清空现有资产，也不改变登录或支付 error。
9. 套餐更新只改变 `subscriptionAccess` 并让任务 001 的稳定快照本地重筛；不得调用 `ModelsForTab` 或 `ModelMarketplace`。
10. App 或账号订阅状态更新与会话导航并发时，按完整账号 scope、目标 tab 和请求代次丢弃迟到结果；稳定身份只用于展示，发送门禁继续独立判断。

## 验收标准

- balance 通知后无需进入账户页触发 `CloudBootstrap`，左侧账号菜单和已打开的账户页余额卡片都与缓存 API 一致。
- subscription 通知后账号套餐和模型候选自动更新，目录 API 调用次数不增加。
- 连续通知在一个读取进行时最多形成一次尾随读取，最终应用最新组合快照。
- 快速切换 context、账号或 binding generation 时，旧通知和迟到响应不覆盖当前状态。
- Bootstrap、支付、手动刷新和事件响应任意交错时，余额与套餐分别保持最高权威版本。
- 缺失/零版本不覆盖正版本；同版本内容冲突失败关闭。
- 读取失败保留同 scope 最后确认值，退出或过期仍按既有规则清理。
- 当前套餐降级后，任务 001 的模型框直接得到最终 Free 列表；当前模型失效要求用户重选。
- 套餐事件与已有会话切换交错时，选择器不误用其他 tab 身份或显示 pending 空态；只有新套餐事实稳定且确认绑定模型失效后才显示“请选择模型”。
