# 首页场景选择器视觉修复计划

## 问题与现状

新建会话首页的“日常办公 / 代码开发 / 设计创意”使用两层相近浅色：外层为
`surface-3` 与灰色边框，选中项为 `accent-soft` 与浅边框。层级对比不足，整体呈现为厚重灰底。

WorkBuddy 的同类控件采用单层胶囊轨道和高对比选中胶囊：外层无边框，按钮透明，选中项使用
实心色，未选中项仅在悬浮时出现浅色反馈。

## 目标

- 将外层中性灰底替换为极浅主题色轨道，并移除外层边框。
- 将选中项改为实心主题色和主题定义的对比文字色。
- 保持未选中项透明，悬浮与键盘焦点使用浅主题色反馈。
- 使用完整胶囊圆角，保持现有场景切换、响应式布局和可访问状态。
- 将“文档处理 / 金融服务 / 数据分析及可视化 / 更多”及展开后的二级场景按钮统一为胶囊轮廓；保留既有颜色和状态反馈。
- 不引入位移、滤镜、阴影或额外合成层，兼容低性能设备。

## 非目标

- 不改变场景名称、图标、切换逻辑、持久化或异步状态。
- 不调整首页标题、场景内容和输入框布局。
- 不改变全局主题令牌。

## 源码依据与影响范围

- `Welcome.tsx` 通过 `welcome-creation__mode--active` 表达当前场景，行为层无需修改。
- 首页主要二级场景、“更多”按钮及展开后的场景均复用 `welcome-creation__scenario`，一次局部圆角调整即可保持一致。
- `theme-overrides.css` 当前外层使用 `surface-3`、`border-soft`，选中项使用 `accent-soft`。
- WorkBuddy 安装包前端的 `mode-selector__switch` 使用无边框胶囊轨道；按钮透明，active 使用实心色。
- 生产改动限于 `theme-overrides.css`，测试更新限于现有主题契约测试。

## 实现方案

- 轨道：`color-mix(in srgb, var(--accent) 7%, transparent)`、无边框、`999px` 圆角。
- 按钮：36px 最小高度、`999px` 圆角，默认透明。
- 选中：`var(--accent)` 背景、`var(--accent-fg)` 文字、透明边框。
- 悬浮/键盘焦点：12% 主题色浅底。
- 动画仅保留 `background-color` 与 `color`。
- 二级场景按钮：沿用现有背景、边框、hover/active/focus 规则，只将 `border-radius` 从 `9px` 改为 `999px`。

## 验收标准

- 默认页面不再出现中性灰色外框和双层浅色块。
- 选中项为清晰的实心主题色胶囊，主题切换后颜色同步变化。
- 未选中项默认透明，悬浮时出现浅主题色反馈。
- 所有二级场景按钮（含“更多”和展开项）呈现一致胶囊轮廓。
- 三个按钮仍可正常切换，`aria-pressed` 行为不变。
- 窄窗口和低高度响应式规则保持有效。
- 专项测试与 `pnpm build` 通过。

## 风险与回滚

风险集中在不同主题下的文字对比和窄窗口尺寸。使用既有 `accent`/`accent-fg` 配对令牌规避对比问题，
并保留原有容器查询。若视觉不符合预期，可单独回滚本 CSS 与契约测试提交。
