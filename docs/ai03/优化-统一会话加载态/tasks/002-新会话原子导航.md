# 任务 002：新会话原子导航

## 1. 任务信息

- 状态：reopened-rollback-completed
- 串并行组：Serial-2，依赖任务 001 的共享等待展示组件
- 任务到 PR：与任务 001 组成同一前端体验修复，但以独立 `fix:` 提交保留导航行为的审查与回滚边界
- 执行者：主会话（当前规则未授权子代理）

## 2. 目标与预期产物

修复选中已有会话 A 后进入模型广场等主工作区，再点击新建时短暂重新显示 A 历史的问题。任务曾以全屏等待事务实现，但用户验收确认该方案造成新建白屏并违背 Composer 固定壳体/草稿首帧合同；当前先回退该方案，再重新建立窄回归。

预期产物：

- 精确旧红复现 A → 其他页 → A → B，并证明中间帧来自 `showChatView` 早于 `EnsureBlankSurface` 完成。
- 不显示新建加载态、不伪造 B identity 的最小可见提交顺序与确定性竞态测试。
- blank B 草稿→A→再次新建时，首帧恢复 B 草稿且不出现空 Composer→草稿闪烁。
- 普通/专家 A 的 canonical scroll 不被等待事务改写，返回 A 继续满足既有恢复合同。
- clean 精确 HEAD Desktop 新建与返回 A 的原生证据。

## 3. 调用链与依赖

- `activeTabId` 同时拥有模型/专家/技能与连接器目标、Composer 配置/草稿、右侧工作区、运行时操作及 Transcript view/scroll；不得清空或伪造。
- `handleNewTab` 当前先 `showChatView(true)` 再 `openBlankSession`，因此 B pending 时重新渲染 A。
- `openBlankSession` 被项目 Composer、专家新任务和项目树复用；主工作区遮罩不能下沉为所有调用的副作用。
- `EnsureBlankSurface` 会创建/复用 B、保存并裁剪其他可见 tab，再把 B 设为 active；本任务不改变 Go/Wails 或增加取消协议。
- 通用无 path/topic blank target 会共享 view/draft identity；本任务不得用 `beginSurfaceTransition` 伪造 B。

## 4. 允许与禁止范围

### 允许修改

- `desktop/frontend/src/App.tsx`
- 任务 001 提供的共享 loading presentation 组件及必要 CSS（仅复用接口或 App overlay modifier）
- 直接相关 App、新会话竞态、导航、Composer/shortcut 门禁和 anchor 集成测试
- 本任务回执、progress 与 OpenSpec tasks

### 禁止修改

- `useController` 的 Transcript 虚拟器、semantic restore、snapshot/cache、single seek、stable/hard-limit 或 identity 算法。
- Go/Wails `EnsureBlankSurface`、tab 裁剪、后台运行或持久化协议。
- 取消当前选中会话、创建通用伪 blank view/draft identity，或改变模型/专家/能力页面作用于当前会话的既有语义。
- 项目 Composer、项目树创建、专家新任务等后台 blank 准备入口的展示行为。

## 5. 必须保持的行为

- A 在等待期间仍是 active/runtime owner；运行中 A 可继续后台运行，非运行 A 在 B 提交时按现有流程保存。
- 等待表面不挂载 A Transcript，不调用 A 的 `onScrollAnchorChange`，不写 bottom、通用 blank key 或新 canonical。
- B 完成绑定前不得显示伪 B、空白遮罩或加载态，也不得误修改 A/B。
- B 成功后一次进入 chat+B；失败保持原 `workspaceView` 与 A，不显示 A 的中间 chat 帧。
- Composer 固定壳体与按 identity 草稿隔离继续成立；可复用 blank 的未发送 prompt 不静默丢失。
- 项目/专家的既有 `openBlankSession` 调用仍返回真实 tab id，并保持当前错误与竞态合同。
