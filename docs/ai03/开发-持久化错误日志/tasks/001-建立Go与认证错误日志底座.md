## 目标与交付物

建立 Desktop-owned、有界、仅本地的 JSONL failure journal，并接入 Go `ERROR`、显式失败型
`WARN`、Go panic 与 cloud auth session failure，使错误在重启和重新登录后仍可取证。

交付物：

- 有界非阻塞队列、单 writer、跨进程锁保护的 journal、严格事件 schema、最终脱敏、重复抑制、
  轮转与清理；
- dev/prod profile cache 初始化、原 `slog` delegate 保留和 best-effort shutdown；
- 两个 auth session transition 分支的安全失败事件；
- Go panic 与少量已证明失败 warning 的接入；
- 文件私有权限、最终字节隐私、容量、时间、跨进程并发、短写恢复、故障降级和 auth 时序测试；
- 本任务完成回执。

## 依据与失败路径

- `desktop/main.go` 未配置文件 `slog.Handler`；进程输出无法在用户重新登录或退出后作为证据。
- `internal/cloud/auth_identity_lifecycle.go:persistFailureLocked` 会在 terminal 分支 scrub token 并覆盖
  durable session，在 retryable 分支写 offline，但不先保存 code/request ID/phase。
- `internal/cloud/auth_application.go:persistFailure` 是显式 refresh lifecycle 的另一条状态覆盖路径。
- `desktop/crash_pending.go` 只保存 `goSafe` panic 的单个 pending 文件，普通 failure 不覆盖。
- `desktop/crash_app.go` 已有 secret、Bearer、JWT、邮箱、username 段和长 token 脱敏，但没有手机号
  规则，也没有删除绝对路径尾段；journal 最终边界必须补齐后再复用。
- 开发 profile 在 `desktop/dev_profile.go` 设置独立 cache root；生产 `config.CacheDir()` 指向
  `%LOCALAPPDATA%\Clouvia`。journal 必须使用 process environment profile，不跟随账号切换删除。

  Authorization、password、device ID、scope/profile/user 原值、完整路径或路径尾段。
- 不改变 auth terminal/retryable 分类、refresh/replay 次数、session schema、保存顺序或业务返回值；
  唯一允许的时序插入是 session save 前非阻塞 enqueue 安全 failure event。
- 不把所有 `slog.Warn` 自动持久化，不把 raw `err` attr 写入 journal。
- 不新增 dependency、config、migration、SQLite、常驻协调服务、UI 或网络行为；只允许 journal 专属短时 advisory lock。
- 不修改 `scripts/code_guard_baseline.json`，不触碰主工作区，不推送、不创建/更新 PR、不继续委派。

## 保留行为

- 原默认 `slog`/stderr 继续收到原记录；journal handler 不吞日志、不递归。
- journal 初始化、write、sync、cleanup、close 失败不改变 Desktop 启动、shutdown 或 auth 返回。
- terminal 仍 scrub credential 并写 expired；retryable/network 仍保留 credential 并写 offline。
- stale observed session guard 继续阻止迟到旧错误覆盖新 rotation。
- logout/account switch 继续按现有 cleanup 清理 auth/assets，但不删除 process-level failure journal。
- `crash-pending.json` 的写入、下次启动处理与 re-panic 语义不变。

## 实施合同

1. 先复述目标、依据、允许/禁止范围和保留行为；有实质歧义立即停止，不得猜测。
2. journal 事件使用固定字段 struct，不接受 arbitrary attrs/message；source/event 由 backend 固定，
   scope/type 使用 allowlist，未知值映射固定 `unknown/Error`。frame 只允许 enum category、ordinal、
   line/column 数值，不接受函数名、文件名/basename 或任何 renderer 原文。剩余字符串在 marshal 前
   再次脱敏并按字节截断。
3. 启动同步阶段只计算路径、创建 256 条内存 queue 并启动单 writer；mkdir/lock/scan/cleanup/open/stat/
   write/sync/close 全在 writer 异步执行。enqueue 永不阻塞；Close 先原子切换 discard，事件 channel
   永不 close，writer 用独立 stop signal 最多 drain 500 ms。Close 幂等，并发 enqueue/Close 不得 panic；
   队列满或超时直接丢弃，不得在 auth mutex 或 `bootstrapDesktopLaunch` 关键路径执行 journal 磁盘操作。
4. 所有进程共享 current JSONL；用已有 `x/sys` 实现最多等待 250 ms 的跨进程 advisory lock。每次
   持锁后按路径重新 open/stat，依次执行 tail repair、cleanup、容量预留、轮转、append、rollback/sync，
   并在解锁前 close；禁止跨 lock 生命周期缓存 descriptor。锁失败丢弃事件。
5. 目录 `0700`、文件 `0600`（Windows best-effort）；单条上限 16 KiB、frames 最多 8 KiB/64 条，
   current 写入后不得突破 2 MiB。
6. writer 启动后立即异步 housekeeping，之后无新事件也至多每小时重试；constructor/bootstrap 不等待。
   首次事件写入前、跨日和轮转仍执行容量检查：先严格早于 7 天的文件，再按最旧文件控制 10 MiB；
   future mtime 不按过期删除，不能腾出预算则丢弃。archive 用 `O_EXCL` 预留并最多重试 16 次。
7. 每次打开 existing current 后先检查末尾换行；partial tail truncate 到最后完整换行（无完整行则
   清空），修复失败则以碰撞安全名称移入同目录 `.corrupt` quarantine，计入 10 MiB 但不按 JSONL
   读取。append 前保存 offset，事件与换行一次编码；短写/失败必须 truncate rollback，rollback 失败
   同样隔离 current。测试需在后续成功 append 后逐行解析全部 JSONL。
8. duplicate fingerprint 只使用已脱敏稳定字段，窗口 30 秒、最多 1024 项；不得使用敏感原文。
9. `slog.Handler` fan-out 保留 delegate；`ERROR` 只落 severity/固定 callsite category/ID/固定 event，
   不读取 `slog.Source.File`，不落 message/attrs；
   `WARN` 只有固定 failure marker 才进入 journal。handler 内部只 enqueue，不调用 `slog`。
10. 从 `crash_app.go` 提取脱敏时补手机号和绝对路径尾段规则，保留现有 crash payload/网络授权。
11. auth failure event 在 session save 前非阻塞 enqueue；auth code 仅接受当前 lifecycle 识别的 typed
   allowlist，未知服务端 code 映射 `UNKNOWN_CLOUD_ERROR`。区分 explicit refresh（不得称 login）、
   automatic refresh/protected request、terminal、offline、stale guard 和 save failure。只读取 typed
   cloud error 安全字段与 session metadata；允许进程在 writer 落盘前崩溃时丢失最后事件。
12. 先写确定性失败测试证明基线无 journal/transition evidence，再实现最小通过代码；运行聚焦测试和
   diff audit。
13. 创建一个小而完整的 `feat:增加有界持久化错误日志` 提交；验证后更新本文件回执并单独创建
    `docs:` 提交。
14. 如果必须改变 auth 构造 API、session DTO、Wails API、配置或引入新依赖，停止并报告主 Agent。

### 实际变更

- 在 `desktop/internal/diagnostics/` 建立固定 schema 的本地 JSONL journal：256 条非阻塞队列、单 writer、启动/小时 housekeeping、30 秒/1024 fingerprint 去重、2 MiB 单文件、10 MiB 总量、7 天清理、跨进程 advisory lock、跨日轮转、partial tail 修复、短写 rollback、quarantine、目录/文件私有权限及最终字节脱敏。
- 在 Desktop 组合根接入 dev/prod profile cache、fan-out `slog.Handler`、固定失败型 warning、Go `ERROR`、Go panic failure 和 best-effort shutdown；保留原 delegate、`crash-pending.json` 写入与 re-panic 语义。共享 sanitizer 补齐手机号/绝对路径规则，并在持久化前提取已脱敏 TopFrame，保持既有 crash metadata 合同。
- 在 `AuthApplication.persistFailure` 与 `authenticatedRequestExecutor` 的真实 session transition/save-failure 路径记录 typed auth failure；terminal 事件在 scrub/save 前保留 token presence/expiry，retryable 事件写 offline 并保留 credential，stale/load/save outcome 不读取 raw error。
- 新增 profile/production metadata、delegate/marker、轮转/容量/保留、双进程 append、partial tail、JSONL 可解析性、privacy canary、私有 mode、dedupe/Close race，以及 terminal/offline/explicit refresh/save-before evidence 回归测试。
- 根据主审复核补齐 auth mutex 内 direct enqueue seam：cloud 仅对 default handler 做小型 exported-method type assertion，Desktop fan-out 只执行非阻塞 `Record`，无 journal 的非 Desktop handler 仍回退原 slog；delegate 仅在自身 `Enabled` 时调用，marked WARN 仍独立落盘。
- 补齐启动无事件时的 current housekeeping：持锁修复 partial tail 后按原始 UTC mtime 跨日轮转或删除超过 7 天的非空 current；Go ERROR callsite 只持久化函数名/行号的稳定 hash，不保存 raw `record.PC`。
- 新增实例级文件操作故障 seam 与回归：阻塞 mkdir/open、short write、sync、remove、close 以及 rollback/quarantine 失败均可达并断言，`Close` 500ms 边界、失败不 panic、恢复追加后的 JSONL 逐行可解析；跨进程测试逐个核验两个 helper 的 24 个唯一 `request_id`。
- 收紧故障注入证据：short write 先完成 rollback 后才开启下一阶段；完整写入 `sync-failure` 事件后才注入 sync failure，并断言故障命中、后续 `recovery-success` 落盘且所有 JSONL 行可解析。
- remove failure 测试预置 5 个 `2 MiB - 1` 归档，将总量置于 `10 MiB - 5`；删除全部失败时新事件不落盘且总量不超过 `10 MiB`。close failure 独立测试确认一次性 close 错误不阻断后续 `close-recovery` 事件。
- 按前端接入合同补齐 journal 最终边界：精确接受源码现有 86 个固定 frontend scope（含 `capabilityErrorMessage`、toast/session wrapper 与三个 global scope），source 固定归一为 `frontend`、event 固定为 `client.failure`；精确接受 `ERROR_CODE_MESSAGES` 与 AccountCenter、AccountRecharge 及 capability 固定 map 的 49 个 code，未知 scope/code 分别归一为 `frontend.unknown`/`UNKNOWN`。新增落盘 JSONL 表驱动测试证明恶意 source/event、合法格式未知 code 和 scope canary 不进入最终字节。
- 修复跨进程关闭阶段的 accepted-event 丢失：启动 housekeeping 的锁等待收敛为 50ms，`Close` 记录绝对 500ms 截止时间；关闭时优先停止消费、收集队列并在单次锁事务中按同日 payload 批量 append/sync，steady-state 写锁失败后将事件重新放回 close batch。新增真实耗时竞争、steady write lock failure requeue、永久锁失败有界性测试；原双 helper 24 个唯一 `request_id` 的跨进程轮转测试在 `-count=100` 下稳定通过。

### 偏差

- 为统一最终脱敏规则，crash 文本 sanitizer 复用 diagnostics helper；该规则会先脱敏 stack 路径，因此 `recoverToPending` 改为从原始 stack 提取 TopFrame 后立即脱敏，避免破坏原有 `TopFrame` 非空合同。
- 为保持生产无新依赖且不改变公开 auth 构造/session DTO，文件故障注入 seam 保持在 diagnostics 实例 `Option` 和同包测试内；生产默认仍使用标准库 OS 操作。direct enqueue 仅在 Desktop fan-out handler 实现该结构化接口时生效，其他宿主保持原 slog fallback。
- 本轮按已批准前端接入边界新增 journal 对 `source=frontend` 的固定归一化；未修改 frontend、Wails API、容量/轮转/队列或 cloud/go 的既有归一化行为。
- 本轮跨进程修正仅改变关闭阶段的调度与批量写入；steady-state 单事件锁等待、10 MiB/2 MiB/7 天预算与队列容量合同保持不变，关闭仍以 500ms 为上界，永久锁失败仍 best-effort 丢弃。

### 剩余风险

- race 检查受当前 Windows 构建环境缺少 C 编译器限制；主 Agent 仍需在可用环境评估或记录该限制。
- 仓库级 `code_guard`/`pr-gate`、两个任务集成后的完整门禁和 patched `wails dev` A/B 属于主 Agent 的最终验收，本任务未声称已完成；真实账号 terminal transition 未执行破坏性测试。
- frontend scope/code allowlist 与当前源码固定 literal/map 同步；后续新增固定值需要显式更新该边界，未知值不会因格式合法而自动放行。
