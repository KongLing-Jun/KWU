## 目标与交付物

把现有 frontend `reportClientError` 与 React/global crash funnel 接入 Task 001 的本地 journal，使
renderer failure 在重新登录和重启后保留，同时不改变用户提示、console、崩溃覆盖层或网络授权。

交付物：

- 一个参数严格、best-effort、仅本地写 journal 的 Wails `App.RecordClientError` binding；
- `reportClientError` 的可注入 local sink 与 fire-and-forget Desktop 接线；
- React、`window.error`、`unhandledrejection` 的单次提交与枚举/数值 stack/component frame metadata；
- 无 binding、binding reject、重复错误和隐私 canary 测试；
- production frontend build；
- 本任务完成回执。

## 依据与失败路径

- `desktop/frontend/src/lib/clientError.ts:reportClientError` 是 36 个现有业务失败调用点的统一 funnel，
  已生成 safe presentation 和结构化 `ClientErrorLog`，但默认只调用 `console.error`。
- `desktop/frontend/src/lib/crash.ts:reportCrash` 当前先调用 `reportClientError`，再构造/绘制 crash
  payload；接入时若另外提交 payload 会重复记录，若只沿普通 DTO 又会丢 frames。
- `desktop/frontend/src/main.tsx` 在 React mount 前安装 global handlers，适合同时安装 local sink。
- `desktop/frontend/src/lib/bridge.ts:AppBindings` 与 late-bound `app` proxy 是唯一 Wails seam；browser
  development 可能没有 binding，不能因 journal 产生 unhandled rejection。
- Task 001 的 Go journal 是最终安全边界；frontend 字段仍须在 Go 再校验、脱敏和截断。

## 实施合同

1. 先复述目标、依据、允许/禁止范围和保留行为；实质歧义时停止，不得猜测。
2. frontend DTO 只包含 scope、allowlisted code/error type、time 和仅 crash 使用的枚举/数值 frame metadata；
   source/event 由 backend 固定。frame 只传 `app/framework/runtime/unknown` category、ordinal、
   line/column，不透传 message、stack 首行、函数名、文件名/basename、breadcrumbs、view、任意 object
   或 raw error。
3. `reportClientError` 保留现有 console/object dedupe，但 local sink 位于永久 WeakSet filter 之外；
   Go journal 以 30 秒稳定 fingerprint 去重，因此同一 Error 对象在窗口后再次发生仍可落盘。
4. local sink 在 `main.tsx` 的 global handlers 之前安装，调用 `app.RecordClientError` 后必须 catch 并
   静默；catch 内不得 console.error 或再次 report。
5. `reportCrash` 先构造一次持久化用枚举/数值 crash fields，再通过一次 `reportClientError` 调用完成 console 与
   local sink，随后 paint 同一 payload；不得直接第二次提交。普通业务 failure 不采集 frames。
6. Go binding 忽略/不接收 renderer source/event；scope 只接受已知 scope allowlist，unknown 映射
   `frontend.unknown`；code 只接受仓库当前固定错误码表（`ERROR_CODE_MESSAGES` 与固定 `knownMessages`
   maps）的并集，其他合法格式也映射 `UNKNOWN`；
   error type 只接受内建 allowlist，unknown 映射 `Error`；frame 重新验证 category enum 和非负
   ordinal/line/column 后调用 Task 001 journal。nil/unavailable journal 返回成功式 no-op，不把持久化
   错误返回 renderer。
7. 测试必须证明：现有 presentation/console object dedupe 不变、journal 30 秒窗口后同对象可再记录、
   每个 React/window/rejection 只有一条 JSONL、无 runtime/reject 不产生 unhandled rejection；恶意
   合法格式但非 allowlist 的 code 与恶意 scope/errorType/function/basename/message/body/路径尾段 canary
   都不能跨 Go boundary 或出现在文件。
8. 运行聚焦 tests 和 `pnpm build`，审计 diff；创建一个
   `feat:接入前端持久化错误日志` 提交，随后更新本回执并单独提交 `docs:`。
9. 如果需要新增 UI、远端 API、全局 state 或修改所有调用点，立即停止并报告主 Agent。

## 完成回执

### 实际变更

- 在 `desktop/error_journal.go` 增加严格的 `ClientErrorRecord`/frame DTO 与 `App.RecordClientError`：source/event 由 Go 固定为 `frontend/client.failure`，只接收 scope、code、error type、发生时间和枚举/数值 frame metadata；journal 不可用或写入失败不返回 renderer 错误。
- 在 `bridge.ts` 增加本地 binding contract 与静默 fire-and-forget wrapper；`clientError.ts` 增加可注入 local sink。sink 位于现有 WeakSet/console 去重之外，并在跨 Wails boundary 前固定化 86 个 scope、49 个 code、内建 error type，普通业务 failure 不附加 frames。
- 在 `crash.ts` 解析 React/global stack 为最多 64 条 `app/framework/runtime/unknown` 与非负 line/column/ordinal；`reportCrash` 构造一次 payload 后只调用一次 `reportClientError`，随后沿原 overlay 路径绘制。`main.tsx` 在 global handlers 前安装 sink，缺失或 rejected binding 静默降级。
- 新增 Go boundary、renderer privacy、console/object dedupe、local sink repeated-object、ordinary-frame filter、React/window/rejection 单提交、frame metadata、overlay 保留和缺失/rejected binding rejection 回归测试。
- 纠正 `WorkspacePanel.refreshSelected` 的返回错误路径：成功返回的 `FilePreview.err` 仍按既有 preview 状态渲染，同时通过 `reportClientError("workspace.preview", ...)` 只记录一次；rejected read 继续只走原有 `catch` 上报路径。新增 workspace 回归测试验证两种路径的单次提交，并确认 journal DTO 不包含原始路径。
