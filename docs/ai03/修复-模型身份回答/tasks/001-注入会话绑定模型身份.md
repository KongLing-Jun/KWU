## 目标与产物

在主会话固定 system prompt 中注入经 `ResolveModel` 解析后的裸模型名
`entry.Model`。当用户询问模型身份时，助手必须回答该绑定名称，不得暴露 Provider
前缀或猜测其他模型。

预期产物：

- 一个安全编码动态模型名的模型身份策略构造函数。
- 活动 `boot.Build` system prompt 组装点接入该策略。
- 新会话、自定义基础 prompt 和桌面模型切换的自动化回归测试。
- 本任务文档完成回执与更新后的 `progress.md`。

## 禁止范围

- 不修改前端模型选择器、Provider 请求、计费或订阅路由。
- 不新增配置项、依赖、持久化 schema、网络请求或模型查询工具。
- 不修改历史 assistant 内容或旧会话文件。
- 不调整 Expert、Memory、Skills、场景、语言及其他 prompt 语义。
- 不声称本地绑定名称能证明上游远程实际路由。
- 不推送、创建/更新/合并 PR，不委派其他代理。

## 必须保留的行为

- 自定义基础 system prompt 仍保留，并获得固定策略。
- 决策、文件交付、时间、语言、Memory、Skills 与场景策略顺序和内容不变。
- 模型切换仍保留非 system 对话历史。
- 请求中的模型引用、Provider 和计费来源不变。
- 主会话只描述其自身绑定模型，不混入 Planner/Subagent 模型。

## 实现约束

- 使用 `entry.Model`，不得使用未经解析的 `Options.Model` 或完整 `modelRef`。
- 模型名必须作为数据进行确定性编码，特殊字符不能破坏策略结构。
- 策略必须区分“云智企办”产品身份与模型身份。
- 策略必须明确禁止依据训练认知、回答风格、Provider 类型或兼容协议猜测身份。
- 活动 `boot.Build` 端到端测试是完成门槛。

## 验收标准

1. `kwu/deepseek-v4-flash` 只向身份策略提供 `deepseek-v4-flash`。
2. 模型身份问题被要求按绑定裸模型名回答，不得猜测 Claude、GPT 等名称。
3. 自定义基础 prompt 保留并追加同一约束。
4. Provider 名、完整模型引用和请求路由不被改变。
5. 从 `old-model` 切换至 `new-model` 后，system prompt 只保留新模型身份，用户历史不变。
6. 含引号、反斜杠和换行的模型 ID 被稳定编码。
7. 相关 Go package 测试和最终 PR Gate 通过。
