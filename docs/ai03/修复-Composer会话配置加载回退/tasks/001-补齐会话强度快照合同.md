# 001：补齐会话强度快照合同

## 任务目标

在现有 Composer 会话身份链路中补齐已持久化的推理强度，使运行标签、历史会话、项目树
节点和前端 `ComposerSessionIdentity` 都能携带同一个目标会话的模型/强度快照；不新增
持久化系统，不改变 `EffortForTab` 的权威能力判断。

## 预期产物

- Go `composerIdentityView` 能区分“有持久化 effort 快照”和“没有可靠快照”。
- `TabMeta`、`SessionMeta`、`ProjectNode` 通过可选字段把快照传给前端。
- TypeScript `ComposerSessionIdentity` 正规化并保留该可选字段。
- 现有专家、权限、协作方式和 session identity 隔离行为不变。
- 后端与前端身份合同测试覆盖运行标签、保存会话和缺失旧字段三类情况。

## 依赖与证据

- 依赖同目录外的 `../plan.md`。
- `desktop/session_composer_state.go` 已从 branch meta 读取 `Effort`。
- `desktop/tabs.go` 的 `desktopTabEntry.Effort` 已持久化标签强度。
- `desktop/composer_identity_view.go` 当前只映射 model/billing/expert/profile，遗漏 effort。
- `desktop/frontend/src/lib/composerSessionIdentity.ts` 是既有首帧身份正规化入口。

## 禁止范围

- 不修改 `App.tsx` 的 pending/entitlement 呈现。
- 不修改 reducer、controller、主动模型/强度切换或发送门禁。
- 不修改 subscription 权限规则、模型 fallback、目录过滤或 Wails 方法名。
- 不新增磁盘文件、store、缓存服务或迁移脚本。
- 不委派其他代理，不推送、不创建或更新 PR。

## 保留行为与约束

- 可选字段必须向后兼容旧 session 和旧 `desktop-tabs.json`。
- 不得根据模型名称猜测 supported、default 或 levels。
- model 与 effort 必须来自同一个 tab/session identity，不能借用当前活动会话。
- 现有 `expertKnown` 语义和运行专家权威覆盖保持不变。
- Windows 检出使用 `core.autocrlf=false`，修改文件保持原 EOL。

## 验收标准

- 运行标签的 identity 返回本标签持久化 effort，不读取别的活动标签。
- 关闭会话的 identity 从 branch meta 返回 effort；branch meta 无字段时保持 unknown。
- SessionMeta、ProjectNode、TabMeta 的 JSON/TS 类型字段一致且为可选。
- runtime identity 覆盖 stored identity 时，模型和 effort 同步采用 runtime tab 值。
- expert/profile 字段测试不回退。
