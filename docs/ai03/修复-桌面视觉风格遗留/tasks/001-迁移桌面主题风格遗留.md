# 001：迁移桌面主题风格遗留

## 目标与交付物

废弃桌面 `theme_style` 偏好：历史配置在桌面启动设置读取时自动清除，所有后续桌面 UI 使用默认 `carbon`；旧设置接口仍接受 `style` 参数但不写入。交付实现、针对性测试、控制组/实验组验收证据，以及本任务回执。

## 依赖与分组

- 依赖：`../plan.md` 的已批准决策。
- 执行：单一串行任务，独占相关桌面配置、启动与前端主题文件。
- PR 映射：与计划、任务文档和实现一起构成后续可审阅交付；当前用户未授权创建 PR。

## 实现依据

- `internal/config/edit.go:SetDesktopAppearance` 当前规范化并保存 `Desktop.ThemeStyle`。
- `desktop/settings_app.go:SetDesktopAppearance` 调用 `applyConfigOnly` 持久化桌面设置；`MigrateDesktopPreferences` 会把旧 WebView 风格写进空配置。
- `desktop/frontend/src/App.tsx` 启动时调用上述迁移，再加载启动设置。
- `desktop/frontend/src/lib/theme.ts` 默认视觉风格为 `carbon`，但显式历史值仍会设置 `data-theme-style`。

## 允许范围

- `internal/config` 的桌面外观规范化与相关测试。
- `desktop` 的启动设置、配置写入、旧偏好迁移与相关 Go 测试。
- `desktop/frontend/src` 的主题迁移/应用与精确前端测试。
- 本目录计划、进度和任务回执的必要更新。

## 禁止范围与保留行为

- 不改 `ui.theme_style` 或 CLI 终端颜色。
- 不删旧 CSS 调色板；本任务保证桌面端不再选择它们。
- 不改主题模式、布局、语言、账号、会话、模型、密钥或 profile 隔离逻辑。
- 不破坏旧 `SetDesktopAppearance(theme, style)` 调用；它必须继续成功并保存 theme。

## 验收标准

1. 含 `desktop.theme_style = "graphite"` 的控制配置在迁移前原样存在。
2. 启动设置读取后，实验配置不再包含 `desktop.theme_style`，而 `desktop.theme` 与其它字段不变。
3. 重复启动/读取不产生反复写入，返回的桌面风格符合默认 `carbon` 语义。
4. 含 WebView 历史 `kwu-theme-style` 的首次启动只迁移主题模式，清除 localStorage 两个旧键，且不写风格字段。
5. 登录、注册、找回密码在真实开发应用中不再显示石墨旧金色；重启后保持。
6. 正式/开发隔离 profile resolver 的单测均不接触真实用户目录。

## 验证计划

- 先新增测试，建立“未迁移有历史值”的控制断言与“迁移后已清除”的实验断言。
- 运行直接变更的根 Go/desktop Go 包测试；运行关联前端精确测试与 `pnpm build`。
- 使用 Codex 内置浏览器优先验证可访问的开发页面；若 Wails 绑定需要原生壳，则用 Computer Use 验证实际窗口。
- 最后记录实际命令、结果、应用观察和任何偏差。
