# 市场包格式与数据模型

## 1. 目录结构

```text
connectors-marketplace/
├─ .codebuddy-connector/
│  └─ connectors.json
├─ connectors/
│  └─ <connector-id>/
│     ├─ connector-meta.json
│     ├─ marketplace-entry.json
│     ├─ mcp.json
│     ├─ cli.json
│     ├─ token-schema.json
│     ├─ icon.svg | icon.png
│     └─ skills/
│        ├─ SKILL.md
│        └─ references/ | scripts/ | assets/
└─ icons/
```

并非每个包都包含全部文件。读取器必须按能力文件是否存在来组装连接器，而不是假设固定模板。

原始资料：

- [中央索引](resources/marketplace/connectors.json)
- [144 份连接器根配置](resources/marketplace/configs)
- [51 份顶层 Skill](resources/marketplace/skills-entry)

## 2. 中央索引

中央索引负责市场级元数据和门控。主要字段如下：

| 字段 | 含义 |
|---|---|
| `id` | 稳定连接器标识 |
| `name` / `name_zh` / `name_en` | 展示名称 |
| `description_*` | 业务描述 |
| `source` | 对应包目录 |
| `type` | 主类型提示，不代表唯一能力 |
| `auth_mode` | 授权模式 |
| `provider_id` | 服务端授权 Provider |
| `visible_in` | 环境、部署和套餐门控 |
| `minWorkbuddyVersion` | 最低客户端版本 |
| `examples_zh/en` | 推荐问题 |

中央索引还声明跨连接器授权注入规则。实测规则字段包括 `when.active_in`、`applies_to_connectors`、`requires_connected_connectors`、`timing` 和 `inject`。腾讯文档个人版与企业版规则会在请求阶段分别注入 MCP OAuth Token 和 OneID Token。

## 3. MCP 配置

市场实测字段并集包括：

```ts
interface MarketplaceMCPConfig {
  url?: string
  type?: string
  transportType?: string
  timeout?: number

  command?: string
  args?: string[]
  runtime?: { type: string; version?: string }

  headers?: Record<string, string>
  env?: Record<string, string>
  staticHeaders?: Record<string, string>
  staticEnv?: Record<string, string>

  npmRegistry?: string
  disabled?: boolean
  disabledTools?: string[]
}
```

WorkBuddy 读取时执行以下归一化：

```text
streamableHttp / streamable-http -> http
command 存在                         -> stdio
type=sse                            -> sse
headers/env                         -> 保留变量模板，不展开真实值
```

## 4. CLI 配置

CLI 配置是声明式安装与授权流程：

```ts
interface MarketplaceCLIConfig {
  runtime?: { type: "node" | "python" | "shell"; version?: string }
  init?: PlatformCommand
  versionCheck?: {
    command: PlatformCommand
    minVersion?: string
    versionPattern?: string
  }
  auth?: PlatformCommand
  status?: PlatformCommand
  unAuth?: PlatformCommand

  authUrlDomain?: string
  statusMatch?: string
  statusMatchJson?: unknown
  authWaitForExit?: boolean
  authSuppressBrowser?: boolean
  authDeviceFlow?: unknown
  authQrModal?: unknown
  userProvidedData?: unknown
  npmRegistry?: string
  npmRegistries?: string[]
  env?: Record<string, string>
}

type PlatformCommand = string | {
  win32?: string
  darwin?: string
  linux?: string
}
```

配置示例见 [feishu/cli.json](resources/marketplace/configs/feishu/cli.json)、[tmeet/cli.json](resources/marketplace/configs/tmeet/cli.json) 和 [emr-query/cli.json](resources/marketplace/configs/emr-query/cli.json)。

## 5. Token Schema

Token Schema 用于动态生成表单：

```ts
interface TokenSchema {
  title: string
  description?: string
  docUrl?: string
  docLabel?: string
  fields: Array<{
    key: string
    label: string
    label_en?: string
    type?: "text" | "password"
    required?: boolean
    placeholder?: string
    description?: string
    help?: string
  }>
}
```

表单提交后，真实值进入凭据存储；密码字段返回 UI 时清空，只返回是否已经配置。

## 6. Skill 元数据

顶层 `SKILL.md` 通常包含：

- 何时应使用该连接器。
- 能力边界和业务术语。
- 常用工具及参数说明。
- 多步调用流程。
- 示例问题和结果解释。
- 对 references、scripts 和 assets 的导航。

目录注册表只需保存 Skill 入口和版本；Skill Runtime 在安装或启用连接器时物化实际内容。

## 7. 运行时合并对象

渲染器中的连接器对象字段并集为：

```text
id
name
description
icon
type
visibleIn
providerId
authMode
mcpConfig
cliConfig
tokenConfig
tokenValues
skills
examples_zh
examples_en
```

运行时 73 条定义全部包含中英文示例。`tokenValues` 在未配置状态为空；图标在渲染器中以 data URI 或资源 URL 表示。
