# 状态存储、版本与环境门控

## 1. 数据根目录

本机正式版数据根目录为：

```text
D:\WorkBuddyData\.workbuddy
```

`C:\Users\<user>\.workbuddy` 是指向该目录的 Junction。

## 2. 关键文件

| 路径 | 内容 |
|---|---|
| `.mcp.json` | Agent 使用的本机 Connector Proxy 配置 |
| `mcp.json` | 用户自定义 MCP |
| `mcp-approvals.json` | 自定义 MCP 审批状态 |
| `.connectors-marketplace.meta.json` | 市场 ETag 和 SHA-256 |
| `connectors-marketplace/.codebuddy-connector/connectors.json` | 市场中央索引 |
| `connectors/<profile>/mcp.json` | 当前 profile 生成后的 MCP Server 配置 |
| `connectors/<profile>/connector-states.v3.json` | 连接器状态和覆盖项 |
| `connectors/<profile>/.credentials.v3.json` | OAuth 客户端注册与加密凭据元数据 |
| `connectors/<profile>/.master.key` | profile 主密钥 |
| `app/connector-keys/<id>.key` | Electron 侧连接器密钥 |
| `connectors/skills/connector-<id>` | 已物化的连接器 Skill |

## 3. 状态文件

`connector-states.v3.json` 的业务字段包括：

```text
enabled
everConnected
userDisabled
headerOverrides
envOverrides
disabledToolsOverrides
accountIdentityKey
```

状态文件使用 AES-256-GCM，加密密钥派生使用 HKDF-SHA256。文件中还包含 salt、userIdCheck 和 keyCheck 等校验字段。

旧版明文状态存在向 v3 加密状态迁移逻辑。

## 4. 凭据文件

`.credentials.v3.json` 保存加密凭据结构和 MCP OAuth 动态客户端注册信息。实测注册结构包含：

```text
client_id
redirect_uris
```

Token Schema 的 password 值返回 UI 时被清空，只返回字段是否存在。

## 5. 生成后的 MCP 配置

市场中的目录型 MCP 配置会合并到：

```text
connectors/<profile>/mcp.json
```

正式版本次观察到 57 个生成项。未启用连接器在生成配置中标记为 disabled。CLI 和 skill-only 包不会作为普通目录型 MCP Server 直接写入该文件。

## 6. 客户端版本门控

中央索引字段 `minWorkbuddyVersion` 在注册表加载阶段比较。

WorkBuddy 5.3.5 市场索引有 74 条，其中：

- `emr-query` 要求 `5.3.10`。
- 当前客户端版本低于最低版本。
- 该条目没有进入 5.3.5 的 73 条运行时定义。

版本过滤代码在市场清单解析后、连接器包加载前执行。

## 7. 环境和套餐门控

`visible_in` 实测值包括：

```text
internal
iOA
cloudhosted
selfhosted

```

运行时 73 条定义中，有 9 条没有出现在本次个人版 UI：

```text

```

`tencent-docs-oa` 同时受 iOA 和特定套餐门控，其余主要受 iOA 门控。

## 8. 市场缓存更新

WorkBuddy 的市场更新流程包含：

1. 对市场 ZIP 执行 HEAD。
2. 比较 ETag 和本地元数据。
3. 下载 ZIP。
4. 计算 SHA-256。
5. 在文件锁内替换市场缓存。
6. 重新加载目录注册表。
7. 重新安装已启用连接器的 Skill。

检查周期约为 10 分钟。默认市场 ZIP 路径位于腾讯云 COS 的 `connectors-config-v2/connectors-config.zip`。

## 9. 市场目录与索引差异

缓存中有 78 个连接器包目录，但中央索引为 74 条。未进入当前索引的 4 个目录为：

```text
github-remote
gmail
jira
supabase
```

它们保留在缓存中，但不会通过当前市场索引进入普通连接器目录。

## 10. SQLite 的作用

本机 `workbuddy.db` 不保存连接器注册表。发现的连接器关联字段为自动化表中的 `connector_ids_json`。连接器目录和连接状态主要由市场缓存及 JSON 状态文件承载。
