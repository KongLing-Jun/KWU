# 功能全景与用户流程

## 1. 产品定位

WorkBuddy 的“连接器”不是单纯的 MCP 配置页面，而是一层面向普通用户的业务能力市场。它把 MCP URL、CLI 安装、OAuth、Token 表单、Skill 提示和运行状态包装成统一卡片。

用户看到的是“腾讯文档、飞书、Wind、GitHub”等业务名称，而不是 `command`、`args`、`headers` 和 transport。

## 2. 用户可见能力

### 2.1 市场浏览

- 连接器卡片展示图标、名称、业务描述和添加按钮。
- 支持搜索连接器。
- 连接器可以按账号环境、部署形态、套餐和客户端版本过滤。
- 已连接项投影连接状态，未连接项显示添加入口。

界面参考：[连接器市场截图](resources/assets/ui/02-连接器市场.png)。

### 2.2 连接器详情

详情面板承担以下职责：

- 解释连接器能够读取、创建或管理什么数据。
- 展示授权方式和当前状态。
- 发起连接、配置、授权、重试、解绑。
- 连接后提供“去试试”，把推荐问题带入新任务。
- 对 Token 型连接器动态生成表单。

### 2.3 自定义 MCP

WorkBuddy 把预置连接器与用户自定义 MCP 分开管理。自定义 MCP 编辑器要求根对象包含 `mcpServers`，有效服务必须至少配置 `url` 或 `command`。

```json
{
  "mcpServers": {
    "example": {
      "url": "https://example.com/mcp"
    }
  }
}
```

界面参考：[自定义 MCP 管理截图](resources/assets/ui/03-自定义MCP管理.png)。

### 2.4 任务内选择

连接器安装或授权完成后，不代表每次对话都自动使用。理想流程是：

1. 用户在输入框旁选择本次任务需要的连接器。
2. 客户端确认连接器已连接并发现工具。
3. 仅将选中连接器的工具集合加入本次 Agent 上下文。
4. Skill 为模型提供工具选择、参数和业务流程说明。
5. 执行结果回到任务时间线。

## 3. 标准用户流程

### 3.1 无授权远程 MCP

`浏览市场 → 添加 → MCP 握手 → tools/list → 保存配置 → 当前会话可用`

适用于公开只读 MCP 或不需要账号的服务。

### 3.2 Token 型 MCP

`浏览市场 → 添加 → 按 token-schema 填写 → 保存凭据引用 → 组装 header/env → MCP 握手 → 可用`

WorkBuddy 的 Token Schema 只描述字段；真实值进入凭据与状态存储，不写入市场 Schema。

### 3.3 OAuth 或服务端授权

`浏览市场 → 添加 → 打开授权页 → 回调客户端 → 轮询授权状态 → 获取凭据引用 → MCP 握手 → 可用`

OAuth 可以由 MCP 服务标准流程完成，也可以由 WorkBuddy 云端 connector gateway 完成。

### 3.4 CLI 连接器

`浏览市场 → 检查运行时 → 安装或升级 CLI → 执行 auth → status 探测 → 安装 Skill → 标记连接完成`

CLI 可能通过浏览器、二维码、Device Flow 或等待命令退出完成授权。

### 3.5 解绑

解绑不是简单断开网络连接，完整语义包括：

1. 执行 CLI `unAuth`（如有）。
2. 删除本地授权引用和连接器覆盖项。
3. 撤销服务端 Token（如支持）。
4. 从 MCP Proxy 断开。
5. 更新 `enabled`、`everConnected` 和界面状态。
6. 卸载或停用该连接器物化的 Skill。

## 4. 连接器能力与资料库的关系

腾讯文档、ima、乐享同时出现在连接器和资料库入口，说明二者不是互斥模块：

- 资料库强调“选择知识范围并检索”。
- 连接器强调“授权外部系统并获得工具”。
- 同一底层服务可以同时提供资源检索、工具调用和 Skill 流程。
