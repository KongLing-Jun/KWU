## 3. `type` 与能力文件的关系

市场 `type` 是主分类，不代表连接器只包含一种能力。实际存在：

- 纯远程 MCP。
- stdio MCP。
- MCP + Token 表单。
- MCP + Skill。
- CLI + Skill。
- CLI 预授权 + MCP。
- Skill-only。

运行时对象分别保留 `mcpConfig`、`cliConfig`、`tokenConfig` 和 `skills`。这些字段可以同时存在，市场 `type` 只表示主分类。

## 4. 主要 Transport

运行时定义中出现：

- `streamableHttp` 与 `streamable-http`
- `sse`
- `stdio`
- 未显式声明，由 MCP 客户端或 URL 规则归一化

WorkBuddy MCP 层把 `streamableHttp`、`streamable-http` 和 HTTP URL 归入 Streamable HTTP transport。

## 5. 授权类别

- 无显式授权：服务公开，或授权逻辑由 MCP/CLI 自己完成。
- Token：根据 `token-schema.json` 收集字段并注入 header/env。
- MCP OAuth：遵循 MCP OAuth 发现与回调。
- server-side：由 WorkBuddy 云端 connector gateway 管理。
- oneid-token：内部身份系统 Token。

授权模式来自中央索引、MCP 配置和 Token Schema；同一连接器还可能在连接阶段进入 CLI 预授权分支。
