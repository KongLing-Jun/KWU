# 目标范围与用户闭环

## 1. 第一版目标

Reasonix 第一版交付可直接上线的 HTTPS 远程连接器系统。用户从 Cloud 目录选择连接器后：

- 无认证连接器直接连接；
- 标准 MCP OAuth 连接器打开官方授权页；
- 第三方只提供 Token/API Key 时，用户在结构化表单一次性填写官方凭据；
- 授权后连接器进入普通 Agent 对话，完成真实工具发现和业务调用；
- 用户可以本地解绑，重启后健康授权可以恢复，OAuth Token 可以按需刷新。

用户不填写 MCP URL、任意 Header JSON、npm 命令、App Secret 或本地路径。

## 2. HTTPS 连接器准入条件

首发连接器必须同时满足：

1. 存在真实公开的 `https://` MCP endpoint。
2. transport 是 Streamable HTTP，不是 SSE、stdio 或厂商本地代理协议。
3. 不需要 Node、npm、CLI、Python、shell、localhost、本地应用或可执行文件。
4. 认证可由 `none|oauth|token` 之一表达。
5. OAuth 必须能由现有标准 MCP OAuth public-client 链路完成；需要 App Secret、云端 Token 交换或非标准 Provider 时先报告。
6. Token/API Key 只通过声明式 Header 注入；不允许放入 URL、query、path 或静态包内容。
7. endpoint、认证和能力有官方资料或真实接口证据。
8. 通过真实 `initialize`、`tools/list` 和至少一个有价值业务调用。

“所有不用环境的连接器”以 [09-HTTPS连接器准入与首发清单.md](./09-HTTPS连接器准入与首发清单.md) 中状态为 `RELEASE-REQUIRED` 的项目为封闭集合，不泛指整个市场、WorkBuddy 内部连接器或无法访问的私有服务。

## 3. 支持范围

### 3.1 Cloud

- 动态 Catalog、版本、SHA-256、不可变 OSS 对象和 current。
- 未知合法 ID 首次发布、新版本发布、下架和权威重查。
- HTTPS-only 包 validator。
- 生产环境须通过 Cloud 正式 migration runner 执行全部待执行 migration，并确认连接器 migration `00083_create_connectors.sql` 已应用；Cloud/管理前端部署和 production current 属于 `G-RELEASE`。

### 3.2 Desktop

- Cloud Catalog 动态卡片、下载、校验、安装和 active pointer。
- HTTPS Streamable HTTP MCP。
- `none|oauth|token`。
- OAuth metadata、DCR、PKCE、回调、Keyring、刷新、401 单次重试和 `invalid_grant` 回退。
- Token/API Key 最少字段表单、官方获取链接、Keyring-only 保存和声明式 Header 注入。
- 可选纯提示型 Skills，但必须与同包 MCP 同时存在，并且只能指导调用同包远程 MCP 工具。
- Windows x64 正式构建不携带或启动连接器 Node/npm/CLI/stdio 运行时。

### 3.3 Agent

- 继续复用现有 CapabilityTurn、MCP Host、Registry、审批和审计链路。
- 连接成功后注册真实 MCP 工具；断开、下架不恢复新安装，`invalid_grant` 撤销工具。
- 不新增项目级连接器继承。项目对话中现有手动选择能力保持不变。

## 4. 三种用户闭环

### 4.1 无认证

点击连接 → 下载并校验包 → initialize/tools/list → Agent 使用 → 本地解绑。

### 4.2 标准 MCP OAuth

点击连接 → 官方 metadata/DCR/PKCE → 浏览器授权 → Token 进入当前 owner Keyring → initialize/tools/list → Agent 使用 → 按需 refresh → 本地解绑。

### 4.3 官方 Token/API Key

点击连接 → 页面展示官方获取链接和厂商必需的最少字段 → 用户一次填写 → 凭据进入当前 owner Keyring → 按 `token-schema.json` 生成运行时 Header → initialize/tools/list → Agent 使用 → 本地解绑。

不得把 Token 拼接到 endpoint；前端、Catalog、包、SQLite、日志和静态 Header 都不得保存 Token 明文。

## 5. 首轮样本与排除项

- 腾讯文档：标准 MCP OAuth，继续作为 OAuth/刷新样本。
- Notion：标准 MCP OAuth，作为未知 ID 动态发布样本；生产 current 需要重新发布。
- 飞书：历史 CLI 能力保留为事实，但退出首发，不发布 production current。

明确不做：

- Node、npm、CLI、stdio、SSE、Python、shell 和 localhost 连接器。
- Skills-only 包或含脚本/二进制/本地命令说明的 Skills。
- Token URL/query/path 注入。
- Cloud MCP 代理和通用第三方 OAuth Provider 平台。
- 自动化、专家、项目级默认连接器继承。
- macOS、Linux、ARM 第一版发布。

## 6. 完成定义

完成不等于两个样本通过。第一版关闭必须满足：

1. HTTPS-only 三仓契约和实现一致。
2. 腾讯文档与 Notion完成当前代码的真实回归。
3. `09` 中所有 `RELEASE-REQUIRED` 连接器完成上架和真实验收；复杂连接器必须先经用户裁决。
4. Cloud、管理前端和正式 Windows x64 安装包部署到生产。
5. 从生产域名完成登录、Catalog、认证、Agent 调用、重启、刷新和解绑验收。
6. 生产交接、PR/merge/tag、包和安装包 Hash 写入 `08` 与提交记录。
