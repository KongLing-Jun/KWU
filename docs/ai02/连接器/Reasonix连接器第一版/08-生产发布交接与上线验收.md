# 生产发布交接与上线验收

## 1. 状态与用途

本文件是 `G-RELEASE` 唯一生产交接事实源。当前状态：**OPEN**。

历史 18080/5173、专用测试数据库、dev-fixed、243 部署前环境、`0.1.0` current 和开发构建都不能关闭本门禁。

2026-08-12，统一发布控制面已在 `192.168.10.243:5173/8080`、`reasonix_cloud` 和固定 OSS 配置下完成三个连接器联调。云平台开发人员无需再次接收一套替代配置；后续应部署这套已验收代码和运行配置，并确认本地修复进入部署 commit/产物。

窗口 10R 和窗口 12 生成的 Wails/NSIS 产物只用于验证 HTTPS-only、三连接器 RC 和无 managed Node 携带，不是干净已合并主线、正式 tag 和签名产生的发布产物，不得填写为本文件第 7 节正式安装包。

## 2. 职责分工

Reasonix 任务方负责代码、审计、分仓提交、PR/merge/tag、migration/连接器包/构建产物/Release Notes 交接；云端控制面可用后，由任务负责人登录生产管理页面发布腾讯文档、Notion和Postman production current，并继续执行生产验收。

云平台开发人员负责生产数据库备份、通过 Cloud 正式 migration runner 执行全部待执行 migration、Reasonix Cloud/nginx/管理前端部署、生产 OSS 配置，并向任务负责人提供可用的生产管理页面、管理员登录方式和部署证据。部署回执必须证明连接器 migration `00083_create_connectors.sql` 已应用；测试数据库不得复制、改名或作为生产数据库。云平台开发人员不负责选择、制作或发布连接器 production current。

## 4. Cloud migration 与配置

- 连接器 migration：`migrations/00083_create_connectors.sql`；`00081_create_workbuddy_projects_v2.sql` 属于 Project v2，不是连接器 migration。
- 由正式 migration owner 在生产数据库运行 Cloud 仓库正式入口 `go run ./cmd/migrate up`，执行全部待执行 migration；执行前备份，执行后返回 Goose 当前 version、`00083` 已应用、表/约束和服务 ready 证据。当前 Goose version 可以大于 `83`。
- 连接器发布 OSS 固定使用：
  - bucket：`kwu-cloud`
  - region：`cn-guangzhou`
  - endpoint：`https://oss-cn-guangzhou.aliyuncs.com`
  - public base：`https://kwu-cloud.oss-cn-guangzhou.aliyuncs.com`
- Cloud 代码默认值、`.env.example` 和已验收运行配置均为以上值；服务器环境必须保持一致，后续连接器继续通过同一管理 API/页面发布。
