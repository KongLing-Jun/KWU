# 阶段开发与顺序门禁

## 1. 执行原则

- 先冻结契约，再改代码，再批量上架。
- 先用腾讯文档、Notion和一个官方 Token/Header 连接器证明通用闭环，再扩充首发清单。
- 新连接器不得要求修改 Desktop/Cloud 主流程；出现协议缺口先报告。
- 功能闭环优先，禁止恢复本地运行时或建设复杂平台。
- 每个执行窗口先出方案、经审计确认后实施但不提交；总控制窗口验收、分批提交和记录。

以下是真实历史证据，不作为当前发布范围：

- 腾讯文档、飞书 CLI、Notion曾完成真实读写。
- 动态 Cloud Catalog、不可变 OSS、current、管理页面曾在 18080/5173 和专用测试数据库闭环。
- MCP Host 重启恢复和 OAuth 最小续期已经通过。

2026-08-10 因本地 Node/CLI 跨系统不稳定，方向改为 HTTPS-only。窗口 10R 已完成 Desktop 子阶段；2026-08-11 Cloud validator、测试 current、Postman Token/Header 和管理页面拒绝回归全部完成，`G-HTTPS-CORE` 与新的 HTTPS-only `G-CLOUD` 已关闭。

## 9. 禁止项

- 为赶进度恢复 Node/CLI/stdio 或使用用户系统环境。
- 把 Token 拼进 URL。
- 用 Mock、dev-fixed、直接 API 调用或手工修改状态冒充验收。
- 为连接器增加厂商 ID 主流程分支。
- 未审计脏工作区直接构建或部署生产。
- 把项目级继承、自动化、专家、macOS/Linux/ARM 混入当前阶段。
