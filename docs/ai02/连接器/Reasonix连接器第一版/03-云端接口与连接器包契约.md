# 云端接口与连接器包契约

## 1. 契约所有权

本文件是 Reasonix 第一版 HTTPS-only 连接器 wire 的最高契约。Cloud validator、Desktop parser/installer、管理前端发布流程和连接器包都必须一致。

当前继续使用 `connector.json schema_version=2`、`mcp.json schema_version=2` 和 `token-schema.json schema_version=1`；这是对现有 schema 2 的生产准入子集收窄，不复制或覆盖历史不可变对象。

## 2. 支持矩阵

| 维度 | 唯一允许值 |
| --- | --- |
| MCP transport | `streamable-http` |
| MCP URL | 绝对 `https://`，无 userinfo |
| auth | `none|oauth|token` |
| connector entrypoints | 必须 `mcp: "mcp.json"`；可选 `skills: "skills"`；不存在 token entrypoint |
| kind | 无 Skills 时 `mcp`；有 Skills 时 `composite` |
| Skills | 只允许 `skills/<name>/SKILL.md`，且只能指导同包远程 MCP 工具 |
| 平台 | 第一版发布门禁为 `windows/x64`；包可声明后续平台但不能引入平台命令 |

拒绝：`cli.json`、CLI entrypoint、stdio、SSE、skills-only、URL Token、脚本、二进制、本地路径、localhost、未引用文件和厂商私有 server-side auth。

`token-schema.json` **不是 entrypoint**。它只在 `mcp.json` 的某个 server 声明 `auth.type="token"`、`auth.schema="token-schema.json"` 时存在并被引用。`connector.json.entrypoints` 不得新增 `token` 或其他等价字段。

## 3. API

### 3.1 公开 Catalog

```http
GET /api/v1/connectors/catalog?platform=windows&architecture=x64&client_version=1.2.0
```

成功响应继续使用统一信封，包含 `catalog_version`、`generated_at`、排序且唯一的 `items`、`request_id` 和 `server_time`。每个 item 至少包含：

```json
{
  "id": "connector-id",
  "name": "Connector",
  "provider": "Provider",
  "description": "Description",
  "category": "office",
  "icon_url": null,
  "examples": ["示例"],
  "kind": "mcp",
  "version": "1.0.0",
  "min_client_version": "0.9.0",
  "compatible": true,
  "blocked_reason": null,
  "capabilities": ["remote_mcp"],
  "package": {
    "url": "https://immutable.example/package.zip",
    "size_bytes": 123,
    "sha256": "64-lowercase-hex"
  }
}
```

Cloud package URL 必须 HTTPS。Desktop 开发固定源可以使用明确端口的 `127.0.0.1` HTTP，但仍走同一个 parser、installer 和状态机。

### 3.2 管理接口

```http
GET    /api/v1/admin/connectors
POST   /api/v1/admin/connectors/{connector_id}/versions
DELETE /api/v1/admin/connectors/{connector_id}/versions/{version}
```

POST 为 multipart：

- `package`
- `version`
- `min_client_version`
- `release_notes`（可选）

首次发布和升级共用同一接口。成功发布新不可变对象并原子更新 current；DELETE 只下架精确 current，不删除 OSS 对象、不自动恢复旧版本。所有写操作后管理前端必须重新 GET 权威列表。

## 4. ZIP 通用限制

- 最大压缩包 10 MiB、最多 600 个文件、最大解压总量 30 MiB、控制文件最大 1 MiB。
- 只接受普通文件；拒绝绝对路径、`..`、反斜线、重复路径、符号链接、reparse point 和未引用根文件。
- 整包 SHA-256、大小、Catalog、对象地址和包内版本必须一致。
- 同 connector/version 不允许不同内容覆盖；每次发布使用新的不可变对象地址，校验完成后更新 current。

允许的文件树：

```text
connector.json
mcp.json
token-schema.json        # token auth 时必需，否则禁止
skills/<name>/SKILL.md   # 可选
```

## 5. connector.json

示例：

```json
{
  "schema_version": 2,
  "id": "sample-mcp",
  "version": "1.0.0",
  "name": "Sample MCP",
  "provider": "Example",
  "description": "远程 HTTPS MCP",
  "category": "office",
  "icon_url": null,
  "examples": ["读取我的数据"],
  "kind": "mcp",
  "capabilities": ["remote_mcp"],
  "min_client_version": "0.9.0",
  "platforms": [{"os": "windows", "architectures": ["x64"]}],
  "entrypoints": {"mcp": "mcp.json"}
}
```

规则：

- ID 为小写字母、数字、连字符，长度 2 至 64。
- version/min client version 使用无 `v` 的 canonical semver。
- Catalog 与包内展示元数据、kind、capabilities 必须一致。
- `entrypoints.mcp` 必须是 `mcp.json`。
- 有 Skills 时 `entrypoints.skills` 必须是 `skills`，kind 必须是 `composite`。
- `entrypoints.cli` 非空即拒绝。

## 6. mcp.json

```json
{
  "schema_version": 2,
  "servers": [{
    "id": "primary",
    "transport": "streamable-http",
    "url": "https://mcp.example.com/mcp",
    "static_headers": {"X-Client": "Reasonix"},
    "auth": {"type": "none"}
  }]
}
```

规则：

- server ID 非空且包内唯一。
- URL 必须是绝对 HTTPS，不允许模板、userinfo、Token query 或本地地址。
- `command` 必须缺失。
- `static_headers` 只允许非秘密固定协议 Header；禁止 Authorization、Cookie 以及名称包含 token、secret、api-key 的 Header。
- `none` 不得携带 scopes/resource/client_id/schema。
- `oauth` 使用现有标准 MCP metadata/DCR/PKCE；scopes 必须显式数组，resource 非空时必须与 server URL 相同。
- `token` 必须引用 `token-schema.json`，不得同时声明 scopes/resource/client_id。

## 7. token-schema.json

```json
{
  "schema_version": 1,
  "documentation_url": "https://provider.example.com/account/api-keys",
  "documentation_label": "获取官方 API Key",
  "fields": [{
    "id": "api_key",
    "label": "API Key",
    "type": "secret",
    "required": true
  }],
  "headers": [{
    "name": "Authorization",
    "template": "Bearer {api_key}"
  }]
}
```

冻结规则：

- `documentation_url` 和 `documentation_label` 必填。Cloud/Desktop 只验证 URL 是合法公网 HTTPS，不是 localhost、私网地址或含 userinfo 的 URL。
- 该链接是否确为厂商官方获取/管理页面，由连接器调研、上架审核和真实验收确认；Cloud/Desktop 不维护厂商域名白名单。
- 只定义厂商实际必需的最少字段；字段类型只允许 `text|secret`，秘密默认使用 `secret`。
- Header 模板只能引用已声明字段；至少一个 Header，Header 名唯一且合法。
- 用户值不进入连接器包、Catalog、Cloud、SQLite、普通文件、日志或前端持久状态，只进入当前 owner Keyring。
- Desktop 每次请求从 Keyring 读取并渲染 Header。
- 第一版不支持 Token 插入 URL、query、path、body、Cookie 或环境变量。

## 8. 纯提示型 Skills

- Skills 可选，但不能单独构成连接器。
- 每个 Skill 根只允许一个 `SKILL.md`；禁止脚本、资源文件、二进制和额外 Markdown。
- 内容只能解释何时、为何、怎样调用同包远程 MCP 暴露的工具。
- 不得依赖或指示执行 shell、Node、npm、Python、CLI、本地文件、localhost、应用内置运行时或可执行文件。
- Cloud 能证明结构约束；自然语言语义由离线审查、上架审核和真实验收负责，不伪装成可由 parser 完全判定。

## 9. 稳定拒绝类别

Cloud 和 Desktop 至少稳定区分：

- `unsupported_transport`
- `non_https_mcp_url`
- `unsupported_cli_entrypoint`
- `skills_only_not_allowed`
- `invalid_token_schema`
- `token_url_injection_not_allowed`
- `unsafe_package_path`
- `package_hash_mismatch`
- `client_too_old`
- `platform_unsupported`

具体错误信封继续沿用现有 `code/message/request_id`，不得把第三方响应正文或秘密写入错误。

## 10. 历史对象

历史飞书 CLI、stdio 或 Skills-only schema 2 对象不覆盖、不改写。它们可以保留在 OSS/数据库历史中，但必须撤销 current，HTTPS-only Desktop 不得安装、恢复或注册其能力。
