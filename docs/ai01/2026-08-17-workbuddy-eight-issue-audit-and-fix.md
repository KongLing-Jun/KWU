## 修复切片与验收标准

### 切片 A：创建后刷新工作空间（任务 6）

- 创建和聚合创建成功后，把权威项目详情写入当前账号的可重建缓存。
- 仅在缓存写入成功后触发项目树变更事件；失败路径不得产生幽灵节点。
- 回归测试证明不需要额外调用 `ListCloudProjects`，`ListProjectTree` 已包含新 `cloud_project`。

### 切片 B：项目会话置顶与删除（任务 7）

- 在会话 sidecar 中保存会话级 `pinned`，只允许当前精确 Cloud scope 操作。
- 云项目子会话按“置顶优先、最近活动优先”排序，并在 `ProjectNode.pinned` 回读。
- 项目会话行提供与普通对话一致的置顶/取消置顶和删除入口；删除复用现有 `DeleteSession` 回收站与运行时清理语义。
- 回归测试覆盖同项目多会话排序、持久化回读、跨账号拒绝、UI 菜单和删除刷新。

### 切片 C：无活动会话也加载默认设置（任务 8）

- 没有活动普通会话时仍加载 `Settings()`；项目 Adapter 首次创建时应用默认模型、计费来源和审批姿态。
- 已初始化草稿或已有项目会话不被后续设置刷新覆盖。
- Adapter 行为测试覆盖默认模型、计费来源、审批姿态和只初始化一次；App 合同检查覆盖无活动会话时加载设置，并保持首发准备阶段可用。

## 跨仓边界

- Cloud 的项目创建、项目自动化 `project_id` 隔离已经具备，不新增本地路径、会话置顶或设备默认权限字段。
- Admin 是只读治理界面，本轮八项问题没有需要修改的 Admin 代码。

- 任务 6：Desktop 在普通创建与聚合创建完成权威回读后写入当前账号项目缓存，并发送项目树变更事件；新项目无需等待下一轮云列表刷新即可出现在工作空间。
