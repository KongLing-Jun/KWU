# 阶段 0：基线、范围与架构决策

## 阶段目标

冻结问题定义、测量方法、数据兼容边界和待批准架构决策，避免各层独立优化后无法比较或无法安全回滚。

## 进入条件

- 以最新 `origin/main-v3` 的独立工作树作为实现基线。
- 保存实现前的 Git 状态、测试结果和性能基准环境。
- 不覆盖用户已有的未提交修改。

## 任务 0.1：建立性能问题账本

**目标**：把“慢”拆成可测量的用户动作和内部阶段。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 定义启动可交互、会话树可见、历史首屏可见、首 Token、流式平滑度等时间点。 |
| 后端功能 | 定义 `ListProjectTree`、`HistoryForTab`、保存、Provider、工具、压缩、重试和启动初始化的计时边界。 |
| 数据库 | 记录 SQLite 打开、迁移、事务等待、查询和提交耗时；区分专家、自动化、计费和未来会话目录。 |
| 测试用例 | 固定 100/300/500 会话数据集，小/中/大消息和包含图片、工具、推理、子代理的组合。 |

**验收证据**：指标字典、基准机说明、数据生成命令、原始结果和汇总报告均可复现，且不包含密钥和真实用户内容。

## 任务 0.2：冻结存储兼容契约

**目标**：明确优化不能破坏的会话事实。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 旧会话打开、继续对话、重命名、分支、删除和恢复的用户行为保持一致。 |
| 后端功能 | JSONL 继续作为正文真相；sidecar 和目录索引可丢弃重建；写入失败必须保留上一份有效正文。 |
| 数据库 | 新目录表不得成为唯一正文来源；不得存储完整 reasoning、图片 Data URL 或工具输出。 |
| 测试用例 | 覆盖旧格式、缺失 sidecar、损坏 sidecar、半写入文件、非默认 profile、全局/项目会话。 |

**验收证据**：兼容夹具在新旧路径下均可读取；索引文件删除后能从 JSONL 恢复。

## 任务 0.3：决策登记

阶段 1 数据确认后记录接受或拒绝结论；昂贵且难以逆转的后续决策仍应提升为仓库统一 ADR。

### D-01：会话正文与目录分离

- **状态**：Accepted（2026-07-29）
- **证据**：2026-07-29 最终重跑 500 会话 / 318.9 MB 基准：缺失索引时有界首响应 3 ms（64 条占位记录），后台精确修复 40.384 s，修复后 5 次目录查询 P50/P95 为 4/5 ms。索引位于独立 `.session-index` 子目录，避免 SQLite journal 污染会话目录 generation；损坏、并发增量写入遗漏和外部正文改写测试均会触发同步或后台精确修复，并从 JSONL/sidecar 重建。
- **决定候选**：JSONL 保持正文真相，SQLite 仅保存可重建目录元数据。
- **原因**：保持现有文件可读性和原子替换语义，同时消除列表页对大量 sidecar 的逐文件访问。
- **替代方案**：继续扩展 sidecar；使用一个共享 JSON 索引；将正文全部迁入 SQLite。
- **拒绝条件**：目录数据库在目标数据集上没有显著优于优化后的 sidecar 扫描。

### D-02：先 dirty generation，后决定是否增量日志

- **状态**：Accepted（2026-07-29）
- **证据**：dirty generation 回归测试覆盖无变化跳过、并发保存和失败后重试；未引入 append journal。
- **决定候选**：第一步只消除无变化重写并复用同一快照；只有大文件保存仍超预算时才引入 append journal + 周期压缩。
- **原因**：dirty generation 改动小、容易回滚，不需要立即增加崩溃恢复协议。
- **替代方案**：直接改为仅追加 JSONL；每条消息同步写入；固定时间全量保存。
- **拒绝条件**：会话在一轮内存在无法可靠纳入 generation 的原地修改。

### D-03：历史窗口化而不是静默截断

- **状态**：Accepted（2026-07-29）
- **证据**：主历史按 200 条原始消息从 JSONL 尾部反向读取，游标同时校验文件 size/mtime 或内存 generation，分页边界不拆分 assistant/tool 组；恢复、频道打开和回退入口不再传输完整历史。子代理正文按 `subagentRef` 展开后继续分页，并提供加载、失败和重试状态。
- **决定候选**：首次返回最近窗口和分页游标，旧消息及子代理正文按需加载。
- **原因**：降低 IPC 与 React 渲染成本，同时保留用户访问完整历史的能力。
- **替代方案**：始终全量传输；只保留最近消息；预生成 HTML。
- **拒绝条件**：分页无法保持消息、工具调用和父子代理引用的完整边界。

### D-04：重试采用总预算而非只限制次数

- **状态**：Accepted（2026-07-29）
- **证据**：保留最多 10 次尝试和有上限的 `Retry-After`，增加 45 秒全局 elapsed 安全预算；调用方取消优先于预算耗尽，预算覆盖连接、响应头、退避等待以及非 200 响应体读取。
- **决定候选**：保留状态码与 `Retry-After` 语义，同时增加总 elapsed budget、取消传播和可观察事件。
- **原因**：固定 10 次重试在慢请求下无法控制用户等待上限。
- **替代方案**：减少固定次数；完全取消重试；每个 Provider 单独硬编码。
- **拒绝条件**：主要 Provider 的限流恢复率明显下降。

### D-05：WAL 必须实验后决定

- **状态**：Rejected（2026-07-29，保持 rollback journal）
- **证据**：阶段 1 未发现可归因于 rollback journal 的显著锁等待；当前瓶颈是重复 open/schema/close，因此先复用 Expert 与 Automation 连接并显式关闭。
- **决定候选**：只在确认读写竞争后，对明确的 SQLite 文件单独评估 WAL；不全局启用。
- **原因**：当前普通聊天正文不在 SQLite，WAL 不是会话列表和全量保存的根因。
- **替代方案**：保持 rollback journal；全库统一 WAL。
- **拒绝条件**：没有锁等待证据，或 WAL 增加关闭、备份、网络盘兼容风险。

## 任务 0.4：安全与滥用边界

**目标**：优化不能放大本地隐私、资源耗尽或路径攻击风险。

- 巨型 JSONL、巨型图片 Data URL 和恶意深层工具参数必须有可观察的资源上限。
- 目录索引只能接受配置解析出的 profile/session 根目录；不得信任前端传入绝对路径。
- 处理符号链接、目录穿越、索引伪造和跨 workspace/session 访问。
- preview 属于潜在敏感数据；不得增加全文索引、遥测正文或外部上传。
- 回填和修复要有并发上限、取消和 I/O 预算，避免启动时形成扫描风暴。
- 磁盘满、数据库 busy、进程崩溃和杀进程后必须保留最近一次有效正文。
