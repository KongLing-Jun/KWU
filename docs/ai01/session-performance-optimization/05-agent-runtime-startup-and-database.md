# 阶段 5：Agent、启动与数据库运行时优化

## 阶段目标

缩短模型/工具多轮链路的可控开销，限制重试长尾，减少多标签启动时的重复扫描和数据库初始化。该阶段不承诺降低模型服务端本身的推理时间。

## 任务 5.1：模型、工具与压缩分段计时

**目标**：将一次回合拆为可行动的耗时段，并展示真实瓶颈。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 诊断视图展示排队、首 Token、流式、工具、重试、压缩和本地收尾；普通模式只显示必要的重试/压缩状态。 |
| 后端功能 | 在每轮 Provider 和工具调用边界记录 duration、round、status、cache usage 和取消原因；压缩的额外模型调用单独计量。 |
| 数据库 | 可复用现有计费调用标识做关联，但性能数据不得改变计费真相，也不得把同一调用重复结算。 |
| 测试用例 | 单轮、多个工具轮、并行只读工具、串行写工具、压缩、重试、取消、planner + executor 双模型。 |

## 任务 5.2：控制工具轮次与调度开销

**目标**：减少可以合并的模型往返，同时保持权限、依赖和写入顺序。

- 保留已知连续只读工具并行、写工具和未知工具串行的安全策略。
- 为可批量读取场景优先使用已有批量能力，不新增绕过审批的万能工具。
- 记录每回合 provider round 数、tool count 和可并行/实际并行数量。
- 对重复读取同一文件或元数据提供回合内只读缓存；文件写入后必须失效。
- 不通过删除工具输出、跳过验证或隐藏错误减少表面轮次。

**验收**：固定任务集的正确率不下降，工具权限事件一致；中位 provider round 数有明确改善或形成“不值得改变”的数据结论。

## 任务 5.3：重试总预算与取消

**目标**：在保留瞬时故障恢复能力的同时，控制当前固定次数重试可能形成的长尾。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 展示 attempt、最大尝试、下一次等待和累计等待；用户取消后立即进入确定终态。 |
| 后端功能 | 增加总 elapsed budget/deadline；继续尊重有上限的 `Retry-After`；所有 sleep 必须可被 context 取消。 |
| 数据库 | 计费调用和任务状态区分“未发送、已发送失败、用户取消、预算耗尽”，不得把本地重试重复记成多个用户任务。 |
| 测试用例 | 429/5xx、连接重置、超长 `Retry-After`、认证错误、流开始后断开、取消与 deadline 竞争。 |

正式默认值必须由 Provider 数据决定；不同 Provider 可配置，但要有全局安全上限和一致 UI 语义。

## 任务 5.4：启动快照与 singleflight

**目标**：并发打开多个标签页时复用相同 workspace/profile 的配置、记忆、技能和专家目录初始化结果。

1. 用配置、记忆、技能根目录和相关文件的 mtime/version 构造缓存 generation。
2. 相同 generation 的并发构建通过 singleflight 共享，只复制不可共享的 Controller/Agent 运行态。
3. 专家目录首次读取结果直接用于 system prompt，避免同一构建重复打开和扫描数据库。
4. 缓存失效必须局部化；修改一个 workspace 不清空所有 profile 的启动快照。
5. 缓存内容不能包含 API key 明文或跨 actor/profile 复用的权限状态。

## 任务 5.5：MCP/LSP 启动预算

**目标**：慢插件不阻塞整个桌面可用性。

- 保留 LSP 懒启动。
- eager MCP 在有界并发下启动，并受一个总启动预算约束。
- 超过预算的服务转后台或按需；页面明确显示 unavailable/starting/retry，而不是假装已就绪。
- 共享 host 只共享协议安全且配置相同的实例；不同 profile/权限配置不得错误复用。
- 测试挂起、立即退出、输出垃圾、超大 stderr、取消和应用关闭。

## 任务 5.6：SQLite 连接和 schema 生命周期

**目标**：减少专家和自动化模板每次操作都打开数据库、检查 schema、关闭连接的重复成本。

| 数据库 | 实施内容 |
| --- | --- |
| Expert | profile 生命周期内复用连接；schema/builtin 同步按版本执行一次；关闭 profile 时显式 close。 |
| Automation | 模板数据库复用连接，migration 幂等；保留任务 JSON 文件的现有职责，除非另有业务迁移决策。 |
| Model billing | 保留现有 `foreign_keys`、`busy_timeout`、连接池和事务规则；只增加等待与慢查询观测。 |
| Session catalog | 使用独立连接生命周期和 schema version；不与计费事务共用数据库文件。 |

### WAL 实验

仅当阶段 1 发现显著锁等待时执行 A/B：rollback journal 与 WAL 在并发读写、关闭、备份、崩溃、杀毒软件及目标 Windows 文件系统上的表现。只有收益稳定且兼容风险可控时才接受 D-05。

2026-07-29 结论：未观察到支持 WAL 的锁等待证据，D-05 拒绝，继续使用 rollback journal。本轮只复用 Expert/Automation 的 profile 生命周期连接并显式关闭，避免把连接初始化开销误判为 journal mode 问题。

## 测试矩阵

| 层级 | 必测用例 |
| --- | --- |
| Agent | provider round、工具依赖、只读并行、写串行、压缩与取消 |
| Provider | retry budget、状态码、jitter 范围、Retry-After、context cancellation |
| 启动 | 1/5/20 标签页、同/不同 workspace、配置变更、技能变更、专家变更、慢 MCP |
| 数据库 | 连接关闭、migration once、busy、并发读写、schema 失败、profile 切换 |
| 计费 | 每次 provider attempt/call/task 的计费状态与现有业务不变量一致 |
| 性能 | startup ready P50/P95、扫描次数、DB open 次数、MCP 启动总时长、内存 |
| 安全 | profile/actor 隔离、缓存密钥泄露、插件配置串用、权限事件不被缓存绕过 |

## 回滚方案

- retry budget、启动快照、eager MCP 策略和持久 DB 连接分别受独立开关控制。
- 缓存异常时清除内存快照并执行当前完整构建路径。
- WAL 若采用，必须提供检查点与回退说明，确认没有活跃连接后再切换 journal mode。
- 任何优化不得修改已经生成的计费事实；计费回归时整个切片回滚。

## 阶段退出门禁

- [ ] 真实回合能区分本地、Provider、工具、压缩和重试时间。
- [ ] 重试总预算和取消在所有 Provider 适配器中语义一致。
- [ ] 多标签启动重复扫描和 DB open 次数显著下降，并达到冻结预算。
- [ ] 慢 MCP 不再阻塞核心会话页面可用。
- [ ] SQLite 生命周期、计费不变量和 profile 隔离测试全部通过。
