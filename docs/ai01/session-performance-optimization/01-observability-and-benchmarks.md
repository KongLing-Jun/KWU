# 阶段 1：可观测性与性能基准

## 阶段目标

建立低开销、默认不采集正文的本地性能观测，并把当前手工基准升级为可重复的后端、前端、数据库和端到端性能门禁。

## 任务 1.1：定义统一事件与关联标识

**目标**：一次用户提交可以贯穿前端、Controller、Agent、Provider、工具和存储进行关联。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 记录 `submit -> optimistic bubble -> backend accepted -> first delta -> final`；开发模式提供性能诊断面板或导出入口。 |
| 后端功能 | 引入 turn/request correlation ID，记录队列、编排、Provider 首包/总耗时、每轮工具、压缩、重试、保存耗时和字节数。 |
| 数据库 | 仅记录聚合耗时、等待和行数；默认不落库保存 prompt、response、reasoning 或工具正文。 |
| 测试用例 | 验证事件顺序、取消传播、重试多轮关联、并发标签页隔离以及敏感字段不出现在导出中。 |

**建议指标**：`session_list_ms`、`history_load_ms/bytes/items`、`save_ms/bytes/reason`、`provider_ttfb_ms`、`provider_total_ms`、`tool_ms`、`retry_sleep_ms`、`compaction_ms`、`react_commits`。

## 任务 1.2：后端与文件系统基准

**目标**：量化会话数量、总字节、消息数量和 sidecar 数量对列表、恢复、保存的影响。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 无产品页面改动；只准备调用列表与历史 API 的性能夹具。 |
| 后端功能 | 为 `ListSessionOrder`、`ListSessions`、`HistoryForTab`、`Session.Save` 和子代理历史加载建立 benchmark。 |
| 数据库 | 阶段 2 原型完成后增加 SQLite 目录查询和回填 benchmark，使用同一数据集对照。 |
| 测试用例 | 每个规模至少多轮执行，输出 P50/P95、分配量、文件打开数、读取/写入字节和冷/热差异。 |

数据集至少包含：空目录、100/300/500/1000 会话、损坏 sidecar、缺失 sidecar、100 MB 单会话、大量小消息、图片、子代理和清理待办状态。

## 任务 1.3：前端渲染与流式基准

**目标**：定位 IPC 数据量、reducer 次数和 React commit 次数，而不是只观察主观卡顿。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 使用 React Profiler 或测试探针记录 100/1000/5000 items 的首次渲染、滚动、Markdown、工具卡片和连续 delta。 |
| 后端功能 | 提供确定性历史和事件夹具，避免真实 Provider 抖动污染前端基准。 |
| 数据库 | 无结构变更。 |
| 测试用例 | 模拟每秒不同 delta 数、前后台标签页、切换会话、取消、重试提示和子代理展开。 |

## 任务 1.4：真实端到端基线

**目标**：在隔离 profile 和独立端口下验证真实桌面运行，并区分本地开销与 Provider 网络耗时。

1. 启动 Wails + Vite + 嵌入式 SQLite。
2. 验证监听端口、HTTP 200、桌面进程路径和 profile 数据文件。
3. 使用本地确定性 Provider 测本地开销；有授权时再用真实 Provider 测 TTFB 和长尾。
4. 保存屏幕录制、性能导出和原始结果；测试后只关闭目标工作树进程树。

## 性能预算冻结

阶段结束时应把建议阈值替换为基准机上的正式预算：

| 指标 | 建议预算 |
| --- | --- |
| 500 会话热列表 P95 | ≤ 500 ms 且改善 ≥ 80% |
| 会话列表主线程长任务 | 不出现 > 50 ms 的连续阻塞 |
| 未变化自动保存正文写入 | 0 次、0 字节 |
| 首屏历史传输 | 只包含窗口内数据，大小随窗口而非总历史增长 |
| 同一流事件 reducer 更新 | 每逻辑 key 每帧 ≤ 1 次 |
| 新增观测开销 | 关闭时近零；开启时 P95 增幅 ≤ 3% |

## 阶段退出门禁

- [ ] 基准可由单条文档化命令生成，并能清理自己的临时数据。
- [ ] 至少连续运行 5 次，记录 P50/P95 而非只记录最快值。
- [ ] 测试结果能区分前端、IPC、Go、文件、SQLite、Provider 和工具耗时。
- [ ] 遥测不包含 prompt、response、reasoning、密钥或本机绝对路径。
- [ ] D-01～D-05 已根据数据接受、调整或拒绝。
