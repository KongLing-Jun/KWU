# 阶段 3：会话持久化优化

## 阶段目标

先消除未变化会话的重复全量写入和重复快照，再根据测量结果决定是否引入增量日志。任何优化都必须保留崩溃安全、完整历史和旧版本可读性。

## 任务 3.1：引入会话 generation/dirty 契约

**目标**：所有可持久化修改都能被一个单调递增 generation 追踪。

| 方面 | 实施内容 |
| --- | --- |
| 前端页面 | 无用户行为变化；诊断模式可显示最近保存时间、原因和失败状态。 |
| 后端功能 | `Add`、`Replace`、压缩、历史规范化、分支/元数据变化等统一更新 generation；成功保存后记录 persisted generation。 |
| 数据库 | 若阶段 2 已启用目录表，同一 persisted generation 写入 `content_generation`；不得提前标记未落盘内容。 |
| 测试用例 | 覆盖每种 mutation、并发 snapshot、保存期间新增消息、失败重试和 generation 溢出边界设计。 |

关键不变量：`persisted_generation <= current_generation`；保存旧快照成功不能把随后新增的消息错误标记为已持久化。

## 任务 3.2：自动保存只保存脏会话

**目标**：长时间等待 Provider 流式结果时，如果完整助手消息尚未加入 session，不重复写相同 JSONL。

1. autosave tick 先比较 generation，不脏则直接返回。
2. 一次 `Snapshot` 同时用于 JSONL 编码、preview 和 turn count，避免保存后再次复制消息。
3. 保存成功后以 compare-and-mark 更新 persisted generation；若期间发生新写，保持 dirty。
4. 结束回合、关闭窗口、新建会话等强制保存路径仍遵守同一一致性协议。
5. 保存失败必须向运行状态和日志暴露，后续周期重试；不得静默清除 dirty。

## 任务 3.3：优化编码与写入路径

**目标**：减少不必要的分配、重复序列化和磁盘写放大。

- 保留临时文件 + 原子替换，临时文件必须与目标同目录。
- 记录编码、flush/sync、replace 和 sidecar/目录更新的独立耗时。
- 设定巨型单消息和图片会话的性能夹具；不得通过丢弃字段提速。
- Windows replace、杀进程、杀电源模拟、杀毒软件占用和磁盘满应有明确失败语义。
- preview/turn count 由同一快照计算并传给目录更新，不重新读取刚写入文件。

## 任务 3.4：增量 journal 探索性切片

**目标**：只有任务 3.1～3.3 后大文件保存仍超过预算时，验证增量日志是否值得增加复杂度。

探索原型必须回答：

- append 单条消息后怎样验证完整性并识别部分尾行？
- `Replace`、压缩和历史规范化不是 append 时如何表达？
- 何时 compact，compact 失败或崩溃怎样回到上一个有效状态？
- 旧版本能否读取；是否需要基线 JSONL + journal 两文件协议？
- 多进程或旧版本共享 profile 时如何防止互相覆盖？

**决策门槛**：相对 dirty + 单快照方案，100 MB 会话新增一个普通回合的 P95 保存耗时或写入字节至少改善 50%，且恢复复杂度有充分故障测试。未达门槛则拒绝该方案。

## 测试矩阵

| 层级 | 必测用例 |
| --- | --- |
| 单元 | dirty 状态机、generation compare-and-mark、单快照 preview/turn count |
| 并发 | autosave 与 Agent Add、压缩 Replace、关闭窗口、切换会话并发 |
| 文件 | 临时文件失败、replace 失败、磁盘满、尾部损坏、权限拒绝、恢复旧文件 |
| 兼容 | 旧 JSONL、旧 sidecar、非默认 profile、旧版本回读 |
| 性能 | 未变化 tick、1/10/100 MB 会话、图片/推理/工具组合，记录写入字节和分配 |
| 集成 | 保存成功后目录一致；目录失败时正文有效并能修复 |

## 回滚方案

- dirty 优化可通过进程环境变量 `KWU_DISABLE_DIRTY_AUTOSAVE=1` 退回当前全量 autosave；重启进程后生效。
- 目录更新失败不影响正文；目录可重建。
- journal 若进入灰度，必须支持先 compact 回单一 JSONL 再关闭功能。
- 不删除旧 sidecar，直到跨版本兼容窗口关闭。

## 阶段退出门禁

- [ ] 未变化 autosave 产生 0 次正文写入。
- [ ] 保存期间新增消息不会被错误标记为已保存。
- [ ] 一次保存只创建一次消息快照。
- [ ] 故障注入后至少保留上一份完整会话，并能给用户明确错误。
- [ ] 是否采用 journal 有量化决策记录；“暂不采用”也是允许结果。
