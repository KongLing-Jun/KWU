先看结论

Reasonix 不是单一网页应用，而是“本地智能工作台 + 云端业务平台 + 管理运营台”组成的多入口 Agent 产品。

3

三个产品边界

Desktop 承载执行体验；Cloud 承载跨设备权威业务；Admin 承载运营控制与只读治理。

6+

六类运行入口

桌面 UI、CLI、HTTP/SSE、ACP、IM Bot、自动化任务，共享同一 Agent 核心。

Local-first

本地优先

工作区、会话正文、Git、个人配置和多数运行状态保留在用户设备。

Cloud-authority

云端权威

账号、订阅积分、目录、项目协作、媒体任务、发布与审计以 Cloud 为准。

CONFIRMED

邀请协作同步的真实含义

被邀请者加入同一个 CloudProject 后，可以读取/修改其权限允许的工作项、标签、活动和资产元数据；这不是两个账号的全量数据镜像，也不会同步本地工作区、个人会话、个人模型密钥或本地计划任务。

CONFIRMED

资产存储

项目资产二进制对象进入私有 OSS，对象关系与状态写入 PostgreSQL，下载通过短时签名 URL；本地工作区文件不因此自动上传。详见 项目业务全流程专题。

01

产品整体结构

入口层统一进入 Desktop 的适配器和本地运行核心；只有需要身份、共享、目录、计费或异步恢复的业务才进入 Cloud。Admin 不绕过 Cloud 直接改数据库。

本地内部调用核心执行链云 API异步恢复/治理

Desktop 技术栈

Go 1.25/1.26 toolchain，Wails v2，React 19，TypeScript 6，Vite 8，Zustand，TanStack Virtual。

Cloud 技术栈

Go 1.26.4，Gin，pgx/GORM，PostgreSQL，Redis，Aliyun OSS，Goose 迁移；Server 与 Worker 分进程。

Admin 技术栈

Vue 3.5，Vite 5，TypeScript，Naive UI，Pinia，Alova；路由元数据和 Cloud Admin API 双重约束。

02

端到端业务价值流

从首次使用到持续运营的主链。每一步都标明主要数据落点，避免把“功能页面”误解成“业务完成”。

关键边界：不登录也可使用本地能力（取决于模型/提供商配置），但跨设备账号、订阅、云目录、项目协作和云端媒体等业务需要 Cloud；“本地执行成功”与“云端业务完成”是两种不同完成态。
03

一次 Agent 请求如何完成

Desktop UI、CLI、HTTP、ACP、Bot 和自动化的外层协议不同，核心都收敛到 Controller/Agent。审批是执行路径的一部分，不是界面装饰。

04

模型、专家、Skill、MCP、Connector 的供应链

能力不是运行时临时拼凑：发布、发现、安装、配置、会话快照、调用和审计形成一条可追踪的数据流。

LOCAL

个人配置

模型密钥、MCP 信任、Skill 启用、专家偏好等主要落在本地配置/数据库，不随项目成员共享。

CLOUD CATALOG

公共目录

专家、Skill、Connector、MCP 可由 Cloud 发布/下架，Desktop 拉取后形成可安装目录。

CONFIG GATED

可用不等于可执行

目录可见只代表可发现；真实调用仍依赖提供商凭证、OAuth、可执行产物、权限和网络策略。

05

订阅、支付、积分与模型用量闭环

购买链与用量结算链相互关联但不是同一事务。Cloud Worker 为支付轮询、授权补偿、冻结超时和结算恢复提供最终一致性。

06

数据归属、同步与存储

“能在 Desktop 看见”不代表“存储在 Desktop”；“加入项目”也不代表同步全部用户数据。下图以权威来源划分，而不是以页面位置划分。

数据域权威位置介质/方式共享或同步边界
工作区、文件、Git用户设备本地文件系统与 Git默认不上传、不随项目邀请同步
会话正文与事件用户设备JSONL + sidecar；SQLite 目录索引个人本地会话；项目任务只建立业务关联，不等于共享全文
专家/自动化/模型运行索引用户设备多个专用 SQLite；配置 TOML/JSON/.env按本地 profile；敏感凭证不作为项目数据暴露

07

运营治理与后台恢复

Admin 是 Cloud 的控制面：受角色/权限保护，通过 API 发出命令或查询；Worker 对跨事务、外部回调和超时状态进行恢复。项目治理在当前实现中刻意保持只读。

部署注意：scripts/reasonix-dev.ps1 的集成开发路径会启动 Cloud Server、Admin Vite 和 Wails Desktop，但不会同时启动独立的 cmd/worker。涉及支付轮询、结算恢复、项目资产清理、媒体恢复等流程时，必须把 Worker 视为单独运行进程。
