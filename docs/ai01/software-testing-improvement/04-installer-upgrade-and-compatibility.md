# Phase 4：安装、升级与兼容性

## Goal

证明 Reasonix 在合同支持的政企终端环境中可安装、可升级、可卸载、可回滚，并且用户数据、注册表、快捷方式和更新来源符合预期。

## 当前基础

项目已经具备：

- NSIS Windows 安装器与中文字符串。
- Windows amd64/arm64 构建和真实 payload 架构校验。
- 注册表安装位置识别、便携版更新和中文/空格路径相关单元测试。
- 更新 manifest、Minisign 签名校验、下载与平台选择测试。
- Draft 构建与 Publish 人工确认分离。

本阶段不是重做发布系统，而是补齐现场验收矩阵。

## Task 4.1：全新安装矩阵

**Goal**：覆盖现场最常见的失败条件。

至少包括：

- 普通用户和管理员；标准目录、受限目录、中文及空格路径。
- amd64 和 arm64 对应机器/VM，不只检查 PE header。
- 无网络、代理、自定义 CA、DNS 失败。
- WebView2 已安装、缺失、损坏和版本不满足。
- 磁盘空间不足、安装中断、重启和重复运行安装器。
- 杀毒/EDR/应用白名单告警与申诉证据。
- 首次启动 profile、日志、SQLite、快捷方式和卸载项。

## Task 4.2：升级与回滚矩阵

**Goal**：证明 N-2/N-1 到 N 的升级不会损坏数据，失败时可恢复。

版本组合由真实发布历史决定，至少验证：

- 已安装版和便携版分别升级。
- 保留安装目录、用户配置、会话、数据库和自定义模型设置。
- 旧产品名/注册表项迁移。
- 下载中断、签名错误、安装中断、应用未退出和文件锁。
- 更新后首次启动失败时的诊断与人工回滚。
- 降级策略：明确允许、拒绝或只允许备份恢复，不做隐式兼容承诺。

每个迁移必须提供前置数据集、预期 schema、备份和恢复证据。

## Task 4.3：卸载与数据处置

**Goal**：满足政企对数据留存与清理的明确要求。

验证：

- 程序文件、快捷方式、注册表和自启动项清理。
- 用户数据默认保留还是删除必须由产品策略决定，并在 UI/文档明确。
- 静默卸载、重复卸载和卸载中断。
- 多用户机器上不删除其他用户数据。
- 日志、缓存、模型凭据和崩溃包的残留检查。

高敏场景如需安全擦除，应单独评估文件系统和 SSD 限制，不能简单声称普通删除等于不可恢复。

## Task 4.4：操作系统与终端策略

- Windows 版本、Server、ARM64 是否 required，由支持政策和合同决定。
- DPI、缩放、多显示器、远程桌面、锁屏、休眠/唤醒按客户使用方式纳入。
- 国产操作系统不得仅靠编译通过宣称支持；需要 Wails WebView、系统托盘、文件对话框、安装包、签名和真实业务链路的目标机验证。
- 使用 VM 快照执行可重复安装矩阵；EDR、驱动和硬件相关问题保留真实机器测试。

## Task 4.5：自动化边界

- PowerShell/Pester 优先验证进程、文件、注册表、服务、签名和安装退出码。
- UIA 工具只覆盖安装器窗口、系统对话框和少量原生 smoke。
- 截图识别不作为关键发布门禁。
- 每次测试保存 OS build、架构、权限、WebView2 版本、安装器 SHA-256、退出码和日志。

## 阶段退出门

- [ ] 支持矩阵中的每个 Windows/架构组合有执行证据。
- [ ] N-2/N-1 升级、失败中断和回滚策略经过验证。
- [ ] 普通用户、中文路径、离线/代理和 EDR 场景有结论。
- [ ] 卸载后的数据保留/清理行为与产品策略一致。
- [ ] 便携版与安装版结果分别报告。
