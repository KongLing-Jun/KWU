# ADR-0002：专家目录区分官方与用户数据并同步内置目录

## Status

Accepted

## Date

2026-07-30

## Context

早期设计把 SQLite 中已存在的 `experts` 表视为完全权威，既不回填空表，也不同步新版内置专家。这会使安装升级后的官方目录长期停留在旧版本，同时官方定义和用户自建定义缺少清晰的所有权边界。

## Decision

专家 Store 使用 SQLite 持久化目录，并通过 `source` 区分官方定义与用户定义：

- 表不存在时创建并写入当前内置目录；
- 旧表迁移到当前 schema；
- 空表重新写入内置目录；
- 初始化时按 ID 同步当前内置定义；
- 官方 ID 只读，用户保存不能覆盖；
- 官方目录整体替换时保留用户定义；
- 删除用户数据只删除 `source=user` 的定义；
- 需要长生命周期复用时使用持久连接，并显式 `Close`。

## Alternatives Considered

### 已存在的表完全权威

不会触碰本地数据，但无法向已有安装分发新增或修正的官方专家，且空表会永久显示为空，因此不采用。

### 每次启动重建整张表

能保证官方目录最新，但会删除用户自建专家，因此不采用。

### 官方与用户分别使用两套数据库

隔离更强，但增加查询合并、迁移和事务复杂度；当前 `source` 边界已经能满足只读官方目录与可变用户目录的需求，因此不采用。

## Consequences

- 内置专家的 ID 是稳定身份，变更 ID 等同于新增/移除目录项。
- 官方同步和远端官方目录替换必须保持用户行不变。
- 用户定义迁移失败会阻止目录初始化，避免静默截断或丢失。
- 旧的“已有表不回填、不覆盖、不同步”设计不再代表当前行为。
