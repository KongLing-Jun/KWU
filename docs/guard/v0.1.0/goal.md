# 代码守卫 v0.1.0 总计划

## 1. 当前问题

当前仓库已有代码体量与复杂度检查，但门禁链路仍存在以下问题：

- Code Guard 未直接进入 GitHub CI；
- 普通检查可能自动收紧并写回 baseline；
- CI 尚未用基础分支 baseline 做可靠增量比较；
- `desktop/` Go 模块和 Frontend 未完整进入统一守卫；
- Frontend 主 CI 未执行完整 `test:all`；
- 覆盖率只有报告，没有失败阈值；
- 尚未识别占位实现、构建遗漏和注册链路遗漏；
- 尚未识别 AI 生成代码的碎片化、机械包装和复制粘贴；
- 本地 Hook 可绕过且当前 clone 未启用；
- 484 条历史 debt 尚未形成持续收敛的统一治理链路。

## 2. 建设背景

AI 生成代码能够快速增加功能，也容易产生“局部看似完成、整体没有接入”“为了降行数机械拆分”“复制已有逻辑”“缺少验证”等问题。单纯限制行数或复杂度无法保证代码可用，必须把结构指标、实现完整性、构建测试、增量覆盖率和历史 debt 治理组合起来。

## 3. 总目标

v0.1.0 建成后，应对新增代码形成以下闭环：

```text
变更识别
  → 结构与完整性扫描
  → 基础分支 baseline 比较
  → Root/Desktop/Frontend 验证
  → 覆盖率与启发式报告
  → 豁免校验
  → 本地反馈与 CI 最终结论
  → debt 趋势更新
```

最终目标不是让所有代码都变短，而是保证新增代码可编译、可测试、进入运行链路、职责清晰，并且没有通过碎片化或复制规避质量要求。

## 4. 核心原则

1. 增量硬门禁，不一次性清理历史债务。
2. 明确不可用的问题直接 `error`。
3. 启发式问题先 `warning`，误报稳定后再升级。
4. 历史问题标记为 `debt`，只允许保持或下降。
5. 检查默认只读，baseline 更新必须显式。
6. 本地用于反馈，CI 用于最终裁决。
7. 一个规则只保留一个实现和一个权威入口。
8. 规则输出必须可定位、可解释、可修复。
9. 豁免最小化、可追踪、会过期。
10. 不允许为通过指标制造新的结构问题。

详细边界见 `docs/guard/v0.1.0/实现边界.md`。

### 5.2 当前扫描范围

- `internal/`
- `cmd/`
- `scripts/`
- `tools/`
- 生产 Go 文件

### 5.3 当前自动化

- Makefile 提供 `code-guard` 和 `pr-ready`；
- `.githooks/pre-push` 当前只执行 `go vet ./...`；
- GitHub CI 已执行格式、vet、build、test、race、lint 和覆盖率报告；
- Frontend 已提供 `test:all`，但主 CI 尚未执行。

### 5.4 当前过渡期 PR 门禁

在阶段 1 完成前，打开或更新 PR 必须按以下顺序执行：

1. 先同步最新 `main-v3` 并解决冲突；
2. 再依次执行：

```sh
go run ./scripts/code_guard
git ls-files --error-unmatch scripts/code_guard_baseline.json
git diff --exit-code -- scripts/code_guard_baseline.json
git diff --cached --exit-code -- scripts/code_guard_baseline.json
go vet ./...
go test ./...
```

3. 任一命令失败，不得打开或更新 PR。

`make pr-ready` 只是上述六项检查的可选快捷入口，不负责同步 `main-v3` 或解决冲突。当前全量 Code Guard 在历史 finding 改善时仍可能自动收紧并写回 baseline；后续工作区和暂存区 `git diff` 检查会因此失败，使流程保持失败关闭，但不能把当前实现描述为“默认完全只读”。默认只读、显式更新 baseline 是 v0.1.0 的目标态，由阶段 1 实现。

## 7. 整体守卫分类

| 分类 | 主要职责 |
|---|---|
| 结构复杂度 | 有效行、复杂度、嵌套、参数数、包文件数 |
| 实现完整性 | 占位、空实现、构建图、注册和配置生效链路 |
| 碎片代码 | 一函数一文件、纯转发、小文件集中新增 |
| 重复代码 | 新增复制块、机械包装、重复实现 |
| 编译与测试 | build、vet、test、race、lint、Frontend test:all |
| 覆盖率 | 变更行、包回退、高风险代码阈值 |
| Baseline/豁免 | 增量比较、显式更新、到期治理 |
| 趋势治理 | debt 数量、热点、误报、豁免和覆盖率趋势 |

## 8. 总体架构和职责划分

v0.1.0 继续使用 `scripts/code_guard` 作为统一代码度量入口。随着规则增加，内部按职责拆分，但不建立多个互相矛盾的命令：

- 扫描层：读取 Go/Frontend 和变更范围，生成统一 finding；
- 规则层：实现结构、完整性、碎片和重复规则；
- 比较层：区分新增、恶化、改善、消失和 debt；
- 治理层：校验 baseline、豁免及到期时间；
- 报告层：输出人读文本和机器可读 JSON；
- 编排层：Makefile、本地 Hook 和 CI 只调用统一入口。

Frontend 优先复用现有 `tsc`、Vite 和测试脚本，不为 v0.1.0 首轮重新实现 TypeScript 编译器。

## 9. 阶段顺序与依赖关系

```text
阶段 0：规则定稿与现状确认
  ↓ 规则、阈值、范围和治理语义冻结
阶段 1：可靠 CI 增量门禁
  ↓ 只读比较、跨模块验证和报告稳定
阶段 2：结构与实现完整性
  ↓ 确定性新代码问题被阻止
阶段 3：碎片、重复与覆盖率
  ↓ 启发式规则误报可控、覆盖率可比较
阶段 4：历史 debt 收敛
```

每个阶段必须满足自己的完成定义，才能将下一阶段规则升级为硬门禁。

硬门禁按阶段累积生效：后续阶段必须继续执行所有前序阶段门禁。各阶段 `硬门禁` 章节只列本阶段新增或收紧的项目，除非章节明确声明为完整清单。

## 10. 各阶段摘要

| 阶段 | 解决的问题 | 核心结果 |
|---|---|---|
| 0 | 标准不统一、边界不清 | 冻结规则、阈值、范围、baseline、豁免和现状报告 |
| 1 | Code Guard 可绕过、会写 baseline、模块覆盖不完整 | 只读 CI 增量门禁和统一本地入口 |
| 2 | AI 代码过长、复杂、占位、未接入 | 新增结构 error/warning 与完整性门禁 |
| 3 | 一函数一文件、复制、覆盖不足 | 碎片/重复观察与变更覆盖率门禁 |
| 4 | 484 条历史 debt 长期不下降 | 趋势报告和分批收敛机制 |

## 11. 总体开发建议

- 优先复用 Go 标准库、现有 AST 和现有测试基础设施；
- 不引入生产依赖，分析依赖必须说明必要性和维护成本；
- 每条规则先写正例、反例、baseline、豁免和跨平台测试；
- 确定性规则与启发式规则分开实现；
- 所有比较使用稳定 key，不依赖单独行号；
- 规则应支持局部扫描和全量扫描；
- 默认命令不得产生文件修改；
- 报告必须解释实际值、阈值和修复方向；
- 结构治理按职责和调用链拆分，不按数字机械切割；
- 改动 Makefile、Hook 或 CI 时保持一个权威命令，避免逻辑复制。

## 12. Baseline 治理策略

- 当前 484 条作为 Root Go v0.1.0 起始 debt；
- Desktop Go 和后续稳定规则建立独立、可追踪的起始快照；
- 普通检查只比较，不写入；
- 基础分支 baseline 是 PR 比较基准；
- 新增和恶化为 error；
- 改善和删除允许，但通过显式命令更新；
- 显式更新前必须完成只读比较；存在新增或恶化时拒绝更新，只允许写入已经确认的改善和消失；
- 格式错误、重复 key、未知版本和阈值漂移为 error；
- baseline diff 必须独立评审，不能混在自动检查副作用里。

## 13. 豁免治理策略

豁免至少记录规则、文件/符号、原因、负责人、创建日期和到期时间。CI 必须：

- 拒绝字段不完整的豁免；
- 拒绝已经过期的豁免；
- 在报告中展示生效和即将到期的豁免；
- 不允许宽泛目录级永久豁免；
- 不允许豁免编译失败、baseline 隐式写入或 baseline 损坏。

## 14. 本地与 CI 总体触发策略

### 本地快速检查

- 针对变更文件和受影响包；
- 执行只读 Code Guard、格式、vet/typecheck 和聚焦测试；
- 目标是快速反馈，不代替全量检查。

### 完整 PR Ready

- Root Go：Code Guard、baseline 洁净、`gofmt` 洁净、vet、build、test、race、lint；
- Desktop Go：格式、tidy 洁净、vet、lint、build、test；
- Frontend：install 锁定、build、typecheck、`test:all`；
- 与 CI 使用同一配置。

### pre-push

- 可选安装；
- 调用统一快速或完整入口；
- 不复制守卫规则；
- 可被绕过，因此不能替代 CI。

### CI

- 对目标主分支的 push 和 PR 执行；
- 从基础分支获取 baseline；
- 默认只读；
- 保存机器可读报告和必要的趋势数据；
- 任何本地状态都不能改变最终结论。

## 15. 总体失败输出

每条 finding 至少包含：

- 结果等级：`error`、`warning` 或 `debt`；
- 规则 ID 和规则名称；
- 文件、行号和符号；
- 基础分支值、当前值和阈值；
- 分类使用机器值 `new`、`worsened`、`improved`、`resolved`、`debt`，人读报告分别显示新增、恶化、改善、消失、历史保持；
- 简短原因；
- 可执行修复建议；
- 命中的豁免及到期时间。

CI 汇总另行显示各分类和等级的数量及最终退出结论。文本输出面向开发者，JSON 输出面向 CI、趋势报告和后续工具。

`severity` 与 `classification` 是两个字段：`severity` 表示 `error`、`warning` 或 `debt` 的处理等级；`classification=debt` 只表示同 key、同值的历史保持项，此时 `severity` 必须为 `debt`。

## 16. 总体测试策略

每条规则至少覆盖：

- 阈值以下通过；
- warning 边界；
- error 边界；
- 新增、恶化、改善、消失；
- baseline 缺失、损坏、重复和版本不兼容；
- 合法豁免、过期豁免和越界豁免；
- 生成代码、测试代码和平台文件排除；
- Windows、macOS、Linux 路径和换行差异；
- 文本与 JSON 输出一致；
- 检查前后 baseline 不变。

集成验证覆盖 Root Go、Desktop Go、Frontend 和 CI 命令组合。

## 17. 总体交付物

- 规则与边界说明；
- 只读 Code Guard 和显式 baseline 更新方式；
- 基础分支增量比较；
- Root/Desktop/Frontend 统一入口；
- 结构与完整性规则；
- 碎片、重复和覆盖率规则；
- baseline 与豁免治理；
- 文本和 JSON 报告；
- 单元、集成、跨平台和夜间检查；
- debt 趋势报告与治理批次。

## 18. 总体验收标准

- 新增和恶化问题能够稳定阻止；
- 当前 484 条历史问题不会一次性阻塞开发；
- 检查过程不修改 baseline；
- Root、Desktop、Frontend 都有明确验证链路；
- Frontend `test:all` 进入最终门禁；
- 确定性占位和接入遗漏能够被识别；
- 启发式规则升级前有误报证据；
- 本地完整检查与 CI 结论一致；
- 绕过本地 Hook 仍无法绕过 CI；
- 报告能够定位并解释每个问题；
- debt 和豁免能够持续统计。

## 19. 整体质量指标

- 新增结构违规为 0；
- Root/Desktop Go 新增函数有效行数 P95 不超过 40；
- 碎片候选占新增生产文件比例低于 20%；
- 普通变更行覆盖率不低于 70%；
- 高风险代码变更行覆盖率不低于 85%；
- 历史包覆盖率下降不超过 2 个百分点；
- baseline 总量持续下降；
- 守卫误报率低于 5%；
- AI 生成代码一次通过编译、测试和注册链路检查；
- 不出现通过机械拆分、聚合或复制规避指标的变更。

## 20. 风险和注意事项

- 结构指标不能单独证明功能错误；
- 调用方和注册链路存在反射、插件和外部 API 误报风险；
- 覆盖率不能替代测试质量；
- 过早硬化碎片和重复规则会诱导指标博弈；
- CI 时间增长需要通过局部检查、缓存和夜间任务分层控制；
- 跨模块 baseline 必须防止 key 冲突；
- 本地 Hook 的平台兼容性不能依赖 Bash-only 实现；
- 历史治理不能与高风险业务修改混在同一批次。

## 21. 完成定义

代码守卫 v0.1.0 只有在以下条件全部满足时完成：

1. 阶段 0–4 的完成定义均已满足。
2. 所有硬门禁已进入 CI，且默认检查只读。
3. Root Go、Desktop Go、Frontend 的规定验证均由统一入口执行。
4. 新增结构问题、确定性不完整实现和覆盖率不足能够被正确分类。
5. 初始 Root Go 484 条 debt cohort 及后续新增 cohort 均可追踪、不恶化并开始下降。
6. Warning 的误报统计和升级机制已运行。
7. 豁免可追踪、会过期并进入报告。
8. 本地与 CI 结果一致，绕过本地 Hook 不影响 CI 门禁。
9. 全套守卫测试、仓库验证和跨平台检查通过。
10. 没有通过指标规避方式制造新的维护债务。
