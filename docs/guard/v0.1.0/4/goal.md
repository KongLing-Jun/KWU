# 阶段 4：历史债务收敛与趋势治理

## 1. 阶段名称

历史债务收敛与趋势治理。

## 2. 阶段背景

阶段 1–3 控制新增违规后，规划起点的 484 条 Root Go 复杂度、体量、嵌套和包文件数量问题构成初始 debt cohort；阶段 2–3 还会为新增规则和其他模块建立独立 cohort 或趋势快照。阶段 4 以阶段 3 完成时的实际 cohort 集合为准分批治理，并同时防止通过机械拆文件、包装函数或复制代码让单一指标下降、整体质量恶化。

## 3. 当前问题

- 初始 Root Go 484 条 debt 中的高风险热点集中在高修改频率核心区域；
- `internal/control/controller.go` 等文件远超体量阈值；
- `internal/boot/boot.go:Build` 等函数同时命中体量、复杂度和嵌套；
- `internal/cli` 同时存在复杂度热点和 56/30 包文件数超限；
- 历史问题只有静态快照，尚无稳定趋势和治理批次；
- 单项拆分可能制造新的碎片、重复和测试风险；
- 豁免可能长期存在而不收敛。

## 4. 阶段目标

建立 baseline、碎片、重复、覆盖率和豁免的周期性趋势报告，按风险和职责分批降低历史 debt，并证明每次治理行为不变、测试充分且没有指标规避。

## 5. 非目标

- 不一次性清零 484 条 debt；
- 不以降低数字为唯一目标；
- 不把历史治理和大型业务功能混在同一变更；
- 不无测试重写核心运行链路；
- 不按固定行数机械拆文件；
- 不强制所有历史文件立即达到阶段 2 新阈值。

## 6. 前置依赖

- 阶段 1–3 完成；
- 新增 finding 和历史 debt 恶化已被 CI 稳定阻止；
- 结构、碎片、重复、覆盖率和豁免数据可聚合；
- 初始 Root Go 484 条逐项台账及阶段 2–3 新增 cohort/趋势快照均可复现；
- 核心区域有可运行的聚焦回归测试。

## 7. 输入条件

- `docs/fix/2026-07-10-code-guard-484-findings-audit.md`；
- Root、Desktop 和后续规则 baseline；
- 文件/函数修改频率；
- 测试与覆盖率数据；
- 碎片和重复趋势；
- 生效、临期和过期豁免；
- 线上缺陷或高风险模块信息。

## 8. 扫描对象

- 所有历史 structure debt；
- 历史碎片和重复趋势；
- Root、Desktop、Frontend 覆盖率趋势；
- 所有守卫豁免；
- 优先治理区域及其调用方、状态所有权和测试；
- 治理 PR 新增的文件、函数和抽象。

## 9. 本阶段新增守卫

- baseline 总量单调不增；
- 已治理条目回归检测；
- debt 趋势报告；
- 豁免到期门禁；
- 治理变更的行为回归和覆盖率要求；
- “拆大又造碎片/重复”交叉检查；
- 已清理区域阈值收紧或 baseline 取消机制。

## 10. 规则定义

### 10.1 趋势维度

周期性报告至少统计：

- 超长文件数；
- 超长函数数；
- 函数参数数问题；
- 圈复杂度问题数和累计超限量；
- 嵌套深度问题数；
- 包文件数量问题；
- 碎片候选数量和比例；
- 重复代码数量和比例；
- 普通与高风险变更覆盖率；
- baseline 总量；
- 生效、临期、过期豁免数量。

### 10.2 治理优先级

优先级综合以下因素：

- 同时命中多个规则；
- 超限倍数；
- 修改频率；
- 位于权限、执行、配置、会话等核心链路；
- 缺少测试或覆盖率；
- 历史缺陷关联；
- 能否形成职责清晰的独立治理批次。

### 10.3 治理约束

每个批次必须：

- 声明行为保持范围；
- 先有或补充回归测试；
- 降低明确 baseline 条目；
- 不增加碎片、重复或纯转发层；
- 不降低覆盖率；
- 不混入无关业务变化；
- 显式更新并评审 baseline。

## 11. 阈值

Root/Desktop Go 历史规则继续使用其启用阈值，治理完成区域逐步采用阶段 2 新阈值。Frontend 结构 cohort 使用等价度量验证后独立冻结的阈值，不直接套用下表：

| 指标 | 原 Root v1 阈值 | 阶段 2 Warning | 阶段 2 Error |
|---|---:|---:|---:|
| 函数有效行数 | 80 | 40 | 60 |
| 圈复杂度 | 10 | 8 | 10 |
| 嵌套深度 | 4 | 3 | 4 |
| 函数参数数 | 不适用 | 5 | 7 |
| 文件有效行数 | 800 | 400 | 600 |
| 单包生产文件数 | 30 | 24 | 30 |

趋势目标：在 cohort 和规则版本集合固定的前提下，各 cohort 及汇总 baseline 总量只能持平或下降，治理批次必须至少减少其声明的目标条目。新增模块或规则版本必须建立独立 cohort，不能混入旧总量制造虚假增减。

## 12. 硬门禁

阶段 1–3 的全部门禁继续生效；以下为本阶段新增或收紧的门禁：

- baseline 总量增加；
- 任一历史条目恶化；
- 已治理并移除的条目重新出现；
- 治理变更缺少要求的回归测试；
- 治理后覆盖率下降超过允许范围；
- 为降低体量新增硬门禁碎片、重复或纯转发包装；
- baseline 更新包含非本批次目标且无说明；
- 豁免到期未处理或未重新审批；
- 治理引入编译、测试或运行链路失败。

## 13. Warning

- baseline 在一个报告周期内没有下降；
- 高风险热点持续修改但没有治理计划；
- 豁免临近到期；
- 单项指标下降但碎片或重复上升；
- 文件拆分后跨文件状态耦合增加；
- 治理批次范围过大；
- 历史 debt 对应代码缺少足够测试证据。

## 14. Debt 处理

- 初始 Root Go 484 条 cohort 保持稳定 ID 和历史轨迹；阶段 2–3 新增 cohort 也必须分别保持稳定身份和版本；
- 每次治理记录移除、改善、移动和规则变化；
- 改名或移动不能被自动视为修复；
- 一项重构同时解决多个 finding 时逐项关闭；
- 暂不治理的问题保持 debt，不使用永久豁免掩盖；
- 趋势报告区分 Root、Desktop 和不同规则版本。

## 15. Baseline 处理

- 治理前记录目标 key 和当前值；
- 治理后运行全量只读扫描；
- 确认目标改善且没有新增/恶化；
- 通过独立命令显式刷新 baseline；
- baseline diff 只包含已证明改善或消失的条目；
- baseline 更新与代码修复在同一评审单元中，但不能由检查命令隐式生成；
- 已清理目录可取消对应历史豁免并启用更严格阈值。

## 16. 豁免方式

- 历史治理可以对明确阻塞、风险过高或外部依赖场景申请延期；
- 延期仍需规则、符号、原因、负责人和到期日期；
- 豁免不改变 debt 实际值和趋势；
- 过期后必须治理或重新审批；
- 不允许以“历史代码”为永久原因。

## 17. 本地触发方式

每个治理批次本地至少执行：

```sh
make guard-fast
make code-guard
make pr-ready
```

先运行聚焦测试，再运行受影响模块和完整 PR Ready。baseline 只在证据确认后通过独立更新入口刷新。

## 18. CI 触发方式

- 普通 PR CI 阻止新增、恶化和已治理条目回归；
- 治理 PR 额外校验目标 key、baseline diff 和覆盖率；
- 定时任务生成 debt、碎片、重复、覆盖率和豁免趋势；
- 趋势 artifact 保留可比较周期；
- 过期豁免在普通 CI 中失败。

## 19. 失败输出格式

趋势和回归输出示例：

```text
ERROR [debt.regression] complexity|internal/x.go|Service.Run resolved_at=<commit> current=12 limit=10
ERROR [baseline.scope] unexpected baseline change key=<key> batch=<batch-id>
```

报告必须显示本周期起点、终点、净变化、目标条目、意外新增、豁免变化和覆盖率变化。

## 20. 开发建议

- 按职责和状态所有权拆分，不按固定行数切块；
- 每批选择一个可独立评审的子系统；
- 优先提取纯逻辑、解析、策略和渲染单元；
- 避免在同一批次改变公共行为；
- 先增强测试再移动复杂控制流；
- 用调用图和实际使用路径确定边界；
- 合并高度相关的小函数，避免 helper 泛滥。

## 21. 实施注意事项

- `controller.go`、`agent.go` 和 `boot.go` 具有高调用半径，必须小批次治理；
- `internal/cli` 文件数已经超限，不能继续按命令碎片化；
- `memorycompiler` 涉及持久状态和策略，需保护数据兼容；
- `chat_tui.go` 同时命中大量问题，拆分时保持事件和键盘状态一致；
- baseline 下降不能替代行为验证；
- 治理文件移动要保留历史 key 迁移说明。

## 22. 对应测试

- 目标行为的现有测试先通过；
- 新增边界测试在重构前能覆盖目标行为；
- 拆分后聚焦测试、模块测试和全量测试通过；
- baseline 只减少声明条目；
- 无新增、恶化、碎片和重复 error；
- 覆盖率不下降；
- 已治理条目回归测试；
- 趋势报告跨周期一致；
- 豁免临期、到期和续期测试。

## 23. 阶段交付物

- 周期性质量趋势报告；
- 历史 debt 优先级清单；
- 分批治理任务及行为边界；
- baseline 收敛记录；
- 已治理条目回归清单；
- 豁免到期报告；
- 已清理区域阈值收紧记录；
- 每批次回归测试和验证证据。

## 24. 验收标准

- baseline 总量不增加并持续下降；
- 每个治理批次有明确行为边界和回归测试；
- baseline diff 与目标条目一致；
- 没有通过碎片、包装或复制规避指标；
- 高风险区域按优先级开始退出 baseline；
- 已治理条目重新出现时 CI 失败；
- 趋势报告能反映结构、碎片、重复、覆盖率和豁免变化；
- 过期豁免不会静默继续生效。

## 25. 完成定义

历史 debt 已进入可持续治理循环：新增与恶化被阻止，趋势可观测，重点区域按测试保护分批收敛，已治理问题不会回归，且没有产生新的指标规避债务。

## 26. 进入下一阶段的条件

阶段 4 是 v0.1.0 最后阶段。完成后进入版本总体验收，必须满足 `docs/guard/v0.1.0/goal.md` 的完成定义和整体质量指标。

## 27. 风险

- 核心文件重构造成行为回归；
- 治理范围过大导致难以评审；
- 指标下降但模块边界变差；
- 测试不足导致“行为不变”证据薄弱；
- baseline key 移动被误认成修复；
- 趋势报告无人负责而失去治理作用。

## 28. 暂不处理事项

- 与 debt 无关的功能开发；
- 无测试保护的全仓重写；
- 一次性清零全部 484 条；
- 仅为数字达标的机械拆分；
- 自动代码重写和自动 baseline 提交。

## 附：建议治理顺序

1. 同时命中多个 P0/P1 指标的函数：`internal/boot/boot.go:Build`、`internal/cli/chat_tui.go:chatTUI.update`、`internal/config/render.go` 的两个大型渲染函数。
2. 核心状态和执行链路：`internal/control/controller.go`、`internal/agent/agent.go`、`internal/memorycompiler/runtime.go`。
3. 包级热点：`internal/cli`，治理时优先重组职责，禁止继续新增零碎文件。
4. 其余集中热点按文件批次处理，最后处理单项轻度超限。
