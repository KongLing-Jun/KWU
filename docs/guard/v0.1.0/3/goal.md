# 阶段 3：碎片代码、重复代码与变更覆盖率守卫

## 1. 阶段名称

碎片代码、重复代码与变更覆盖率守卫。

## 2. 阶段背景

结构阈值能够限制大函数和大文件，却可能诱导 AI 通过一函数一文件、纯转发包装或复制粘贴规避。编译与测试通过也不能证明新增逻辑被充分验证。阶段 3 使用组合规则识别这些问题，并采用 warning 观察后逐步硬化的方式控制误报。

## 3. 当前问题

- 小文件不一定是碎片，单一最小行数规则会误伤清晰边界；
- 机械拆函数可以让单函数指标下降但整体维护成本上升；
- 新增代码可能复制已有实现；
- 全仓历史重复代码量未知，直接硬化会阻塞开发；
- 当前覆盖率只有报告，没有变更行门槛；
- 生产代码变化但测试不变时缺少统一证明；
- flaky 和 fuzz 验证尚未分层。

## 4. 阶段目标

建立可解释的碎片候选、增量重复和变更覆盖率规则；先收集 warning，误报可控后只将确定性场景升级为 error，同时保持平台、协议、迁移、模型和插件边界不被误伤。

## 5. 非目标

- 不把所有短文件判为错误；
- 不对全仓历史重复代码立即失败；
- 不要求历史低覆盖率包一次达到 70%；
- 不以覆盖率替代断言质量和行为测试；
- 不在普通 PR 中执行长时间 fuzz；
- 不为了消除碎片把无关职责重新塞入大文件。

## 6. 前置依赖

- 阶段 2 完成；
- 新增/修改文件和语法声明可可靠识别；
- 结构 finding、豁免和报告模型稳定；
- Root/Desktop/Frontend 测试能够产生可映射的覆盖数据；
- 基础分支覆盖率和当前分支覆盖率可比较。

## 7. 输入条件

- 阶段 2 的 warning 样本；
- PR 新增生产文件集合；
- 基础分支和当前分支源码 diff；
- Go 与 Frontend 覆盖率报告；
- 高风险目录清单：权限、沙箱、路径、审批及后续明确加入的等价区域；
- 自动排除目录和文件语义。

## 8. 扫描对象

- Root Go、Desktop Go、Frontend 新增生产文件；
- 新增和修改的生产代码块；
- 新增顶层声明和函数调用包装；
- 同包和跨包新增重复；
- PR 变更行及对应测试覆盖；
- 测试代码只参与覆盖率和单独的重复提示，不参与生产碎片 error；
- 生成、迁移、平台、协议、数据模型、插件入口按规则排除。

## 9. 本阶段新增守卫

- 碎片候选组合识别；
- 纯转发小文件 warning，以及观察期达到升级条件后的 error；
- PR 碎片数量和比例；
- 增量相似代码 warning；
- 完全相同生产逻辑 warning；
- 多层纯转发包装 warning；
- 普通和高风险变更行覆盖率；
- 包覆盖率回退；
- 无测试变化证明要求；
- 受影响包 flaky 重复执行；
- 夜间 fuzz smoke。

## 10. 规则定义

### 10.1 碎片候选

文件必须同时满足：

1. 有效行不超过 30；
2. 顶层声明不超过两个；
3. 主要内容只有一个私有函数、包装函数或常量；
4. 没有独立平台、协议、接口、迁移、测试、数据模型、插件或适配器边界。

自动排除：平台专用文件、build tag、生成代码、数据库迁移、明确接口、协议类型、数据模型、独立插件和适配器入口。

### 10.2 碎片升级

- 初始版本全部 warning；
- warning 收集至少 30 个 PR 样本，误报率低于 5% 后才允许升级；
- 不超过 10 个有效行且只做一次转发的生产文件升级为 error；
- 同一 PR 新增至少三个碎片候选升级为 error；
- PR 新增至少三个生产文件时，碎片候选占比超过 40% 升级为 error；
- 新增文件导致单包生产文件数超过 30 继续为 error。

### 10.3 重复代码

- 100 token 以上相似新增代码块：warning；
- 200 token 以上高度重复：观察后候选 error；
- 完全相同的 12 行以上生产逻辑：warning；
- 连续两层以上纯转发包装：warning；
- 历史重复只报告为 debt。

重复规则必须忽略格式、标识符轻微变化造成的表面差异，同时对协议映射、表驱动数据和必要平台实现提供豁免。

### 10.4 变更覆盖率

- 普通新增或修改可执行行覆盖率不低于 70%；
- 权限、沙箱、路径、审批等高风险代码不低于 85%；
- 历史包整体覆盖率相对基础分支下降不得超过 2 个百分点；
- 纯删除、类型声明和不可执行行不进入分母；
- 无测试文件变化时，报告必须给出现有测试命中的覆盖证据或具体豁免。

## 11. 阈值

| 规则 | Warning | Error |
|---|---:|---:|
| 碎片候选有效行 | ≤30 | 观察期后符合组合条件 |
| 纯转发生产文件有效行 | ≤30 | ≤10（观察期后） |
| 同 PR 碎片候选数 | 1–2 | ≥3（观察期后） |
| 碎片占新增生产文件比例 | >20% | >40% 且新增生产文件≥3（观察期后） |
| 相似代码块 | ≥100 token | ≥200 token 经验证后 |
| 完全相同生产逻辑 | ≥12 行提示 | 经规则升级评审后 |
| 普通变更行覆盖率 | — | <70% |
| 高风险变更行覆盖率 | — | <85% |
| 历史包覆盖率回退 | warning 接近 2pp | >2pp |

## 12. 硬门禁

阶段 1–2 的全部门禁继续生效；以下为本阶段新增或收紧的门禁：

- 已完成观察升级的纯转发小文件、碎片数量和碎片比例规则；
- 普通变更行覆盖率低于 70%；
- 高风险变更行覆盖率低于 85%；
- 历史包覆盖率下降超过 2 个百分点；
- 覆盖率报告缺失、无法映射或基础分支不可用；
- 已升级为 error 的高置信度重复代码；
- 使用无效豁免绕过测试或覆盖率。

## 13. Warning

- 观察期内所有碎片候选；
- 碎片候选比例超过 20%；
- 100 token 以上相似代码块；
- 完全相同的 12 行以上生产逻辑；
- 两层以上纯转发包装；
- 200 token 高度重复在升级前；
- 生产代码变化但测试文件无变化；
- 受影响包重复执行出现不稳定结果；
- fuzz smoke 发现非确定失败。

## 14. Debt 处理

- 阶段启用时扫描全仓历史碎片和重复，只做趋势 debt；
- 不把历史碎片数量计入当前 PR 的新增比例；
- 历史低覆盖率包只要求不回退；
- 历史重复修复后从趋势数据下降，不要求立即维护逐项 baseline；
- 新增问题不得通过重新生成 debt 快照被吸收。

## 15. Baseline 处理

- 碎片和重复历史快照与结构 baseline 分开标识规则版本；
- 变更覆盖率使用基础分支报告，不把百分比写入静态 baseline；
- warning 升级为 error 时重新记录启用日期和历史 debt；
- 普通检查只读；
- 规则算法变化必须提供前后差异报告。

## 16. 豁免方式

允许对必要平台重复、协议映射、生成边界、数据库迁移、明确接口/模型和无法自动采集覆盖率的受控场景申请豁免。覆盖率豁免必须说明不可执行行或已有验证证据，不能使用“测试以后补”作为原因。

## 17. 本地触发方式

- `make guard-fast`：当前 diff 的碎片、重复和相关包测试；
- `make code-guard`：全量结构及历史趋势报告；
- `make pr-ready`：完整变更覆盖率和模块验证；
- 夜间 flaky/fuzz 不进入默认快速入口。

## 18. CI 触发方式

- PR CI 读取完整 diff、基础分支覆盖率和当前覆盖率；
- warning 写入 step summary；
- error 进入必需检查；
- 覆盖率报告作为 artifact 保存；
- 夜间任务执行受影响包重复测试和限定时间 fuzz；
- warning 升级需通过规则配置变更和评审，不随数据自动切换。

## 19. 失败输出格式

碎片报告必须显示候选条件：

```text
WARNING [fragment.file] internal/x_helper.go lines=18 declarations=1 private_wrappers=1 boundary=none
```

覆盖率报告必须显示文件、变更可执行行、覆盖行、百分比、要求和未覆盖行号。重复报告必须显示两处位置、token/行数和相似度证据。

## 20. 开发建议

- 碎片规则采用组合判断，不设置全局最小文件行数；
- 重复分析只聚焦新增或修改代码，控制 CI 时间；
- 覆盖率复用 Go coverprofile 和 Frontend 现有测试运行时可验证输出；
- 高风险目录使用显式清单和评审变更；
- warning 数据按规则记录确认、误报和豁免结果。

## 21. 实施注意事项

- 小文件可能是正确边界，不能只凭行数失败；
- 单个 PR 只有一个新文件时不能因 100% 比例直接失败；
- TypeScript 类型、声明和不可执行 JSX 行不能错误进入覆盖分母；
- 测试覆盖率上升不代表断言有效；
- 重复检测必须控制测试 fixture 和协议映射误报；
- fuzz 失败需要保存 seed 和复现命令。

## 22. 对应测试

- 四个碎片候选条件的排列组合；
- 所有自动排除类型；
- 1、2、3 个候选和 20%/40% 比例边界；
- 10 行纯转发 error 与合法小型接口；
- 99/100/199/200 token 重复边界；
- 完全相同 11/12 行边界；
- 普通覆盖率 69.99/70、高风险 84.99/85；
- 包覆盖率下降 2pp 边界；
- 删除、声明和不可执行行排除；
- 基础分支报告缺失和覆盖映射失败；
- 合法、过期和越界豁免；
- fuzz seed 可复现。

## 23. 阶段交付物

- 碎片候选分析器；
- 自动排除规则；
- PR 碎片数量与比例报告；
- 增量重复分析；
- 变更行和包覆盖率比较；
- 高风险清单；
- warning 误报统计；
- flaky 重复执行和夜间 fuzz；
- 单元、集成和边界测试；
- 使用与豁免说明。

## 24. 验收标准

- 一函数一文件和纯转发文件能被识别；
- 合法平台、协议、迁移、模型和插件边界不被误判；
- 新增复制块能被定位；
- 历史重复和碎片不阻塞普通 PR；
- 普通和高风险覆盖率阈值稳定执行；
- 包覆盖率回退能被阻止；
- warning 升级前至少有 30 个 PR 样本且误报率低于 5%；
- 报告能够解释每个判定条件。

## 25. 完成定义

碎片、重复和变更覆盖率规则已运行，确定性场景形成硬门禁，启发式场景具有误报统计和升级机制，历史问题保持 debt，不会诱导机械聚合或拆分。

## 26. 进入下一阶段的条件

- 阶段 3 完成定义满足；
- 新增结构、碎片、重复和覆盖率违规已被稳定控制；
- 趋势数据至少能按规则、目录、包和时间聚合；
- 历史治理优先级可依据热点、修改频率和测试风险排序。

## 27. 风险

- 启发式误报诱导无意义合并；
- 重复检测增加 CI 时间；
- 覆盖率工具跨语言口径不一致；
- 开发者可能编写无价值测试只为覆盖率；
- 动态 import 和平台代码造成覆盖映射缺口；
- warning 自动升级会造成不可控门禁变化。

## 28. 暂不处理事项

- 全仓历史重复 error；
- 全部 484 条 debt 修复；
- 长时间普通 PR fuzz；
- 用 AI 语义判断替代可解释静态规则；
- 自动修改代码以消除碎片或重复。
