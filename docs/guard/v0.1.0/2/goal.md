# 阶段 2：新增代码结构与实现完整性守卫

## 1. 阶段名称

新增代码结构与实现完整性守卫。

## 2. 阶段背景

阶段 1 只能保证现有检查可靠执行，仍不能阻止 AI 生成过长函数、参数过多、占位实现、未进入构建图或未进入注册链路的代码。阶段 2 优先实现可确定判断的问题，并为高误报设计问题保留 warning。

## 3. 当前问题

- 当前函数有效行 error 80、文件 error 800，对新增 AI 代码约束偏宽；
- 没有 warning 层；
- 没有参数数量规则；
- `panic("TODO")`、`not implemented`、空函数体可能进入生产代码；
- 新文件可能不在 Frontend 构建图；
- 新工具、命令、路由或配置可能只完成定义，没有注册和运行时接入；
- 机械拆出的纯转发函数可规避行数规则。

## 4. 阶段目标

对新增和修改的 Root/Desktop Go 生产代码应用更严格的结构阈值；Frontend 只在等价度量验证并单独冻结阈值后启用结构门禁。所有模块都阻止确定性占位、构建遗漏和已知接入契约遗漏，同时用 warning 暴露可疑抽象、迁移和测试缺口。

## 5. 非目标

- 不对所有历史代码追溯执行新 error；
- 不一次性修复阶段启用时发现的新规则历史 debt；
- 不用引用次数硬判所有反射、插件或外部 API；
- 不在本阶段硬化碎片比例和重复代码；
- 不用静态接入检查替代运行测试。

## 6. 前置依赖

- 阶段 1 完成；
- finding、严重度、baseline、豁免和报告模型稳定；
- Root/Desktop/Frontend 均进入 CI；
- 能够识别基础分支与当前分支的新增、修改和历史条目。

## 7. 输入条件

- 当前 Root 484 条 debt；
- 阶段 1 提供只读增量比较；
- 阶段 0 已冻结 40/60 等新阈值；
- 已列出项目中可确定检查的工具、命令、路由和配置注册模式；
- Frontend build/typecheck/test 能识别构建遗漏。

## 8. 扫描对象

- Root Go 新增和修改的生产文件、函数和方法；
- Desktop Go 新增和修改的生产文件、函数和方法；
- Frontend TypeScript/TSX 新增和修改代码；在等价度量验证完成前只应用构建图、确定性完整性和既有构建测试，不应用 Go 结构阈值；
- 新增工具、命令、路由和配置声明；
- 相关注册表、构造函数、配置加载/保存和运行时读取点；
- 测试变化只作为完整性证据，不套用生产结构硬限制；
- 生成代码排除结构检查，但生成器本身参与。

## 9. 本阶段新增守卫

- Root/Desktop Go 结构 warning/error 双阈值；
- Root/Desktop Go 函数参数数量；
- 确定性占位实现；
- 新增空函数体；
- 源文件构建图检查；
- 已知工具、命令和路由注册契约；
- 用户可配置字段的加载、保存和运行时读取契约；
- 无生产调用方、单实现接口、新旧并存、无测试变化 warning；
- 纯转发包装链 warning。

## 10. 规则定义

### 10.1 结构规则

- 有效行数使用语法分析，排除空行、纯注释、单纯括号和生成内容；
- 复杂度沿用项目 AST 定义，warning 和 error 共用同一计算器；
- 参数数不包含 receiver，包含普通参数和命名结果参数；
- 新增函数直接应用 warning/error；
- Frontend 结构规则只有在语法级等价度量验证、阈值独立冻结和边界测试完成后才启用，禁止直接复用 Go 物理行数或数值阈值；
- 修改的历史函数不得恶化，跨过 error 阈值时失败；
- 规则启用时已超新阈值的代码进入该规则的起始 debt。

### 10.2 占位与空实现

确定性匹配包括：

- Go `panic("TODO")` 或等价明确 TODO panic；
- TypeScript `throw new Error("TODO")`；
- 明确返回 `not implemented` 的新生产实现；
- 新增无语句函数体或方法体。

合法 no-op 必须通过具体、未过期豁免说明契约原因，不能靠模糊注释自动跳过。

### 10.3 构建图

- Go 新文件必须被所属模块的 `go list`/build 识别；
- TypeScript/TSX 新文件必须被 tsconfig、import 图或明确入口包含；
- 平台和 build tag 文件必须至少进入对应平台的构建验证。

### 10.4 接入契约

只对项目已有、可确定的模式启用 error：

- 工具声明必须进入工具注册表；
- 命令声明必须进入命令目录或分派表；
- 路由声明必须进入路由注册入口；
- 用户可配置字段必须进入加载、保存/渲染和至少一个运行时读取点。

反射、插件发现或外部消费无法可靠判断时只 warning。

## 11. 阈值

以下数值适用于 Root Go 和 Desktop Go：

| 指标 | Warning | Error |
|---|---:|---:|
| 函数有效行数 | 40 | 60 |
| 圈复杂度 | 8 | 10 |
| 嵌套深度 | 3 | 4 |
| 函数参数数 | 5 | 7 |
| 文件有效行数 | 400 | 600 |
| 单包生产文件数 | 24 | 30 |

阈值只对新增和恶化形成硬门禁。启用日之前的同规则超限值进入 debt。

Frontend TypeScript/TSX 的结构阈值不在本表中预设；完成等价度量验证后，必须通过独立规则版本冻结其适用阈值、排除项和边界测试，再启用对应门禁。

## 12. 硬门禁

阶段 1 的全部基础门禁继续生效；以下为本阶段新增或收紧的门禁：

- 新增结构值超过 error；
- 修改后结构值相对基础分支恶化并超过 error；
- 新增确定性 TODO/not implemented 占位；
- 新增空生产函数体；
- 新源文件未进入应有构建图；
- 已纳入确定契约的工具、命令或路由未注册；
- 已纳入确定契约的配置缺少加载、保存/渲染或运行读取；
- 通过删除测试或弱化现有断言规避门禁。

## 13. Warning

- 指标超过 warning 但未达到 error；
- 导出符号没有已知生产调用方；
- 新接口只有一个实现且没有替换说明；
- 配置字段只出现在定义或序列化位置；
- 新旧能力并存但缺少迁移说明；
- 生产代码变化但测试没有变化；
- 两层及以上纯转发包装；
- 函数拆分后参数和状态几乎原样传递；
- 接入链路因反射或插件机制无法确定。

## 14. Debt 处理

- 当前 484 条继续保持原 debt；
- 新阈值启用前，对 Root、Desktop，以及已完成等价度量验证并启用结构规则的 Frontend 生成一次只读起始快照；
- 例如历史 61–80 行函数可进入 `func_lines_v2` debt，不立即失败；
- 同一源码问题不得在旧规则和新规则 baseline 中无解释重复计数；
- debt 只允许保持或下降。

## 15. Baseline 处理

- 新规则使用独立规则 ID 和版本；
- 启用新规则时显式生成并评审起始 baseline；
- 普通检查继续只读；
- 新增函数不允许借 baseline 更新进入历史 debt；
- 规则计算方式变化必须升级规则版本并提供迁移报告。

## 16. 豁免方式

允许对合法 no-op、平台占位、外部 API、反射注册和协议生成边界申请具体豁免。豁免必须指向规则和符号，解释为何代码在运行时有效，并提供到期日期。不得用豁免接受普通 TODO 或未编译代码。

## 17. 本地触发方式

- `make guard-fast`：扫描变更函数、文件和已知接入契约；
- `make code-guard`：全量结构和完整性只读扫描；
- `make pr-ready`：扫描后运行 Root/Desktop/Frontend 验证；
- IDE 或 pre-commit 集成不作为 v0.1.0 必需入口。

## 18. CI 触发方式

- 阶段 1 Code Guard job 加载阶段 2 规则；
- 使用基础分支扫描结果判断新增和恶化；
- build graph 和接入契约检查在结构扫描后运行；
- Root/Desktop/Frontend 构建测试继续作为最终硬门禁；
- warning 写入 step summary 和 JSON artifact，不改变退出码。

## 19. 失败输出格式

结构 finding 示例：

```text
ERROR [go.func_lines] new internal/x.go:42 Service.Run current=74 warning=40 error=60
```

完整性 finding 必须显示缺失链路：

```text
ERROR [tool.registration] internal/tool/x.go:20 NewXTool
  declaration: found
  registry: missing
  expected: tool registration entry and focused registration test
```

## 20. 开发建议

- 使用现有 Go AST，不增加另一个 Go 解析器；
- Frontend 优先复用 TypeScript compiler API 或现有构建图；
- 接入规则按工具、命令、路由、配置分别实现，不写一个泛化猜测器；
- warning 与 error 共享度量，避免同指标结果不一致；
- 把合法例外写成小范围豁免，不在规则里堆路径特判。

## 21. 实施注意事项

- 60 行 error 不能追溯阻止所有历史函数；
- 匿名函数如何计入复杂度必须沿用并记录现有定义；
- Go 平台文件需要跨平台构建证据；
- 空函数可能是合法 no-op，必须支持可审计豁免；
- 无调用方检测不能把公开库 API 或插件入口直接判为 error；
- 配置链路检查要区分反射序列化与显式读写。

## 22. 对应测试

- 每个结构阈值的 warning-1、warning、error-1、error、error+1；
- Frontend 等价度量未验证时不启用结构门禁，验证并冻结独立阈值后才执行相应边界测试；
- 新函数、修改历史函数、未修改 debt；
- TODO panic、TypeScript TODO throw、not implemented、空函数；
- 合法 no-op 豁免和过期豁免；
- Go/TypeScript 构建图包含与遗漏；
- 工具、命令、路由注册正反例；
- 配置加载、保存和运行读取正反例；
- 反射/插件不确定场景只 warning；
- 纯转发包装 warning；
- 文本和 JSON 输出一致。

## 23. 阶段交付物

- 新结构阈值规则；
- 参数数规则；
- 占位和空实现规则；
- 构建图检查；
- 已知注册/配置契约检查；
- warning 规则集；
- 新规则起始 debt；
- 单元、集成和跨模块测试；
- 规则说明和修复建议。

## 24. 验收标准

- 新增 61 行函数失败，41–60 行 warning，40 行及以下不触发行数规则；
- 现有历史超限函数未恶化时不失败；
- 确定性占位、空实现和构建遗漏被阻止；
- 已纳入契约的注册遗漏被阻止；
- 启发式调用方和抽象问题只 warning；
- Root/Desktop/Frontend 都有对应验证；
- Frontend 不会在等价度量验证前直接套用 Go 结构阈值；
- 没有通过 baseline 更新把新增 error 变成 debt；
- 误报能够通过具体、到期豁免处理。

## 25. 完成定义

新增和修改的 Root/Desktop Go 生产代码已经受到结构双阈值约束；Frontend 仅在等价度量验证和独立阈值冻结后启用对应结构门禁。所有模块均受到确定性完整性门禁约束，历史代码兼容，启发式问题有可统计 warning，且全套规则测试通过。

## 26. 进入下一阶段的条件

- 阶段 2 完成定义满足；
- 结构和完整性 warning 运行稳定；
- warning 样本能够支持碎片和重复规则设计；
- 受影响文件和 PR 新增文件可可靠识别；
- 覆盖率能以基础分支为参照计算。

## 27. 风险

- 新阈值历史快照不完整会阻塞正常修改；
- 接入契约过度泛化会误报插件和反射路径；
- 参数数规则可能诱导无意义参数对象；
- 行数规则可能诱导机械拆函数；
- Frontend 构建图识别可能受到动态 import 影响。

## 28. 暂不处理事项

- 碎片候选比例 error；
- 重复代码 error；
- 变更行覆盖率门禁；
- 全仓历史结构修复；
- 对所有外部插件的通用调用链证明。
