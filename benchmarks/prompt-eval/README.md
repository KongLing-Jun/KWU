# Prompt evaluation benchmark

This benchmark reuses the production `boot.Build` path, Scene selection, tools,
Controller, and usage events. It never reads the user's normal profile. Real
runs require all three values explicitly:

```powershell
$env:PROMPT_EVAL_API_KEY = '<runtime-only key>'
go run ./benchmarks/prompt-eval -endpoint '<confirmed URL>' -model '<confirmed model>' -suite diagnostic
```

The runner pins that environment value into the disposable profile credential
store required by production boot, then deletes the whole profile after the run.
It never writes the key to the project config, report, or result directory.
Each scored attempt runs in a child process. The parent sends cancellation at
the configured task timeout and forcibly reclaims a worker that ignores it after
a short cleanup grace, so a stuck provider request cannot stall the full suite.
When grader equivalences change, `-rescore-dir <raw-result-dir>` writes a new
derived report tied to the original manifest without making model calls or
overwriting the source report.

Use `-manifest-only` for a network-free manifest check. `-prompt-file` evaluates
an alternate base prompt; `-scene-mode unset` supports Scene on/off comparison.
Use `-task <exact-id> -repeats 1` for a minimal connectivity smoke run.
Raw artifacts and reports go under ignored `.codex-run/prompt-eval/results`.
Only sanitized summaries may be copied into versioned documentation.

The Compact, Standard, and Extended files in `candidates/` cover the same
execution loop with different explanatory depth. Reports record both the
repository's conservative static token estimate and provider-reported runtime
usage. End-to-end success wins; equal-effect candidates are ranked by cost.

## Frozen Desktop task assets

Desktop execution is intentionally separate from the Controller runner. The
following command creates one deterministic, initially empty task workspace and
prints the exact user prompt, Scene, fixture hash, suite manifest, and absolute
workspace path. It does not call a model or read the normal user profile:

```powershell
go run ./benchmarks/prompt-eval -task desktop-office-project-report -desktop-prepare '<new-or-empty-directory>'
```

Run the printed prompt through the real Wails Desktop in the printed workspace.
Then grade the artifacts offline:

```powershell
go run ./benchmarks/prompt-eval -task desktop-office-project-report -desktop-grade '<completed-workspace>' -desktop-observation '<observation.json>'
```

The frozen task IDs are:

- `desktop-office-project-report`
- `desktop-office-budget-analysis`
- `desktop-coding-retry-policy`
- `desktop-coding-nested-config`
- `desktop-design-empty-state`
- `desktop-design-operations-dashboard`

`-desktop-prepare` refuses a non-empty directory and never deletes an existing
workspace. Office fixtures are deterministic DOCX/XLSX containers generated by
the benchmark, not opaque hand-edited binaries. The manifest covers task text,
fixture content, expected outputs, preserved inputs, and embedded task/grader
source hashes.

Artifact grading never infers whether Desktop completed normally. Supply a
separate observation JSON after inspecting the real application. All four
boolean fields below are required; Design tasks additionally require
`visual_opened` and `visual_passed` after rendering the artifacts:

```json
{
  "build": "baseline",
  "repeat": 1,
  "run_completed": true,
  "scope_preserved": true,
  "false_claim": false,
  "timed_out": false,
  "visual_opened": true,
  "visual_passed": true,
  "model_calls": 0,
  "tool_calls": 0,
  "approval_count": 0,
  "model_duration_ms": 0,
  "approval_wait_ms": 0,
  "runtime_finding_ref": "",
  "notes": ""
}
```

Raw workspaces, observations, and reports belong under ignored
`.codex-run/prompt-eval/`. They must not contain provider credentials; only
sanitized conclusions may be copied into versioned documentation.
